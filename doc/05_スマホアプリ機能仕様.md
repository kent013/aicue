# 05. スマホアプリ機能仕様

出典: `動画マニュアル作成支援システム_スマホアプリ_2.xlsx`（ユースケース / 機能一覧 / 構成要素）、`動画マニュアル作成支援システムページ展開_スマホアプリ6.pptx`、モックアップ `モック/動画アプリ/SP_アプリ`。

スマホアプリは **現場での撮影ツール**。PC で作られたシナリオを受け取り、カットごとの指示に従って撮影素材を集め、サーバーへ返す。iPhone を主対象とする。

## 5.1 画面一覧と遷移

```
ログイン画面
   ▼
シナリオ選択画面（一覧）──[絞り込み/検索]
   ▼ シナリオをタップ（＝登録済みテイクを自動DL）
シナリオ詳細画面 ─────────────────────────────┐
   │  ・手順/急所リストと撮影状況を確認              │
   │  ・撮影アイコン → 上部プレビューがカメラUIに切替  │
   │  ・[プレビュー] 全体連結再生                    │
   │  ・[アップロード] 新規テイクを送信              │
   ├──▶ 撮影UI（縦持ち：詳細画面内 / 横持ち：全画面）  │
   ├──▶ 再生画面（テイク個別再生・コメント編集）      │
   └──▶ 横持ち撮影/再生画面（全画面）───────────────┘
アカウント画面（ID/表示名/メール確認・ログアウト）
```

## 5.2 主要画面と機能

### ログイン画面
- ユーザー ID・パスワードでログイン（PC 版と共通 ID）→ シナリオ選択画面へ。ログイン失敗時はエラー表示。

### シナリオ選択画面
- シナリオをカード形式で一覧表示（サムネイル / タイトル / カテゴリ / 作成者 / 更新日 / **撮影進捗（未撮影 等）**）。
- **絞り込み**（右上アイコン）: 「すべてのシナリオ」「自分が作ったシナリオ」/ カテゴリ別（掃除・洗濯・料理・健康・技術 …）。
- **検索**: タイトルや原稿のキーワード。
- シナリオをタップ → 詳細画面へ。このとき**既に採用済みのテイクがサーバーから自動ダウンロード**される。

### シナリオ詳細画面（アプリの中心）
- 上部にプレビューエリア、中央にシナリオメタ情報（タイトル / TIME 合計 / カテゴリ・日付・作成者）、その下に **手順/急所リスト**。
- リストの各行は「`1 <手順>` ほうき・ちり取りの取り出し」「`2 <急所>` 落とさないように柄をしっかり握る」のように **番号・種別・内容** を表示。各行に赤いカメラ（撮影）アイコン。
- **撮影モード起動**: 行の撮影アイコンをタップ → 上部プレビューがカメラ映像（撮影 UI）に切替。
- **撮影ガイド**: 電球アイコンの横に、そのカットの撮影方法（構図指示）を表示。
- **ナレーション試聴**: 録画ボタン左の発話アイコンで当該カットのナレーションを再生（再タップで停止）。
- **字幕表示**: 録画ボタン右の字幕アイコンで、カメラ映像上に字幕を重畳（構図確認用。再タップで非表示）。
- **[プレビュー]**: 各カットの先頭（左端）テイクを連結した全体映像を確認。
  - **実装注記 (T191)**: 連結の素材は **採用テイク (`adopted_take_id`)** である。元資料の「一番左のテイクが
    全体プレビュー・採用候補」という記述は「左端 = 採用候補 = プレビューに使われるもの」という 1 つの概念を
    指しており、本実装はそれを明示的な採用状態として持つ。完成動画・サーバ生成プレビューと**同じ素材**を
    使わないと「通しで見て問題なかったのに完成動画は別物」になるため、採用テイクを正とする。
    使用できる採用テイク（採用済みかつ ready）が無いカットはプレースホルダになる
    （尺は `config('manual.preview_placeholder_seconds')`）。契約と保証しないものは
    `docs/architecture.md` §撮影 PWA の通し再生 (端末側連結再生) が正本。
- **[アップロード]**: 確認ダイアログで OK → その端末で新規撮影したテイクのみをサーバー送信 → 完了で「全テイクのアップロードが完了しました」。

### 撮影 UI（縦持ち / 横持ち）
- 中央の**赤い録画ボタン**で撮影開始。録画中はナレーションアイコン→**一時停止ボタン**、録画ボタン→**録画終了ボタン（四角）**に変化。
- **一時停止/再開**: 録画中に中断し、再タップで同じテイクの録画を継続。
- **録画終了**: 1 つの「テイク」として手順リストに保存。
- 補助機能: グリッド表示切替、カメラ反転（イン/アウト）、録画時間タイマー（00:00）。
- **横持ち（全画面）**: 上部カット名エリアを**左右スワイプで手順を前後移動**。録画制御は同様。録画後は下部サムネイルをタップして即再生確認 → 再撮影も即開始可能。撮影ガイド・字幕は透過オーバーレイで表示。

### テイク管理
- **複数テイク**: 同じカットに繰り返し録画。新しいテイクはリスト**左側（先頭）**に順次追加。
- **並べ替え（D&D）**: ドラッグで順序変更。**一番左のテイクが全体プレビュー・採用候補**として扱われる。
- **個別再生**: テイクをタップ → 再生画面へ。再生/一時停止、再生中のナレーション音声・字幕の ON/OFF（デフォルト両方 ON）。
- **コメント**: 再生画面の鉛筆アイコンから、テイクにコメント（例「このテイクがいちばんおススメ」）を登録・編集。
- **削除**: ゴミ箱アイコンで端末内テイクを削除。ただし**サーバーからダウンロードしたテイクは削除不可**。

### アカウント画面
- ログイン中のユーザー ID・表示名・メールアドレスを確認。ログアウトでログイン画面へ。

## 5.3 同期の要点（重複防止ロジック）

- 詳細画面遷移時: サーバーの採用済みテイクを端末へ**自動 DL**（入室時に `fetch` で実バイトを取得 → ACK `POST .../downloaded`。DL 済み枠は色/枠線で区別）。online 復帰時にも一度試みる。
- アップロード時: **新規撮影テイクのみ**送信。DL 済みテイクは自動的に除外。
- **`downloaded_at` は取得済み・同期済みを示す可用性指標であり、端末内保存・オフライン再生・ブラウザキャッシュ残存を保証しない**（ワークフロー単位のグローバル同期状態であり端末単位ではない。手動 DL ボタンと同一意味・同一 ACK 経路）。
- → PC ↔ アプリ間でテイクが二重登録されない設計。詳細は [02_システム全体像.md](02_システム全体像.md#23-テイクとカットの関係連携の核)。

## 5.4 検討中の論点（資料内メモ）

- 詳細画面のテイク一覧で、「はじめにダウンロードしたテイクを最初から表示するかどうか」は要検討。
- アップロード前に、送信したくないテイクをこの段階で選択削除する運用を想定。
