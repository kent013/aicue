# 08. システムアーキテクチャ設計（laravel-claude-template ベース）

本章は `tmp/laravel-claude-template`（LLM 駆動開発向け Laravel + Svelte SaaS テンプレート）をベースに、本プロジェクト（作業手順書 → AI シナリオ生成 → スマホでナビ撮影 → 自動合成）の**システム全体**を設計する。テンプレートの `docs/app-integration-guide.md` §2〜§7 が要求する「どの構造に何をマップしたか」の形式に沿う。

前提: [02_システム全体像](02_システム全体像.md)（ドメイン）／[03_AI解析とシナリオ生成](03_AI解析とシナリオ生成.md)（AI パイプライン）／[04](04_PCサイト機能仕様.md)・[05](05_スマホアプリ機能仕様.md)（画面・機能）。

## 8.2 ドメインモデル → tenancy マッピング（§2）

app-integration-guide §2 の「Project 配下が既定」に従い、[02章](02_システム全体像.md#24-データモデル主要エンティティ)の各エンティティを配置する。

| 本プロジェクトのエンティティ | テンプレート上の配置 | 根拠 |
| :-- | :-- | :-- |
| 契約企業 | **Organization** | テナント境界 |
| 部門（所属） | **CustomTeam** | 不要な導入は **Default Team パターン**で非表示（東洋金属のような単一部門はこれ） |
| 現場／ワークスペース | **Project** | 動画マニュアルの入れ物。最小導入は Default Project 1 個で可 |
| カテゴリ | **Category**（Project 配下マスタ）`project_id` NOT NULL | 複数マニュアルで共有される分類。削除時は所属マニュアルを「未分類」に |
| 動画マニュアル | **VideoManual**（Project 配下）`project_id` NOT NULL, `category_id` nullable | 迷ったら Project 配下（Item と同型）。1 レコード＝1 本の動画マニュアル |
| 手順書（AI 解析の入力） | **SourceDocument**（VideoManual 配下）`video_manual_id` NOT NULL | 抽出元ファイル＋構造化 JSON を保持 |
| 手順・急所 | **Cut**（VideoManual 配下）`video_manual_id` NOT NULL, `parent_cut_id` nullable, `type`(手順/急所) | シナリオの 1 行。急所は手順に紐づく親子構造 |
| テイク | **Take**（Cut 配下）`cut_id` NOT NULL | 撮影データ。採用フラグ・採用順・コメント・S3 キー |
| ローカル撮影データ | 端末内のみ。アップロードで **Take** に昇格 | アプリ固有・DB 非管理 |
| 非同期処理 | **AnalysisJob / RenderJob**（VideoManual 配下） | AI 解析・動画合成の状態機械（§8.7） |

> **設計判断（統合しないもの）**: `Category` と `Project` は「似ているから」で統合しない（AGENTS.md 原則4）。Project はテナント境界の重い概念、Category は削除で「未分類」に落ちる緩い分類。別物として保持する。

> **多態スコープの回避**: メディア実体を汎用 polymorphic テーブルにしない（§2.3 の多態スコープ trap）。ファイル参照は所有モデルの属性（`Take.video_path` 等）として持ち、実体は S3 の Project スコープ prefix に置く（§8.7）。

### ER（簡略）

```
Organization ─< CustomTeam(既定Team) ─< Project
                                          ├─< Category
                                          └─< VideoManual (category_id?)
                                                ├─ SourceDocument (手順書+抽出JSON)
                                                ├─< Cut (type=手順/急所, parent_cut_id?)
                                                │     └─< Take (adopted?, order, s3_key, comment)
                                                ├─< AnalysisJob (状態)
                                                └─< RenderJob (状態, output s3_key)
```

### 各リソース追加時の機械的手順（Item 見本のトレース）

VideoManual / Cut / Take / Category それぞれについて、Item の実装ファイル一式を写して作る:

- マイグレーション: 親 FK `constrained()` + NOT NULL + cascade
- Model: FK は `$fillable` 外、親 `BelongsTo`。子作成は `$parent->children()->create([...])`
- `MassAssignmentProtectedKeys` に**新規 FK 名**（`video_manual_id` / `cut_id` / `category_id`）を追記
- FormRequest: `ProhibitsProtectedKeys` + `missing` rule
- ルート: nested（Web は org-scoped 解決＋URL 整合 guard、API は `Route::scopeBindings()` / UrlIntegrityGuard）
- `NestedRouteIdorDefenseTest` の inventory に登録（**認可より前に 404**）
- Policy: 親 Policy 経由で org 所属確認（直 fetch 禁止）
- Factory: 親 Factory へ連鎖
- Feature テスト: 保護キー 422 / cross-org・cross-project 404 / 権限

## 8.3 ロール・権限マッピング（§3）

**構造（2 軸 5 ロール）は維持**し、アクター名はリネームで表現する。

| テンプレ既定ロール | 本プロジェクトの意味（リネーム） |
| :-- | :-- |
| organization_owner | 契約管理者（課金・組織管理） |
| organization_admin | 管理者（PC の管理メニュー: ユーザー/カテゴリ管理） |
| organization_member | 一般社員 |
| project_admin | **編集者**（PC でシナリオ作成・編集・合成・DL） |
| project_member | **撮影者**（スマホで撮影・アップロード、閲覧） |

- 「組織管理者は配下プロジェクトに暗黙アクセス」の継承は維持。
- permission は機能カテゴリごとに enum: `ManualPermission`（create/edit/delete/render/download）/ `ShootingPermission`（capture/upload/adopt-take）/ `CategoryPermission`。permission チェックは常に `$org->laratrust_team_id` を明示（strict_check=true）。
- **ロールは増やさない**。撮影者と編集者で到達画面集合が違うため 2 ロール（既定の project 2 ロール）で足りる。管理者の管理メニューは org ロールで分岐。

## 8.4 課金・上限マッピング（§4）

要件を 2 プリミティブに分解する。

### チケット台帳（reserve → commit/release の 2 フェーズ）

消費を伴う長時間処理に割り当てる。消費点は Service 層に 1 箇所ずつ定義。

| 消費点 | チケット種別 | フロー |
| :-- | :-- | :-- |
| AI シナリオ生成（手順書解析 1 回） | `ai_analysis` | reserve → 成功時 commit / 失敗時 release |
| 動画自動合成（1 本レンダリング） | `video_render` | 同上 |

付与数は `PlanSeeder` の `monthly_ticket_grant`。stale reservation 解放 cron を前提。

### 多次元 Quota（`config/quota.php` + `QuotaKey` enum に case 追加）

| Quota キー | 意味 |
| :-- | :-- |
| `max_projects`（既存） | 現場/ワークスペース数 |
| `max_members`（既存） | メンバー数 |
| `max_manuals` | 動画マニュアル本数（組織 or プロジェクト単位） |
| `max_storage_bytes` | 登録データ容量（テイク等。[02章](02_システム全体像.md)の「登録データ容量」に対応） |
| `feature_multilang`（boolean） | 多言語字幕・ナレーション |

規則: Quota チェックは `QuotaService` 経由のみ、超過は 402。プラン名でのコード分岐禁止（能力は常に Quota/チケット値で表現）。課金ゲートは `BillingAccess` + `require-active-subscription` middleware。

## 8.5 API・外部公開面マッピング（§5）

### スマホアプリ（iPhone ネイティブ）＝ REST API v1 の主要クライアント

- **認証**: Passport OAuth（`auth:api-oauth` guard、ネイティブアプリは PKCE）。エンドユーザ文脈のため API キー（機械/連携用）ではなく OAuth を使う。
- **ルート形状**: 既存 `Item` と同じ nested + flat ability + dual/oauth guard + 書き込みは `idempotent` middleware。rate limit は既存 4 バケット（api-read/write/status/mcp）に割当。
- **ability 定義**（1 箇所に追記）: `manuals:read` / `takes:write` / `takes:adopt` / `manuals:render` 型。

想定エンドポイント（すべて Project nested、テナント整合は認可前 404）:

| メソッド | パス | 用途 |
| :-- | :-- | :-- |
| GET | `/api/v1/projects/{project}/manuals` | シナリオ一覧（絞り込み/検索） |
| GET | `/api/v1/projects/{project}/manuals/{manual}` | シナリオ詳細（cuts + 採用テイク） |
| POST | `.../manuals/{manual}/takes/upload-url` | **S3 presigned PUT URL 発行**（大容量は直 S3 アップロード） |
| POST | `.../cuts/{cut}/takes` | テイク登録（S3 キー + メタデータ） |
| PATCH/DELETE | `.../takes/{take}` | 並べ替え・コメント・削除 |
| POST | `.../manuals/{manual}/sync` | 撮影データ一括同期（新規テイクのみ。DL 済みは除外） |

> **大容量メディアの原則**: テイク動画はアプリサーバを経由させず **S3 presigned URL で直アップロード**。API はメタデータ登録のみ扱う。ダウンロード（同期時の採用テイク取得）も `temporaryUrl()`（署名付き期限付き URL）。

### MCP（任意・LLM クライアント向け）

テンプレの `whoami / list-projects / show-project / list-items` に倣い、`list-manuals / show-scenario / apply-scenario` 等を追加可能（書き込みは `McpIdempotencyService` 経由）。本セッションのような Claude クライアントからシナリオを操作する運用面に有用（aigenba が同型）。初期スコープでは read 系のみでよい。

### API キー prefix

`config` でアプリ固有値に変更（テンプレ必須事項）。

## 8.6 LLM 機能マッピング（§6）

利用形態は **構造化 one-shot（spirux 型）** に分類される（対話でも tools でもない）。コアのみ（UserInput + prompt YAML + canary）で実装する。

### プロンプト（`resources/prompts/*.yaml` + `app/Prompts/*Prompt.php` のペア）

[03章](03_AI解析とシナリオ生成.md)のパイプラインを YAML prompt 群に落とす。

| prompt name | 役割 | 入力 | 備考 |
| :-- | :-- | :-- | :-- |
| `sop-extract` | 手順書 → 統一 JSON 構造化 | 手順書（画像/PDF） | **マルチモーダル**（vision）。OCR 誤読前提で後段の人手確認あり |
| `work-decomposition` | 構造化 JSON → 作業分解表（1 動作 1 行、手順/急所分離） | 抽出 JSON | [03章 §3.2](03_AI解析とシナリオ生成.md#32-プロンプト-a作業分解sop-再構築) |
| `scenario-generation` | 作業分解表 → シナリオ（8 列） | 作業分解表 | [03章 §3.3](03_AI解析とシナリオ生成.md#33-プロンプト-bシナリオ生成動画構成案への垂直展開) |
| `scenario-validation`（任意） | マニュアル有効性判定・分割提案 | 抽出 JSON | 検証 v2 のバリデーション出力 |
| `translation`（任意） | 字幕/ナレーションの多言語化 | 日本語原稿 | `feature_multilang` 有効時のみ |

### 必須ルール（テンプレ規約、崩さない）

- 手順書テキスト・end-user 由来の自由テキストは **`UserInput` 型経由でのみ** prompt に入れる（生 string は PHPStan が落ちる）。
- prompt 文字列はコード直書き禁止（YAML のみ）。
- 呼び出しは `PromptOperation` 経由（Prism Facade 直呼び禁止、guardrail テストあり）。
- コストは `LlmCallLog` に自動記録。新しい呼び出し点もこの経路を通す。
- パイプラインは長時間処理 → **queue job** 化し、`ai_analysis` チケットを reserve→commit/release（§8.4）。`AnalysisJob` が状態を保持し、PC 側は「解析中…」をポーリング/イベントで表示。

## 8.7 新規サブシステム（テンプレ範囲外・divergence 登録）

以下は本プロジェクト固有で、テンプレに雛形がない。**logic-driven な逸脱**として `docs/template-divergence.md` に「なぜ必要か・どの不変条件をどの機構で保証し続けるか」を記録した上で新設する。

### (A) メディアストレージ

- 実体は **S3**（`s3` disk）。キーは **Project スコープ prefix**（`orgs/{org}/projects/{project}/manuals/{manual}/...`）でテナント隔離。
- ファイル参照は所有モデルの属性（`SourceDocument.file_path` / `Take.video_path`, `thumbnail_path` / `RenderJob.output_path`）。polymorphic media テーブルは作らない（§8.2 の多態回避）。
- アップロード/ダウンロードは presigned URL（§8.5）。容量は `max_storage_bytes` Quota に計上。
- **不変条件の維持**: S3 キー生成はサーバ側で Project から導出（クライアント payload の path を信用しない＝tenant キー不信の延長）。署名 URL は短命・単一オブジェクト限定。

### (B) 動画合成パイプライン（レンダリング）

- **ffmpeg ワーカー**による: ①採用テイクの連結 → ②ナレーション音声の合成 → ③字幕（テロップ）焼き込み → ④尺調整（カット尺＝ナレーション尺と素材尺の比較で決定、[02章](02_システム全体像.md)）。
- 専用 queue（`media`）＋専用ワーカー（重処理のため web/default から分離）。`RenderJob` が状態機械。`video_render` チケットを 2 フェーズ消費。
- **プレビュー**（テイク未登録でも字幕＋ナレーションで再生, [02章](02_システム全体像.md#プレビューの特徴)）: 黒画面/静止画＋TTS＋字幕の簡易レンダ、またはクライアント側合成。初期はサーバ簡易レンダで統一。

### (C) TTS（ナレーション自動音声化）

- 外部 TTS プロバイダへの outbound（既知ホスト）。多言語は言語別音声。
- **SSRF**: プロバイダ host を `config/ssrf-pin.php` に pin（`PinnedHttpClient` 経由）。ユーザ入力由来 URL の外部取得（手順書を URL 指定で取り込む等をやる場合）は必ず SSRF 検査経由。
- 生成音声も S3 の Project prefix に保存。

> これら 3 つは互いに結合する 1 つの「メディア処理サブシステム」。実装は独立サービス（`app/Services/Media/*`）に閉じ込め、ドメイン（Cut/Take/VideoManual）とは job + イベントで疎結合にする。

## 8.8 守るべき不変条件の適用（§7）

追加コードすべてに適用（Architecture/Feature テストへの登録まで含めて「実装済み」）:

1. **tenant キー不信**: `project_id / video_manual_id / cut_id / category_id / created_by` を payload から受けない（`missing` + `MassAssignmentSafetyTest`）。S3 キーもサーバ導出。
2. **子は親に属する**: `manual ∈ project`, `cut ∈ manual`, `take ∈ cut` を URL で構造保証し、不整合は**認可前 404**（`NestedRouteIdorDefenseTest` inventory 登録）。
3. **cross-org 不可**: relation / org-scoped Builder 経由のみ。S3 prefix でも隔離。
4. **untrusted 文字列**: 手順書テキストは `UserInput` 型経由でのみ prompt へ。
5. **権限判定**: 常に team 明示 + strict_check=true。
6. **課金の冪等性**: `ai_analysis` / `video_render` は 2 フェーズ、webhook は冪等マシン、gate は `BillingAccess` のみ。
7. **テストなしの完了なし**: 上記各項に新リソース（Manual/Cut/Take）を登録。
