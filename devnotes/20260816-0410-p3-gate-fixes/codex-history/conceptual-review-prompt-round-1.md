## 使命 (North Star)

<!-- app-codex-review スキルはこのセクションをレビュー使命として参照する。 -->

**AI-CUE** は、現場に既にある**作業手順書(SOP)を起点に**、AI が撮るべきカットを設計した**動画シナリオ**を生成し、そのシナリオを**スマホ(PWA)でナビゲーション撮影**することで、専門知識ゼロの現場作業者でも**標準化されたマニュアル動画**を作れるようにする。

- 「思考ゼロ・編集ゼロ」— 台本作成・撮影判断・編集の 3 ハードルを AI とナビ撮影で肩代わりする。
- 競合(OJT を撮って形式化する tebiki)と異なり、**標準作業を起点に AI が教材設計し撮影を指示する**（撮影者・教える人のスキルに品質を依存させない）。
- 熟練者の暗黙知を動画マニュアルという形式知へ変換する装置（SECI）。

> 詳細な設計は本リポジトリの `doc/`（01〜10）に置く。ドメインをテンプレート構造へどうマップしたかは `doc/08`〜`doc/10`（特に `doc/10 §10.8` に設計レビュー反映済み）。
> **v1 スコープ**: 字幕のみ(TTS 後回し) / 撮影は PWA(同一オリジン・セッション認証) / 動画合成は自前 ffmpeg / 単一 Default Project。

## 思考原則

1. **フレームワークのレンジ内でやる**。自前機構の前に Laravel / 同梱モジュールの公式作法を確認する
2. **今必要なものだけ作る**(オーバーエンジニアリング禁止。「あったら便利」は作らない)
3. **後方互換の並走を残さない**。書き換えると決めたら同じ PR で旧実装を消す
4. **別物の概念を「似ているから」で統合しない**
5. **テストファースト**。fail を確認してから実装に入る
6. **タコツボ実装を避ける**。各ステップで他要素との結合観点を確認する

## 禁止事項

1. テストなしの実装完了報告(不変条件は対応する Architecture/Feature テストへの登録まで含めて「実装済み」)
2. PHPStan エラーの widen(型を緩めて黙らせる)・baseline 化
3. dev DB への破壊操作(`migrate:fresh` 等)をエージェント判断で実行すること
4. `response()->json()` の直書き(DTO / JsonResource / Inertia を使う。仕様固定 endpoint のみ例外)
5. LLM 呼び出しの Prism 直呼び(`app/Prompts/` の factory → 窓口 (`PromptDefense`) →
   実行単位 (`GuardedPrompt`) の**1 本道のみ**。`PromptGuardrailTest` が
   app/ routes/ database/ config/ bootstrap/ の 5 走査根で検出する)。
   **実行経路を持つ prompt factory は `LlmCallContextData` を必須引数で受け、
   `PromptDefense::load()` へ渡して帰属 (organization / subject) を付ける** — 付け忘れは
   PHPStan level 10 が落とす。帰属の対象を持たない見本 (`ExampleSummaryPrompt`) だけが
   `PromptDefense::loadUnattributed()` を使え、窓口 gate が**この 1 件を名指しで pin** する。
   併せて `PromptUntrustedInputContractTest` の inventory へ**帰属キーを空配列で exempt 登録**する
   (deny-by-default なので exempt にする操作がレビューで必ず見える)。
   欠けると `llm_call_logs.metadata_missing` になり組織別・対象別の費用が出せない
6. prompt 文字列のコード直書き(`resources/prompts/*.yaml` に置く)
7. 操作系 POST の応答での `redirect()->intended()`(ログイン直後フロー専用。
   招待送信等は `back()->with(...)` で完結させる)
8. 必須条件未充足を理由にボタンを disabled にする UI(押下時にエラー表示する。DESIGN.md)
9. Artifact の使用(Artifact ツールでの成果物公開を行わない。成果物はリポジトリ内のファイルとして出力する)

## 概念設計

# 概念設計: p3-gate-fixes (既存 gate の是正)

## 背景・課題

家系の機能台帳 (lctl) が aicue に割り当てた「既に持っている検査の精度を上げる」小さな是正が 4 件たまっている。
4 件それぞれに独立した設計を立てるのは AGENTS.md 思考原則 2 (オーバーエンジニアリング禁止) に反するため、
1 つの設計に施策として畳む。**新しい gate を作る話ではなく、既にある gate の穴を塞ぐ話**である。

台帳が挙げた 4 件と、実物を読んで確かめた現状は次のとおり。

| # | 台帳の指摘 | 実物の確認結果 | 判断 |
|---|---|---|---|
| 1 | 許可語の除去が語境界を見ていない (`tests/js/support/ds-purity.ts` の `stripAllowlisted`) | 130-136 行が `split(pattern).join("")` の素の部分文字列除去。裁定 AG-063 の対象リストに aicue が入っている | **採用** |
| 2 | 非複合 global use の gate が正典 t1 に届いていない + 正典に無い誤検出がある | 必須 4 点のうち (2) 未達 / (4) 部分的。別名つき import を違反として数える偽陽性を実測で確認 | **採用** |
| 3 | enum ⇔ TypeScript 同期の抽出器を型情報ベースへ置換 (AG-099) | 置換だけでは終わらず、正典 v2 は発見・分類・検査の 3 段 + 逆走査 2 規則を含む新規 gate である | **不採用** (理由は下記) |
| 4 | 撤去物の不在 gate に字句走査の層が無い | 撤去したのは middleware の結線であって名前ではない。名前は現役で残っており、復活の経路は設定行の**削除**なので字句走査では原理的に見えない | **不採用** (理由は下記) |

## 改善アイデア

### 施策 1 — 許可語の除去を語境界で行う (採用)

`stripAllowlisted` は、ファイル別許可一覧に載せた class 文字列を本文から取り除いてから禁止パターンを当てる。
現在は**素の部分文字列**として取り除くため、許可語を部分に含む別の語まで一緒に消える。
消えた語は禁止パターンに掛からないので、違反が**静かに見逃される** (赤くならない = 検出漏れ)。

区切り文字で分割した class トークンの**完全一致**でだけ取り除く形へ直す。
これは家系の標準形 (追従元 laravel-claude-template が確定させた形) と同じで、裁定 AG-063 が aicue に求めている是正そのものである。

あわせて、この検査は走査対象が 0 件でも緑になる (`resources/js` が読めないと空配列を返して両方の検査が素通りする)。
走査件数の床を固定して空振りを赤くする。これは家系の規約 (空振りを緑にしない) の適用であり、施策 1 と同じファイルの中で閉じる。

### 施策 2 — 非複合 global use の gate の偽陽性是正と正典 t1 追従 (採用)

3 つを直す。

1. **偽陽性の除去**: 別名つきの import (`use Foo as Bar;`) を違反として数えているが、
   手元の PHP 8.4.24 で `php -l` を取り直すと**別名つきの 4 形はいずれも警告を出さない**。
   正典 t1 は `php -l` を真値と定めているので、これは正典に無い誤検出である。
2. **検出漏れの解消**: 名前空間トークンを 1 個見た時点でファイルごと対象外にしているため、
   `namespace { ... }` と明示的に書いたグローバル名前空間の内側を**原理的に検出できない**。
   実測でこの形は警告が出る (= 本 gate が防ぎたい事故の経路)。名前空間の文脈を追う形へ直す。
3. **自己検査の完成**: いまは対照の見本を持つが、正解を人が書いた期待値で持っている。
   `php -l` の出力を真値として、検出結果を**名前と行番号まで**照合する自己検査へ替える。

### 施策 3 — enum ⇔ TypeScript 同期の抽出器を型情報ベースへ置換 (不採用)

台帳の指摘は事実である (`tests/Support/TsUnionValues.php` は二重引用符の型宣言専用の抽出器のままである)。
ただし**この束の前提が崩れている**。

- 型情報を使う抽出は TypeScript コンパイラの API が要る = 検査を PHP のレーンから JavaScript のレーンへ移す作業になる。
  さらに正典 v2 は抽出器の置換だけでなく、**発見 (PHP の列挙を全数拾う) → 分類 (登録の無い列挙は落とす) → 検査 (値集合の一致)** の 3 段構成と、
  **逆走査 2 規則** (登録の無い写しの発見 / 既にずれた写しの発見) を必須にしている。これは新しい gate 一式であって、既存検査の精度の是正ではない。
- 抽出器だけを広げる (単一引用符・定数配列に対応させる) 案は、**いま呼ぶ側が 1 つも無い**。
  現行の対象 6 件はすべて二重引用符の型宣言であり、広げても検出力は 1 ミリも増えない。「あったら便利」なので作らない (思考原則 2)。
- 現行の抽出器に**静かに間違える穴は無い**ことも確かめた。読めない書き方に当たると値 0 件で例外を投げて落ちる (fail-closed)。
  実際の弱点は「対象が手書きの 6 件しか無く、新しい列挙は永久に対象外」という**網羅の欠落**で、これは上記の新規 gate でしか埋まらない。

よって施策 3 は本設計から落とす。埋めるべき穴 (網羅の欠落) は実在するので、**別の TODO として起票する**ことを申し送る。
規模が他の 3 施策と 1 桁違うため、この束に入れると束そのものが大きくなり、思考原則 2 に反する。

### 施策 4 — 撤去物の不在 gate に字句走査の層を足す (不採用)

台帳の指摘 (`tests/Architecture/PasswordConfirmMiddlewareAbsenceTest.php` は実行時の検査だけで字句走査の層を持たない) は事実である。
しかし実物を読むと、**この対象に字句走査の層は当たらない**。

1. **撤去したのは名前ではなく結線である**。`password.confirm` という名前は現役で残っている —
   Fortify の route 名 `password.confirm.store` が実在し (`app/Providers/FortifyServiceProvider.php` の流量制限の割当)、
   画面題の対応表 (`config/seo.php`) にも項目がある。撤去したのは「その middleware をどの route にも付けない」という結線だけである。
   したがって「撤去した名前が 1 つも残っていない」を 0 件で固定することは**そもそもできない**。
   例外一覧を積めば書けるが、正典 (許可一覧 0 件固定) と正反対の形になる。
2. **復活の経路が字句では見えない**。撤去済みテスト自身の説明が書いているとおり、復活は
   依存パッケージの既定値に戻ること = 設定行 `'confirmPassword' => false` の**削除**で起きる。
   「撤去した語が現れたら落とす」検査は、語が**消えること**では原理的に鳴らない。
3. **その経路は既に機械で固定されている**。`tests/Architecture/PasskeyPackageContractTest.php` が
   `fortify-options.passkeys.confirmPassword` が false であること、`passkeys.management_middleware` が空であること、
   設定の往復後も同じであることを固定している。つまり実行時の層 (現行) と設定値の層 (既存) の 2 枚が既に掛かっている。
4. **同種の機構は既にある**。字句で撤去物の再流入を止める作法は本日入った
   `tests/Architecture/RetiredRecoveryReferenceGateTest.php` (撤去した滞留回収の実装が戻らないことの gate) が持っている。
   当たらない対象のために 2 本目を作るのは二重の機構である。

よって施策 4 は**作らない**。台帳の「字句走査の層が無い」という観測は正しいが、
その層が有効なのは「撤去した名前が丸ごと消えている対象」であり、本件は該当しない。

## 期待効果

- **使命への貢献**: 直接の機能ではなく、撮影 PWA と動画生成の土台を守る検査の信頼性である。
  検出漏れを抱えた検査は「緑だが何も見ていない」状態へ静かに落ちる。施策 1 と 2 はどちらもその静かな落下を止める。
- 施策 2 の偽陽性の除去は、別名つき import という**言語仕様上まったく正当な書き方**を書けない状態を解く
  (家系の他リポジトリのテストには実在する形である)。
- 施策 3・4 を落とすことで、束が「小さな掃除」の範囲に収まる。
