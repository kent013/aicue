# 対応マトリクス: design-review Round 2

## [Warning] A: PHP の引用符終了判定が逆斜線の偶奇を扱っていない
- 判断: 対応する
- 根拠: 指摘のとおり。`'…\\'` を終端でないと誤認すると、**以降の case を丸ごと文字列の中として
  食い潰す** = 取り残しを緑にする最悪の壊れ方になる。
- 対応内容: 状態表の出口を「直前の連続する `\` が偶数個のとき終端」へ変更し、
  誤ったときの帰結を本文に明記した。行列に P31 (奇数) / P32 (偶数) / P33 (3 個以上) を追加し、
  **例外になることだけでなく「同じ見本の中の別の case を正しく読めていること」**を
  併せて確かめる形にした (食い潰しの回帰はそこにしか現れない)。

## [Warning] A: `?>` は行注釈の中でも閉じタグとして働く
- 判断: 対応する
- 根拠: 知らなかった挙動。`// ?>` を見逃すと以降の HTML を PHP として読む。
- 対応内容: 状態表の行注釈の出口を「改行 **または `?>`**」に変更し、
  「コード状態と行注釈状態の `?>` は例外 / 引用符とブロック注釈の中の `?>` は無視」を明記。
  未終端の扱いも「単一引用符・二重引用符・ブロック注釈は例外、行注釈は EOF で閉じたものとする」
  へ分けて定義した。行列に P24 / P25 / P26 を追加した。
- 併せて、リスク欄の「静かに間違えない」の主張を指摘の文面へ差し替えた
  (ファイル全体についての主張にしない)。

## [Warning] B: 目録パスの検証より前に program がファイルを使ってしまう
- 判断: 対応する
- 根拠: 検査の意味が「使用前の安全境界」でなくなる、という指摘は正しい。
- 対応内容: 体裁の検査を純関数 `validateMirrors(rows)` に切り出し、
  **`beforeAll` の冒頭で program を作る前に呼ぶ**。体裁のテストからも同じ関数を呼ぶ
  (実装を 2 つに分けない)。包含の判定を `startsWith(root + path.sep)` に直し、
  `realpath(ts) + declaration` の一意性も加えた。

## [Warning] C: T25 が縮めた program への回帰を検出できる配置になっていない
- 判断: 対応する
- 根拠: 見本を全部 `exclude` に入れると、増える側も `parsed.fileNames` に入らないので
  差が出ない。指摘のとおり回帰にならない。
- 対応内容: **`program-fixtures/`(正常な TS のみ・`tsconfig` の対象に残す)** と
  **`fixtures/`(壊れた見本を含む・除外)** に分け、増える側 (`registry-augmentation.ts`) を
  前者へ置いた。対象 (`t25-target.ts`) は拡張を import しない。
  全体 program で `{a,b}` / 起点だけの program で `{a}` の**両方を pin** する形にした。
- `@/*` については T10 を 2 つに分けた — **T10a**(見本どうしを相対 import)と
  **T10b**(実在する `resources/js` の型を `@/` 経由で import)。
  見本専用の `paths` は作らない (リポジトリ本来の解決を確かめる意味が消えるため)。

## [Warning] C: P25 の複合ケースは個別の字句状態を固定できない
- 判断: 対応する
- 対応内容: 未終端を 3 件 (単一引用符 / 二重引用符 / ブロック注釈) に分け、
  pin を「概念上の行数」ではなく **`it.each` に渡す実際の case 数**へ変更した
  (現設計で TS 26 件 / PHP 38 件。実装時に確定した実数で pin する)。

## [Suggestion] F: 「実装日」「実装日 + 180 日」を式のまま書かない
- 判断: 対応する
- 対応内容: メタ表の欄に「`YYYY-MM-DD` で確定して書く(式のまま残さない)」と明記した。
