# 対応マトリクス: design-review Round 3

Codex 全体判定: CHANGES_REQUESTED (§6 のみ。他 8 節は APPROVE)

## [Warning] 「作成者限定 manual は撮影工程へ進まない」は T-1 から導けない過剰制約
- 判断: **対応する (指摘が正しい。前ラウンドの修正が振れすぎていた)**
- 根拠: T-1 の A・C が要求するのは「終端まで**作成者以外に見せない**」ことであって、
  「撮影工程へ進まない」ことではない。現行 `ProjectPolicy::capture` は
  `canManageProject` を先に見るため、**編集者である作成者自身は capture を通る** =
  作成者が自分で PWA 撮影するライフサイクルは成立する。これを禁じる根拠は T-1 に無く、
  workflow 制約を先回りして設計することになる (思考原則 2 違反)。
  また「撮影対象として割り当てられない」と「撮影 PWA の一覧・詳細に出ない」は同値ではなく
  (前者は workflow 制約、後者は主体別の可視性制御)、`あるいは` で並べると
  昇格後の設計者が別々の実装へ到達する。
- 対応内容:
  - §6-6 を**主体ごとの期待値**へ書き換えた —
    (1) 作成者は capture 権限を持つなら作成者限定 manual を撮影 PWA で閲覧・撮影できる、
    (2) 非作成者は capture 権限や project role を持っていても一覧・詳細・cuts/takes 経由の
    いずれからも閲覧・操作できない、(3) 作成者限定でない manual の撮影者アクセスは後退しない。
  - §6-7 の最大リスクを「**非作成者を撮影担当として割り当てられる機構が存在する場合**、
    不整合を検出して操作を拒否する (可視性を例外的に開いて解決しない)。
    **割当機構が無いならその workflow 制約を先回りして追加しない**。
    作成者自身が撮ることは矛盾しないので禁止しない」へ差し替えた。

## [Suggestion] §6-1 の見出し「読み取り経路」は内容と一致しない
- 判断: **対応する**
- 根拠: 一覧には更新・削除・解析・レンダも含まれる。
- 対応内容: 見出しを「manual に到達する**参照・操作経路**」へ変更した。
