# 対応マトリクス: design-review Round 4

## [Warning] 施策 4: P-7 では `env -i` を外す退行を検出できない
- 判断: 対応する
- 根拠: 指摘のとおり。「起動側が組み立てた配列」と「子が実際に受け取ったプロセス環境」は
  別物で、前者だけを見ても `env -i` を外した退行は映らない。観測できるのは子だけである。
- 対応内容:
  - probe が **Dotenv を読む前に** `getenv()` (引数なし) で自分のプロセス環境を観測し、
    **キーだけ**を出力に載せる (値は載せない = 万一の混入を出力へ流さない)
  - P-7 を 3 条件へ: (a) 必須 3 キーが存在する / (b) 禁止する接頭辞
    (`DB_` / `PG` / `AWS_` / `STRIPE_` / `TESTING_FAKE_` / `GOOGLE_`) が 0 件 /
    (c) それ以外の余りが無い (実行環境が足すキーがあるなら理由付きで目録へ登録して初めて許す
    = deny-by-default)
  - 受入の変異に「起動コマンドから `env -i` を外す」を追加した
  - 定数 `ALLOWED_PROCESS_ENV_KEYS` の docblock に「これは起動側が載せる分の宣言であり、
    子が受け取った分は probe が観測する。両方を突き合わせて初めて退行が映る」と書いた

## [Warning] 施策 4: 使い捨て鍵の生成形式が未指定
- 判断: 対応する
- 対応内容: 生成形式を明記した — `APP_KEY` は `'base64:'.base64_encode(random_bytes(32))`、
  `CIPHERSWEET_KEY` は `bin2hex(random_bytes(32))` (現行 config は文字列鍵の提供元が
  `env('CIPHERSWEET_KEY')` をそのまま読む)。`random_bytes()` の失敗は握り潰さず子を起こす前に
  失敗させる。形式の妥当性は「子が起動できたこと」自体が示す (起動できなければ赤)。
