# 対応マトリクス: design-review Round 3

## [Critical] 施策 4: 一時環境ファイルが新しい秘密の漏れ口になる
- 判断: 対応する (指摘より一歩強い形にする)
- 根拠: 指摘の末尾にある「親の実キーを複写せず、起動に有効なテスト専用キーを生成する方が
  境界が明確」が正しい。本観測は container の解決とルーティングしか見ず、既存データの復号も
  DB 接続もしないため、実鍵は 1 つも要らない。**秘密を書かなければ漏れ口にならない**。
- 対応内容:
  - `APP_KEY` / `CIPHERSWEET_KEY` は起動のたびに**使い捨ての値を生成**する
    (親の実鍵を複写しない)。P-8 で「親の設定値と異なること」を機械固定し、
    複写へ戻す変異が赤くなるようにした
  - 置き場所の保護も設計へ入れた: 専用の一時ディレクトリを `0700`、環境ファイルを
    作成時点から `0600`、symlink を追わない書き方、起動前の権限確認 (違えば子を起こさない)、
    `finally` での削除 (timeout・JSON 解釈失敗・Process 例外でも通る)
  - 受入に P-9 (権限) / P-10 (正常終了・非ゼロ終了・timeout のいずれでも残らない) を追加

## [Warning] 施策 4: `getenv()` の `string|false` を絞らずに渡している
- 判断: 対応する
- 対応内容: probe のコードを `Assert::stringNotEmpty()` で絞ってから
  `useEnvironmentPath()` / `loadEnvironmentFrom()` へ渡す形へ書き換え、PHPStan 適合チェックにも
  1 行追加した。`APP_CONFIG_CACHE` については P-11 (絶対パス / 一時ディレクトリ配下 /
  対象ファイルが存在しない) を追加した。

## [Warning] 施策 4: 設定キーの allowlist とプロセス環境の allowlist が混同されやすい
- 判断: 対応する
- 対応内容: 定数を 2 つに分けた (`ALLOWED_ENV_FILE_KEYS` = 一時ファイルの 7 キー /
  `ALLOWED_PROCESS_ENV_KEYS` = 子へ渡すプロセス環境の 3 キー)。
  P-7 で後者を**集合一致**で固定し、`DB_*` / `AWS_*` / `STRIPE_*` が 1 つも無いこと
  (= `env -i` の退行) も落ちるようにした。
