# 対応マトリクス: conceptual-review Round 1

## [Warning] 禁止事項: `migrate:fresh --seed` と dev DB 破壊禁止の境界が曖昧
- 判断: 対応する
- 根拠: 指摘のとおり、設計書だけを読むと本件が DB 操作を増やすように読める。実際には検査
  (静的走査 + container 解決) しか増やさない。
- 対応内容: 「制約・前提」の先頭へ「DB 操作は 1 つも増やさない / 既存の投入経路は読むだけ /
  生 artisan・生 psql は扱わない / 別プロセス観測は DB へ接続しない」を追記した。

## [Warning] 施策 4 の別プロセス観測が壊れやすい
- 判断: 対応する
- 根拠: 観測の責務を絞らないと、環境差 (設定キャッシュ・autoload) で赤くなる脆い検査になる。
- 対応内容: 観測用スクリプトの責務を 4 つ (DB 非接続 / container 解決 / 転送先 URL の組み立て /
  終了コード) に限定し、HTTP サーバもブラウザも起動しないことを明記した。本番の対照も
  「`ProductionEnvGuard` が実値を検出して非ゼロ終了する」1 点に絞った。

## [Warning] 正典 v1 (3) 「レーンからの個別 fake 直呼びの静的禁止」への対応が無い
- 判断: 対応する (ただし対象を限定する)
- 根拠: HEAD 実読では違反 0 件であり、「増えないことを今固定する」のが最も安い。ただし
  `tests/Support/Fake*` の per-test 代役は Laravel 公式作法のテストダブルで、bug-hunt レーンの
  差し替えとは別概念である。これを巻き込むと公式作法を禁じることになり誤り。
- 対応内容: 施策 1c を新設。「テスト側のファイルが `app/` の偽物実装クラスを container へ
  直接結ぶこと」だけを禁じ、per-test 代役は対象外と明記。保証範囲 (字句として現れる形だけ) も明記。

## [Warning] 安全下限集合を「新設しない」判断は標準未充足に見える
- 判断: 対応する (減算機構は作らず、名前付き正本だけ置く)
- 根拠: 指摘のとおり、既存 gate は「特定の環境ひな型で必須フラグが true」を固定しているだけで、
  「安全下限集合」という名前付きの正本ではない。一方で減算機構そのものを作るのは
  aicue に無い仕組みの新設であり過剰。
- 対応内容: 宣言に `bughuntRequiredFlags()` を置き、既存 `BughuntEnvExampleContractTest` が
  自前定数をやめて宣言を読む形へ寄せる。新しい検査は増やさない。

## [Suggestion] seeder 目録を全 seeder に広げるとスコープ過大に見える
- 判断: 対応する (文面で意図を明確化)
- 対応内容: 「母集団を全 seeder に取るのは抜け道を作らないためであり、bug-hunt に関係しない
  seeder の区分は 1 行で終わる」ことを施策 2 に明記した。

  本番側へ移せば満たせる。
- 対応内容: 施策一覧に「`final readonly` + `class-string` 型」を明記した。
