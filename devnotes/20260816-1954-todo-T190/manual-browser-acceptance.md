## なぜ空欄なのか

実装は LLM エージェントが行ったが、**エージェントは実ブラウザでマウスを動かせない**。
詳細設計の実装順序 6 は次のように定めている:

> 6. 実機で 1 度、シナリオ編集画面のホバー再生と D&D の並べ替えを手で確認する

また同設計の施策 3 リスクは、D&D との干渉について次のように明言している:

> ただし**「ブラウザ実機で並べ替えの体感が変わらないこと」は自動テストでは保証しない** —
> 実装時に手で 1 度確認する。

この方針に従い、**確認していないことを確認したと書かない**。本ファイルは
「まだ埋まっていない」という事実そのものを記録として残すために置く
(ファイルが存在すること自体は何の保証でもない)。

`pnpm test` の緑は **jsdom 上の意味論と生死の固定**である。jsdom は
`HTMLMediaElement.play()` を実装しておらずテストでは差し替えているため、
**実際に映像が再生されること・自動再生ポリシーの実挙動・滞留 200ms の体感**は
自動テストの守備範囲の外にある。

## 埋める人がやること

マウスの使えるデスクトップブラウザ (Chrome と Safari の 2 つ) でシナリオ編集画面
(`/projects/{project}/manuals/{manual}/edit`) を開き、以下を確認して上の表を埋める。
確認には**採用済みかつ ready かつサムネイル生成済みのテイク**を持つカットが要る。

- [ ] 動画列の採用テイクのサムネイル (64px) が静止画で出ている
- [ ] サムネイルにマウスを載せて 200ms ほどで**無音のまま**再生が始まり、末尾でループする
- [ ] マウスをすっと通り過ぎただけでは再生が始まらない (滞留 200ms の体感)
- [ ] マウスを外すと即座に静止画へ戻る
- [ ] サムネイルをクリックするとテイク選択画面へ遷移する (再生操作と競合しない)
- [ ] ブラウザの「動きを減らす」設定を有効にすると再生が始まらない (静止画のまま)
- [ ] 別タブへ切り替えると再生が止まる
- [ ] **行の並べ替え (D&D) の体感が T185 のときと変わらない** —
      ハンドルを掴んだままサムネイルの上を通過しても再生が始まらず、ドロップ位置もずれない
- [ ] 採用テイクが無い行・非 ready の行の見た目が従来と変わっていない
      (サムネイルが出ないだけで「テイクを選択 / ファイルの選択」は押せる)

## 未確認のまま先行マージした理由

- 自動テストは全レーン green で、Codex 実装レビューも Round 1 で APPROVED
  (Critical / Warning 0 件)。**コードへの未対応の指摘は残っていない**。
- ホバー再生は**補助的な確認手段**であり、失敗しても静かに静止画へ戻る設計である。
  仮に実機で再生が始まらなくても、利用者は従来どおり「テイクを選択」から
  `controls` 付きのプレビューでテイクを観られる (**詰みを作らない**)。
- この非対称を理由に「ホバー再生は動作確認済み」と書かないこと —
  本ファイルが埋まるまで**実ブラウザでの再生は未検証**である。
