## なぜ空欄なのか

実装は LLM エージェントが行ったが、**エージェントは実機のブラウザで動画を再生できない**。
詳細設計 S5 のリスクは、この非対称を次のように明言している:

> jsdom は実メディア再生を行わないため、component テストで固定できるのは
> **DOM 契約とイベント配線まで**である (実際の連続再生の滑らかさは実機確認の領域)。

`pnpm test` の緑は **jsdom 上の意味論と生死の固定**である。jsdom は
`HTMLMediaElement.play()` / `pause()` / `load()` を実装しておらずテストでは差し替えているため、
**実際に映像が連続再生されること・iOS Safari の自動再生ポリシーの実挙動・
先読みが本当に 1 クリップ 1 回取得になっていること・全画面へ勝手に切り替わらないこと**は
自動レーンの守備範囲の外にある。この方針に従い、**確認していないことを確認したと書かない**。
本ファイルは「まだ埋まっていない」という事実そのものを記録として残すために置く
(ファイルが存在すること自体は何の保証でもない)。

## 埋める人がやること

撮影 PWA (`/app/projects/{project}/manuals/{manual}`) を **iOS Safari の実機**で開き、
以下を確認して上の表を埋める。確認には**採用済みかつ ready のテイクを持つカットが 2 枚以上**と、
**使用できる採用テイクが無いカットが 1 枚**あるマニュアルが要る
(プレースホルダと連結の両方を通すため)。

- [ ] 左ペイン見出しの「通し再生」を押すとダイアログが開き、先頭カットの映像が再生される
- [ ] **全画面に切り替わらない** (インライン再生のまま = `playsinline` が効いている)
- [ ] カットが終わると**間が空かずに**次のカットへ進む (先読みが効いている体感)
- [ ] 使用できる採用テイクが無いカットではプレースホルダ文言が
      `config('manual.preview_placeholder_seconds')` 秒だけ出て次へ進む
- [ ] 事前告知 (「N / M 件のカットに、撮影・処理が完了した採用テイクがありません」) が
      再生前に出ている。**ボタンは押せる** (disabled になっていない)
- [ ] 自動再生が止められた場合、「再生を続ける」「このカットをスキップ」「閉じる」の
      3 つの出口がすべて操作できる
- [ ] 再生中に別アプリへ切り替える (ホーム / 通知センター) と**音が止まり、裏で再生され続けない**。
      戻ると同じカットの位置から再開する
- [ ] ネットワークを機内モードにして開くと、そのカットは「再生できませんでした」になり
      **通し再生が止まらず次へ進む** (有限時間で必ず前進する)
- [ ] 撮影中 (録画中) に「通し再生」を押すと、ダイアログは開かず
      「撮影中は通し再生を開始できません。撮影を停止してからお試しください。」が出る
- [ ] 通し再生を閉じるとカメラプレビューが復帰する (撮影に戻れる)
- [ ] 通信量の観点: 同じカットの動画が**続けて 2 回取得されていない**
      (可能なら Mac の Safari Web Inspector を接続してネットワークを見る)

## 未確認のまま先行マージした理由

- 自動テストは全レーン green (`composer test` / `composer phpstan` / `vendor/bin/pint --test` /
  `pnpm lint` / `pnpm typecheck` / `pnpm test` / `pnpm build` / packages 3 種) で、
  Codex 実装レビューも Round 4 で APPROVED。**コードへの未対応の指摘は残っていない**。
- 通し再生は**確認のための補助機能**であり、失敗しても撮影・採用・レンダの主経路を止めない。
  1 本のカットが再生できなくてもプレースホルダに落ちて次へ進むため、
  **行き先のない詰みを作らない**。
- この非対称を理由に「通し再生は実機で動作確認済み」と書かないこと —
  本ファイルが埋まるまで**実機での連続再生は未検証**である。
