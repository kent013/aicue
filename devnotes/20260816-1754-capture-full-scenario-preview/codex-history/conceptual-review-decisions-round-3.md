# 対応マトリクス: conceptual-review Round 3

## [Warning] 利用者の一時停止・画面非表示と通信停滞が区別できていない
- 判断: 対応する
- 根拠: 指摘のとおり。一時停止やバックグラウンド化で進捗イベントは止まるため、現契約のままでは
  「意図的に止めたら勝手に次のカットへ進んでいた」という壊れ方をする。撮影 PWA は画面ロックが
  日常的に起きる面であり、実際に踏む。
- 対応内容: 状態機械に `paused` (利用者の一時停止) と `suspended` (ページ非表示) を追加し、
  **その間は停滞監視を止める**ことにした。不変条件を
  「**ダイアログが前面に表示され、かつ再生を要求している間**に進捗が途絶えたら有限時間で `failed` へ進む」
  に限定し、これより広い保証はしないと明記した。`visibilitychange` での停止/再開は撮影 PWA 既存の
  `handleVisibility` と同じ考え方に揃える。Vitest に「一時停止・非表示の間は監視を止め、復帰で再開する」を追加。

## [Warning] `play()` の reject を一律に自動再生拒否として扱うのは不正確
- 判断: 対応する (契約の置き場所ごと変更)
- 根拠: `src` 差し替え・`load()` 中断でも reject する。2 枚の要素を入れ替える方式では
  **正常な切り替えによる中断**を誤って `blocked` / `failed` にしうる。かつ例外名の分類は環境差が大きく、
  名前に依存した分類は必ずどこかで外れる。
- 対応内容: 契約を**世代トークン**に置いた —
  「**現在のクリップ (世代) と一致する非同期結果だけが状態を変えられる**。古い世代の遅延 reject は無視する」。
  そのうえで世代一致の拒否を 2 分類だけにした: 自動再生制限と判定できるものは `blocked`、
  **それ以外は状態を変えず**、失敗の確定は `error` イベントと停滞監視に委ねる
  (例外名の分類で失敗を確定させない)。component テストに
  「**旧クリップの遅延 reject が新クリップを `blocked` / `failed` にしない**」を追加した。
  「保証しないもの」にも「拒否理由を正確に分類できるとは言わない」を明記した。

- 判断: 対応不要 (合意済み)
