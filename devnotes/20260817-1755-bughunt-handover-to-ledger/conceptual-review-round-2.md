Round 1 の Critical は解消されています。設計の根幹である「単一正本」「照合器と生成器の fail-closed 境界」「全登録の可視化」は成立しました。

### 4. 期待効果の妥当性

[Warning] A-003 の `context` を新規に補う根拠が明示されていません。A-003 には既存の申し送り文書がないため、後から `title`・`spec_basis`・`narrative` を作ると、当時確認していない経緯や根拠を確定事実として記録する危険があります。

修正提案: A-003 の `context` は、既存の adjudication、finding、run 成果物、commit など追跡可能な一次資料だけから構成し、その出典を詳細設計に示してください。十分な根拠が復元できない場合は `context` を追加せず、「経緯は未記入」の簡潔な項目として出すべきです。完全性契約により、無理に散文を創作しなくても A-003 は欠落しません。

### 7. 型安全性・機構の健全性

[Warning] 「全 `adjudication_id` が生成物に現れる」というテスト契約では、部分文字列一致、重複掲載、孤児 ID を見逃す余地があります。例えば `A-001` の検索は `A-0010` にも一致し得ます。また、各 ID が一度以上あるだけでは生成物との全単射を保証しません。

修正提案: 生成物から構造的に ID を抽出し、registry の ID 集合と完全一致することを固定してください。

- 欠落がない
- 余分な ID がない
- 各 ID が正確に1回掲載される
- 識別子境界を伴う完全一致である

supersede 表示についても、後継を単数と仮定せず、既存 validator が一意性を保証していない場合は、該当登録を supersede する全 ID を決定的な順序で表示する契約にしてください。

この2点を反映すれば、概念設計として APPROVED にできる状態です。
