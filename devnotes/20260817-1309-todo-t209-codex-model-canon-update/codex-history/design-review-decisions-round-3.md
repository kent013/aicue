# 対応マトリクス: design-review Round 3

## [Warning] フェンス内で無視する対象に層 3 の表の行が入っていない

- 判断: **対応する**
- 根拠: 「見出し・宣言」しか書いていないと、正本の節の中にある**コード例の表**を
  実体の表として読む実装が通ってしまう。
- 対応内容: 「コードフェンスの中の行は、構造の解析 (層 2 と層 3) から丸ごと除外する —
  見出し・宣言・**表の行**の 3 つすべて」と明記した。
  層 1 だけがフェンスの中も走査する非対称は維持する (意図した非対称であると明記)。

## [Warning] 新しい規約 (フェンス除外 / `###` は層 3 を終えない) に対応する検体が無い

- 判断: **対応する**
- 根拠: 負の検体は「点灯すること」しか見ないため、
  「フェンスの中を実体として読む」「`###` で節を終える」という誤実装は
  現物でも検体でも緑になりうる。
- 対応内容: **違反 0 件を期待する正の検体 4 件 (P-01〜P-04)** を追加した。
  - P-01 フェンス内のモデル宣言・ラベル宣言が層 2 の割当を増やさない
  - P-02 フェンス内の `## 利用可能モデル` が見出し数を増やさない
  - P-03 フェンス内の表が層 3 の正本の表にならない
  - P-04 `## 利用可能モデル` の直下に `### 補足` があっても同じ節として解析される
  1 検体 = 1 つの `it` は負の検体と同じ。受け入れ条件 A5 も
  「負の検体 23 件すべてで点灯し、正の検体 4 件では 1 件も点灯しない」へ直した。
  なお正の検体は段 0 のスタブでは緑になるため、**判定関数の実装後**に走らせる用途であり、
  テストファーストの赤は負の検体が担うことも明記した。

## [Warning] 「ATX 見出し」の呼称と字句規則が一致していない

- 判断: **対応する**
- 対応内容: 見出しの定義を `^#{1,6}(?:[ \t]+|$)` に一致する行と明記した
  (`#` の並びの後ろに空白か行末が要る。`#not-a-heading` は見出しではない)。
  層 3 は一致した `#` の数をレベルとして読み、1 か 2 で節を終える。

## [Suggestion] 対応マトリクスの「4 件の変種」は列挙上 5 件である

- 判断: **対応する**
- 対応内容: Round 2 の記録の言い回しの誤りである。正しくは
  N-19〜N-23 の **5 件**である (詳細設計の総数 23 件は変わらない)。
  本ファイルで訂正として記録する (過去の記録は書き換えない)。
