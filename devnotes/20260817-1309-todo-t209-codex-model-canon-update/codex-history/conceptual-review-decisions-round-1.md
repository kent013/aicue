# 対応マトリクス: conceptual-review Round 1

全体判定: CHANGES_REQUESTED

## [Critical] ファイル単位の集合比較では用途の取り違えを検出できない

- 判断: **対応する**
- 根拠: 指摘のとおり。`app-design/SKILL.md` には `gpt-5.6-terra` と `gpt-5.6-sol` の
  両方が現れるため、概念設計と詳細設計の指定を入れ替えても集合は変わらない。
  「静かな後退を赤にする」という期待効果が満たされない。
- 対応内容: 検査を 3 層に分ける。
  1. **綴りの既定拒否** — 走査根の全ファイルで、許可 3 綴り以外の出現は 0 件。
  2. **用途割当の固定** — `**model**: \`X\`` の宣言を全数え上げし、
     同じ節の `**label**: \`Y\`` と対にして (用途ラベル → 綴り) の写像を作り、
     期待写像と**完全一致**で突き合わせる。対にできない書き方 (label が無い /
     model が無い) は**読めない書き方として赤にする**。
  3. **正本の表の固定** — 正本の「利用可能モデル」表の行から綴りを取り、
     3 綴りちょうどであることを完全一致で確認する。
  併せてファイルごとの**出現回数**も期待値で pin する (重複追記の検出)。

## [Warning] 追跡下ファイル列挙と読み込みの仕様が曖昧

- 判断: **対応する**
- 根拠: 列挙と読込の失敗を黙って除外すると、検査が空振りしても緑になる。
  この repo の既定拒否 gate は「空振りを合格と誤読しない」を必ず持つ。
- 対応内容: `git ls-files -z` で NUL 区切りで取得し、リポジトリルート基準で解決する。
  列挙の失敗・読込の失敗は**握り潰さず赤にする**。走査件数が 0 なら赤にする。

## [Warning] 正本と期待表で割当が二重に存在する

- 判断: **反論する (現状の形を維持し、意図をコメントで明記する)**
- 根拠: 本リポジトリの既定拒否 gate は目録 (inventory) と実測を突き合わせる形を
  一貫して採っており、「意図の宣言」と「実測」が二重になるのは仕様である
  (片方だけ直すと赤になるのが目的)。自動抽出で一本化すると、
  正本が壊れたときに検査も一緒に壊れて緑になる (fail-open) 側へ倒れる。
- 対応内容: 期待表が「正本から独立した意図の宣言」であることをテスト内コメントに書き、
  概念設計の「保証しないもの」にも「正本と期待表は同じ変更で直す必要がある」と明記する。

## [Suggestion] 期待表を `as const` + ユニオン型にする

- 判断: **対応する**
- 対応内容: 許可綴りを `as const` の配列とユニオン型で持ち、期待表の値を
  そのユニオンに限る (任意文字列を書けなくする)。
