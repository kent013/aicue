### gate を変更するので共通規約の 4 点を同じ変更で揃える

`tests/Architecture/GlobalTestLockInventoryTest.php` へケースを足すのは
「判定条件・走査対象の変更」に当たるので、AGENTS.md §静的検査 (gate) と走査器の共通規約の
「同じ PR で揃える 4 点」が発火する。次のとおり揃える。

1. **負例と正例**。正例は現行の `run-test.sh` / `run-browser-test.sh` の呼び方が通ること。
   負例は合成入力 — ロックを通さない `php scripts/ci/ensure-test-db.php` の行を持つ
   レーンのスクリプトを検出すること。**先に赤くしてから**本体を書く (テストファースト)。
   負例の置き場は既存ケースと同じ gate 内の合成入力に揃える。
2. **解決できない形を落とす**。`ensure-test-db.php` を含む行が、
   `global_test_lock_run` から始まる形でもコメント行でもないときは、
   **解釈できない呼び出し形として違反にする** (無言で候補から外さない)。
   コメント行を除く判断は docblock に書く。
3. **走査が空振りしていないことの検査**。対象のスクリプトの母集団が空でないことと、
   `ensure-test-db.php` への言及が 1 件以上あることを確かめる
   (綴りを変えられたら判定が丸ごと空振りするため)。
4. **docblock**。走査対象 (グローバルテストロックを取るレーンのスクリプト) と
   保証しないもの (`setup-worktree.sh` はロックの外で呼ぶのが仕様なので対象外 /
   CI の workflow から直に叩く形は見ない) を書く。

5 条のうち (a) は非適用である (クラス名や名前参照を解決しない)。(e) も非適用である
(語彙一致の否定形を持たず、判定は呼び出し形の肯定一致で行う)。
