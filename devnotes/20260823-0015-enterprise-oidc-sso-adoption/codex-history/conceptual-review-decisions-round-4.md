# 対応マトリクス: conceptual-review Round 4

## [Critical] 試行を表へ移したことで「開始したブラウザとの結び付け」が消えた（login CSRF）

- 判断: **対応する（指摘は正しい。設計の欠落である）**
- 根拠: `state` の役割は 2 つある — (1) 推測不能であること、(2) **その認可要求を開始した
  ユーザーエージェントに結び付いていること**。Round 3 で保管先をセッションから
  グローバルな表へ移したとき、(2) が構造から落ちた。
  攻撃者が自分のブラウザで開始し、自分の IdP アカウントで認可した callback URL を
  被害者に開かせると、表だけを根拠にする限り**被害者のブラウザが攻撃者のアカウントへ
  ログインする**（login CSRF）。
- 対応内容: 試行の行に**開始時のブラウザへ結び付く指紋**を持たせる。
  - 開始時にセッションへ**結び付けの秘密**（十分な乱数）を置き、
    行にはその **HMAC 指紋だけ**を保存する（原文もセッション ID も保存しない）
  - callback では現在のセッションの秘密から同じ指紋を計算し、**定時間比較**する
  - 不一致は、行の存在も理由も漏らさず**一様に拒否**する
  - **別のブラウザで callback URL を開くと失敗する** Feature テストを追加する
  - `session()->regenerate()` は**照合と consume を終えてログインを確定した後**に行う
  - 保管先は表のままでよい（DB の原子性とブラウザ結合は併用できる）

## [Warning] consume のアルゴリズムが「1 文の DELETE」では値を読めない

- 判断: **対応する**
- 根拠: 正しい。通常の DELETE は削除した行の値を返さないのに、
  `nonce`・PKCE 検証子・接続 id を読み出す必要がある。「1 文」は手段であって不変条件ではない。
- 対応内容: **不変条件を正本に据え直した** —
  「**同じ試行の使用権を、ちょうど 1 つの要求だけが得る**」。
  実現手順は「トランザクション内で `SELECT … FOR UPDATE` → 期限とブラウザ結合を検査 →
  `DELETE`（影響行数 1）→ commit」と確定した。

## [Warning] 表に載る短期の秘密（PKCE 検証子・nonce）の保護が未定義

- 判断: **対応する**
- 対応内容: 保存の形を項目ごとに確定した。
  - `state`: **指紋だけ**（原文を保存しない）
  - `nonce`: **指紋だけ**（ID トークンの `nonce` を同じ関数へ通して定時間比較すれば足りる）
  - **PKCE 検証子**: トークン交換でそのまま送る必要があるので原文が要る →
    **暗号化して保存**し、ログ・例外・モデルの配列化から除外する
  - 有効期限に加え、**期限切れ行の掃除**を既存の実行点の形（日次の掃除コマンド。
    準拠実装 `idempotency:prune`）へ載せ、**取得時のオンアクセス掃除**も併せて持つ
  - **Factory を追加**し、モデル・Factory の文書上の登録も同じ変更で行う

## [Warning] 3 本目の移行は正典 v1 からの意図的な差分であり「還流候補」だけでは弱い

- 判断: **対応する**
- 根拠: aicue の `docs/template-divergence.md` は「**登録するか迷ったら登録する**」を
  記録の原則に持ち、テンプレートに無い領域への上積みも登録側へ倒すと明記している。
- 対応内容: **逸脱の登録を 1 件追加する（D37）**ことを施策に明記し、
  `docs/template-divergence.md` の「登録エントリ: N 件」と
  `tests/Support/TemplateDivergence/LedgerPins.php` の `DIVERGENCE_ENTRY_COUNT`
  （36 → 37）を**同じ変更で**更新する。正典へ還流されて正典側の版が上がったら、
  独自差分ではなく新しい正典追従として登録を消す（再判定の条件に書く）。
