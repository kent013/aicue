## [Warning] 反転後の W12/W15 のテスト名・メッセージ・fixture に `nightly` を使わない

- 判断: **対応する**
- 根拠: 検証条件 (`rg -i nightly` が 0 hit) と実装が矛盾する。
  そもそも nightly という語は「除去された機構の名前」なので、除去後の gate 名に残すのは
  死んだ語彙の残置であり、思考原則 3 (後方互換の並走を残さない) と同型の問題。
- 対応内容: 概念設計 §4-2 に「反転後の W12/W15 は `nightly` という語を使わず
  `schedule` / `定期実行` で書く」を追記。詳細設計のテスト名も
  `W12: on のトリガー集合が push / pull_request と完全一致すること`、
  `W15: どの job も job-level if を持たないこと` とし、`nightly` を使わない。

## [Warning] W15 の「job-level if 全面禁止」の deny-by-default 性をテスト側にも書く

- 判断: **対応する**
- 根拠: 設計文はマージ後に読まれない。gate を読んで「なんでこんなに厳しいのか」と思った
  次のセッションがテストを緩めるのを止めるには、理由がテストの中に無ければならない
  (W14a/W14b の allowlist が同じ作法でコメントを持っている)。
- 対応内容: 概念設計 §4-2 に「W15 のテスト本文コメントに『job-level `if` は deny-by-default。
  必要になったら理由付きで allowlist 化する (W14a/W14b と同じ形)』を明記する」を追記。

## [Warning] 最終判定は rg ではなく YAML 構造テストを正とする

- 判断: **対応する**
- 根拠: 指摘のとおり `if: contains(github.event.…)` のような等価物は rg で拾えない。
  rg は「読み手向けの語彙が残っていないか」を見る補助検査であり、
  「機構が残っていないか」の正本は parse 後の構造を歩く W12/W15 である。
- 対応内容: 概念設計 §7 の検証手順の順序を入れ替え、
  「正本 = W12/W15 の構造テスト、rg = 補助 (語彙の残置検出)」と明記。
