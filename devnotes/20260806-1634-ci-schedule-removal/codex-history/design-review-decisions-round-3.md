## [Warning] W17 が GitHub Actions の配列形式・scalar 形式のトリガーを検出できない

- 判断: **対応する** (本ラウンド最重要。実在する偽グリーン経路)
- 根拠: 指摘のとおり。`on:` は GitHub Actions では 3 形式すべて有効:
  - map 形式 `on:\n  push:\n  schedule:\n    - cron: ...`
  - **配列形式 `on: [push, schedule]`**
  - **scalar 形式 `on: schedule`**
  `Object.keys()` は配列に対して `["0","1"]`、文字列に対して文字位置のキーを返すため、
  後 2 形式では `schedule` を返さず **W17 も W12 も素通りする**。
  「schedule を再導入させない」という gate の目的そのものが達成できないので必ず直す。
- 対応内容: `Workflow.on` を `unknown` に変え、`triggerNames` で 3 形式を正規化する。
  負のコントロールに配列形式・scalar 形式の fixture を追加する
  (**この 2 本が無いと修正が効いていることを証明できない**ので必須)。

## [Warning] #8 をコミット後に実行すると常に 0 hit になり、混入を検出できない

- 判断: **対応する**
- 根拠: Round 2 で「本実装を先にコミットしてから実測する」手順にした結果、
  #8 (`git diff` ベース) がコミット後は常に空になる。
  **手順の変更が検証を無効化していた**という指摘で、正しい。
- 対応内容: #8 を 2 本立てにする。
  - **#8a (コミット内容の検査)**: `git diff-tree --no-commit-id --name-only -r HEAD` を
    allowlist と突き合わせる。コミットへの混入を検出する本体。
  - **#8b (作業ツリーの検査)**: 従来の `git diff` + untracked。
    負のコントロール実測後に「未復元の差分が残っていないこと」の確認として使う。

## [Warning] テスト計画の W17 の記述が矛盾している

- 判断: **対応する**
- 根拠: 「書いた時点で green」と「ci.yml に schedule が残っている段階では赤」を
  同じ箇所に書いていた。W17 は施策 2 を書いた直後は `ci.yml` を検出して**赤**が正しい。
  誤った期待値を書くと、実装者が赤を見て「W17 の実装が間違っている」と誤診する。

  施策 1 適用後に緑」と統一した。
