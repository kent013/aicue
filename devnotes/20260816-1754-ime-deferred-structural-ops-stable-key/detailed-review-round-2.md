### 施策6: REQUEST_CHANGES

[Warning] 現在の走査は「function宣言への帰属」を保証していません。

`current` は関数の閉じ括弧で解除されず、単に最後に現れた関数宣言名を保持します。そのため、次のような追加は直前の関数へ誤帰属します。

```ts
const newOperation = (): void => {
    runSettled(...);
};
```

件数増加だけなら赤になりますが、既存呼び出しの削除と未登録arrow functionの追加が同時に起きると、件数と集合が一致して緑になる配置があり得ます。既知の限界には「間接呼び出し」と「別モジュール」しか書かれておらず、この直接呼び出しの誤帰属が抜けています。

修正案は次のいずれかです。

- 推奨: Svelte/TypeScriptを扱える既存パーサーでAST走査し、包含する関数宣言を特定する。
- 最小変更: このテストは「関数への正確な帰属」ではなく、「現行の書式を前提に直近のfunction宣言名へ便宜的に関連付ける」と明記し、arrow function、method、入れ子関数、複数行呼び出し、文字列・正規表現内のコメント記号を保証外へ追加する。

[Warning] コメント除去について、「誤検出時は件数不一致で必ず赤になる」とは保証できません。

正規表現によるコメント除去は文字列・テンプレートリテラル・正規表現リテラルを識別しません。誤除去と別の増減が相殺すれば緑になり得ます。`://` がないことだけでは、文字列中の `//` や `/* ... */` がないことの証明にもなりません。

修正案:

- 「必ず赤になる」という記述を削除する。
- 字句走査を維持するなら、保証範囲を「現在のソース書式に対するトリップワイヤ」に限定する。
- 負のコントロールでは通常のfunctionだけでなく、arrow functionからの直接呼び出しも追加し、現在の限界を実測して記録する。

提示された現行コード上では、通常の名前付き関数8個に各1回ずつ直接 `runSettled` があり、このロジックは8件を数えます。ただし、それは現在の書式に依存した結果であり、設計にある「呼び出し元関数名の目録」という一般的保証までは持ちません。

PHPStan、DTO/JsonResource、Inertia Props、サーバ認可は引き続き該当なしで妥当です。UI構造、DESIGN token、Atomic Design、Lucide、`disabled` 規約にも新たな問題はありません。
