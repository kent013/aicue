# 対応マトリクス: design-review Round 2

## [Critical] ASS 改行の正規化順に論理矛盾（手順 1 で生成した \N を手順 2 が潰す）
- 判断: 対応する
- 根拠: 指摘のとおり。CR/LF→\N の後にリテラル \N 無効化を行うと正規の ASS 改行が失われる
- 対応内容: 順序を「(1) 入力中のリテラル \N/\n/\h 無効化 → (2) CRLF/CR→LF 正規化 →
  (3) LF→\N 変換（以降この \N は触らない）→ (4) {} 置換 → (5) 不可視制御文字除去 →
  (6) 長さ上限 → (7) BOM なし UTF-8」に固定。テストに「実改行とリテラル \N が同一入力に
  共存し、実改行のみが ASS 改行として残る」ケースを追加

## [Warning] S3 削除を DB トランザクション内（行ロック保持）で実行
- 判断: 対応する
- 対応内容: DeleteRenderOutputsJob::handle を 3 段に分離:
  (1) 短い検証（ロックなし読み取り: 冪等 guard・最新世代・prefix）→
  (2) tx 外で S3 削除 →
  (3) CAS（`where('output_path', 検証時の値)`）で NULL 化。
  CAS 不一致は NULL 化しない（最新世代の誤 NULL 化防止）、途中クラッシュは再実行/
  reconcile が冪等に収束。ロック順表も「行ロックなし」に更新
