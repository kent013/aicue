# 対応マトリクス: conceptual-review Round 3

## [Warning] テストファースト手順 1 の「正例 (タブを含む値 …)」が新しい受理規則と矛盾する
- 判断: 対応する
- 根拠: 指摘どおりの文書内矛盾。Round 2 で TAB を制御文字集合へ入れたのに手順側を直し忘れていた。
- 対応内容: 手順 1 を負例と正例に分けて書き直した。
  負例 = 値の中の NUL / キー側の SOH / DEL / **TAB を含む代入行** / C1 (U+0085) / 不正 UTF-8 /
  制御文字だけの行 / `\f#` で始まる行。
  正例 = TAB だけの行 / TAB で字下げしたコメント行 / コメント行の中の NUL / 妥当な多バイト値。

## [Warning] i13 の記述が「タブは許容」とだけ読めて値の TAB も許すように見える
- 判断: 対応する
- 根拠: 妥当。保証範囲の記述が実際の受理規則より緩く読める形は、まさに本 feature が
  正典 i13 で禁じている「名前が能力を誇張する」型の欠陥である。
- 対応内容: i13 の更新内容を
  「**TAB は「空白だけの行」と「コメントの字下げ」でのみ許容し、代入行 (値になりうる行) では
  形式違反である**」/ 「コメント行の中身は見ない (制御文字も不正 UTF-8 も沈黙する)」/
  「不可視文字 (U+200B / U+FEFF 等) は対象外」/ 「i12 の主張は『見本を env として選んでいない』
  ことに限る」の 4 点へ具体化した。
- 併せて期待効果の「制御文字を混ぜて値を差し替える」も
  「解釈差を招く不正形式 (制御文字・不正 UTF-8) を通す」へ書き換えた (Round 1 の Suggestion の残り)。
