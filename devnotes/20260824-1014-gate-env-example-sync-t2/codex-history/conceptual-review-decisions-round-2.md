# 対応マトリクス: conceptual-review Round 2

## [Critical] i3 の受理規則が正典と一致していない (TAB の許容 / コメント行の非検査)
- 判断: **一部対応・一部反論** (TAB は指摘どおり厳しくする / 判定順は正典の文面に従い維持する)
- 根拠:
  - **TAB について指摘を受け入れる**。`\x09` は Unicode 上も C0 制御文字であり、
    「値になりうる行に制御文字を含めない」という i3 の目的から見て、値の中の TAB を
    通す理由が無い。実測でも `.env.example` に TAB は 1 件も無いので、厳しくしても
    見本の変更は 0 行である (走査器規約 (b)「見逃す方向へ倒すのは不可」に従う)。
  - **判定順の変更 (行分割 → 制御文字 → 分類) には反論する**。正典 i3 の文面は
    「空白だけの行とコメント行は実効値を作らないので飛ばす。**それ以外の行は**素の代入行だけを
    受理する … 制御文字を含む行も形式違反にする」であり、制御文字の規則は
    **飛ばした後の「それ以外の行」に対する規則**として書かれている。
    さらに i3 は「空白だけの行」を飛ばすことと「コメント行の字下げを許すかは各リポジトリの裁量」を
    明示しており、TAB を含む字下げ・空白だけの行を一律違反にすると**この 2 文と矛盾する**。
    正典の同じ不変条件を満たす唯一の家系実装 (aigenba) も同じ順序を採っている。
    よってコメント行の中身を検査しないことは i3 の適用範囲の縮小ではなく、i3 の文面どおりの
    範囲である (縮小と読まれないよう docblock に「値になりうる行だけを見る」と明記する)。
- 対応内容:
  1. 制御文字の集合に `\x09` を**追加**した: `/[\x00-\x09\x0B\x0C\x0E-\x1F\x7F]/`。
     TAB が許されるのは「空白だけの行」と「コメントの字下げ」だけで、
     **値になりうる行に TAB が現れたら形式違反**である。
  2. 反証で TAB を含む値 (`A=1\t2`) を**正例から負例へ移した**。
     TAB だけの行とコメントの TAB 字下げは正例として残す (i3 の 2 文が求める挙動である)。
  3. コメント行の中身を検査しないことを「保証しないもの」として docblock に明記する
     (反証にコメント行内の NUL のケースを置き、**沈黙することを固定する**)。
- 併せて **C1 域の指摘にも対応した** (下記)。

## [Critical] C1 域を「UTF-8 継続バイトと衝突する」という実装理由で除外している
- 判断: 対応する (除外をやめ、符号位置として検出する)
- 根拠: 妥当。「実装が難しいから範囲を狭める」は保証範囲の縮小であり、走査器規約 (b) に反する。
  UTF-8 では U+0080〜U+009F は必ず `\xC2` + `\x80`〜`\x9F` の 2 バイトで表されるので、
  **行が妥当な UTF-8 であることを先に確かめれば**継続バイトとの衝突なしに検出できる。
- 対応内容: 値になりうる行に対して
  (1) `mb_check_encoding($line, 'UTF-8')` が偽なら**形式違反** (不正 UTF-8 は fail-closed)、
  (2) `/[\x00-\x09\x0B\x0C\x0E-\x1F\x7F]|\xC2[\x80-\x9F]/` で C0 + DEL + C1 を検出、
  の 2 段にした。反証に C1 (U+0085) のケースと不正 UTF-8 (孤立した `\xC3`) のケース、
  および**妥当な多バイト値を誤検出しない**正例を置く。
  「不可視文字 (U+200B / U+FEFF 等) は対象外」は保証しない範囲として明記する
  (正典が求めるのは制御文字であり、不可視文字の無害化は prompt 防御の窓口の責務である)。

## [Warning] i9 の「種別ごと (値の固定 2 / 必須キー 1 の 2 種別)」が不明確
- 判断: 対応する
- 根拠: 妥当。「2 / 1」は種別の数え方の説明であって申告件数ではなく、誤読を招く書き方だった。
- 対応内容: 申告する map を実数で明記した —
  種別: `value_pin => 5` / `required_key => 35`、
  分類: `value_pin` = `ag007_core 2` / `canonical_t2 1` / `aicue 2`、
  `required_key` = `setup 8` / `production_guard 9` / `integration 14` / `object_storage 4`。
  併せて指摘のとおり**分類別 map の合計が種別別 map と一致すること**も検査に加えた。

## [Suggestion] 使命 / 禁止事項 / 実現可能性 / スコープ / 型安全性は妥当
- 判断: 反映不要 (肯定的指摘)
