## [Warning] S4: `nameResolved: false` の分岐に locator の `name` として何を入れるか未定義
- 判断: 対応する
- 根拠: 指摘のとおり。採番は三値の分類より前に `(file, shape, name)` 単位で行うので、
  名前対応に使えない分岐でも locator 用の名前は必ず要る。
- 対応内容: **locator 用の構文名と規則 2 用の解決名を分けた** (提案の形をそのまま採用)。
  - `siteName` … `switch:${式の字面 (空白を 1 つに畳む)}`。構文が正常なら必ず得られる。
    **locator の `name` には常にこれを使う**
  - `correspondenceName` … 型別名が取れるか、識別子・`this`・プロパティ参照の連なりのときだけ値を持つ
  - `nameResolved` は `correspondenceName !== null`。規則 2a / 2b へ渡すのは
    `correspondenceName` だけで、**任意の式の字面を名前対応に使わない**
  - 式の字面が空になる形は構文の診断か解析の失敗として落とす
  - 負例に「**呼び出し式の分岐が 2 件**あるとき `occurrence` が 0 と 1 になり、
    交差する列挙を持つ側だけが判定不能になる」を足した
