### 施策 2: 文書更新スキルへの整合確認追加

**判定: REQUEST_CHANGES**

[Warning] `mktemp` 失敗時にルート直下へ一時ファイルを書こうとする可能性があります。

現在の記述では、`mktemp -d` が失敗して `WORK` が空のまま処理が継続すると、`"$WORK/table.md"` は `/table.md` になります。

```bash
WORK=$(mktemp -d); trap 'rm -rf "$WORK"' EXIT
```

修正案:

```bash
WORK=$(mktemp -d) || exit 1
trap 'rm -rf -- "$WORK"' EXIT
```

スキル全体が `set -e` を保証していないため、コマンド自身で失敗を閉じる必要があります。

[Warning] 「保証しないもの」の表抽出範囲の説明が実装と逆です。

現在の記述:

> この節より上に第 1 列がバッククォートの表を置くと台帳の一部と誤認される

実際のコマンドは次のため、「節より上」は抽出されません。

```bash
sed -n '/^## スクリプト一覧$/,$p'
```

誤認されるのは「同節より下に追加された別の表」です。

修正案:

> **照合は `## スクリプト一覧` からファイル末尾までを見る**。この節より下に別の表を置き、その第1列をバッククォートの識別子にすると台帳の一部と誤認される。

README側の「別の表は上に置く」という規約とは、この修正により整合します。

### テスト・受け入れ条件

**判定: REQUEST_CHANGES**

[Warning] A3・A4のコマンドは「全項目が存在すること」を終了コードでは保証しません。

OR検索なので、候補のうち1つだけ存在しても `grep` は成功します。「4点すべてヒット」「すべてヒット」は人が出力を数える条件であり、「機械検証可能」という表題と一致しません。

修正案として、各条件を個別に `grep -q` します。

```bash
for pattern in \
  '2-1. scripts/ 台帳の整合確認' \
  'scope 引数によらず' \
  '機械検査へ昇格させない' \
  'AG-192'
do
  grep -q "$pattern" .claude/skills/app-update-docs/SKILL.md || exit 1
done
```

A4も同じ形式で各語を個別確認してください。あるいは期待値を「出力を確認し、全項目の存在を人手判定」と改めれば整合しますが、受け入れ条件としては個別 `grep -q` が明確です。

PHPStan、DTO/JsonResource、Inertia Props、DESIGN.md、Atomic Design、セキュリティ不変条件は今回の変更対象外です。提示された変更から、それらへの後退リスクは認められません。
