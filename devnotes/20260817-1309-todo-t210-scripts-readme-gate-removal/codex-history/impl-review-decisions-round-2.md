## [Warning] A2 を「読み替えて達成」と書くのは設計との一致性として不十分

Codex の提示した 3 択:
1. 詳細設計の A2 を `docs/TODO.md` 除外込みへ改訂する
2. A2 を未達のままとし、`app-todo-close` 後に達成される後続条件として扱う
3. 読み替えた検査を A2 とは別の代替確認として採番し、A2 達成とは表現しない

- 判断: **対応する (2 と 3 を採る。1 は採らない)**
- 根拠:
  - 1 を採らない理由は 2 つ。①詳細設計は Codex レビュー Round 4 で APPROVED 済みの
    確定文書であり、実装ブランチで受け入れ条件を書き換えると「達成できるように条件を直した」
    形になる (まさに Codex が言う「検証条件のすり替え」)。②本 run は
    `docs/TODO.md` に触れない前提で走っており、条件を改訂しても実体は変わらない。
  - 2 と 3 は両立する。A2 は本ブランチでは**未達**と明記し、
    `app-todo-close` が T210 の行を `docs/TODO-closed.md` (設計の A2 が既に除外しているファイル) へ
    移した時点で追加作業なしに満たされる後続条件として扱う。
    実装側で確認できる範囲は A2' (代替確認) として別に採番し、A2 達成とは呼ばない。
- 対応内容: `verification.md` を次のとおり直した。
  - §1 の但し書きを「読み替え」から「**本ブランチでは未達。クローズ後に達成される後続条件**」へ変更
  - §4 の表を A2 (設計どおり = 未達 1 件) と A2' (代替確認 = 0 件) の 2 行に分離
  - A8 行の下に「A2 だけが本ブランチでは未達」と明記
  - §6 (保証しないもの) に「『残存参照 0 件』と書けるのは A2' の範囲まで」を追加
- なお本件は実装完了報告の `deviations` にも記載する (統合エージェントがクローズ時に
  設計どおりの A2 が 0 件になることを確認できるようにするため)。
