## [Warning] 施策 1 — 旧テストの S3 / S4 の行き先が扱われていない
- 判断: 対応する
- 根拠: 指摘のとおり。撤去で「落とすもの」と「手順へ移すもの」を分けずに書いていたのは、
  保証範囲の説明として不十分である。用途・実行タイミングの空欄は `scripts/README.md` の規約そのもので、
  落としてよい性質ではない。
- 対応内容:
  - 施策 1 に「旧検査が見ていた 4 つの性質の行き先」の表を新設し、
    S1 / S2 / S3 は形態 A へ**移す**、S4 (除外登録) は**落とす** (除外を README の宣言で
    本書自身の 1 件に固定し、登録簿そのものを持たない) と明記した。
  - 形態 A のコマンド列へ空欄・書式不正の検出 (`awk`) を追加した。
  - `scripts/README.md` の対象範囲の宣言にも「用途と実行タイミングを空にしない」を足した。
  - 「保証しないもの」に、除外の仕組みが無くなること (2 件目を理由付きで外す手段は無い) を書いた。
  - 受け入れ条件 A4 / A6 / A7 と負のコントロールを 4 ケースへ更新した。

## [Warning] 施策 2 — 表の抽出範囲が README 全体で広すぎる
- 判断: 対応する
- 根拠: 将来 README に別の表が増えたら台帳外の行を拾う。指摘のとおり範囲を絞るほうが堅い。
- 対応内容: 形態 A の先頭で `sed -n '/^## スクリプト一覧$/,$p'` により
  「スクリプト一覧」節以降だけを切り出してから照合する形にした。
  併せて `scripts/README.md` の宣言へ「台帳の表はこの節より下の 1 つだけ。別の表は上に置き、
  第 1 列をバッククォートの識別子にしない」を明記した (Codex の Suggestion も同趣旨)。
  機械では止まらない前提であることは「保証しないもの」に書いた。

## [Warning] 施策 2 — 形態 B の grep がノイズだらけになる
- 判断: 対応する
- 根拠: `.git` / `vendor` / `node_modules` / `devnotes` を含めると呼び出し元の判断ができない。
  README 自身のヒットを呼び出し元と誤認する事故も現実的である。
- 対応内容: `--exclude-dir` 4 つを付け、「README 自身のヒットは呼び出し元ではない」
  「実行されている記述 (package.json の script / CI の job / 他スクリプトの実行行 / hook の配線) で判断する」
  という注意書きを足した。
