# 対応マトリクス: conceptual-review Round 3

## [Critical] 3 持ち回りの口では `finally` の構造をそのまま使えない (適用途中の失敗が巻き戻らない)
- 判断: 対応する
- 根拠: 指摘のとおり。閉包の口は「退避 → try { 適用 + 本体 } finally { 復元 }」で閉じるが、
  持ち回りの口は**適用が終わった時点で呼び出し側へ戻る**ので、同じ `finally` を本体の終わりまで
  開いたままにできない。しかも適用の途中で例外になると snapshot が呼び出し側へ返らないため、
  後処理フックはその snapshot を使って戻すこともできない — つまり
  「適用途中の失敗が巻き戻る」保証が持ち回りの口だけ欠ける。
- 対応内容: 概念設計の「口の契約」を **口ごとに 2 つへ分けて**書き直した。
  - 閉包の口: 検証 → 退避 → `try { 適用 + 本体 } finally { 復元 }`
  - 持ち回りの口: 検証 → 退避 → `try { 適用 } catch (Throwable) { 復元して再送出 }` →
    snapshot を返す → 後処理フックが `restore()` を呼ぶ。
    **適用がすべて成功して snapshot が返った後の復元だけ**を枠組みの後処理へ預ける。
  共有するのは「全キー検証 / 全 3 面の退避 / 適用 / 復元」の**プリミティブ**であって
  制御構造ではない、と明記した。
  構造の固定 (q2 の代替) も**2 つの口それぞれについて**何を見るかを分けて書いた。

## [Warning] 4 期待効果の書き方が閉包の口にしか成立していない
- 判断: 対応する
- 対応内容: 期待効果の該当項を「閉包の口は `finally`、持ち回りの口は適用失敗時の即時の巻き戻しで
  同じ性質を得る。どちらも構造の固定で代え、動的には検査しない」と書き分けた。

  (fail-closed)。負例として契約テストへ入れる。
