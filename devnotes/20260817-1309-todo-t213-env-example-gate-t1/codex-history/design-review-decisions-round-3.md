# 対応マトリクス: design-review Round 3

## [Warning] B3 について表と直後の説明が矛盾する

- 判断: 対応する (指摘が正しい)
- 根拠: t0 は `toContain('TRUSTED_PROXIES=')` を持つので、B3 (その行を消す) は t0 でも赤になる。
- 対応内容: 説明を「**B3 は t0 でも赤になる**」「**B4 / B5 / B6 には対応する t0 の検査が無い**」の
  2 行へ書き直した (表の「現行 t0 での結果」列と一致する)。

## [Warning] AC4 に古い junit ファイルによる偽グリーンが残る

- 判断: 対応する (指摘が正しい)
- 根拠: 2 つのコマンドが独立していると、テストが落ちた後に前回の 22 件の XML を読んで
  件数判定だけ成功する。
- 対応内容: `mktemp` で実行ごとに一意な出力先を作り、`trap` で後始末し、
  テスト実行と件数判定を `&&` で繋いだ。偽グリーンの機序も注記として書いた。

## [Warning] `vendor/bin/pest` の直接実行はグローバルテストロックの運用と整合しない

- 判断: 対応する (指摘が正しい。逃げ道を削除する)
- 根拠: 「DB を使わないから安全」という局所の正しさで実行経路を二重化すると、
  後方互換の並走を残さないという原則 (思考原則 3) に反する。
- 対応内容: 逃げ道を削除し、代わりに
  「`--log-junit` が通ることを**実装セッションで確認する**。通らなければ
  `composer test` の経路の中で機械判定できる別法へ AC4 を差し替え、判断を証跡に残す。
  ロックの外で走らせる案は採らない」と書いた。
