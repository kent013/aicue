**AI-CUE** は、現場に既にある**作業手順書(SOP)を起点に**、AI が撮るべきカットを設計した**動画シナリオ**を生成し、そのシナリオを**スマホ(PWA)でナビゲーション撮影**することで、専門知識ゼロの現場作業者でも**標準化されたマニュアル動画**を作れるようにする。

## 背景・課題

### 何が足りていないか

`.env.example` は「読み物」ではなく **生きた既定値** である。本リポジトリでは 3 つの経路が
このファイルをそのまま実環境にする。

- `composer setup` の 2 行目 — `file_exists('.env') || copy('.env.example', '.env')`
- `composer.json` の `post-root-package-install` — 同じコピー
- `scripts/setup-worktree.sh` の復旧案内 — 「親のチェックアウトで `cp .env.example .env`」

したがって見本の欠落・危険な値は「文書の不備」ではなく **実環境の不備** になる。

現行の検査 `tests/Architecture/EnvExampleInvariantTest.php` は、家系の機能台帳 lctl が
`gate-env-example-sync` として追跡している仕組みの **t0 の形** にとどまる。実測 (本設計時点):

| 現行の検査 | 形 |
|---|---|
| `SESSION_SECURE_COOKIE=true` | `toContain` の部分一致 |
| `SESSION_ENCRYPT=true` | `toContain` の部分一致 |
| `TRUSTED_PROXIES=` | `toContain` の部分一致 |
| `PASSKEYS_USER_HANDLE_SECRET=` | 行頭一致 (`/^…=/m`) |
| `TEMPLATE_APP_SLUG=` | `toContain` の部分一致 |
| 3 つの見本ファイルの `${VAR}` 自己参照・前方参照 | aicue 固有。家系で本リポジトリだけが持つ |

t0 の穴は 3 つある。

1. **コメント偽装**: `# SESSION_SECURE_COOKIE=true` と書き換えても部分一致は通る。
   実効値は失われているのに緑のままになる。
2. **重複代入**: `SESSION_SECURE_COOKIE=true` の後ろに `SESSION_SECURE_COOKIE=false` を
   足しても、部分一致は前者に当たって通る。どちらが実効値かは読み込み側の解決順に
   依存し、検査は何も言わない。
3. **キーの網羅が無い**: 本番起動時に `App\Support\ProductionEnvGuard` が要求する座標
   (`CIPHERSWEET_KEY` / `PRIMARY_HOST` / `TRUSTED_PROXIES` 等) が見本から消えても
   1 つも赤くならない。消えたことに気づくのは「本番が起動しなかった当日」である。

## 改善アイデア

**`tests/Architecture/EnvExampleInvariantTest.php` 1 本だけを書き換え、4 部品と誠実性の検査を
足す。見本ファイル (`.env.example` / `.env.testing` / `.env.bughunt.local.example`) と
アプリの実行コードは 1 行も変えない。**

これが成立する根拠は実測にある。正典と同じ解析規則 (空行を飛ばす → `^\s*#` のコメント行を
飛ばす → 残りは `^[A-Z][A-Z0-9_]*=` のみ受理) で本リポジトリの見本 3 枚を機械的に読んだ結果:

| ファイル | 代入キー数 | 形式違反の行 | 重複キー |
|---|---|---|---|
| `.env.example` | 81 | 0 件 | 0 件 |
| `.env.testing` | 46 | 0 件 | 0 件 |
| `.env.bughunt.local.example` | 20 | 0 件 | 0 件 |

値の固定の候補 4 件 (`SESSION_SECURE_COOKIE=true` / `SESSION_ENCRYPT=true` /
`ADMIN_MFA_REQUIRED=true` / `MCP_STRICT_TRANSPORT=true`) も、キー網羅の候補 36 件も、
すべて `.env.example` に素の代入行として実在する。**台帳化で赤くなる既存キーは 1 件も無い。**

### 追従の中身 (4 部品 + 2 つの追加)

1. **(a) 値の固定** — 4 件を行の完全一致で固定する。
   - 裁定 AG-007 が名指しする 2 件: `SESSION_SECURE_COOKIE=true` / `SESSION_ENCRYPT=true`
   - 本リポジトリ固有の 2 件: `ADMIN_MFA_REQUIRED=true` (管理画面の二要素の実質無効化を防ぐ) /
     `MCP_STRICT_TRANSPORT=true` (Origin を送らないクライアントの受け入れ拡大を防ぐ)
2. **(b) キー網羅の台帳** — 4 分類 36 件。分類ごとに定数を分け、削るときに
   「どの根拠を外すのか」がレビューで見える形にする (平らな 1 本の配列にしない)。
3. **(c-1) 行の形式の検査** — `export` つきの行・先頭に空白がある代入・小文字のキー・
   等号の前後に空白を置いた代入・素の区切り線を形式違反として赤にする。
   これらは「存在検査と重複検査の母集合から外れたまま実効値だけを変えられる迂回」になる。
4. **(c-2) 重複の検査** — 代入キーが一意であることを要求する。
   読み込み側の解決順 (先勝ちか後勝ちか) に **依存しない** — 重複そのものを禁じるので、
   どちらの解決順であっても値の固定を無音で覆せなくなる。
5. **台帳の誠実性の検査** — 値の固定とキー網羅の二重登録、および各台帳内の重複を禁じる。
6. **(追加) 解析器の反証の検査** — 解析を「文字列を受け取る純粋な関数」と
   「ファイルを読むだけのアダプタ」に分け、壊した入力を合成して食わせる検査を恒久で置く。
   見本ファイルを実際に壊さずに「壊れたら赤くなる」ことを証明できるようにするためで、
   これが本設計のテストファーストの土台になる (後述)。

### 既存の aicue 固有の検査を失わない

`${VAR}` の自己参照・前方参照を 3 つの見本ファイルについて検査する仕組み
(`ENV_EXTERNAL_REF_ALLOWLIST` + `collectUnresolvedEnvRefs`) は、家系 6 リポジトリで
本リポジトリだけが持ち、台帳でも還流候補として印が付いている。実害の記録もある
(bug-hunt F-01: `.env.bughunt.local` の `APP_NAME="${APP_NAME}"` が全画面のタイトル・
ロゴ・フッターに文字列のまま露出した)。

**この検査は無改変で残す。** 正典の 4 部品は値の固定とキーの網羅の 2 軸しか持たないため、
統合形へ寄せる作業で吸収されて失われる恐れがある。禁止事項「既存テストの削除・上書き」にも
直接あたる。

## 実装方針 (概要)

変更するのは **`tests/Architecture/EnvExampleInvariantTest.php` の 1 ファイルだけ**。

- 台帳を file スコープの定数として持つ (値の固定はキーと値の組のリスト、キー網羅は
  分類ごとの文字列リスト)。連想配列にしないのは、同一リテラル内の重複キーが
  コンパイル時に後勝ちで無音に潰れ、「追加に見える差分」で既存の固定を反転できてしまうため。
  リスト形式なら重複がそのまま残り、誠実性の検査 1 本で台帳内・台帳間の重複を同じ機構で捕まえられる。
- 解析器は純粋な関数 (`string` を受け取り、値の写像・重複キー・形式違反の行番号を返す) と、
  `base_path('.env.example')` を読むアダプタに分ける。
- 検査は 5 本 (行形式 / 重複 / 値の固定 / キー網羅 / 台帳の誠実性) + 反証の検査 (データ駆動)。
- 失敗メッセージにはキー名と行番号だけを出す (見本の実値を出力しない)。

## 制約・前提

- **PHPStan の解析対象に `tests/` は入っていない** (`phpstan.neon` の paths は
  app / config / database / routes)。ただし書式は `vendor/bin/pint --test` の対象なので
  Laravel preset に従う。型注記は正典と同じ水準で書く (将来 tests を解析対象に入れても通る形)。
- **テストは `--parallel` で走る**。本設計の検査はファイル読み取りのみで DB を触らず、
  グローバル状態も持たないため並列で安全。
- **PHP の関数名・定数名はプロセス大域**。Pest は全テストファイルを同一プロセスに読み込むため、
  新設する関数・定数の名前はリポジトリ全体で一意にする (既存の
  `collectUnresolvedEnvRefs` / `ENV_EXTERNAL_REF_ALLOWLIST` と衝突させない)。
- **依存の向きは一方向**: キー網羅の台帳は `app/Support/ProductionEnvGuard.php` が
  本番で要求する座標から人が導出する。guard が変われば台帳が古くなる
  (台帳の関係宣言 depends_on trusted-hosts-production-preflight と同じ形)。
  機械で結線しないことの理由はスコープ外の節に書く。

## スコープ外 (やらないと決めたこと)

1. **見本ファイルの内容を変えない**。実測で 1 件も赤にならないため変更が要らない。
   増やすのは検査だけである。
2. **`.env.testing` / `.env.bughunt.local.example` に値の固定とキー網羅を広げない**。
   テストレーンの正しい値は本番の安全側と **逆向き**である (`.env.testing` は
   `SESSION_ENCRYPT=false` が正しい)。同じ台帳を当てると意味が反転する。
   これらのファイルには既存の `${VAR}` 検査だけが掛かる。
3. **`SECURITY_HSTS_ENABLED` / `SECURITY_CSP_ENABLED` を台帳に載せない**。
   `ProductionEnvGuard` はこの 2 つを本番で true と要求するが、本リポジトリの
   `.env.example` は現在この 2 つを 1 行も持たず、`config/security.php` の既定
   (hsts=false / csp=true) で local が動く設計になっている。台帳に載せると見本の変更が
   必要になり、「検査だけを増やす」という本 TODO の方針から外れる。載せるかどうかは
   見本の書き方 (コメントで提示するか、値つきで提示するか) を決める別の判断であり、
   必要になったら別 TODO として起こす。
4. **禁止キーの台帳を持たない** (偽の外部サービスのフラグが見本に載らないことの検査)。
   これは aigenba が正典に対して足した純増であり、AG-007 の 4 部品ではない。
   本リポジトリでは 3 つのフラグ (`TESTING_FAKE_EXTERNALS` / `TESTING_FAKE_STORAGE` /
   `TESTING_FAKE_LLM`) はいずれも `.env.example` に無く、仮に載っても
   `ProductionEnvGuard` が本番起動を止めるため被害が閉じている。今は要らない。
5. **台帳の件数を固定しない** (完全一致の件数 pin を置かない)。aigenba の申し送りは
   「台帳から契約が 1 枚落ちても縮むだけで赤くならない」と指摘するが、それは
   台帳が別ファイルにあるデータ駆動の検査の話である。本設計の台帳は検査と同じファイルの
   リテラル定数なので、削除はその差分に直接現れる。件数を別の場所へ書くと
   同じ事実を 2 か所に持つことになり、必ず食い違う。
6. **制御文字・不可視文字を見ない**。aigenba の申し送りの 3 点目にあたるが正典には無い。
   保証しないものとして明記する。
7. **キー網羅を完全一致の集合にしない**。台帳は **床** であって天井ではない。
   `.env.example` へ任意のキーを足すことは責務外である (正典と同じ判断)。
8. **`${VAR}` の検査と新しい解析器を 1 本に統合しない**。前者は 3 ファイルを走査し、
   `export` つきの行と先頭空白を意図的に許容する (`.env.bughunt.local.example` 等で
   将来混ざりうるため)。後者は `.env.example` 専用で、まさにその 2 つを違反にする。
   受理規則が逆なので統合すると片方の意図が壊れる。緑のまま動いている既存の検査を
   書き換える利得も無い。**役割の境界はファイル冒頭のコメントに明記する。**
9. **`ProductionEnvGuard` と台帳をリフレクションで結線しない**。guard が読むのは
   config のキー (`config('security.hsts.enabled')` 等) であって環境変数名ではない。
   環境変数名は `config/*.php` の `env()` 呼び出しの中にしかないため、機械で結ぶには
   config ファイルの構文解析が要る。今必要な範囲を超える (思考原則 2)。
   一方向の依存であることは台帳と本設計の両方に書いてある。

## 保証しないもの (誇張しない)

- 見るのは **`.env.example` の中身だけ**である。実行中の `.env`、環境変数、
  設定キャッシュには **無言で効かない**。
- キー網羅は **存在だけ**を見る。空の値も通る (`STRIPE_KEY=` は合格)。
  「見本に提示されている」ことの検査であり、「正しい値が入っている」ことの検査ではない。
- 値の固定は台帳に載せた 4 件だけである。他の値がどう変わっても沈黙する。
- 行の形式の検査が受理を拒むのは **`.env.example` に現れた行**だけである。
  他の 2 つの見本ファイルの行の形は見ない。
- 「この検査があれば見本と設定が一致している」とは読めない。
  config の既定値と見本の値が食い違っていても検出しない (同期の検査ではなく、
  **提示の検査**である)。
