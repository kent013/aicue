# 対応マトリクス: conceptual-review Round 2

## [Warning] §3 に「5 レーン」が 2 か所残っている (母集団の不一致)
- 判断: **対応する**
- 根拠: 単純な追随漏れ。目録の母集団が設計内で 2 通りあると実装が割れる。
- 対応内容: 2 か所とも 6 レーンへ統一し、レーン割当目録の側にも 6 つの limiter 名を列挙した。

## [Warning] コスト軸表の数値がレーン構成と一致しない (32/min・42/min の根拠不明)
- 判断: **対応する**
- 根拠: 指摘の算術が正しい。6 レーンの単純合算は 48/min であり、
  32 / 42 という数字は「状態変更を伴わないレーンを除いた」中途半端な集計だった。
  また現状側の「合算 6/min」も不正確で、共有カウンタは `max=10` の route が
  続く限り 10 まで進む (さらに `livewire.upload-file` は 60 まで通る)。
- 対応内容: 表を全面的に書き直した。
  - 現状の天井を「認証面 12 本の受理リクエスト総数 = **10/min**」と正確に書いた
    (最小比較値 6 で `max=6` の 6 本が死に、10 で残りも死ぬ、という順序も本文に明記)。
  - 変更後を **48/min** (6+6+6+10+10+10) とし、
    「throttle だけから導ける保守的上限 = 受理されるリクエスト数」であることを明示。
  - 「実際に成功する永続状態遷移数」は事前条件と一回性で 48 未満になるが、
    それは throttle の保証ではないと明記 (具体例 3 つ)。
  - 副作用 (監査ログ / 通知 / セッション失効 / rehash / ジョブ dispatch) は
    独立軸にせず「状態変更に付随するもの」として同じ枠で確認する、と位置づけた
    ([Suggestion] への対応を兼ねる)。
  - `livewire.upload-file` (60/min) は本変更で動かないため軸に含めないことを明記。

## [Warning] `two-factor-manage` 内の意図的な巻き添えを明文化すべき
- 判断: **対応する**
- 根拠: 「数える対象」という 1 つの原則では、`confirm` (秘密照合) が
  `enable` / `disable` (照合なし) に食われる構造を説明しきれないという指摘は正しい。
- 対応内容: **統合の基準を 2 つに分けて明記**した。
  - 同じ credential を照合する面 → 秘密に対する**試行予算** (`password-verify`)
  - 同じ feature のフロー → フローの**操作予算** (`two-factor-manage` / `email-verification`)
  そのうえで `two-factor-manage` は後者であり、フロー内の相互消費を
  **受容リスクとして明示**した (他 feature との巻き添え遮断が目的であり矛盾しない)。

## [Suggestion] メール送信以外の副作用 (通知 / 監査ログ / rehash / ジョブ) の扱い
- 判断: **対応する** (独立軸は増やさない)
- 対応内容: 上記コスト軸表の直後に、「状態変更に付随する副作用」として
  同じ枠で確認する旨を明記。独立軸を増やさない根拠 (成功条件に強く制約される) も併記。

## [Suggestion] `RateLimiterKeys` の型設計 (lane を enum 化 / identifier / ip / non-empty-string)
- 判断: **一部対応 + 1 点反論**
- 根拠: `non-empty-string` での閉じ込め、`int|string|null` の identifier 分岐、
  `ip()` の null 明示はいずれも採用する。
  ただし **lane の enum 化は採らない**。`RateLimiter::for()` の第 1 引数は
  `RateLimiterRegistrationScanner` の制約でリテラル文字列である必要があり
  (解析不能な登録は `RateLimiterKeyConventionTest` が unresolved として fail させる)、
  enum を入れると「`for()` にはリテラル / helper には enum」の二重管理になる。
  AGENTS.md 思考原則 3「後方互換の並走を残さない」= 同じ事実の表現を 2 つ持たない。
- 対応内容: §制約・前提に型の閉じ方 3 点と enum を採らない根拠を追記。
