## 施策2: `IntegrationGuideGateTableSyncTest`

判定: **REQUEST_CHANGES**

- [Warning] データ行の列数をヘッダと一致させていません。

  現在はデータ行が3列以上なら通るため、次のような不正な表を受理します。

  ```markdown
  | ゲート | 説明 | 登録先 | 備考 |
  |---|---|---|---|
  | `SomeGateTest` | 説明 | 登録先 |
  ```

  反対に、3列ヘッダに対する4列のデータ行も通ります。未エスケープの`|`による意図しない列分割も検出できません。

  修正案: データ行も次の完全一致にしてください。

  ```php
  if (count($cells) !== count($headerCells)) {
      // RuntimeException
  }
  ```

  「ヘッダより少ない」「ヘッダより多い」の負例を追加してください。`INTEGRATION_GUIDE_MINIMUM_COLUMNS`はヘッダの最低列数検査にのみ使えます。

- [Warning] 施策一覧直後の「実施順」が旧版のままです。

  現在は以下になっています。

  > 最小の抽出器 + 負例テスト群を置く

  これは後段の「正例を例外stubに対して先に赤くする」手順と矛盾します。

  修正案: 冒頭の実施順も、後段の8ステップと同じ「正例赤 → 最小正常系 → 負例赤 → fail-closed実装」の順へ統一してください。

- [Warning] 規約適合表では依然として「負例7形」と書かれていますが、実際は表形状の負例12形です。

  修正案: `(c)`の記述を「表形状12形、アンカー2形、§2見出し2形、違反報告3観点と正例」に合わせてください。

- [Warning] `integrationGuideCells()`のdocblockに旧記述が残っています。

  ```php
  (走査器共通規約 (e) の宣言)
  ```

  今回は(e)を対象外と整理したため、規約適合表およびファイル先頭docblockと矛盾します。

  修正案: 「独立した走査契約として、区切りを半角縦棒1文字に固定する」へ変更してください。

- [Suggestion] 「dataset展開後19シナリオ」はPestの実行ケース数として正しい一方、内訳では一つのテスト内の複数assertionも「検証」として数えています。`19テストケース、内部assertionは別計数`と区別すると誤解がありません。

区切りセルの完全一致、§2見出しとアンカーの一意性、PHPStanの型絞り込み、正例を先に赤くする手順自体は適切です。
