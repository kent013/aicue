# 対応マトリクス: conceptual-review Round 1

## [Critical] 「復帰」と称しつつ原文が参照不能。D40 登録と債務除去で未検証の差異を意図的逸脱として固定するのは AG-116 完了根拠として不十分（観点 2）

- 判断: **一部対応する / 一部反論する**
- 根拠:
  - **反論の部分**: 「別議題として位置づけ直す」は取れない。lctl 台帳の
    `laravel-claude-template` セルは本作業を「テンプレートセルの作業ではない／これは **aicue 側の
    取り込み作業**である」と名指しし、テンプレート側の担当から明示的に外している。aicue が
    勝手に「独自索引の新設」へ読み替えると、台帳が指す残タスクは誰の担当でもなくなる。
  - また「原文が無いので写像にする」のは本件の発明ではなく**家系の正が既に採った作法**である。
    テンプレート側の還流 `T121` は aicue 本文を実読できない環境で実施され、
    「aicue 本文の逐語復元ではなく裁定の所見を実装へ写像した規約」と本文自身に明記する形で
    完了し、台帳はそれを `implemented (t2)` として受理している。同じ作法を逆向きに適用する。
  - **対応の部分**: 「AG-116 の合成版が完成する / 残タスクが 0 になる」という**到達の主張は
    過大**である。台帳セルの status を上げる判断はキュレーターの巡回の責務であり、
    こちらから完了を宣言する立場にない。期待効果の記述を「台帳が aicue 側に名指しした
    取り込み作業を、参照可能な一次資料の範囲で写像として実施する」へ下げる。
  - 「復帰」という語も単独では誤読を招くので、本文・D40 の両方で
    **「逐語復元ではなく判定規準としての写像」**であることを必ず併記する。
- 対応内容: 概念設計の「期待効果」から完了主張を削除し、「改善アイデア」に写像であることの
  明示と台帳が名指しした担当関係を書き足した。詳細設計では §2 本文の導入文にも
  「逐語復元ではない」旨を書く行を含める。

## [Critical] 債務一覧から削除すると、将来テンプレート現物が取得可能になったときの差分検出経路を失う（観点 5）

- 判断: **対応する**（指摘は正しい。突合 gate 自身の docblock が
  「登録済みのパスの追加の drift は検出しない（検出するのは一致から不一致へ移る瞬間である）。
  **債務パスは例外**で、採用時ハッシュとの一致まで見る」と明記しており、債務から登録へ移すと
  ハッシュ追跡は実際に失われる）
- 根拠: ただし「債務削除を行わない」は選べない。`AdoptionDebtInventory` の docblock と D34 が
  「一覧が縮む契機は (1) 内容をテンプレートへ戻す / (2) 意図的逸脱として登録簿へ書く の 2 つだけ」
  と定め、突合 gate の F10 が編集を `mutatedDebtPaths` で落とす。テンプレート現物が無いので
  (1) は物理的に取れない。よって (2) が唯一の経路であり、**分離は機構的に不可能**である。
  対処は「経路を失うことを登録に明記し、再照合の契機を登録側で持つ」に限られる。
- 対応内容: D40 の内容を概念設計の段階で具体化した — (a) テンプレート現物が参照不能だった事実、
  (b) 逐語復元ではなく意味的写像であること、(c) 再照合が必要になる条件（テンプレート更新の
  一括取り込み時 / 家系の巡回で合成版の現物が配られたとき）、(d) 再照合時の正本
  （lctl の feature `app-integration-guide` と テンプレートの `docs/app-integration-guide.md`）、
  (e) 状態は `恒久` ではなく **`監視中` + 見直し期限**（D34 と同じ期限管理に乗せる）。
  併せて「債務のハッシュ追跡を失うこと」自体を D40 の本文に書く。

## [Warning] 「8 本 / 13 本 / 34 行」と「ゲート名 21 本」の関係が不明確（観点 4）

- 判断: 対応する
- 根拠: 台帳の記述は「ゲート表 8 本 / 13 本」（= ゲートの本数）と「2 表 計 34 行」（= 表 2 本が
  占めていた Markdown の物理行数）で、単位が違う。混ぜて書いていたのが原因。
- 対応内容: 「契約にするのは 8 + 13 = 21 件のゲート」「34 行は小見出し・表ヘッダ・区切り行・
  空行を含む物理行数の記述であって復元の根拠には使わない」と定義を分けて明記した。

## [Warning] 8 本を「無条件」と分類する根拠を明示し、各行に発火条件・登録先・要求される判断を書け（観点 5）
