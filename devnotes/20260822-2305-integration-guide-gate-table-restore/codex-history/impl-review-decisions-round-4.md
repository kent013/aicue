# 対応マトリクス: impl-review Round 4

## [Critical] `integrationGuideRejectHtml()` の呼び出しが §2 切り出し**後**なので、HTML block 内の偽の §2 を検出できない

- 判断: **対応する**
- 根拠: 指摘のとおり。Round 3 の修正は「切り出した §2 の中の HTML」しか見ていなかったため、
  `<pre>` の開始行を偽の `## 2. ` より**前**に置くと、(1) mask は HTML block を分類しないので
  `<pre>` 内の `## 2. ` が構造行になり、(2) block 内の偽の `## 3. ` で §2 が終わり、
  (3) 切り出し結果は `## 2. ` から始まるので `<pre>` も `</pre>` も拒否検査に渡らない。
  結果として描画上は preformatted の中にある索引が「正常な索引」として抽出される。
  **章の境界を決める入力そのものが汚染される**形なので、境界を決めた後に検査しても間に合わない。
- 対応内容:
  1. `integrationGuideSectionTwo()` で mask を作った直後、**`## 2. ` を探す前に文書全体へ
     `integrationGuideRejectHtml($lines, $mask, '契約文書')` を掛ける**ようにした。
     切り出した §2 に対する検査 (`'§2 内'`) はそのまま残す (合成入力を直接受け取る負例の経路のため)。
  2. `integrationGuideRejectHtml()` に違反位置の呼び方 (`$scope`) を渡すようにし、
     メッセージが「契約文書 N 行目」「§2 内 N 行目」で読み分けられるようにした。
     HTML block のメッセージには「章の境界を HTML で覆えないようにするため §2 の外も対象である」と書いた。
  3. docblock を「§2 の中に HTML は書けない」→「**契約文書に HTML は書けない**」へ改め、
     「拒否は §2 を探す前に文書全体へ掛ける (章の境界を安全に確定する前提)」を走査契約として明記した。
     「保証しないもの」8 項目目の列挙も「§2 内の HTML」→「文書内の HTML」へ直した。
  4. 負例を 1 本追加: `負例: §2 の手前に置いた HTML block で偽の章を作れない (境界を決める前に拒否する)` —
     `<pre>` の開始行を偽の `## 2. ` より前に置き、偽の `## 3. ` も block の中に置いた文書を
     `integrationGuideSectionTwo()` へ渡して例外を要求する (Codex が指定した形そのもの)。
     テスト宣言は 8 → 9 本、dataset 展開後は 30 → 31 ケース。
