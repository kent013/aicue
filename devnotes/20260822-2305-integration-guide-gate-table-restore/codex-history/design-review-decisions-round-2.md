## 施策 2

### [Warning] 区切り行の検査が不十分(`||||` / 列数不足 / `|---|` を受理してしまう)

- 判断: **対応する**(指摘は正しい。`/^\|[\s\-:|]+\|$/` は空セルだけの行も列数違いも通す)
- 対応内容:
  1. 区切り行も `integrationGuideCells()` で分割し、**ヘッダと同じ列数**であることを先に検査する
     (offset を直接触らない `foreach` にした)。
  2. 各セルを `INTEGRATION_GUIDE_SEPARATOR_CELL = '/^:?-{3,}:?$/'` の**完全一致**で検査する
     (配置指定の `:` は任意、ハイフンは 3 つ以上)。
  3. 負例を 4 形追加 — 区切り行が見出し語 / 列数がヘッダと違う / 空セルだけ (`||||`) /
     セルの 1 つだけが不正 (`|---|--|---|`)。
  4. **正例に配置指定つきの区切り (`|:---|---:|:---:|`) を追加**し、狭めた範囲を裏取りした。
  5. ハイフン 2 つ以下を受理しないのは意図的な狭め方(本書の表記を `|---|` 系に固定する)であり、
     リスク節に明記した。

### [Warning] 正例が実装後に追加される計画で、「負例と正例を先に赤くする」を満たしていない

- 判断: **対応する**(指摘は正しい。前回の順序は「最小抽出器 → 負例 → 本体 → 正例」で、
  正例だけが最初から緑になる位置にあった)
- 対応内容: 提示された 5 段の順序をそのまま採った —
  (1) **正例を、常に例外を投げる stub に対して赤くする** →
  (2) 最小の正常系を実装して正例を緑にする →
  (3) 負例を追加し、素朴な実装が受理して赤くなることを確認する →
  (4) fail-closed 分岐を順次実装する(実装のたびに正例が緑のままであることも見る) →
  (5) 実文書との統合テストを赤 → 緑にする。

### [Warning] 走査器共通規約 (e) を「適用」としているが 3 負例が無い

- 判断: **対応する(「対象外」へ整理する)**
- 根拠: レビューの整理が正しい。本検査は許可語彙の除去も否定形の判定も持たず、
  見ているのはゲート名の構文とファイルの実在である。AGENTS.md も (e) の適用範囲を
  「語彙一致を判定する走査」に限っている。3 負例を無理に作ると、規約の意図(許可語の除去を
  素の部分文字列で書いたために接頭辞・打ち消し・接尾辞の 3 形が一緒に消える事故)と
  無関係な形式的テストになる。
- 対応内容: 規約適合表の (e) を **対象外**へ改め、理由を書いた。
  **区切り文字の宣言は独立した走査契約として残す**(docblock 側も同じ位置づけへ書き換えた)。

### [Suggestion] 負例数の記述が 8 形 / 7 形 / 9 形で食い違っている

  併せて「`test()` 宣言 7 個 / 展開後 19 シナリオ」へ数え直した。

### [Suggestion] `integrationGuideSectionTwo()` も §2 見出しの一意性を検査するとよい

## 施策 3

### [Warning] D40 の削除条件が「意味的一致」と「ファイル指紋の一致」を混同している

- 判断: **対応する**(指摘は正しい。突合 gate はファイル単位のハッシュを見るので、
  意味が一致していても指紋は一致せず、D40 だけを消すと未登録の不一致として再び赤くなる)
- 対応内容: 「削除の判断基準」を書き直した — 本登録を消せるのは**ファイル単位の不一致そのものが
  解消したとき**だけで、条件を 3 つ列挙した(正規の取り込み手順での採用 / 正規のテンプレート台帳
  更新による新しい指紋の取り込み / 別の承認済み同期機構による解消)。
  **意味の一致だけが確認できてファイル内容が異なる場合は D40 を削除できない**ことを明記し、
  そのときに行うのは削除ではなく「残っているのは表記の差である」旨への説明更新と
  見直し期限の引き直しであると書いた。メタ表の「再判定の条件」セルにも同じ趣旨を 1 文で入れた。
