# 対応マトリクス: impl-review Round 3

## [Critical] HTML コメント内の見出し・表を本物として受理できる (HTML block も同様)

- 判断: **対応する**
- 根拠: 指摘は正しい。走査が隠していたのは fenced code block だけだったため、
  (a) `<!-- ... -->` の中に 2 表を丸ごと退避させると、描画された §2 には索引が無いのに件数・実在・
  一意性がすべて緑になる、(b) コメントの中の偽の `## 3. ` で §2 の切り出しを早期終了させられる、
  (c) `<pre>` などの HTML block の中に置いても同じ、という 3 経路が残っていた。
  Round 1・2 と同じ根 (「描画されない領域を構造行として数える」) である。
- **方針の転換**: これで 3 ラウンド続けて「Markdown の別記法」が 1 つずつ出てきた。個別の記法を
  後追いで潰し続ける限り同じ指摘が再発するので、**記法を後から広げるのではなく、契約を狭めて
  構文ごと拒否する**方向へ倒した (Codex が挙げた 2 案のうち「§2 内の HTML block 構文を明示的に
  全面拒否する」側)。走査対象は本アプリの 1 文書であり、その文書に HTML は 1 行も無い
  (実測: `docs/app-integration-guide.md` に `<!--` / `-->` / 行頭 `<` は 0 件) ため、
  拒否しても現行文書に影響が無く、将来の書き手にも「§2 は限定文法で書く」と明示できる。
- 対応内容:
  1. `integrationGuideFenceMask()` を **`integrationGuideHiddenMask()`** へ拡張し、行を
     `visible` / `fence` / `comment` の 3 分類にした。HTML コメントは fence と同じく
     「描画されない領域」として構造行から外し、**閉じない HTML コメントは例外**にした。
     → コメント内の偽の `## 3. ` では §2 が終わらない (章の終端も描画される本文だけで決まる)。
  2. **`integrationGuideRejectHtml()` を新設**し、§2 の走査範囲に HTML コメント行が 1 行でもあれば例外、
     描画される本文の行が (3 スペースまでの字下げを含めて) `<` で始まっていれば HTML block として例外にした。
     「無視する」ではなく「書かせない」ことで、コメント退避も HTML block 退避も同時に閉じる。
  3. docblock に走査契約として「§2 の中に HTML は書けない」を明記し、「保証しないもの」8 項目目の
     列挙に「字下げ fence」「§2 内の HTML」を加えた。あわせて
     **「文法を広げる変更をするなら、その記法の負例を同じ変更で足すこと」**を書き、
     この再発パターン自体への歯止めを残した。
  4. 負例を 3 形追加 (`HTML コメントの中のアンカーと表` / `HTML block の中のアンカーと表` /
     `閉じていない HTML コメント`)。加えて **負のコントロールの test に、コメント内の偽の `## 3. ` では
     §2 が早期終了しないことの assertion を 2 つ**足した (章の切り出し側も裏取りする)。
     dataset 展開後のケースは 27 → 30 件、テスト宣言は 8 本のまま。

## [Warning] D40 の保証文が実態より強い

- 判断: **対応する (検査を閉じる側で解消)**
- 根拠・対応内容: Round 1・2 と同じ。バイパスを塞いだので D40 の文言は据え置き、
  保証範囲の正本である docblock 側を今回の契約 (HTML 拒否) まで含めて正確にした。

## 合議ラウンド数についての申し送り

app-implement スキルの規定は「最大 3 ラウンド」であり、本ラウンドでその上限に達した。
Round 3 の Critical は上記のとおり修正済みで、全検証コマンドも green に戻したが、
**修正後の再判定 (APPROVED) を得るには 4 ラウンド目が必要**である。
Critical を残したまま「完了」と報告することは禁止事項 1 に触れるため、修正は行った上で、
規定超過の事実を隠さずに 4 ラウンド目の再判定を受ける。
