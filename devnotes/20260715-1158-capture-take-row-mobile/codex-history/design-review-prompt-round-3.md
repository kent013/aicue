# design-review Round 3（対応報告）

Round 2 の残論点（`sm` 境界の実証）へ対応しました。再判定をお願いします。

## [Warning] 施策1: `sm` は viewport 基準・640-767 の 1 行成立を実証すべき → 対応

受け入れゲート（実ブラウザ screenshot 証跡）の対象幅を **320 / 375 / 640 / 641 / 768px** に拡張しました。
うち **640px / 641px** は「`sm` は viewport 基準で TakeStrip の実効幅は親（CaptureShow のカード/カラム余白）
の影響を受ける」ため、**実際の親レイアウト内で**「両バッジ・全操作表示・1 行維持・窮屈化無し」を
両バッジ最悪ケースで目視実証する項目として明記しました。

加えて **contingency** を設計に追記しました: 640-767px 帯で 1 行が窮屈だった場合は、
行の `sm:flex-nowrap` と操作列の `sm:w-auto sm:flex-nowrap sm:justify-start` を **`md:` 版へ差し替える**
（768 境界へ後退。375/320 の 2 段改善は不変、クラス prefix 変更のみで施策構造は変えない）。

これで残論点は解消と考えます。全体判定のご確認をお願いします。
