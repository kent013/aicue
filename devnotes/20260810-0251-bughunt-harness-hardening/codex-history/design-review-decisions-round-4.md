Critical 1 件 + Warning 1 件。**両方対応**した（反論なし）。

## [Critical/H-0] `BUGHUNT_SANDBOX=/` を防ぐという説明と検証条件が一致していない
- 判断: **対応する**
- 根拠: 指摘のとおり。`[[ "$sandbox" == /* && -d "$sandbox" ]]` は `/`・`/workspace`・
  リポジトリルートを**すべて許可**する。`/` を渡せば `RUN_BASE=/devnotes` /
  `TMP_BASE=/tmp/bug-hunt` となり、**削除しなくても書き込みで実資源を壊せる**。
  「事故防止」と書きながら条件が防いでいなかった。
- 対応内容: **専用マーカーファイルを要求**する形にした。
  - `/` の明示拒否 + 絶対パス要求
  - **リポジトリルート (`${WORKSPACE}`) の明示拒否**
  - **`${sandbox}/.bughunt-selftest-sandbox` の存在を必須**にする
    （= 呼び出し側が「捨ててよい空き地」を意図的に用意したときだけ受け付ける）
  Pest 側は空の一時ディレクトリを作り、**`0600` のマーカーを置いてから**起動する手順を設計に書いた。
  後始末の契約も「外部指定は削除しない / 内部生成も現時点では削除しない（現行挙動を変えない）」と
  **両方明記**した。

## [Warning/H-3] inventory の母集団・件数・識別キーが整合していない
- 判断: **対応する（自分の数え間違い）**
- 根拠: 指摘のとおり。`L1314-1319` は 6 行なのに「self-test の 5 行」と書き、
  全体を「13 行 / 必須 2 + 許可 11」としていた。実際に走査すると **15 行**
  （L209 / L327 / L332 / L333 / L909 / L1161 / L1185 / L1314 / L1315 / L1316 / L1317 /
  L1318 / L1319 / L1741 / L1753）。表も「ほか 5 行」と集約していて完全一致 inventory の体を成していなかった。
- 対応内容: **1 行ずつ列挙**し、**一意な識別キー + 理由 + 現行行番号**を持たせた:
  - **(A) 必須実行行 2 件**（A1: `op_cmd=(createdb -O bughunt` / A2: `op_cmd=(dropdb --if-exists`）
  - **(B) 存在してよい行 13 件**（B1〜B13。wrapper 呼び出し 2 件・メッセージ 3 件・
    inline コメント 1 件・self-test 7 件）
  件数を **`2 + 13 = 15`** としてテスト上で突き合わせ、
  **抽出結果と inventory の双方で重複キーを拒否**する仕様も明記した。
  あわせて **「この 15 件は実装前のベースラインであり、本 TODO の実装で
  `dropdb` の語を含む行が増える見込みなので、inventory は実装完了時点の実ファイルで確定させる」**
  と注記した（実装前の値を書いて最初から赤にしないため）。
