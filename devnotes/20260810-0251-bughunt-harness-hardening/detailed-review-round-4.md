## H-0: REQUEST_CHANGES

[Critical] `BUGHUNT_SANDBOX=/` を防ぐという説明と検証条件が一致していません。

```bash
[[ "${sandbox}" == /* && -d "${sandbox}" ]]
```

`/`、`/workspace`、リポジトリルートなど、既存の絶対ディレクトリをすべて許可します。`/`を渡すと、例えば`RUN_BASE=/devnotes`、`TMP_BASE=/tmp/bug-hunt`となり、「実資源に触れない」というself-testの境界が崩れます。削除しなくても、既存ファイルの上書き・削除を行うself-test処理があれば危険です。

修正案: 外部sandboxには専用マーカーを要求してください。

```bash
[[ "${sandbox}" == /* && "${sandbox}" != / && -d "${sandbox}" ]] \
    || die 2 "..."

[[ -f "${sandbox}/.bughunt-selftest-sandbox" ]] \
    || die 2 "外部 sandbox に専用マーカーがない"
```

Pest側で空の一時ディレクトリを作り、`0600`のマーカーを置いてから起動します。最低限、`/`、`WORKSPACE`、リポジトリルートを明示拒否する必要があります。

また、現在cleanupを行わないなら、`sandbox_owned`は将来契約だけでなく、コメントまたはテストで「外部指定は削除しない」「内部生成も現時点では削除しない」を明確に固定すれば十分です。
