## [Warning] R2 の故障点の記述が不正確 (観点 2)

- 判断: 対応する
- 根拠: 指摘のとおり。`@theme` を `:root` に書き換えても、取り込まれた生の CSS 変数は
  出力に残り得る。失われるのは Tailwind のテーマとしての解釈と、そこから生成される utility である。
- 対応内容: R2 を「変数が消えること」ではなく「**テーマ由来 utility が生成されず、密閉の層の
  C〜E が赤になること**」を確認する Red として書き換えた。どの assertion が赤になるかは
  詳細設計で固定すると明記した。

## [Warning] D27 の分類が論理的に両立していない (観点 6)

- 判断: 対応する (提案の前者 = 独立 literal pin は正典実装の副次的性質、を選ぶ)
- 根拠: 家系台帳の裁定文が「**揃えるべきは検査の仕組みであり、テーマ値やデザインシステムの中身は
  プロジェクト別カスタマイズ点で drift ではない**」と明記している。値そのものを別表で pin することは
  「テーマ値を揃える」側に属するので、t1 が求める不変条件ではない。
- 対応内容: 「意図的に採用しない不変条件が 1 つある」という書き方をやめ、
  「正典の literal 表が持つ独立 pin の性質は **t1 の不変条件ではなく正典実装の副次的な性質**である」
  と台帳の裁定文を根拠に確定させた。よって D27 の分類は**同一不変条件・別実装**のままで矛盾しない。
  aicue が独立 pin を採らない理由も併記した。
