## 施策 10

### [Critical] `/app` は旧 capture URL の接頭辞であり、同時に今後も残す正規の分岐入口
- 判断: **対応する**
- 根拠: 指摘が正しい。「分岐入口以外」には機械的な分類方法が無く、
  `manifest.webmanifest` の `start_url`・`GET /app` の route 定義・入口へのリンクを
  文字列抽出だけでは旧 URL 参照と区別できない。
- 対応内容: 「正規入口 `/app` の許可目録」節を新設した。
  `CaptureEntryUrlAllowance`（**パス + rule ID + 件数 + 30 文字以上の理由**）で
  **正規入口としての `/app` の出現だけを名指し**し、それ以外の裸の `/app` は旧 URL として検出する。
  **ファイル全体を許可しない**（登録箇所以外の `/app` は同じファイルの中でも検出する）。
  登録対象を表にした（manifest の `start_url` / `capture.entry` の route 定義 /
  `route('capture.entry')` の呼び出し。**URL 直書きは許可しない** /
  `capture-sw.js` の navigation fallback は**実測で該当が無ければ件数 0 で明示登録**）。
  併せて「`/organizations/{slug}/app/...` は旧パス判定に一致しないので許可目録に載せない」も書いた。
  テスト計画に**「許可目録に無い裸の `/app` を検出する」**（許可が効きすぎていないこと）を追加した。

### [Critical] `LegacyUrlSelfDetectionExemptions.php` 自身が検出語を保持して再帰する
- 判断: **対応する**
- 根拠: そのとおり。旧 URL 文字列を持つ目録を作れば、その目録が検出対象になる。
  抽出器の Unit テストに置く負例も同じ問題を持つ。
- 対応内容: **2 段で閉じる**形にした（どちらも「ファイルを黙って走査対象外にする」ことはしない）。
  1. **目録は旧 URL 文字列を複写しない** — 自己検出の例外は
     **検出器が発行する安定した rule ID（`legacy-path` / `removed-route-name` 等）+ パス + 件数 + 理由**
     で表す。目録自身は検出語を持たない。
  2. **語彙を持たざるを得ないファイル**（負例 fixture / 抽出器の自己テスト）は
     rule ID で表せないので、**「自己検査専用」という名指しの分類**へ入れる。
     `LegacyUrlScanRoots` の分類を **3 つ → 4 つ**（走査する / 走査しない（理由付き）/
     **自己検査専用（名指し + 件数）** / 未分類）に増やし、
     新設の `LegacyUrlSelfCheckPopulationTest` が**ファイル名と検出語の一致件数を完全一致で pin** する
     （増えても減っても赤 = fixture を黙って増やせない）。
     この gate 自身は**件数とパスだけ**を持ち、旧 URL 文字列を持たない。

### [Warning] テスト計画がファイル種別ごとの抽出の検出力を固定していない
- 判断: **対応する**
- 対応内容: **種別ごとの正例・負例の表**を追加した
  （PHP 文字列 / TypeScript・Svelte 文字列 / Blade・HTML 属性 / Markdown リンク /
  Markdown プレーン URL / JSON・webmanifest 値の 6 種別、各 1 つ以上）。
  加えて **「未分類のファイル種別が現れたら fail-closed」**（新しい拡張子を足した合成入力で赤）も入れた。

## 施策 2

### [Warning] 例外目録が許可対象の SQL・書き込み構文を文字列で持つと、目録自身が検出される
- 判断: **対応する**
- 根拠: 施策 10 の Critical と同じ再帰の問題である。
- 対応内容: `OrganizationSlugWriteExemptions` を
  **パス + 検出器が発行する安定した rule ID + 件数 + 理由**の形へ変え、
  **禁止している書き込み構文そのものを目録へ複写しない**と明記した。
  rule ID の例（`raw-sql-update` / `query-builder-update` / `mass-assignment` /
  `force-fill` / `factory-definition`）を挙げ、登録する 2 件の表も rule ID + 件数の形に直した。

## 施策 4

### [Warning] 全体リスク R10 が「1 試行 = 1 savepoint」のままで本文と食い違う
- 判断: **対応する**
- 対応内容: R10 を **「1 試行 = 1 transaction 境界（外側 transaction 内では savepoint、
  外側が無ければトップレベル transaction の rollback）」**へ統一し、
  権限 cache の残留検査も緩和欄に足した。
