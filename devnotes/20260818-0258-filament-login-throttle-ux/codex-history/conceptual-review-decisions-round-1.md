# 対応マトリクス: conceptual-review Round 1

## [Critical] 既存検査 (ThrottleExemptionPremiseTest) を子クラスへ差し替えても継承元の本文を検査できない

- 判断: **一部反論・一部対応**
- 根拠: 既存の走査器はクラスのソース文字列ではなく **`ReflectionMethod($class, $method)`** を使い、
  そこから `getFileName()` / `getStartLine()` / `getEndLine()` を取って本文を切り出している
  (`tests/Feature/Security/ThrottleExemptionPremiseTest.php` の `throttlePremiseMethodRateLimits()`)。
  Reflection は継承メソッドについて**宣言元クラスのファイルと行**を返すため、対象を子クラスへ
  差し替えても走査されるのは vendor の `authenticate()` 本文であり、検査は成立する。
  よって「成立しない」という前提は事実と異なる。
- 対応内容: ただし指摘の**主旨 (子クラスが `authenticate()` を上書きしたら検査の意味が変わる)** は正しい。
  Codex の修正提案どおり、`authenticate()` の**宣言元が vendor の Login であること**を明示的に
  固定する検査を足す形へ設計を変更した (宣言元が子クラスへ移った瞬間に赤くなる = 閾値・判定順序の
  複写を検出できる)。反論は次ラウンドのプロンプトに書いて確認を取る。

## [Warning] テストファーストの順序が明文になっていない

- 判断: 対応する
- 根拠: 規約 (思考原則 5 / 禁止事項 1) の要求そのもの。
- 対応内容: 概念設計の実装方針に「現行実装で赤を確認 → 独自クラス導入 → 緑化」の順序を明記した。

## [Warning] 親メソッドのシグネチャ完全一致 / 取り込む型

- 判断: 対応する
- 根拠: 引数型・戻り値型・可視性がずれるとクラス読み込み時に致命的エラーになる。
- 対応内容: 「vendor 親メソッドのシグネチャをそのまま踏襲する」ことと、上書きの本体は
  「入力エラーの消去 + `parent::getRateLimitedNotification($exception)` の返却」に限ることを明記した。

## [Warning] 期待効果の書き方 (「通知だけが残る」は通知が消える説明と両立しない)

- 判断: 対応する
- 根拠: 指摘のとおり表現が不正確。
- 対応内容: 「古い認証失敗の説明を残さず、既存の上限到達通知の説明を妨げない」に書き直した。

## [Warning] 流量制限の鍵が変わり、反映時点で失敗回数が 1 度リセットされる

- 判断: **反論する (影響の大きさを事実で限定したうえで受容として明記する)**
- 根拠: この計数の減衰は **60 秒**である (`WithRateLimiting::rateLimit($maxAttempts, $decaySeconds = 60)`
  を Filament が既定のまま呼ぶ)。したがってリセットで失われるのは**高々 60 秒ぶんの計数**であり、
  しかも鍵は IP 単位なので影響範囲も限定される。低トラフィック帯の反映や監視手順を要する規模ではない。
  なお鍵を vendor 側の名前へ固定する上書き (`getRateLimitKey`) も検討したが、
  trait 側が型宣言を持たない引数のため子で型を足せず (LSP 違反)、PHPStan level 10 のために
  PHPDoc を積む必要が出る。60 秒の計数のために増やす構造ではない。
- 対応内容: 概念設計の制約節に「減衰 60 秒 / IP 単位」という事実つきの受容として書き直した。

## [Warning] 全エラーを消すと、上限到達時に残すべき別種のエラーまで消えないか (特に MFA)

- 判断: 対応する
- 根拠: 消しすぎは実害になりうるため、実測で固定すべき。
- 対応内容: 消去は「上限に達した要求」でだけ走り、その要求では**まだ検証を 1 つも走らせていない**
  (vendor は `rateLimit()` を `authenticate()` の先頭で評価する) ことを設計に明記し、
  検査に (a) 上限前は従来どおり入力エラーが出ること、(b) MFA チャレンジ表示中に上限へ達しても
  チャレンジ表示状態 (`userUndertakingMultiFactorAuthentication`) と入力値が保たれること、
  を追加した。

- 判断: 見送る (指摘なしの確認)
- 根拠: いずれも現設計の判断を追認する内容。
