# 対応マトリクス: conceptual-review Round 4

## [Critical] `unauthenticated-redirected` を現在の観測値だけでは確定できない (§3)
- 判断: **対応する（提示された選択肢のうち「手動確認イベント」+「証跡セット化」を採用）**
- 根拠: 指摘が正しい。guard は `unauthenticated` のとき属性を `verifying` のまま
  `location.replace(LOGIN_PATH)` を呼ぶため、A から観測できるのは
  `pending → verifying → 秘匿を維持したまま離脱` までである。
  「guard が `/login` へ飛ばした」「利用者が別ページへ移動した」「タブが閉じられた」は
  保存ログ上で同じ形になり、遡っても区別できない。
- **選択肢の検討**:
  - `/login` 側に debug 試行の観測を足す案（証跡は最も強い）は、
    **auth 経路の production ページに debug 専用ロジックを持ち込む**ことになる。
    local 限定ゲートを別途要し、sessionStorage を読む箇所が
    認証critical なページに増える。debug 設備のために払う代償として重く、
    「今必要なものだけ作る」(思考原則 2) に反すると判断した
  - guard 側に検証フックを設ける案は「検証対象を変更しない」要件と正面から衝突するので採らない
  - よって**手動確認イベント**を採る。あわせてスクリーンショット 1 枚の主張を撤回し、
    **1 試行の証跡セット（`/login` 到達画面 + stored report の 2 枚）**とする
- 対応内容:
  - 軸 2 を **自動観測部分と手動確認部分に分割**し、**完全自動判定とは主張しない**
  - 自動観測だけで言えるのは `hidden-then-left`（秘匿を維持したまま A から離脱した）まで
  - `unauthenticated-redirected` の確定には、利用者が `/login` 到達を確認して記録する
    **手入力イベント (`RedirectObserved`)** を必須とする
  - 期待効果の「スクリーンショット 1 枚」を「**1 試行の証跡セット**」に修正

## [Warning] 「1 枚で PASS を証明できる」は現状成立しない (§4)
- 判断: **対応する**（上記と同じ対応。1 枚の主張を撤回し 2 枚の証跡セットにした）

## [Warning] `scenario-mismatch` は実際より強い断定 (§5)
- 判断: **対応する**
- 根拠: 指摘のとおり。分かるのは「宣言した期待結果と観測結果が一致しない」ことだけで、
  利用者のログアウトし忘れとは限らない（セッション失効判定やプローブの異常もありうる）。
  名前が原因を断定してしまっていた。
- 対応内容: **`expectation-mismatch`** に改名し、
  「操作不一致またはシステム異常のいずれかで、**原因未確定**」と定義した。
  総合 PASS にしない判断は維持。

## [Warning] `StorageFailed` は保存不能の永続証拠にならない (§5)
- 判断: **対応する**
- 根拠: 自己矛盾ではないが、sessionStorage が故障している場合
  `StorageFailed` 自身も永続化できない。「stored report に必ず残るイベント」として
  扱っていたのは誤りだった。
- 対応内容:
  - **試行開始時に保存テストを行い、失敗したら離脱させず live 画面で `unrecordable` を表示**する
    （そもそも試行を始めさせない）
  - 試行途中の保存失敗は可能な範囲で live 表示するが、**再表示後の回収は保証しない**と明記
  - `StorageFailed` は「**保存できれば記録する診断イベント**であり、
    保存不能の永続証拠ではない」と明記
  - read-back validation の方式は詳細設計へ送る

## [Warning] verdict を event log に保存すると stale になる (§7)
- 判断: **対応する**
- 根拠: 指摘が正しい。`RedirectObserved` を後から追加する設計にした以上、
  先に保存した `GuardVerdict` は確実に stale になる。
  「verdict もイベントとして追記」と「レポートはイベント列から導出」は競合していた。
- 対応内容:
  - **event log には観測事実だけを保存する**
  - `TrialVerdict` / `GuardVerdict` / 総合判定は**すべて表示時に純粋関数で導出**する
  - union から `TrialVerdict` / `GuardVerdict` を削除した
