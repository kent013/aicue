# 対応マトリクス: conceptual-review Round 4

## [Critical] B の `imagesEnabled()` に実行時の不在検査が無く、観測軸の当てはめも誤っている
- 判断: **対応する**
- 根拠: 指摘のとおり。撤去されたのは**既存クラスのメソッド**であり、クラスそのものも表も消えていない。にもかかわらず観測軸表で「クラス・表の不在」を『検査する』としていたのは当てはめの誤りであり、しかもその中身は静的走査で、正典 (1) が求める**実行時層になっていない**。
- 対応内容: 2 点直す。
  1. 観測軸表の B「クラス・表の不在」を **該当なし** に改め、理由 (`AcceptedSourceDocumentTypes` クラス自体は現役、削除された表は無い) を書く
  2. B の「機構に対応する等価の実行時層」に **`method_exists(AcceptedSourceDocumentTypes::class, 'imagesEnabled') === false`** を追加する。これで「撤去メソッド自体の復活」を実行時に捕捉できる。静的層は従来どおり**指定クラスでの宣言の再流入と静的呼び出しの再流入**を見る (実行時のメソッド不在と production surface の参照不在を**別々に**固定する)

## [Warning] バイナリ除外後の走査母集団の非空が保証されていない
- 判断: **対応する**
- 根拠: 「各根に追跡ファイルが 1 件以上」は**除外前**の数であり、全件が NUL を含むファイルになれば実走査 0 件でも緑になる。`.sh` / YAML の存在検査も、そのファイルが走査可能な UTF-8 テキストであることまでは保証しない。AGENTS.md (b) 第 3 項「母集団が 0 件なのに緑」の禁止に正面から触れる。
- 対応内容: 空振り検査を**除外・検証後に実際に走査した UTF-8 テキストファイルの集合**に対して行う形へ変更する:
  - 各走査根について、**実走査母集団が 1 件以上**
  - `scripts/` の**実走査母集団**に拡張子なしのファイルが 1 件以上、かつ `.sh` が 1 件以上
  - `.github/workflows/` の**実走査母集団**に YAML が 1 件以上
  - Tier 1 (PHP) と Tier 2 (非 PHP) それぞれについて実走査母集団が 1 件以上

## [Warning] `class_exists()` / `interface_exists()` は autoload を発生させ、gate の結果を autoload 可能性に依存させる
- 判断: **対応する (提示された「より単純な代替」を採る)**
- 根拠: 指摘のとおり、任意の文字列を autoload させるのは静的 gate として筋が悪く、autoload 中の例外の扱いという新しい未解決ケースまで抱え込む。Codex が併記した「クラス名らしい値を**字句形**で拒否するほうが単純」という代替のほうが、静的分類だけで完結し、AGENTS.md (b) の未解決ケースも増やさない。
- 対応内容: 許可条件 3 を **`class_exists()` を使わない字句判定**へ置き換える。値の文字列が次のいずれかに当たれば**クラス名らしい値**とみなして違反にする:
  - namespace 区切り `\` を含む
  - 全体が PascalCase の識別子 (`^[A-Z][A-Za-z0-9_]*$`) である
  - `::class` / `::` を含む
  これを docblock に「値の分類は字句形だけで行い、autoload を発生させない」と明記する。自己検証では (i) 実在クラス名の直書き / (ii) namespace 付きクラス名 / (iii) PascalCase 短名 が**いずれも違反として検出される**ことと、(iv) 日本語の見出し文字列が許可形になり得ることを固定する。

## [Suggestion] 未解決を型上区別する / FQCN 解決は過大化ではない / 効果の記述分離は適切
- 判断: **対応する (詳細設計へ持ち越し)**
- 対応内容: 走査器の戻り値は「出現のリスト」と「未解決のリスト」を別の値オブジェクトで返す。走査中に発生した例外も「一致しなかった」へ落とさず**未解決**として型上区別する。詳細設計で型注釈まで書く。あわせて期待効果に「撤去メソッド自体の復活を実行時に捕捉できる」を追記する。
