# 対応マトリクス: conceptual-review Round 5 (APPROVED)

Round 5 で全体判定 **APPROVED**。Critical / Warning は 0 件。残った Suggestion 3 件は詳細設計へ持ち越す。

## [Suggestion] FQCN 解決で未解決にする対象は `imagesEnabled` の候補となるクラス参照に限定すべき
- 判断: **対応する (詳細設計へ反映)**
- 根拠: 無関係な動的クラス参照まで走査失敗にすると gate の責務を超え、他の変更を無関係に止める。
- 対応内容: 未解決として gate を落とすのは、**`::imagesEnabled` を伴うクラス参照**に限る。それ以外のクラス参照は走査対象にしない (`imagesEnabled` を伴わない参照は本 gate の関心事ではない)。詳細設計の走査器仕様へ明記する。

## [Suggestion] NUL 判定・UTF-8 検証・実走査母集団への登録の順序を 1 経路に固定すべき
- 判断: **対応する (詳細設計へ反映)**
- 根拠: 検証前のファイル数を母集団件数として使うと、Round 4 で直した空振り問題が再発する。
- 対応内容: 走査対象の確定を**単一のメソッド**に閉じ、「git 追跡下の列挙 → 読み取り (失敗は未解決) → NUL 判定 (含むならバイナリとして除外) → UTF-8 検証 (不正は未解決) → 実走査母集団へ登録」の順を固定する。**件数を数える集合は、本体の検査が実際に走査した集合と同一のオブジェクト**にする (別々に数え直さない)。

## [Suggestion] 型安全性 (出現 / 未解決を別の値オブジェクトで表す) は PHPStan level 10 と整合
- 判断: **対応する (詳細設計で型注釈まで書く)**
- 対応内容: 読取失敗・トークン化失敗・対象参照の名前解決失敗を「正常なゼロ件」と混ぜない型で表現する。
