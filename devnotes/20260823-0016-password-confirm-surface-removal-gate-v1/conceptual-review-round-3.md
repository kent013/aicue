## 3. 実現可能性・型安全性

[Critical] `imagesEnabled` の宣言検出について、設計内で主張が矛盾しています。

本文では次の形を違反としています。

> `function` の直後の `imagesEnabled`

この定義では、クラスを問わずすべての `imagesEnabled()` 宣言を検出します。一方、自己検証では「別クラスの同名メソッド宣言」を保証範囲に応じて扱うとしています。これでは、一般名による過剰検出を解消できていません。

また、`AcceptedSourceDocumentTypes::imagesEnabled` を短名だけで照合すると、AGENTS.md (a) の「完全修飾名で突き合わせる」に違反します。

修正案:

- 宣言形は、宣言を包含するクラスの完全修飾名が `App\Support\Manual\AcceptedSourceDocumentTypes` である場合だけ違反にする
- 静的呼び出しは `use`、group use、alias、現在の namespace を解決した完全修飾名で判定する
- クラス参照を解決できない場合は未解決として gate を失敗させる
- 別クラスの `imagesEnabled()` 宣言・呼び出しは負例として固定する
- alias import と同名別クラスを正例／負例に含める

これは走査器共通規約 (a)〜(c) の直接適用対象です。

[Warning] A の許可条件3にある「その文字列」が、キーと値のどちらを指すか曖昧です。例示された SEO 配列が次の形なら、route 名と照合すべきなのはキーです。

```php
'password.confirm' => 'Password confirmation',
```

修正案: 「撤去語を含むキー文字列が、登録済み route 名と完全一致する」と明記してください。

[Warning] 条件2の「値が単独の文字列リテラル」は、`::class` を防げても、クラス名を文字列で直接書く形は許します。

```php
'password.confirm' => 'App\\Http\\Middleware\\ExampleMiddleware',
```

実行時 middleware 不在検査が最終的な再有効化を捕捉するとはいえ、「見出し文字列である」という静的分類までは証明できません。

修正案: 外側の route metadata 構造まで形として識別するか、保証を「登録済み route 名をキーとする文字列値の対応表」に限定してください。少なくとも「見出し文字列である」と断定しない方が正確です。

## 4. 期待効果

[Warning] 「宣言した許可形の外にある出現をすべて落とす」という記述は、全撤去語に対する主張としては広すぎます。`imagesEnabled` は意図的に限定検出であり、非PHPや動的呼び出しに沈黙します。

修正案: 効果を分けて記述してください。

- A と OCR の固有3語: 語境界に一致する出現を、宣言した例外以外すべて検出
- `imagesEnabled`: 指定クラスのメソッド宣言と、完全修飾名へ解決できる静的呼び出しを検出

## 5. リスク

[Warning] `imagesEnabled` を Tier 2/3 で全面的に見ない判断は、`.github/`・`scripts/` 必須走査との関係が不足しています。特に `scripts/` には PHP ファイルや、対象クラスを参照するコードが将来置かれ得ます。

修正案:

- `.github/`・`scripts/` の PHP も、指定クラスの宣言・静的呼び出し検査の対象にする
- 非PHPでは少なくとも完全なクラス＋メソッド参照文字列を対象にするか、「実行可能な参照にならない」という前提を正典 (5) と照合して説明する

「非PHPに現れても意味を持たない」は、シェルから PHP コード、設定、静的解析対象を参照できるため、そのままでは強すぎる主張です。

## 6. 自己検証

[Warning] CSS 正例の `#password\.confirm` は、生テキストとして `password.confirm` を含みません。バックスラッシュが間に入るため、提示された境界一致では検出されない可能性があります。

修正案: 期待する検索語を実際に連続して含む例にしてください。

```css
#password.confirm {
    content: "retired";
}
```

または:

```css
* {
    content: "password.confirm";
}
```

自己検証は「検出できるはずの文字列」がfixtureに本当に存在すること自体も assertion で固定すると安全です。
