# 対応マトリクス: design-review Round 1

## 施策 1

### [Warning] lock / warn flag の symlink 保証が TOCTOU で成立しない

- 判断: **一部対応する + 保証範囲を下げる**（Codex が提示した 2 案のうち後者を基本に、告知フラグだけ前者へ寄せる）
- 根拠:
  - **告知フラグ**は `set -C` (noclobber) による作成に変えれば `O_CREAT|O_EXCL` になり、
    symlink があれば作成そのものが失敗する = 検査と作成が原子的になる。追加コストが無いので採る。
  - **ロック**は `flock` を使う以上どうしても「開いてから」になる。ディレクトリロックへ変えれば
    symlink 安全になるが、**プロセスが落ちたときに解放されない** (flock は解放される) ため、
    索引更新が恒久的に止まる事故を招く。可用性のほうが重い。
  - そもそも「置き場の中に symlink を差し込める者」は既にリポジトリへの書き込み権を持っており、
    hook スクリプト自体を書き換えられる。ここは意味のある安全境界ではない。
- 対応内容:
  - 告知フラグは `warned-${reason}-${session_id}` を `( set -C; : > "$flag" )` で作る形にする
    (作れたときだけ 1 行出す)。
  - ロックは `[ -L ]` の 1 回検査のみとし、「**ロックファイルの差し替え (TOCTOU) までは防がない**」を
    保証しないものへ明記する。テストも「事前に symlink になっていれば更新しない」までに揃える。

### [Warning] 重複抑止が「セッションごと・理由ごと」になり切っていない

- 判断: **対応する**（上と同じ変更で解決する）
- 対応内容: フラグ名を `warned-${reason}-${session_id}` にする。`session_id` は既に
  `^[A-Za-z0-9._-]{1,64}$` で検証済みなのでファイル名に使える。
  ファイルは 0 バイトで、置き場ごと消してよいことを AGENTS.md に 1 行書く。

### [Warning] 拡張子を `case` のパターンに埋めている (`*` や `[` で誤 skip)

- 判断: **対応する**（指摘のとおり。untrusted 値をパターン側に置いてはいけない）
- 対応内容: 固定リストを for で回して**文字列等価**で比較する。

### [Suggestion] `cd` の失敗時 stderr

- 判断: **対応する**。`2>/dev/null` を付ける (契約 2 を厳密にする)。

## 施策 2

### [Warning] 「判定条件は 1 文字も変えない」と抽出失敗時の fail-closed が矛盾

- 判断: **対応する**（指摘のとおり。現行は抽出失敗で素通りする）
- 対応内容: 文言を
  「**正常に `command` を抽出できた経路の拒否対象・許可シグナルは不変**。抽出失敗時のみ、
  概念設計の規則 (明示解除だけを見て、無ければ拒否) を新たに採る」へ直す。

### [Suggestion] 拒否メッセージを `printf` に寄せる

- 判断: **対応する**。これで**ガードは外部コマンドを 1 つも使わない**スクリプトになる
  (判定経路に限らず全体で。説明が単純になる)。

### [Suggestion] `provision-all` のテストを足す

- 判断: **対応する**。B28 系に 1 ケース追加する。

## 施策 3

### [Warning] matcher `Write|Edit` だと `MultiEdit` が漏れうる

- 判断: **一部対応する**（値は変えず、根拠を設計に明記する）
- 根拠: Claude Code の matcher はツール名に対する**アンカーなしの正規表現照合**である。
  したがって `Edit` は `MultiEdit` / `NotebookEdit` にも一致する。逆に
  `^(Write|Edit|MultiEdit)$` へ変えると、この harness に存在しないツール名を台帳へ書くことになり、
  かつアンカーによって将来の派生ツールを取りこぼす。
- 対応内容: 台帳のコメントに「**意図的にアンカーを付けない**。`Edit` は `MultiEdit` /
  `NotebookEdit` にも一致する」と書き、テスト計画にも 1 行残す。

### [Suggestion] Bash によるファイル変更は対象外

- 判断: **対応する**。保証しないものへ明記する。あわせて緩和策も書く —
  索引ツールの差分更新は「直前のコミット以降の差分」を再解析するため、`sed -i` 等で変わった
  ファイルも**次の Write / Edit のときにまとめて取り込まれる** (取りこぼしが恒久化しない)。

## 施策 4

### [Warning] S12 の走査範囲が広すぎて偽陽性になる

- 判断: **対応する**（指摘のとおり。設計書・devnotes・逸脱台帳の説明文で落ちる）
- 対応内容: 走査を**実行面だけ**に限定する — `scripts/**/*.sh` / `.claude/settings*.json` /
  `docker/Dockerfile` / `composer.json` / `package.json` / `.github/workflows/*`。
  文書側は「AGENTS.md に禁止の明文がマーカー付きで存在する」ことだけを別ケースで見る
  (S12a: 明文の存在 / S12b: 実行面の走査)。

### [Warning] S10 の「最初の外部コマンド呼び出しより前」の判定は難しい

- 判断: **対応する**（shell parser は作らない）
- 対応内容: S10 を次に限定する —
  (a) 2 本にプロローグの開始・終了マーカーが 1 組ずつある
  (b) 2 本のマーカー間の内容が byte 一致する
  (c) マーカー**より前**の行に、コメント・shebang・空行以外の実行行が無い
  (= プロローグがファイル先頭に来ていることを見る。これで「最初の外部コマンドより前」は
  自動的に成立する)。

### [Suggestion] stub PATH に system path を残す前提を明記

- 判断: **対応する**。`mkdir` / `flock` / `timeout` が要るので、stub ディレクトリを
  system path の**前に**足す形だと明記する。

## 施策 5

### [Warning] `uv tool install` の導入先と `ENV PATH` の一致が保証されていない

- 判断: **対応する**（指摘のとおり。`USER` に依存させない）
- 根拠: 実測で `uv tool dir --bin` = `/home/vscode/.local/bin`。ただしこれは HOME 依存であり、
  Dockerfile 上の `USER` の位置に依存するのは脆い。
- 対応内容: `ENV UV_TOOL_BIN_DIR=/home/vscode/.local/bin` と
  `ENV UV_TOOL_DIR=/home/vscode/.local/share/uv/tools` を明示してから導入する。
  Dockerfile テストは (a) 版固定の導入行 (b) `UV_TOOL_BIN_DIR` の宣言 (c) `ENV PATH` への
  同じディレクトリの追加、の 3 点を固定する。
