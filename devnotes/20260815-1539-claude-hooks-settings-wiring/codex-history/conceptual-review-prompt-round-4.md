# Round 4: 概念設計の修正

Round 3 の Warning 2 件と Suggestion 1 件に対応した。

## [Warning] 親ディレクトリの symlink → 対応した

起動条件に `scripts/` の検査を加えた。

```
d=${CLAUDE_PROJECT_DIR:-}; f=$d/scripts/bughunt-worktree-hook.sh; s=0
if [ -n "$d" ] && 絶対パス($d) && ".." を含まない($d) \
   && [ -d "$d/scripts" ] && [ ! -L "$d/scripts" ] && [ -f "$f" ] && [ ! -L "$f" ]; then
  /bin/bash -p "$f"; s=$?
fi
if [ "$s" = 97 ]; then exit 2; fi
exit 0
```

実起動テストに「`scripts/` を symlink にし、その先の同名スクリプトが 97 を返す」ケースを追加する。`$d` 自体とそれより上のパス要素は、明記済みの信頼境界 (Claude Code が渡す絶対パス) に含める。

## [Warning] 抽出失敗時の明示解除は別フィールドからも成立する → 受容し、主張を正確に書き直した

「別フィールドの文字列で誤って許可される実害は消えた」という記述を**削除**した。専用トークンの新設は解除手順を 2 本立てにするので採らず (語彙を増やさない)、解除を一切認めない案は逃げ道を消すので採らない。「保証しないもの」節へ次を追加した。

> **既定拒否が成立するのは `"command"` を正常に抽出できた経路までである**。抽出に失敗した経路では、`BUGHUNT_ALLOW_MAIN=` が払い出しのどのフィールドにあっても解除が成立する。これは限定的な fail-open であり、早期に気づける層という位置付けの上で受容する。

失敗モード表の当該行にも「どのフィールドにあっても成立する = 限定的な fail-open (受容)」と併記した。

## [Suggestion] 読み取り上限のテスト → 対応した

「入力を閉じない producer」のケースで、(a) hook プロセスが自分で終了すること、(b) 終了コードが 0 であること、(c) 経過時間が 5 秒 + 余裕の範囲に収まること、の 3 点を固定する、と受け入れ条件へ書いた。
