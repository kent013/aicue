# 対応マトリクス: conceptual-review Round 2

## [Critical] `CLAUDE_PROJECT_DIR` が空・相対・不正なら 127 という前提が成立しない

- 判断: **対応する**（指摘は正しい）
- 根拠: 相対値なら「その値を基準に組み立てたパス」が実際に起動される。そこに 97 を返す
  同名スクリプトが置かれていれば、無関係な Bash 呼び出しがブロックされる。写像器の
  「意図した拒否だけが 2 になる」という不変条件が破れる。
- 対応内容: 写像器が**内側を起動する前に**、bash 組み込みだけで次を検査する。
  1. `CLAUDE_PROJECT_DIR` が空でない
  2. `/` から始まる (絶対パス)
  3. `..` を含まない
  4. 組み立てたスクリプトのパスが**通常ファイル**である (`[ -f ]`)
  5. そのパスが **symlink でない** (`[ ! -L ]`)
  いずれかが不成立なら内側を起動せず 0 で終える。実起動テストに「空」「相対値」「`..` を含む値」
  「別ディレクトリに置いた、97 を返す同名スクリプト」の 4 ケースを追加する。
- あわせて記録: リポジトリルート自体のすり替えは証明できない。**Claude Code が渡す絶対パスを
  信頼境界とする**という前提と、その保証限界を「保証しないもの」節に明記する。

## [Warning] 「JSON のエスケープは探すバイト列を消さない」は強すぎる

- 判断: **一部対応する + 残りは受容として明記する**
- 根拠:
  - `\/` については影響が無い。段 0・段 2 が探す `bug-hunt-shard.sh` には `/` が含まれない。
  - ただし**許可シグナル側**の `.claude/worktrees/` は `/` を含むため、`\/` 形式で来ると
    許可を取りこぼし、正当な worktree 走行を誤って拒否する (fail-safe の逆方向ではないが
    使い勝手を壊す)。→ 照合パターンで各 `/` の前の `\` を任意にして対応する。
  - `\uXXXX` 形式は検出できない。これは**受容する**。本 hook は早期に気づける層であり、
    権威層は `bug-hunt-shard.sh` 本体の `assert_worktree_context` である。脅威モデルは
    「LLM がうっかり main から直叩きする」であって、エスケープを使った意図的な回避ではない。
    回避したい人は `BUGHUNT_ALLOW_MAIN=1` を付ければよく、迂回に手間をかける動機が無い。
- 対応内容: 「保証しないもの」節に `\uXXXX` の取りこぼしを受容リスクとして記録し、
  許可シグナルの `\/` 対応を実装契約に書く。

## [Warning] command 抽出失敗時に生入力の許可シグナルを効かせると別フィールドで解除できる

- 判断: **一部対応する**（`.claude/worktrees/` は評価しない。`BUGHUNT_ALLOW_MAIN=` だけ評価する）
- 根拠: 完全に評価しない案は筋が通るが、**逃げ道の無い詰みを作る**。抽出できない入力は
  再実行しても同じ形で来るため、「正しく抽出できる形で再実行せよ」という指示が実行不能になりうる。
  2 つの許可シグナルは性質が違う — `.claude/worktrees/` は偶然そこにあり得る**痕跡**、
  `BUGHUNT_ALLOW_MAIN=` は人が意図して置く**明示の解除**である。偶然混入しうる方だけを外せば、
  指摘された「別フィールドの文字列で解除される」経路の実害 (誤って許可される) が消え、
  逃げ道は残る。
- 対応内容: 失敗モード表を次に改める。
  - 抽出成功 → 抽出値だけで判定 (許可シグナル 2 種とも有効)
  - 抽出失敗 かつ 生入力に `BUGHUNT_ALLOW_MAIN=` がある → 通す
  - 抽出失敗 かつ 上記が無く `bug-hunt-shard.sh <空白> provision` を含む → 拒否
  拒否メッセージは既存どおり `BUGHUNT_ALLOW_MAIN=1` の付け方を案内する (逃げ道を示す)。

## [Warning] 1 MiB 制限は「実際に読み込む量の上限」でなければならない

- 判断: **対応する**
- 根拠: 全部読んでから切り詰める形では、読み込みの待ち時間もメモリも抑えられない。
  さらに、標準入力を閉じない相手に対して**上限に達するまで待ち続ける**危険がある
  (`read -N` は指定数か EOF まで待つ)。
- 対応内容: 標準入力の読み取りを
  `IFS= read -r -N 1048576 -t 5 input` の 1 回だけにする (`LC_ALL=C` でバイト = 文字)。
  - 最大 1 MiB で打ち切る
  - **5 秒で打ち切る** (bash は時間切れ時も読めた分を変数へ残す)
  - 読めた分だけで判定する。判定できなければ通す (早期層としての fail-safe 方向)
  実起動テストに「1 MiB より後ろにだけ拒否対象を置いた入力」と「入力を閉じない producer」の
  2 ケースを追加し、**上限到達後に待ち続けないこと**を実測で固定する。
