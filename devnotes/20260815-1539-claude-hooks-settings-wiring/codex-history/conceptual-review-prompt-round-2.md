# Round 2: 概念設計の修正

Round 1 の指摘への対応を反映した。対応マトリクスと、変更後の該当箇所を示す。

## 対応マトリクス

### [Critical] PreToolUse の失敗モードが曖昧 → 対応した

指摘は正しく、しかも「表を書く」だけでは足りないと判断した。bash は**構文エラーでも終了コード 2 を返す**ため、スクリプトにタイプミスを 1 つ入れただけでセッションの Bash が全滅する。ブロックする力をスクリプトの正しさに委ねないため、**起動文字列そのものを終了コードの写像器にした**。

```
/bin/bash -p -c '/bin/bash -p "$1"; s=$?; if [ "$s" -eq 97 ]; then exit 2; fi; exit 0' _ "$CLAUDE_PROJECT_DIR/scripts/bughunt-worktree-hook.sh"
```

- スクリプトが意図して 97 を返したときだけ 2 になる。構文エラー (2) / ファイル不在 (127) / 実行不能 (126) / 予期しない失敗はすべて 0 に畳まれる
- 外部コマンドを 1 つも使わない (`[` / `exit` は組み込み)
- PostToolUse 側は末尾を無条件 `exit 0` にした写像器にする
- 写像器は設定ファイルに直書きされ、台帳テストが完全一致で固定する = スクリプト側の退行から独立する
- 代償: ガードのスクリプトが壊れていると拒否が黙って止まる。これは意図した取引 (権威層は `bug-hunt-shard.sh` 本体の `assert_worktree_context`、本 hook は早期に気づける層)。スクリプトの実在と構文は静的層が守る

あわせて失敗モードの表を概念設計に入れた (下記に転記)。

### [Warning] bash 組み込みだけの JSON 抽出は脆い → 方針維持 + 壊れた入力時の判断を明文化

完全な JSON パーサは書かない。必要なのは「この払い出しは `bug-hunt-shard.sh provision` の実行か」という 1 つの述語だけである。3 段に分けた。

- 段 0: 生の入力に `bug-hunt-shard.sh` というバイト列が無ければ通す (外部コマンドを 1 つも起こさない)
- 段 1: `"command"` の値を bash 正規表現で抽出できたら、その文字列だけで判定する (現行と同じ意味。説明文への言及で誤発火しない)
- 段 2: 抽出できなければ生の入力全体で判定し、許可シグナルが無ければ拒否側へ倒す。影響半径は「`bug-hunt-shard.sh` に言及する払い出し」に限定され、拒否は `BUGHUNT_ALLOW_MAIN=1` を先頭に付けるだけで解除できる (詰みを作らない)

### [Warning] CLAUDE_PROJECT_DIR 前提 → 対応した

hook 本体はこの変数を読まない (リポジトリルートを自分の位置から解決する)。使うのは起動子だけで、未設定なら 127 になり写像器が 0 に畳む。台帳テストに「`CLAUDE_PROJECT_DIR` を外して固定起動文字列を実行しても 2 にならない」ケースを入れた。

### [Warning] 告知のチャネル → 対応した

「標準出力は常に空。告知は標準エラーに 1 行だけ」と明記した。重複抑止はセッションごと・理由ごとに 1 回で、1 セッションの上限は理由の種類数になる。

### [Warning] symlink の親 / traversal / TOCTOU → 対応した

置き場を `.claude/code-review-graph-update-hook/` に固定し、リポジトリルートから置き場までの各段と、置き場・ロック・告知フラグの各ファイルを、作成の前後 2 回検査する。セッション識別子は `^[A-Za-z0-9._-]{1,64}$` かつ `.` / `..` でないものだけをファイル名に使い、外れたら固定語に落とす。安全に作れなければ何も書かずに終える。

### [Warning] Dockerfile と配線で受け入れ条件を分ける → 対応した

「配線系 (索引ツール未導入でも成立する)」と「導入系 (コンテナ再作成後にしか確認できない)」に分けて受け入れ条件を書いた。

### [Warning] 実起動層のケースが詳細設計送り / 台帳テストの責務 → 対応した

静的層 9 項目を列挙し、実起動層の必須ケースを「受け入れ条件」節に書いた (網羅表は詳細設計)。

### [Suggestion] 効果は補助的 → 対応した

「見落としが減る」を断定せず、「減る可能性がある」に直し、確実に言えるのは「更新されない索引が供給される状態が終わる」ことまでだと明記した。

## 変更後の該当箇所 (抜粋)

### 最重要の設計原則: 失敗しても作業を止めない

(a) ブロックする力を起動子の側で封じる (上記の写像器)。
(b) 索引更新 hook は、何が起きても終了コード 0 で終わり、標準出力に何も出さない。告知は標準エラーに 1 行だけ。
(c) ガードは判定を bash の組み込みだけで完結させる。判定経路に外部コマンドを置くと、検索パスが壊れているだけで拒否対象が黙って通る (追従元で実測された欠陥)。

### PreToolUse ガードの失敗モード表

| 状況 | 判定 | 理由 |
|---|---|---|
| 標準入力が空 / 読めない | 通す | `bug-hunt-shard.sh` を含まない = 影響半径の外 |
| JSON でない・壊れている。`bug-hunt-shard.sh` を含まない | 通す | 同上。組み込みの部分一致 1 回で抜ける |
| JSON でない・壊れている。`bug-hunt-shard.sh <空白> provision` を含み許可シグナルが無い | 拒否 (97→2) | 既に疑わしい集合の中でだけ拒否側へ倒す。`BUGHUNT_ALLOW_MAIN=1` で解除できる |
| `"command"` の値を抽出できた | 抽出値だけで判定 | 現行と同じ意味。説明文への言及では誤発火しない |
| `"command"` の値を抽出できない | 生の入力全体で判定 | 影響半径は言及を含む払い出しに限定される |
| 入力が 1 MiB を超える | 先頭 1 MiB だけで判定 | 正規表現の実行時間に上限を置く |
| 改行・エスケープ・多バイト文字 | `LC_ALL=C` のバイト列として照合 | JSON のエスケープは探すバイト列を消さない |
| `CLAUDE_PROJECT_DIR` が空 / 相対 / 不在 | 通す | 127 になり写像器が 0 に畳む |
| スクリプトが構文エラー / 実行できない | 通す | 写像器が 2 を 0 に畳む。静的層の `bash -n` が別途守る |
| 検索パスが空 / `.` を含む / 存在しない | 判定に影響しない | 判定経路に外部コマンドが無い |

### 受け入れ条件 (配線系)

- 索引更新 hook は次のすべてで終了コード 0・標準出力は空: 索引ツール未導入 / 壊れた JSON / 空の標準入力 / 検索パスが空・`.`・存在しないディレクトリ / ロック競合 / 更新が終わらない / 置き場が symlink / 置き場の親が書けない / セッション識別子が不正
- 索引更新 hook は成功時に標準エラーにも何も出さない。告知はセッションごと・理由ごとに 1 行だけ
- 索引更新 hook は対象外拡張子の編集では更新を起動せず、副作用をひとつも作らない
- ガードは拒否対象で 97 を返し、固定起動文字列を通したときに 2 になる
- ガードは非対象コマンドで外部コマンドを 1 つも起こさず 0 で抜ける (検索パスが壊れていても同じ)
- ガードのスクリプトを構文エラーにしても、固定起動文字列の終了コードは 2 にならない
- `CLAUDE_PROJECT_DIR` を外しても、固定起動文字列の終了コードは 2 にならない
- `.claude/settings.local.json` に `hooks` を書くと静的層が落ちる / 見本ファイルを復活させると静的層が落ちる

### 台帳テストの静的層 9 項目

1. `.claude/settings.json` が実在し git 追跡下にあり有効な JSON である
2. トップレベルキーが台帳の申告と完全一致 (既定拒否)
3. hook 種別・matcher・起動コマンド文字列・timeout が台帳と完全一致。台帳に無い hook は違反
4. 起動文字列が写像器の形であること (絶対パス起動 / `-p` / 97 の写像 / PostToolUse は無条件 0)
5. `.claude/settings.local.json` があれば `hooks` キーを持たない
6. 見本ファイルが存在しない
7. 2 本の hook スクリプトが実在し `bash -n` を通る
8. 2 本が共有する検索パス安全化の前置きが byte 一致
9. 対象外拡張子の一覧が台帳と完全一致 + `AGENTS.md` に「索引ツール自身に配線を書かせない」明文があり、追跡ファイル内に `code-review-graph install` / `uninstall` の呼び出しが無い
