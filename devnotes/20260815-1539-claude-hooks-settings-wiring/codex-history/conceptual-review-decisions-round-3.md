# 対応マトリクス: conceptual-review Round 3

## [Warning] 起動先検証が最終ファイルだけでは親ディレクトリの symlink を拒否できない

- 判断: **対応する**（指摘は正しい。`$d/scripts` が symlink なら `-f` も `! -L` も成立する）
- 対応内容: 写像器の起動条件に `[ -d "$d/scripts" ] && [ ! -L "$d/scripts" ]` を加える。
  実起動テストに「`scripts/` を symlink にし、その先の同名スクリプトが 97 を返す」ケースを追加する。
  `$d` 自体とそれより上のパス要素は、明記済みの信頼境界 (Claude Code が渡す絶対パス) に含める。

## [Warning] 抽出失敗時の `BUGHUNT_ALLOW_MAIN=` は依然として別フィールドから解除できる

- 判断: **受容する。ただし主張を正確に書き直す**
- 根拠: 指摘のとおり、消えたのは偶発一致しやすい痕跡による解除だけである。専用トークンを新設する案は
  既存の解除手順 (`BUGHUNT_ALLOW_MAIN=1` を先頭に付ける) を 2 本立てにするので採らない
  (思考原則 3・語彙を増やさない)。抽出失敗時に解除を一切認めない案は逃げ道を消すので採らない。
- 対応内容:
  - 「別フィールドの文字列で誤って許可される実害は消えた」という記述を**削除する**。
  - 「保証しないもの」節へ次を明記する — **deny-by-default が成立するのは `"command"` を
    正常に抽出できた経路までである**。抽出に失敗した経路では、`BUGHUNT_ALLOW_MAIN=` が
    払い出しのどのフィールドにあっても解除が成立する。これは限定的な fail-open であり、
    早期に気づける層という位置付けの上で受容する。

## [Suggestion] 読み取り上限のテストは経過時間だけでなくプロセス終了まで固定する

- 判断: **対応する**
- 対応内容: 「入力を閉じない producer」のケースで、(a) hook プロセスが自分で終了すること、
  (b) 終了コードが 0 であること、(c) 経過時間が 5 秒 + 余裕の範囲に収まること、の 3 点を固定する。
