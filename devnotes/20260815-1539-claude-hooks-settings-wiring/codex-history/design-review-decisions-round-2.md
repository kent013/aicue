# 対応マトリクス: design-review Round 2

## [Warning] matcher の「アンカーなし部分一致」という前提が公式の説明と一致しない (施策 3)

- 判断: **対応する**（こちらの前提が誤り。公式の説明に従う）
- 根拠: 指摘された公式ドキュメントは `"Edit|Write"` について「`Edit` または `Write` のときだけ
  発火し、その他のツールでは発火しない」と明記している。設計側で観測して確かめられない前提
  (harness の内部仕様) を、都合のよい方向へ推測して保証に書いてはいけない。
- 対応内容:
  - 値は `Write|Edit` のまま据え置く (v1 の対象はこの 2 つで足りる)。
  - 「アンカーなしなので `MultiEdit` / `NotebookEdit` も拾う」という説明を**削除**し、
    「**対象はこの 2 ツールだけ**」と書き直した。テスト前提からも同趣旨の記述を外した。
  - 存在しない `MultiEdit` を台帳へ先回りで足さない。`NotebookEdit` は本リポジトリに
    notebook が無いので対象にしない (必要になったら明示列挙して台帳・テストを同時に直す)。
  - 「保証しないもの」を `Bash` 限定から広げ、「**`Write` / `Edit` 以外の経路による
    ファイル変更は拾わない**」(`sed -i` / `NotebookEdit` / 外部エディタ) と書き直した。
    緩和策 (次の Write / Edit でまとめて取り込まれる) はそのまま残す。

## その他 (施策 1 / 2 / 4 / 5 / 6 は APPROVE)

- 追加対応なし。施策 4 の「matcher のコメントと期待値も同時に更新すること」は上の対応に含まれる
  (台帳の matcher 値そのものは変わらないため、変わるのはコメント文だけ)。
