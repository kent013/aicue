### 3. 実現可能性

[Warning] 起動先検証が最終ファイルだけでは、親ディレクトリの symlink を拒否できません。

`[ ! -L "$f" ]` は `bughunt-worktree-hook.sh` 自体しか検査しません。`$d/scripts` が symlink で、その先に通常ファイルがあれば、`-f "$f"` と `! -L "$f"` はともに成立します。そのファイルが97を返すと終了コード2になります。

修正提案: 信頼する `$d` の直下について、少なくとも次も起動条件に加えてください。

```bash
[ -d "$d/scripts" ] && [ ! -L "$d/scripts" ]
```

あわせて「`scripts/` が symlinkで、その先の同名スクリプトが97を返す」実起動テストを追加してください。`$d` 自体とそれより上のパス要素は、明記済みのClaude Code信頼境界に含めて構いません。

[Warning] 抽出失敗時の `BUGHUNT_ALLOW_MAIN=` は、依然として別フィールドから解除できます。

今回消えたのは `.claude/worktrees/` による偶発的解除だけです。生入力全体から `BUGHUNT_ALLOW_MAIN=` を探す限り、説明文や将来追加されるフィールドにその文字列があれば通ります。したがって、「別フィールドの文字列で誤って許可される実害は消えた」という主張は成立しません。

本hookの脅威モデルから、この限定的なfail-openを受容する判断自体は可能です。修正提案は次のいずれかです。

- 抽出失敗時は解除を認めず、hookの修正・一時的な設定変更など、Bash払い出し以外の復旧経路を正式な解除手順にする。
