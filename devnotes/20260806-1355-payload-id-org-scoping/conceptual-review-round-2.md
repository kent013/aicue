全体判定: **CHANGES_REQUESTED**

404 方針を 422 / 403 へ変更する判断自体は妥当です。残る問題は MCP の入力分類です。

### 1. 使命との整合性

[Suggestion] 直接的な機能価値ではなく、組織データを預かる前提となるセキュリティ債務返済として適切です。スコープも使命から逸脱していません。

### 2. 禁止事項違反

[Warning] §7-2 の検証コマンドが AGENTS.md の必須セットを満たしていません。`pnpm typecheck`、`pnpm test`、`pnpm build`、packages 系などが欠けています。

修正提案: 個別テスト後の完了条件を「AGENTS.md の `VERIFICATION_COMMANDS` に列挙された全コマンドが green」とし、コマンドの重複記載を避けるなら正本を参照してください。

### 3. 実現可能性

[Critical] MCP の「`'001'` は `FILTER_VALIDATE_INT` を通過して 1 になる」という前提は、通常の PHP の挙動と整合しません。`FILTER_VALIDATE_INT` はフラグなしでは先頭ゼロ付き文字列を拒否するため、提示された境界テストは実装前から失敗する可能性が高いです。

さらに `sprintf('%03d', $id)` は `$id >= 100` ならゼロ埋めにならず、境界を検証できません。

修正提案:

- 現行 PHP・実行環境での `filter_var()` の実測結果を正本として再確認する。
- 先頭ゼロを受理する要件がなければ、`'001'` を形式不正 422 側へ移す。
- 受理が要件なら、`filter_var()` のままではなく明示的な正規化仕様を詳細設計で定義する。
- テストは固定値または確実に一桁となるIDを用い、実際に先頭ゼロを含むこともassertする。

### 4. 期待効果の妥当性

[Suggestion] relation 起点の解決、global `exists` の撤去、debt cap のゼロ化により、主張された効果は合理的に期待できます。

### 5. リスク

[Suggestion] actor 権限判定を payload 検証より前に固定するテストが追加され、Round 1 の主要リスクは解消されています。

### 6. スコープの適切さ

[Suggestion] 対象3経路、inventory、関連テスト・コメントに限定されており適切です。タイミング差を別スコープとする判断も妥当です。

### 7. 型安全性

[Suggestion] `Assert::integerish()` と明示的 cast を既存パターンとして詳細設計へ送る判断は、概念設計の粒度として許容できます。PHPStan level 10 を完了条件から外さないことが前提です。

### 8. セキュリティ

[Warning] MCP の形式境界が上記のとおり不正確なため、422 / 403 の分類契約を現時点では承認できません。

修正提案: PHPの実挙動に合わせて§4-3と§7-1を同期してください。それ以外の判断、つまりフォーム経路を統一422、MCPの有効な整数IDを統一403とする設計は妥当です。
