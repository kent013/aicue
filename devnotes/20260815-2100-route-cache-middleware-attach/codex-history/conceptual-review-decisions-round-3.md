# 概念設計レビュー Round 3 への対応マトリクス

| # | 分類 | 指摘 | 判断 | 対応内容 |
|---|---|---|---|---|
| 1 | Warning | 焼き込み検査 1 の対象が不足 (`throttle:two-factor-secret-read` / `no-store` などが漏れる)。列挙した全 route・全 middleware を覆うべき | 対応 (ただし手段は列挙でなく全数一致に変える) | 個々の alias を数え上げた表は**作らない**方針にした。表を作ると 2 binder の呼び出し側 (Provider の定数) と二重管理になり必ず食い違うためである。代わりに **全数の一致検査**へ変更した — 名前のついた route すべてについて `attributes[route 名]['action']['middleware']` が実際の経路一覧の middleware 列と完全に一致することを見る。これで「後付けした列がそのまま焼き込みの入力になる」を alias の増減に依らず覆える。空振り防止として 5 系統がそれぞれ 1 本以上現れることと、passkey 削除 route の 3 つの順序を固定する。件数の完全一致は既存目録検査の担当として二重管理にせず、どの不変条件をどのテストが担うかは D19 に表で書く (Codex 提案どおり) |
| 2 | Suggestion | 検査 3 は複製前の元 route の値・prepare 後の複製の値・prepare 後も元が変わらないことの 3 点を見よ。比較対象は `gatherMiddleware()` でなく `action['middleware']` | 対応 | 3 点の表明と比較対象をそのまま設計へ書いた |
| 3 | Suggestion | 隔離方針の成立条件 (別テスト化 / 差し替え後は対象 HTTP 以外を検査しない / dataset で持ち越さない / 静的状態へ保存しない) | 対応 | 「dataset やループで持ち越さない」「自前の静的変数や共有 singleton へ保存しない」を制約へ追記 (他の 2 点は記載済み) |
