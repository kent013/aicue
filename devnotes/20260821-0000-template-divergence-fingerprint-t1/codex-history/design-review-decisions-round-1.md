# 対応マトリクス: design-review Round 1

## [Critical] (S5) 債務一覧がパスだけなので、債務パスの以後の変更を検出できない = 恒久的な許可一覧になっている
- 判断: 対応する (本レビューで最も重い指摘。設計の中心を変えた)
- 根拠: 指摘のとおり。「採用時点の凍結された観測」と説明しながら、実装モデルは
  「そのパスは不一致でありさえすれば合格」だった。凍結の意味が保証されていない
- 対応内容: 債務一覧を `path<TAB>採用時のアプリ側 sha256` の 2 列にした
  (ファイル名も `adoption-debt.txt` → `adoption-debt.tsv`)。判定を 3 分岐にし、
  現在値 = 採用時ハッシュ → 許容 / 現在値 = 正典ハッシュ → `resolvedDebtPaths` /
  どちらとも異なる・削除 → `mutatedDebtPaths` (違反)。
  結果 DTO を 5 種別 → **8 種別**へ増やし (`mutatedDebtPaths` / `duplicateRegisteredPaths` /
  `inspectionFailures` を追加)、gate は種別ごとに個別 assert する

## [Critical] (S3) byte 一致移植の `AtomicLedgerWriter` は JSON 専用で平文の債務一覧を書けない
- 判断: 対応する
- 根拠: 指摘のとおり。正典版は読み戻しを `FingerprintLedger::fromJson()` に通す
- 対応内容: JSON は正典版を使い、債務一覧は `AtomicTextWriter` (検証関数を注入する平文版) を新設。
  移植した `AtomicLedgerWriter` には対の説明を docblock へ 1 段落足すので **byte 一致から外れ**、
  D33 の対象パスに入る。件数予測も更新した (byte 一致移植 3 → 2 / 新規同名 3 → 4。
  母集合の増加 6 件は変わらず、整合式を `281 = 78 + 27 + 176` へ訂正)

## [Critical] (S4) `--adopt-new-template-ledger` で新規債務を追加できると、正規経路が 3a の回避口になる
- 判断: 対応する
- 根拠: 指摘のとおり。正典入力が変わっていないのに新しい食い違いを債務へ入れられるのは
  「登録しないと通らない」の中核を壊す
- 対応内容: 生成器の債務更新規則を 3 つに固定した。**維持** (採用時ハッシュを持ち越す) /
  **削除** (一致へ戻った・登録された) / **追加は原則禁止**。追加を許すのは載せ替え時に
  「現在のアプリ側ハッシュが**載せ替え前の**正典ハッシュと一致する」ときだけで、
  これはテンプレート側が前進したことの証明になる。それ以外は exit 3 で
  「登録を書くか内容を戻せ」と告げる。分岐は生成器のプロセステストで固定する

## [Critical] (S4) exit code の契約と 2 ファイルの原子性が矛盾している
- 判断: 対応する
- 根拠: 異なるディレクトリの 2 ファイルを rename するだけではセット単位で原子的にならない
- 対応内容: 契約を 4 行の表に分けた。exit 3 と**書き込み開始前**の exit 1 は両ファイル不変 /
  書き込み開始後の I/O 失敗は片方だけ更新され得るが件数 pin が合わず **gate が必ず赤**。
  両出力は書き込み開始前に完全生成・検証する。**セット単位の原子性は主張しない**
  (世代ディレクトリ + ポインタ切替は本件の規模に対して過剰。思考原則 2)

## [Critical] (S6) symlink・非 regular file・読み取り不能を `MissingCurrent` へ畳むと、登録済み・債務パスでは違反にならない
- 判断: 対応する
- 根拠: 指摘のとおり。「実行不能は不合格」と矛盾しており、D33 対象の gate 自身を
  symlink 化して黙らせる経路が残る
- 対応内容: 観測を `PathObservation` (状態 + 現在ハッシュ + 検査不能の理由) にし、
  `MissingCurrent` は **git index / working tree から消えた場合だけ**に限定した。
  symlink / 非 regular / 読めない / ハッシュ失敗は独立した `inspectionFailures` として
  F8 が 0 件 assert する。F6 は必須メンバに **regular file (symlink でない)** を無条件で要求する

## [Critical] (S9) `決めた日` 2026-08-21 が未来日で、形式検査が必ず落ちる
- 判断: 対応する
- 根拠: 事実。判定基準日は `CarbonImmutable::today()` (アプリ timezone) であり、
  設計時点は UTC ではまだ 2026-08-20 である
- 対応内容: 両エントリの決めた日を **`2026-08-20`** にし、注記で
  「基準日以前であることを `config/app.php` の timezone で確認してから書く」ことを明示した。
  見直し期限の日数計算も 191 → 192 日へ訂正 (上限 400 日の内側は変わらない)

## [Critical] (S11) 「債務のまま残す」を選べる手順は、債務ファイルへの追加変更を許してしまう
- 判断: 対応する
- 根拠: 上記 S5 の Critical と同根。債務にハッシュを持たせた設計と手順が食い違っていた
- 対応内容: スキルの確認段から「債務のまま残す」を削除し、3 択
  (採用時の姿へ戻す / テンプレートへ同期して債務から削る / 登録を書いて債務から削る) に固定した。
  採ったものをコミットメッセージに書く

- 判断: 対応する

  最上位が `[]` / `entries` が `[]` / 空 object と空配列の区別を追加した
  (正典は持たない上積みなので D33 に書く)
