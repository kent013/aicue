# 対応マトリクス: design-review Round 3

## [Critical] 施策 8 の静的検査がコメント内の旧実装リテラルを検出し、正しい実装が偽赤になる
- 判断: **対応する**
- 根拠: 完全に正しい。変更後の `run-test.sh` / `run-vitest.sh` は
  「旧 worktree-local な `storage/framework/testing/test.lock` は廃止した」
  「`flock -n` ではなくブロッキング取得にした」「旧 `app-vitest-*` ロックを置き換えた」という
  **設計意図をコメントに書く**。生ソースを走査する検査はこれらを違反として拾い、
  正しい実装で必ず fail する。ゲートが正しい状態を赤にするのは、偽グリーンと同じくらい有害
  (エージェントがゲートを無効化する方向に動く)。
- 対応内容: 純関数 **`globalTestLockCodeLines(string $source): string`** を新設し、
  **全ての静的検査を単一の解析入力 (実行行のみ) に対して行う**ようにした。
  - 行頭 (空白除く) が `#` の行だけを落とす。
  - ご指摘どおり**行末コメントの除去はしない** — `'#'` のような引用符内の `#` を壊して
    コードを誤って削るリスクの方が大きいため。
  - 旧ロック検査 / `flock -n` 検査 / `GLOBAL_TEST_LOCK_DIR` 検査 / `exec` 検査 /
    EXIT trap 検査 / API 使用検査を全て `$code` ベースへ統一した
    (Round 2 で EXIT trap 検査だけが独自にインライン `#` 除去をしていた不整合も解消)。
  - 施策 8 のリスク節に「静的検査は必ず `globalTestLockCodeLines()` の出力に対して行う」を
    教訓として明記した。

## [Warning] `acquire` / `run` の検査が `str_contains` なのでコメントだけでも通る / 順序未検査
- 判断: **対応する**
- 根拠: 正しい。コメントを除外しても、文字列や説明的な記述で通ってしまう可能性がある。
  また本文に「必ず acquire → run の順」と書きながら順序を検査していなかった
  (本文とテストの不一致は Round 2 でも同種の指摘を受けている)。
- 対応内容: 実行行に対する**呼び出し形の正規表現** (`/^\s*global_test_lock_acquire\b/m` /
  `/^\s*global_test_lock_run\b/m`) を `PREG_OFFSET_CAPTURE` 付きで判定し、
  - どちらか不在なら違反
  - **最初の `acquire` のオフセットが最初の `run` より後なら違反**
  とした (順序の固定)。

## [Warning] `_gtl_wait_group_gone` が SIGKILL 後 5 秒で復帰し、「グループが空になるまで保持」契約を破る
- 判断: **対応する**(提示 2 案のうち「**警告を出しながらロックを保持し続ける**」を採用)
- 根拠: 正しい。5 秒で諦めて戻ると fd 7 が閉じ、残党と次のレーンが併走する。
  非交渉と書いた契約を実装が破っていた。
  2 案のうち保証を降ろす方 (best-effort へ格下げ) は採らない: SIGKILL を生き延びるのは
  **割り込み不可能な待ち (D state = stuck IO)** だけであり、その状況でロックを手放すのは
  「壊れているときに保護を外す」最悪の選択になる。保持し続ける方が安全であり、
  ロック取得を「待つことが目的なので上限を設けない」とした本設計の一貫性とも合う。
- 対応内容: `_gtl_wait_group_gone` を 2 段構成に整理:
  - 第 1 段: 猶予 (`GLOBAL_TEST_LOCK_GRACE_SECS`) 内の自発終了を待ち、超過で グループへ SIGKILL。
  - 第 2 段: **上限を設けず空になるまで待ち続ける**。ハングと区別できるよう、heartbeat 間隔で
    **残存 pid を列挙した警告**を出し続ける。
  - 猶予の既定値を `10` → `30` 秒へ引き上げた (SIGKILL は最後の手段であり、
    paratest / Playwright の正常な後始末を 10 秒で打ち切るのは早すぎるため)。
  - 層 1 に **C23**「`_gtl_group_alive` を『常に生存』へ差し替えると**ロックが解放されない**まま
    警告が出続ける」を追加。`_gtl_group_alive` は shell 関数なので、スイートは source 後に
    再定義して注入できる (テスト可能性を設計に明記した)。
