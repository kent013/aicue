# 対応マトリクス: conceptual-review Round 5

## [Critical] 「シグナル転送 → 直接子を wait → 上限付きポーリング」は TERM 無視の子で deadlock する
- 判断: **対応する**
- 根拠: 完全に正しい。`wait` を先に置くと、子が INT / TERM を無視した瞬間に `wait` から戻れず、
  猶予超過の `SIGKILL` に永久に到達できない。**ロックを永久保持する deadlock** になる。
  「上限つき」と書いていても、上限つき処理より前にブロッキング待機を置いていては意味がない。
- 対応内容: 順序をご提案どおりに入れ替えた:
  (1) プロセスグループ全体へ同シグナル転送 → (2) **上限つきで `kill -0 -"$pgid"` をポーリング** →
  (3) 猶予超過でグループへ `SIGKILL` → (4) 直接の子を `wait` して reap →
  (5) nonce 一致確認で sidecar 削除 → (6) fd 7 を閉じて解放 → (7) trap 解除後に親も自死。
  併せて「**先に直接の子を `wait` してはならない**」理由 (deadlock 経路) を本文に明記した。
  正常終了時も同じ上限つき手順でグループの消滅を確認する。
  層 1 に「**INT / TERM を無視する直接子と孫**を使い、猶予超過後に強制終了されて
  第三のレーンが取得できること (deadlock しないこと)」を追加した。

## [Warning] `set -m` が保証するのはプロセスグループであって「プロセスツリー全体」ではない
- 判断: **対応する**
- 根拠: 正しい。子孫が `setsid()` / `setpgid()` で自らグループを離脱すれば管理境界から逃れる。
  「プロセスツリー全体」という表現は保証を過大に述べていた。
- 対応内容: 保証を「**専用プロセスグループに残る全プロセスの消滅**」に限定して書き直し、
  ロック保持期間の定義も「取得 〜 **専用プロセスグループが空になった後**」に修正した。
  **離脱プロセスは SIGKILL と同様に保証外**として記録。
  現行 4 レーン (paratest / pest + Playwright / vitest / pnpm) が自発的に離脱しないことは
  実査で確認し、層 1 の検証項目 (「自発的にグループを離脱しないこと」) で固定する方針を追加した。

## [Warning] `set -m` は source 元 shell のグローバル状態を変える / 専用グループには background 起動が必要
- 判断: **対応する**
- 根拠: 妥当。`set -m` を有効にしただけでは専用グループは作られず、
  background job として起動して初めてグループリーダーになる。また monitor mode の変更は
  source 元シェルに残る副作用になる。
- 対応内容: 起動形態を明文化した:
  現在の monitor mode を**記録**してから `set -m` を有効化 → レーンを **background job として起動** →
  `$!` から PID を取り **PGID == PID を検証** (グループ管理境界を作れたことの確認) →
  検証に失敗したら**明示エラーで停止** (黙って保証を落とさない) → cleanup 時に **monitor mode を復元**。
  層 1 に「**TTY あり / なしの両方**で成立すること (monitor mode の復元を含む)」
  「レーンが専用プロセスグループのリーダー (PGID == PID) になっていること」を追加した。

## [Warning] 「SIGKILL 時の壊れ方は安全側」は強すぎる
- 判断: **対応する**
- 根拠: 正しい。ロックは解放されるが、残存子孫と次レーンの併走は起こりうる。
- 対応内容: 表現を「防げるのは 2 つだけ」に限定して書き直した:
  (a) **ロックリーク** (flock が正本なので OS が fd を閉じて必ず解放。残留 sidecar は
  次の取得者をブロックせずアトミックに上書きされる)、
  (b) **stale nonce による誤再入** (殺された owner の nonce は新 sidecar と一致しない)。
  そのうえで「**残存子孫と次レーンの併走は防げない。ここは保証しない**」と明記した。
