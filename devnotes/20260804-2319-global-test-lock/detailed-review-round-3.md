## 指摘

- [Critical] 施策8の静的検査がコメント内の旧実装リテラルを検出します。例えば変更後スクリプトの説明コメント自身に `storage/framework/testing/test.lock`、`flock -n`、`app-vitest-` が存在するため、正しい実装でもテストが失敗します。

  修正案: 全検査で共通の「実行行のみ」の文字列を生成してください。少なくとも行頭の空白を除いて `#` から始まる行を除外し、その結果に対して旧ロック、`exec`、API呼び出し、EXIT trapを検査します。引用符内の `#` を壊すため、現在の `preg_replace('/#.*$/', ...)` による全面的な行末削除は避けるのが安全です。

- [Warning] `global_test_lock_acquire` / `global_test_lock_run` の検査は単なる `str_contains` なので、コメントだけでも合格します。また「acquire → run の順」と書かれていますが順序は検査していません。

  修正案: コメント除外後の実行行に対して関数呼び出しを正規表現で検出し、最初の `acquire` の位置が最初の `run` より前であることも確認してください。

- [Warning] `_gtl_wait_group_gone` はSIGKILL後に5秒待つと、非zombieプロセスが残っていても復帰します。その後fd 7が閉じるため、「グループが空になるまで保持」という非交渉契約を満たしません。

  修正案: 5秒後も生存している場合は警告を定期出力しながらロックを保持し続けるか、「SIGKILL後5秒までのbest-effort」に保証を明示的に変更してください。現行の契約を維持するなら前者が整合します。層1にも群生存判定をスタブ化した回帰ケースを追加してください。

- [Suggestion] 施策8のテスト計画は「負のコントロール3本」のままですが、骨子では5本あります。件数を同期してください。
