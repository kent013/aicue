## 該当箇所 (改訂後)

### 割当列の複数値化と、その波及 (実測で確認した副作用)

正典の `operations.md` は割当列に `S4 S7` のような**空白区切りの複数値**を出す (原本実読で確認)。
aicue も同じ形にする。ここで 1 つ実害がある。

`coverage/correlate.py` は route 名を持たない finding を「割当が一致する機構群」へ
capability 経由でブロードキャストする (`rows_by_story[row.story]`)。セルを**そのままキー**に
使うため、`"S3 S7"` というセルは `"S3"` の finding と一致しなくなる。
現状 aicue は全行が単一値なのでブロードキャストが効いており、**複数値化はこの経路の後退になる**。

正典の `correlate.py` も同じ書き方であり (原本実読で確認)、正典側にも同じ不正確さがある。
本設計は**後退を作らない**ため、`rows_by_story` の構築時にセルを空白で分解する。
単一値のときの挙動は不変 (厳密な上位互換) であり、家系への還流候補として記録する。

**割当セルの表記は書式の正本に置き、両側が同じ厳格な契約を実装する**。

セルの値域を次の 2 形だけに閉じる。

- 載せるカードが 1 枚以上: `S{n}` を**番号の昇順**で**半角空白 1 つ**区切りで並べた列 (前後に空白を置かない)
- 載せるカードが 0 枚 (= `kubun` が 外): 半角ハイフン 1 文字 `-`

この値域の**正本は目録の書き出し側**であり、規則そのものは `stories/README.md` と
`operations.md` / `screens.md` の前書きに文章で置く。
共有モジュールを新設して両者に import させる形は**採らない** —
生成器は `scripts/bug-hunt-inventory.py` でハイフンを含み通常の import 対象にならず、
照合器は別ディレクトリ (`coverage/`) にあるため、動的ロードか `sys.path` 操作が要る。
CLI スクリプトを共有モジュールとして読む構造は脆く、しかも照合器はテンプレートと共有するファイルなので
アプリ固有モジュールへの依存を増やすと乖離が深くなる。

代わりに**両側を自己テストで固定する**。ここで重要なのは、
**読み取り側が不正な形を寛容に正規化しないこと**である。
`str.split()` は前後空白も連続空白も黙って吸収するので、それだけで済ませると書式違反を見逃す。

読み取り側の検証は 2 段にする。

1. **セル全体を `^(S[1-9][0-9]*( S[1-9][0-9]*)*|-)$` で完全一致検証**する (文法)。
2. 分解したうえで **番号が厳密昇順であること・重複が無いこと**を検証する (順序と一意性)。

どちらかに反したセルは**明確に失敗させる** (黙って読み飛ばさない)。
書き出し側は同じ値域だけを出す。

**カード id の実在は読み取り側では検証しない**。`S8` のように「文法は正しいが実在しないカード」は
読み取り側を通るが、これは意図した責務分割である。

- 目録は**生成物**であり、その中身の実在は書き出し側が構造的に保証する
  (割当列は実在するカードの前付けからしか作られない)。
- 手編集で `S8` を紛れ込ませた目録は **F6 (生成物の byte 一致)** で落ちる。
- 読み取り側にも実在検査を持たせると、照合器が `stories/README.md` を新たな入力に取ることになり、
  **同じ規則が 2 か所**に増える (本アプリが最も避ける形)。しかも照合器はテンプレートと共有するファイルなので、
  アプリ固有ファイルへの入力依存を増やすと乖離が深くなる。

両側のテストケースは同一の列挙で揃える (`実在` 行だけは担い手が分かれる)。

| ケース | 読み取り側 (照合器) | 書き出し側 (生成器) |
|---|---|---|
| 単一値 `S3` | 1 件として索引される (現行と同じ挙動) | 出しうる |
| 複数値 `S3 S7` | `S3` と `S7` の両方に索引される | 出しうる |
| 対象外 `-` | どの story にも索引されない | 出しうる |
| 前後に空白 | **失敗** | 出さない |
| 連続空白 `S3  S7` | **失敗** | 出さない |
| 空セル | **失敗** | 出さない |
| 未知の綴り `SX` / `S0` / `S03` | **失敗** | 出さない |
| 降順 `S7 S3` | **失敗** | 出さない |
| 重複 `S3 S3` | **失敗** | 出さない |
| 実在しないカード `S8` | 通す (責務外) | **出さない** (前付けの母集団に無いため構造的に発生しない。自己テストで固定) |
