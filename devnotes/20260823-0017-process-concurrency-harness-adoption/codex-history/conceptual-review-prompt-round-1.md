# アプリの使命（North Star）

## 使命 (North Star)

<!-- app-codex-review スキルはこのセクションをレビュー使命として参照する。 -->

**AI-CUE** は、現場に既にある**作業手順書(SOP)を起点に**、AI が撮るべきカットを設計した**動画シナリオ**を生成し、そのシナリオを**スマホ(PWA)でナビゲーション撮影**することで、専門知識ゼロの現場作業者でも**標準化されたマニュアル動画**を作れるようにする。

- 「思考ゼロ・編集ゼロ」— 台本作成・撮影判断・編集の 3 ハードルを AI とナビ撮影で肩代わりする。
- 競合(OJT を撮って形式化する tebiki)と異なり、**標準作業を起点に AI が教材設計し撮影を指示する**（撮影者・教える人のスキルに品質を依存させない）。
- 熟練者の暗黙知を動画マニュアルという形式知へ変換する装置（SECI）。

> 詳細な設計は本リポジトリの `doc/`（01〜10）に置く。ドメインをテンプレート構造へどうマップしたかは `doc/08`〜`doc/10`（特に `doc/10 §10.8` に設計レビュー反映済み）。
> **v1 スコープ**: 字幕のみ(TTS 後回し) / 撮影は PWA(同一オリジン・セッション認証) / 動画合成は自前 ffmpeg / 単一 Default Project。

## 参考: 追従元の正典 (lctl 機能台帳) 原文抜粋

### 正典 (lctl feature `process-concurrency-test-harness` / canonical_version v1) の boundary 原文抜粋

含む: 実プロセスを 2 本立てて barrier で同期させる並行テストの作法一式。
(1) フレームワークを自前で起動し、引数で受けた ready / go ファイルで親と同期してから対象処理を叩く実行スクリプト。
(2) 子プロセスから見えるよう、フィクスチャをテストの transaction の外 (別名の独立接続) に作り、末尾で明示的に片付ける。
(3) 守りたい層以外を意図的に無効化してから測る — 子プロセスのキャッシュ store を配列固定にし、プロセス間でアプリ側ロックが共有されない状態を作ってから DB 層だけで守れることを確かめる。
(4) 合図待ちのループでファイル状態のキャッシュを毎回捨てる (捨てないと合図に気付くのが遅れ、2 本の実行が重ならず並行テストの意味が消える)。
(5) 待ちには締切を置き、超えたら例外にする。
(6) 重いので実プロセス版は 1 本に絞り、細かい分岐 (実行中 / 再生 / 順序) は同一プロセスのテストへ回す。

含まない: 何を並行で守るかという個別の不変条件 (ハーネスはそれらを証明する道具であって主張ではない)。
同一プロセス内の並行テスト (家系に多数あるが、DB の一意制約や advisory lock の実効性は証明できない別層)。
テスト実行を直列化して衝突を避ける仕組み (global-test-lock — こちらは逆に意図的に衝突させる)。
テストレーンの構成 (pest-lane-wiring / php-test-pgsql-lane)。

gates: 正典 (spirux) にはハーネス自体を見張る検査は無い (テスト支援コードであり、実働は呼び出し側のテストが示す)。
aigenba にはハーネス自身の失敗経路を固定する単体検査 5 件がある。

aicue セル (status: pending): 同一プロセス内の並行テストを 2 本持つ (プレビュー描画 / 偽オブジェクトストア)。
いずれも DB の一意制約の実効性を主張する種類ではないため、優先度は低め。
ただし冪等キーと課金の確保経路を持つので、そちらを実プロセスで裏取りする余地はある。
【領域深掘り 2026-08-14】台帳は 2 本と書くが実測は 3 本である。増えた 1 本 (冪等キーの実行前確保の契約) は
docblock で自ら証明の限界を宣言している。本 feature が埋めようとしている穴を実装者自身が文書化した状態。

先行追従例 (laravel-claude-template): アプリコードは 1 バイトも変更せずに導入。tests/Support/Concurrency に 11 本。
開発 DB への到達遮断は 6 段。実装レビューで実在した穴を閉じた主なもの:
DB 座標キーを取り除くと子側の .env 読み込みで復活するため空文字固定へ変更 /
起動中に DB へ触る provider に間に合うよう provider 登録前の検査段を新設 /
締切を壁時計から単調時計へ / 整数 cast の飽和で別の主キーが通る穴を書き戻し文字列の一致要求で閉じた。

家系からの警告 (motivation セル): コミットを要する並行テストは並列 worker と組み合わさると
PostgreSQL の排他ロックスロットを枯渇させる。このハーネスを導入する前に効いてくる前提条件。

## 背景・課題

### 正典が言っていること

正典 (spirux) の主張は 1 行で言うと **「同時に来ても 1 回だけ、はふつうのテストでは原理的に証明できない」**である。

1 つのプロセスの中で順番に呼ぶテストでは、テスト用のトランザクションもアプリ側のロックも
共有されてしまうため、DB の一意制約や排他が本当に効いているかは確かめられない。
通っていても「ロックが効いていたから」かもしれないし「そもそも同時ではなかった」かもしれない。

そこで正典は、フレームワークを自前で起こす小さな実行スクリプトを**別プロセスで 2 本**立て、
両方が「準備できた」と合図したところで親が同時に解き放ち、業務処理がちょうど 1 回だけ走ることを
実経路で確かめる。さらに**守りたい層以外をわざと無効化してから測る**ので、
「アプリ側のロックが効かなくても DB 側だけで二重にならない」ところまで言い切れる。

### 正典 v1 の不変条件 (boundary の 6 要素) — 全列挙

| # | 正典が要求すること |
|---|---|
| (1) | フレームワークを自前で起動し、**引数で受けた ready / go ファイル**で親と同期してから対象処理を叩く実行スクリプトを持つ |
| (2) | 子プロセスから見えるよう、**フィクスチャをテストの transaction の外** (別名の独立接続) に作り、**末尾で明示的に片付ける** |
| (3) | **守りたい層以外を意図的に無効化してから測る** — 子のキャッシュ store を配列固定にし、プロセス間でアプリ側ロックが共有されない状態を作ってから DB 層だけで守れることを確かめる |
| (4) | 合図待ちのループで**ファイル状態のキャッシュを毎回捨てる** (捨てないと合図に気付くのが遅れ、2 本の実行が重ならず並行テストの意味が消える) |
| (5) | 待ちには**締切**を置き、超えたら例外にする |
| (6) | 重いので**実プロセス版は 1 本に絞り**、細かい分岐 (実行中 / 再生 / 順序) は同一プロセスのテストへ回す |

正典が **含まないと明記している**もの (= 本設計のスコープ外の根拠):

- 何を並行で守るかという個別の不変条件 (冪等キー / ジョブ重複排除 / チケット確保 などが持つ。
  ハーネスはそれらを**証明する道具**であって主張ではない)
- **同一プロセス内の並行テスト** (家系に多数あるが、DB の一意制約や advisory lock の実効性は
  証明できない**別層**)
- テスト実行を直列化して衝突を避ける仕組み (`global-test-lock` — こちらは逆に**意図的に衝突させる**)
- テストレーンの構成 (`pest-lane-wiring` / `php-test-pgsql-lane`)

### 依頼文の triage 要約と正典の食い違い (先に潰す)

本設計の依頼文は正典を「**同一プロセス内**の並行実行を決定的に検証するテストハーネス」と要約していたが、
これは正典と逆である。正典の boundary は「同一プロセス内の並行テスト」を**含まないものとして名指しで除外**している。
したがって本設計は**正典本文 (実プロセス 2 本 + barrier 同期) に従う**。

同じ理由で、依頼文にあった「既存の同一プロセス並行テスト 2 本を標準形へ載せ替える」も採らない。
正典の要素 (6) は「細かい分岐は同一プロセスのテストへ回す」と**明示的に同一プロセス側の存続を前提**にしている。
既存 2 本は**そのまま残すのが正典準拠**であり、載せ替えは正典が要求しない一般化にあたる。

### aicue の現状 (実読で確認)

| 観点 | 実測 |
|---|---|
| 実プロセス barrier 同期の並行テスト | **0 本** (`tests/Support/Concurrency` は存在しない) |
| 同一プロセス内の並行テスト | 3 本 — `tests/Feature/Manual/RenderPreviewConcurrencyTest.php` / `tests/Unit/Services/Storage/FakeObjectStoreConcurrencyTest.php` / `tests/Feature/Api/IdempotencyConcurrentClaimTest.php` |
| 子プロセス起動の作法 | **既にある** — `tests/Support/ExternalFakes/FakeWiringProbeRunner.php` + `fake-wiring-probe.php` (`env -i` / 専用 env ファイル 0600 / 0700 ディレクトリ / 締切 / fail-closed な JSON 解釈 / finally 片付け) |
| 台帳の aicue セル | `pending`。「冪等キーと課金の確保経路を持つので、そちらを実プロセスで裏取りする余地はある」 |

**穴を実装者自身が文書化している**のが aicue の特徴である。
`tests/Feature/Api/IdempotencyConcurrentClaimTest.php` の冒頭 docblock は自ら証明の限界を宣言している:

> ★**保証しないこと**: PHP のテストは単一プロセスであり、真の並行 2 本は走らせていない。
> `RefreshDatabase` 下では全操作が同一接続・同一トランザクション内で見えるため、
> claim の commit も別接続からの可視性も検証していない。本番で後着から claim が
> 見えるのは「middleware を包む外側 transaction が無い + pgsql の autocommit /
> read committed」という前提の帰結であって、**テストによる保証ではない**。

そして守られている当の実装 (`app/Http/Middleware/IdempotentRequest::claim()`) は、
docblock で **「unique 制約が唯一の調停者で、cache ロック等の補助機構は使わない」**と宣言している。
これは正典が証明したい命題 (「アプリ側ロックが効かなくても DB 側だけで 1 回に収まる」) と**同一形**である。

もう 1 つ、`docs/template-divergence.md` の **D7** が同じ穴を別の言い方で登録している:

- 業務要件起因の説明: 「`RefreshDatabase` が検体を未コミットのトランザクション内に置くため、
  別プロセスからは検体が見えず、直列化の実証には**非トランザクションの専用レーンが要る**」
- **再判定の条件: 「非トランザクションのテストレーンを導入したとき」**

本設計はまさにその「非トランザクションの検体を置く仕組み」を入れるので、**D7 の再判定条件が発火する**。

## 改善アイデア

**正典 v1 の 6 要素を満たす最小のハーネスを `tests/Support/Concurrency/` に新設し、
それを使う実プロセス並行テストを「ちょうど 1 本」だけ載せる。**
証明対象は aicue が自分で「証明していない」と書いている冪等キーの実行前 claim とする。

### なぜ冪等キーを対象に選ぶか

1. 台帳の aicue セルが名指ししている (「冪等キーと課金の確保経路」)
2. 守られている実装が **「unique 制約が唯一の調停者」**と宣言している = 正典の命題とぴたり一致する
3. 既存テストが**自分で穴を宣言している** = 埋めた/埋めていないの判定が主観にならない
4. アプリコードを 1 バイトも変えずに叩ける (middleware は既存の production 経路)

対抗馬だった「org 同時 preview 上限」(D7) は **行ロックによる直列化**の主張であり、
一意制約の実効性という正典の中心命題からは 1 段遠い。要素 (6) は 1 本に絞れと言うので、選ぶのは 1 つだけである。

### 何を証明するか (テストの主張文)

> 「準備完了を互いに確認してから**同一の合図で同時に解き放った実プロセス 2 本**が、
> 同一 actor・同一 route・同一 Idempotency-Key・同一 body の書き込み要求を送ったとき、
> **本処理を実行したのはちょうど 1 本**であり、もう 1 本は本処理を実行せずに
> `in_progress` (409) で弾かれる。**プロセス間で共有されるアプリ側ロックは 1 つも無い**状態で、である。」

**勝者の判定は行の最終状態ではなく一次観測で行う** (正典・テンプレートの作法):
各子が自プロセス内で数えた「本処理ハンドラの実行回数」と受け取った HTTP ステータスを
JSON で親へ返し、親はその**合計が 1** であることを主張する。DB の行の状態は**裏取り**に置く。
(行だけを見ると「2 本とも実行したが後着が上書きした」形と区別がつかない)

### 守りたい層以外の無効化 (要素 (3)) — aicue での具体形

| 層 | 子プロセスでの扱い | 狙い |
|---|---|---|
| キャッシュ (アプリ側ロックの土台) | `CACHE_STORE=array` に固定し、子が起動後に**実体まで確認して JSON で申告** | プロセス間で共有されるロックが存在しないことを観測で示す |
| キュー | `QUEUE_CONNECTION=sync` | 本処理の副作用が子プロセス内で完結する |
| セッション | `SESSION_DRIVER=array` | 同上 |

配列固定を「渡した」だけでなく**子が申告し親が突き合わせる**のは、
`FakeWiringProbeRunner` が既に採っている作法 (「起動側が載せる分」と「子が実際に受け取った分」を
両方見て初めて退行が映る) の踏襲である。

### 既存資産の再利用 (先人の知恵を探せ)

正典の台帳は本 feature が `subprocess-boot-probe-harness` に **depends_on** すると書き、
aigenba/テンプレートはその「起動器の回収規約」を踏襲している。
aicue における相当物は **`tests/Support/ExternalFakes/FakeWiringProbeRunner.php`** であり、
以下の 6 点の回収規約が既に実装されている:

`env -i` で環境を作り直す / 専用の一時 env ファイル 1 つだけを設定の出所にする /
一時ディレクトリ 0700・env ファイル 0600 を起動前に検査して違えば子を起こさない /
締切つき実行 / 解釈できない子の出力は fail-closed で例外 / `finally` で必ず片付ける。

**新しい起動器はこの規約を明示的に踏襲する** (docblock で名指しする)。作法を 2 つに分岐させない。

### 開発 DB への到達遮断 (aicue 固有の最重要リスク)

`FakeWiringProbeRunner` は **DB に接続しない**観測なので DB 座標を子に渡していない。
本ハーネスの子は**逆に DB へ接続しなければならない**ため、遮断の設計を新規に持つ必要がある。
テンプレートが実装レビューで穴を 6 段まで塞いだ箇所であり、aicue でも最も慎重に設計する。

1. 子へ渡す `DB_DATABASE` は**親が実行時に解決した実効 DB 名**とし、渡す前に
   既存の単一点ガード `Tests\Support\Ci\TestDatabaseEnv::assertPgsqlTestDatabaseSafe()`
   (allowlist 一致 + dev denylist) を**親側で**通す。落ちたら子を起こさない
2. 子側でも起動前に**同じ判定をもう一度**通す (親を信用しない)
3. `DB_URL` は**空文字で固定**して env ファイルに書く (キーを消すと子の `.env` 読み込みで復活する。
   テンプレートが実装レビューで見つけた実在の穴)
4. 親のチェックアウトの `.env` / `.env.testing` は読ませない (専用 env ファイルだけを設定の出所にする)
5. `APP_CONFIG_CACHE` を一時ディレクトリ配下の**存在しない絶対パス**へ向け、
   共有の `bootstrap/cache` を作らない・消さない (並列実行と衝突しない)
6. 子は**マイグレーションを一切実行しない** (スキーマは親のレーンが用意済み)

### 検体の置き場 (要素 (2)) と後始末

`RefreshDatabase` の transaction の外に検体を作る仕組み (`OutOfTransactionFixtures`) を新設する:

- 既定接続の設定を**複製した別名接続**を作り、その接続を一時的に既定へ差し替えて Factory を回す
  (テストデータは必ず Factory で生成する規約を守るため)
- その接続の**明示トランザクションで commit** する
- **片付けは呼び出し側の責任**と docblock に明記し、見本テストの末尾で冪等に削除する
  (子が **commit した** `idempotency_keys` 行も同じ経路で消す。
  `RefreshDatabase` の rollback では消えないので、放置すると同一 worker の後続テストへ漏れる)
- 片付けは `finally` で必ず通し、子が落ちても走る

## 期待効果

### 使命への貢献

AI-CUE の使命は「思考ゼロ・編集ゼロ」で現場作業者が標準化されたマニュアル動画を作れること。
その入口である API は**外部システムからの自動連携**を受ける前提で `Idempotency-Key` を提供しており、
**同じ要求が同時に 2 回届いたときに撮影ジョブやレンダジョブが二重に走らない**ことは、
現場の「思考ゼロ」を成立させる土台である (二重に走れば作業者に二重の指示が出る)。
今それは**証明されていない主張**として立っている。本設計はそれを実経路の証拠に変える。

### 具体的な改善見込み

- `IdempotentRequest::claim()` の「unique 制約が唯一の調停者」という宣言が、**実プロセス 2 本の証拠**を持つ
- `IdempotencyConcurrentClaimTest` の「保証しないこと」宣言のうち、
  **claim の commit と別接続からの可視性**の 2 点が実測で埋まる (docblock も是正する)
- 家系台帳の aicue セルが `pending` → `implemented` (v1) の候補になる
- 以後、課金のチケット確保など**別の不変条件を実プロセスで裏取りしたくなったとき、道具が既にある**
  (道具は主張と独立、という正典の設計思想の恩恵)

## 実装方針 (概要)

**アプリコードは 1 バイトも変更しない。** 変更は `tests/` と `docs/` の 2 箇所に閉じる。

### 新設: `tests/Support/Concurrency/` (最小構成)

| 部品 | 役割 | 対応する正典要素 |
|---|---|---|
| `ProcessBarrier` | ready / go ファイルによる待ち合わせ。**毎回 `clearstatcache()` してから存在確認**。締切は**単調時計** (`hrtime`) で測り、超過で専用例外 | (1) (4) (5) |
| `BarrierTimeoutException` | 締切超過の専用例外 | (5) |

### 見本テスト (ちょうど 1 本)

`tests/Feature/Concurrency/IdempotencyClaimProcessConcurrencyTest.php`

要素 (6) を守り、**実プロセスを起こすテストはこの 1 本だけ**にする。
実行中 / 再生 / 順序 / 期限切れ再 claim といった細かい分岐は
既存の `tests/Feature/Api/IdempotencyConcurrentClaimTest.php` (同一プロセス) に残す。

### ハーネス自身の失敗経路の検査

`tests/Unit/Support/Concurrency/ConcurrencyHarnessFailurePathTest.php` (子を起こさない単体検査)

家系では aigenba とテンプレートが持ち、台帳の gates 欄が名指ししている層である。
ハーネスが**黙って緑になる**壊れ方 (合図が来ないのに通る / 観測が無いのに通る) を塞ぐ。

### 既存資産の扱い

| 対象 | 扱い |
|---|---|
| `tests/Feature/Api/IdempotencyConcurrentClaimTest.php` | **残す**。冒頭 docblock の「保証しないこと」から、実測で埋まった 2 点を落とし、実プロセス版へのポインタを書く |

### 共通化しない判断 (オーバーエンジニアリング禁止)

`FakeWiringProbeRunner` と新しい起動器の**共通基底を抜き出すことはしない**。
両者は目的が違う (片方は DB に**接続しない**ことが要件、もう片方は**接続する**ことが要件) ため、
「似ているから」で統合すると DB 遮断の設計が片方の都合で緩む。
**規約は docblock の名指しで踏襲し、コードは分けたまま**にする (家系の aigenba も同じ選択をしている)。

## 制約・前提

- `RefreshDatabase` はグローバル適用。個別の `DatabaseTransactions` は使わない。
  本設計は RefreshDatabase を**外さない** — 検体だけを別名接続で transaction の外へ出す
- テストは `--parallel` (paratest) 実行。DB は worker ごとに `<base>_test_<token>` へ分離済みなので
  子が commit する行が別 worker を汚すことはない。子が使う DB 名は**親が実行時に解決した実効名**を渡す
- `composer test` は global-test-lock 配下で走る (`scripts/run-test.sh`)。
  本テストは**意図的に衝突させる**側なので、ロックとは層が違い干渉しない
- PHPStan の解析対象は `app / config / database / routes` であり `tests` を含まない
  (`phpstan.neon`)。したがって**`phpstan.neon` は変更しない** —
  同ファイルは `docs/template-fingerprints.json` の共有パスかつ採用時債務にあり、
  触ると乖離台帳の突合 gate を巻き込む。触らないのが最小である
- 禁止する文 (`echo` 等) の走査は `tests/` 配下にも及ぶため、実行スクリプトの出力は
  `fwrite(STDOUT, …)` を使う (既存 `fake-wiring-probe.php` と同じ)
- 実プロセス版の所要時間は子 2 本で数秒を見込む (家系の実測: テンプレートで約 3 秒)。
  1 本に絞る限りレーン全体への影響は許容範囲

### 家系からの警告 (motivation セルの一次情報)

motivation の台帳セルは、**コミットを要する並行テストと並列 worker の組合せが
PostgreSQL の排他ロックスロットを枯渇させた**実測を記録し、
「**このハーネスを導入する前に効いてくる前提条件**」と書いている。
aicue は本設計でスキーマを作り直さない (既存 worker DB へ commit するだけ) ため同じ形は踏まないが、
**子が持つ接続を最小 (1 本 × 2) にし、締切で必ず回収する**設計にして予防する。

## スコープ外

正典が要求していない一般化・過大化は行わない。以下は**やらない**と明記する。

| # | やらないこと | 理由 |
|---|---|---|
| 1 | 既存の同一プロセス並行テスト 3 本をハーネスへ載せ替える | 正典の要素 (6) が「細かい分岐は同一プロセスのテストへ回す」と**同一プロセス側の存続を前提**にしている。載せ替えは正典が要求しない |
| 2 | 実プロセス並行テストを 2 本以上作る | 要素 (6) に反する。証明対象は最も価値の高い 1 本 (冪等 claim) に絞る |
| 3 | D7 (org 同時 preview 上限) の実証を subprocess へ移す | #2 と同じ。**ただし D7 の再判定条件が発火するので、据え置きの判断と根拠は登録簿へ記録する** |
| 4 | 課金のチケット確保 (`ticket-reserve-commit`) を実プロセスで裏取りする | 同上。道具ができるので**次の TODO で選べる**状態にはなる |
| 5 | 子プロセス数を N 本に一般化する / 任意の処理を叩ける汎用ハーネスにする | 「今必要なものだけ作る」。正典も 2 本立てを基本形として書いている |
| 6 | `FakeWiringProbeRunner` との共通基底の抽出 | 目的が逆 (DB へ接続しない / する)。統合すると DB 遮断が緩む |
| 7 | `phpstan.neon` へのハーネス追加 | aicue は `tests` を解析対象に含めない。かつ共有パス + 採用時債務で、触ると突合 gate を巻き込む |
| 8 | アプリコード (`app/`) の変更 | 家系の先行 2 例 (aigenba / テンプレート) がいずれも「本番コードは 1 バイトも変更していない」で達成済み。aicue も注入点を必要としない (middleware は既存の production 経路をそのまま叩ける) |
| 9 | 非トランザクションの独立テストレーン (別 suite / 別 CI ジョブ) の新設 | 検体を別名接続へ出すだけで足りる。レーン構成は正典の boundary が**含まないと明記**している (`pest-lane-wiring` / `php-test-pgsql-lane` の担当) |
| 10 | ハーネスを見張る Architecture gate (目録検査) の新設 | 正典 gates 欄が「正典にはハーネス自体を見張る検査は無い (テスト支援コードであり、実働は呼び出し側のテストが示す)」と明記 |
