## [Warning] 「追加の LLM 呼び出しは 0 回」はリトライを含めると成立しない (§2 の「最大 3 試行分」と矛盾)
- 判断: **対応する**
- 根拠: 指摘が正しい。validation を必須にした以上、従来なら起きなかった 2 段目の再試行が
  最大 2 回増えうる。同じ設計書の中で矛盾した数え方をしていた。
- 対応内容: 費用の項 1 を
  「**新しい必須段・新しい実行経路は追加しない**。必須段数は 3 段のまま、
   有界リトライの上限も時間 budget も変えない。通常成功時の呼び出し回数は 3 回のまま。
   ただし validation のスキーマ違反により、従来なら起きなかった 2 段目の再試行が
   最大 2 回発生しうる」に書き換えた。
  チケットの項も「新しい呼び出しが無いため」ではなく
  「必須段数とリトライ上限を変更しておらず、validation 起因の実費増分は実装後に観測するため、
   現時点で価格を変更する根拠が無い」に書き換えた。

## [Suggestion] 違反パスをメッセージだけでなく固定キーの構造化 context で記録せよ
- 判断: **対応する**
- 根拠: 集計するならメッセージ文字列に頼るのは弱い。
- 対応内容: 観測条件を「リトライログに固定キーの構造化 context
  (`stage` / `failure_category` / `failure_path` / `attempt`) を載せる。
  可変の LLM 応答本文は含めない」に書き換えた。
