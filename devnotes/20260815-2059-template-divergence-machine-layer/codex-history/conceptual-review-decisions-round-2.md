# 対応マトリクス: conceptual-review Round 2

## [Warning] 3 点一致を「登録漏れ」の検出と書いているのは過大 (観点 1)
- 判断: 対応する
- 根拠: 逸脱を作って誰も登録簿を触らなければ 3 つの数はどれも動かない。指摘のとおり
- 対応内容: 表の行名を「登録を触ったときの同期漏れ」へ変更し、「3 点一致は新しい登録を書かせる仕組みではない」
  「実逸脱の未登録を見つけるのは台帳リポジトリの巡回だけ」を本文に明記。期待効果も同じ語へ揃えた

## [Warning] 実行不能を不合格にする規定が検査仕様に無い (観点 3)
- 判断: 対応する
- 根拠: 正典 i12 の要求。空集合フォールバックや skip は偽グリーンになる
- 対応内容: 「実行不能は不合格 (fail-closed)」節を新設。読めない / 見出し 0 件 / メタ表を解析できない /
  明示行が読めない / 基準日が取れない をすべて明示的な検査失敗とし、skip 経路を作らないと明記

## [Warning] 掃除漏れの検出範囲の説明が過大 (観点 4)
- 判断: 対応する
- 根拠: ファイルを残したまま中身をテンプレート準拠へ戻した場合は検出できない
- 対応内容: 掃除漏れを「登録対象の消滅」と「解消を状態で表す形」の 2 行に分けて限定し、
  「内容としては解消済みの逸脱が残っていること」を保証しないものへ追加した

## [Warning] 移行で新設するメタデータの証拠規則が無い (観点 5)
- 判断: 対応する
- 根拠: 推測で埋めると形式は正しくても来歴が虚偽になる
- 対応内容: 「移行で新しく決める値の出どころ (推測しない)」の表を新設。決めた日は**逸脱を最初に決めた日**で
  統一 (移行時の再確認日ではない)、出どころは設計 devnotes の日付か TODO の完了日、
  導出できないものは移行ブロッカーとして判断ログへ書き差し戻す、と定めた

## [Warning] 「逸脱ではない」の根拠に権威性が要る (観点 5)
- 判断: 対応する
- 根拠: 自分で文書を書いて自己証明できてしまう
- 対応内容: 根拠を (a) 台帳リポジトリから届いた判定 / (b) 既に確定している正典の管理範囲定義 /
  (c) 指摘元 (巡回) が認めた分類 の 3 つに限定し、自己証明を明示的に禁じた

## [Suggestion] スコープ外の書き方が施策 5 と衝突する (観点 6)
- 判断: 対応する
- 対応内容: スコープ外を「既存登録 (D1〜D18) の是非の再判断」に限定し、施策 5 は別の行為であると明記

## [Suggestion] 解析エラーを欠損値や空配列で表さない (観点 7)
