# 全体判定: CHANGES_REQUESTED

Round 3 の指摘事項は解消されています。特に Safari を主要プラットフォームとして設計対象へ戻した判断は North Star と整合します。ただし、P3-b の現在案では「PIIを再表示しない」ことをまだ保証できません。

## 1. 使命との整合性

[Suggestion] iOS Safari を除外せず、P3-b とブラウザ方針を成果物へ追加した判断は適切です。撮影 PWA という使命に直接整合しています。

## 2. 禁止事項違反

[Suggestion] Browser E2E を恒久テストかつ完了条件とし、bug-hunt を補助確認へ戻したことで、禁止事項 #1 への抵触は解消されています。

## 3. 実現可能性

[Critical] `pageshow.persisted` を受けてから非同期にセッションを再検証する方式では、検証完了まで復元済みの古い DOM が表示され、PII が一瞬露出する可能性があります。「無効なら遷移する」は「再表示しない」と同義ではありません。

修正提案: P3-b の成立条件として、復元内容を検証前に表示しない仕組みを追加してください。例えば次の構成です。

- `pagehide` 時に画面を同期的に秘匿し、その状態を bfcache snapshot に含める
- `pageshow.persisted` 時は秘匿状態のまま、再検証または強制再読込する
- セッション有効時のみ表示を戻す
- 無効時はログイン画面へ hard navigation する

単純な `pageshow → 非同期検証` だけでは不十分、という不変条件を詳細設計と Browser E2E に固定する必要があります。

[Warning] 「再検証」の通信契約が未定義です。通常ページを再取得するのか、専用 endpoint を追加するのかで、キャッシュ・認証・DTO規約・攻撃面が変わります。

修正提案: 概念設計では「専用 endpoint を安易に追加せず、まず hard reload で既存の session middleware に再判定させる」を第一候補にしてください。専用 endpoint が必要なら、同一オリジン、`no-store`、セッション認証、DTO/JsonResource 応答を必須条件とします。

## 4. 期待効果の妥当性

[Warning] 「サポート対象ブラウザの代表 E2E」だけでは、iOS Safari 対応を実証したことにならない可能性があります。Playwright WebKit と実機 Mobile Safari は同一ではありません。

修正提案: P3-c で、各対象ブラウザに対する検証レベルを明記してください。少なくとも WebKit 自動回帰テストと、iOS Safari 実機での受入確認を区別し、自動化できない実機確認を「恒久テスト済み」と表現しないことが必要です。

## 5. リスク

[Warning] `pagehide/pageshow` の全体処理は、撮影中の media stream、未送信フォーム、Inertia の履歴状態へ影響し得ます。

修正提案: Browser E2E に「撮影画面からの通常遷移」「bfcache 復元」「未ログアウトでの復元」「ログアウト後の復元」を分けて登録してください。秘匿処理は DOM表示に限定し、撮影データやフォーム状態を破棄しない設計にします。

## 6. スコープの適切さ

[Suggestion] P3-b は追加スコープですが、iOS Safari が主要プラットフォームである以上、過剰設計ではありません。aigenba との差分として記録する扱いも適切です。

## 7. 型安全性

[Suggestion] P1・P3-a に型安全上の問題はありません。P3-b では `PageTransitionEvent` を明示し、専用 endpoint を追加する場合のみ DTO/JsonResource と PHPStan level 10 の対象へ含めてください。

承認に必要な修正は、P3-b を「復元後に検証」から「検証完了まで復元内容を秘匿」へ強化し、その状態遷移をE2E契約として固定することです。
