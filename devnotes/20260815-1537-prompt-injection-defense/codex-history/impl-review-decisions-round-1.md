# 対応マトリクス: impl-review Round 1

## [Warning] ログ漏洩テストが空振りし得る (`tests/Feature/Llm/PromptDefenseTest.php`)

- 判断: **対応する**
- 根拠: 指摘のとおり `in_array('機密の手順', $context, true)` は**完全一致**の検査なので、
  `context['input'] => '機密の手順です'` のように部分文字列として混ざった場合を捕まえられない。
  設計 J-9 は「ログに untrusted 文字列そのものが出ない (件数だけ)」を要件にしているので、
  回帰検出力が要件に届いていない。
- 対応内容: context を `json_encode`(`JSON_UNESCAPED_UNICODE`) で 1 本の文字列へ畳み、
  **untrusted 本文の断片が 1 つも含まれないこと**を部分一致で検査する形へ変えた。
  併せて「message にも本文が出ない」ことと「除去した文字そのものが出ない」ことも見る。
  修正後、`PromptDefense` の `Log::info` に本文を足すと赤くなることを実測した。

## [Warning] 「これ以外の道は構造的に存在しない」が強すぎる (`docs/architecture.md`)

- 判断: **対応する**
- 根拠: 同じ節の「保証しないもの」に「gate が見るのは静的な出現だけで、文字列キーの
  container 解決や動的なクラス名には沈黙する」と書いてあり、見出しと自己矛盾している。
  AGENTS.md の「保証範囲を誇張しない」に反するので、弱い側 (正しい側) へ揃える。
- 対応内容: 見出しを「経路 (静的に書ける道はこれだけ)」へ変え、直後の本文に
  「静的に書ける限りこの 1 本道しかない。反射・動的クラス名・文字列キーの container 解決で
  作った経路には gate が沈黙する (本節末尾の『保証しないもの』)」という限定を明記した。
