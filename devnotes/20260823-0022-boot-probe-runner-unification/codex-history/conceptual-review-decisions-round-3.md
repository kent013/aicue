## [Critical] gate の主張の縮小が全文へ反映されておらず、3 箇所に旧来の強い主張が残る

- 判断: **対応する (指摘は正しい。同一設計内の矛盾である)**
- 根拠: Round 2 で C 節だけを直し、他 3 箇所を直し忘れた。「gate が緑だから 1 本である」という
  裏の取れない主張が残るのは、本設計が最も避けたい「観測が緑のまま嘘をつく」形そのものである。
- 対応内容: 指摘の 3 箇所をすべて C 節の主張へ統一した。
  1. 改善アイデア 5: 「**一元化そのものは載せ替えの実測で確認する**。gate が固定するのは
     `PHP_BINARY` の明示参照 / リテラルのアプリ起動点 / 既存の子入口への参照が申告なしには増えないこと**だけ**」へ
  2. 「なぜ全数申告 gate を置くのか」: 新しい不変条件の定義を上の 3 点へ書き換え、
     「アプリ起動経路は runner 1 本」を**不変条件として掲げない理由**を引用ブロックで明記
  3. 実装順の段 2: 赤の根拠を「`launches_app` の 1 件固定への違反」から
     「**軸 A の実測 (旧 2 経路が `PHP_BINARY` を直接持つ) が申告集合と一致しない**」+
     「軸 C の `runtime` 参照元が `BootProbeRunner` を参照していない」へ置き換え
  4. `launches_app: true` の 1 件固定は残すが、**実際の起動経路の全数性を表さない補助的な申告値**である
     ことを引用ブロックで明記した

## [Warning] 軸 C の走査に gate 自身が入る (自己参照) の扱いが未定

- 判断: 対応する
- 根拠: 正しい。gate は inventory に子入口の完全なパス文字列を持つので、必ず軸 C の母集団に入る。
- 対応内容: **除外しない** (除外は迂回口になる) 方針を採り、軸 C の entry に `reference_kind` を持たせた。
  値は `runtime` (実行経路として子入口を起こす) / `inventory` (検査定義として path 文字列を保持する) の
  ちょうど 2 値で、**`runtime` はちょうど 1 件 = `FakeWiringProbeRunner.php`**。gate 自身は
  `inventory` として自らを申告する。**文字列を分割して検出を逃れることは禁止**し
  (軸 C が防ぎたい迂回そのもの)、その禁止を走査器の見本検査で固定することを受入条件に入れた。

## [Warning] P-14 のパス配下判定の方法が未確定 (sibling パスの取り違え)

- 判断: 対応する
- 根拠: 正しい。素の前方一致は `/tmp/boot-probe-abc` と `/tmp/boot-probe-abc-evil` を取り違える。
- 対応内容: 取り込む runner が**この目的のために公開している** `BootProbeRunner::isInside()` を使うと明記した。
  区切り文字を境界にし、末尾の区切りを正規化し、両引数が絶対パスであることだけを表明する
  (**存在しない予定パスに `realpath()` を要求しない** = キャッシュの指し先を測れる)。
  `base_path()` の外の判定は `! isInside(realpath(base_path()), $path)` と書き、
  **`base_path()` 自身との一致も「外ではない」に含まれる** (`isInside` は同一パスを true にする) ことを明記。
  sibling パスの負例は取り込む自己検査 S11 が既に固定している旨も書いた。

## [Warning] `interpret(): array` と「無型の配列を漏らさない」の整合

- 判断: 対応する (主張を検出力へ合わせる)
- 根拠: 正しい。子が書いた JSON は原理的に `array<string, mixed>` にしかならない。
- 対応内容: 戻り値を既存の**完全な array shape** で PHPDoc 固定すると明記したうえで、主張を
  「**無型の値が漏れるのは子の JSON という 1 か所だけで、そこは呼び出し側 gate が各キーごとに
  型を確かめてから使う**」へ縮小した (「無型の配列が 1 つも無い」とは言わない)。

## [Warning] 「2026-08-23 実測」が提示された現在日付より未来

- 判断: 対応する
- 根拠: 設計ディレクトリ名は app-design スキルの規定により `TZ=Asia/Tokyo` で採る (JST 2026-08-23 00:22)。
  一方でセッションが提示する現在日付は UTC の 2026-08-22 である。誤記ではなくタイムゾーン差だった。
- 対応内容: 見出しを「設計時に実読で実測。JST 2026-08-23 / UTC 2026-08-22」へ改め、根拠が分かる表現にした。
