# 対応マトリクス: conceptual-review Round 2

## [Critical] 使い捨て `APP_KEY` が環境ファイルからでは効かない (優先順位の矛盾)

- 判断: **対応する (指摘は実測で裏が取れた)**
- 根拠: 設計時に実測して確かめた。Laravel の `Env::getRepository()` は immutable なので、
  **プロセス環境に既に在る値を Dotenv は上書きしない**。runner の基底が `APP_KEY` を載せる以上、
  0600 の環境ファイルに書いた使い捨て `APP_KEY` は無視される。
  実測: 環境ファイルに `APP_KEY=base64:ZmlsZS1r…`、プロセス環境に `APP_KEY=base64:cnVubmVy…` を置いて
  子を起こすと `config('app.key')` は **`base64:cnVubmVy…` (プロセス環境側)** になった。
  同じ実測で `CIPHERSWEET_KEY` (プロセス環境に無い) は環境ファイルの値が効いた。
- 対応内容: 4 段表を修正した。
  - ケース別上書きへ **使い捨て `APP_KEY` を移す** (3 件: `FAKE_WIRING_PROBE_ENV_DIR` /
    `FAKE_WIRING_PROBE_ENV_FILE` / `APP_KEY`)。正典 (2) の「ケース別が最後に効く」順序をそのまま使う
  - 環境ファイルの許可キーから `APP_KEY` を**外す** (`ALLOWED_ENV_FILE_KEYS` から削除)
  - P-7 の期待集合を「ケース別 3 件」へ
  - P-8 を「**子が観測した `APP_KEY` が生成した使い捨て値と一致し、親の `config('app.key')` とは一致しない**」へ
    (従来は起動側の配列を見ていたので、子で効いたことまでは示していなかった = 主張の強化)
  - `CIPHERSWEET_KEY` は runner の基底にも予約にも無いので**環境ファイルのままで効く** (実測済み)
- 反論なし。runner は `APP_KEY` のケース別上書きを禁じていない (予約鍵は書き出し先 7 キーのみ) ので、
  バイト一致取り込みと両立する。

## [Critical] 軸 A + 軸 B から「アプリ起動経路は runner 1 本」は導けない

- 判断: **対応する (提案 2 = 主張の縮小を採る。ただし挙げられた抜け道の 1 つは軸 C で塞ぐ)**
- 根拠: 指摘は正しい。文字列の `'php'` / `env php` / シェル経由 / 変数から取り出した実行体パスは
  **字句走査では原理的に追えない**。ここで「1 本に閉じる」と書き続けるのは嘘である。
  提案 1 (プロセス起動 API の全数申告) は実測すると **`tests/` 配下 25 ファイル**が母集団になる
  (`Process::fake()` の単体テストや `git ls-files` の列挙まで含む)。3 欄の申告を 25 件書くのは
  本 TODO の目的から外れた別作業であり、禁止事項の「やたらに複雑な案」に当たる。
- 対応内容:
  - gate の主張を検出力へ**縮小**した。主張するのは「`PHP_BINARY` を明示する起動能力 /
    リテラルで検出できるアプリの起動点 / 既存の子入口スクリプトへの参照 の 3 つが、
    **申告なしには増えない**」までとし、「アプリ起動経路が runner ちょうど 1 本である」とは**主張しない**
  - Codex が挙げた 5 番目の抜け道 (既存の子入口スクリプトを別経路から起こす) は
    **軸 C (子入口スクリプトのパス文字列を参照するファイルの全数申告)** で直接塞いだ
  - 追えない 4 形 (`'php'` / `env php` / シェル経由 / 変数の実行体パス) を
    **gate の docblock に「保証しないこと」として名指しで書く**ことを受入条件にした
  - 一元化そのものの証拠は「載せ替えの実測」であり、gate は**退行の検出器**であって証明ではない、と明記した
  - `tests/` 全域のプロセス起動 API 全数申告は**スコープ外**に移し、再判定条件を書いた

## [Warning] fail-first の段 4 が赤にならない

- 判断: 対応する
- 根拠: 正しい。「制限時間超過を例外にする」は旧実装 (`ProcessTimedOutException`) でも通る。
- 対応内容: 両経路に**純粋な変換関数の境界**を置き、そこを先に検査する形へ変えた。
  `StrictTypesRuntimeProbe::decide(BootProbeResult, string $nonce): bool` /
  `FakeWiringProbeRunner::interpret(BootProbeResult, …): array` を公開し、
  「`timedOut === true` なら例外 / `exitCode !== 0` なら false (経路 2) / 標識不一致なら例外」を
  **子を起こさずに**負例で固定する。旧実装にはこのメソッドが存在しないので段 4 は確実に赤になる。
  副次効果として、分岐の検査に子プロセスが要らなくなる (実行時間の短縮)。

## [Warning] P-14 の snapshot 比較は内容変更を検出できず、`--parallel` で偽陽性になる

- 判断: **対応する (指摘を受けて P-14 の測り方そのものを変える)**
- 根拠: 両方とも正しい。とくに `--parallel` の指摘は決定的である —
  `storage/logs/` / `storage/framework/views/` / `bootstrap/cache/` は**他の worker が実際に書く**ので、
  起動前後の差分比較はどう精密にしても偽陽性になる。「対象ディレクトリへ他テストが書かない」ことを
  aicue の既存不変条件では保証できない。
- 対応内容: P-14 を**方向の検査**へ置き換えた。子が起動後に解決した書き出し先の絶対パス
  (`storagePath()` / `getCachedConfigPath()` / `getCachedRoutesPath()` / `view.compiled` /
  `logging.channels.single.path`) を持ち帰らせ、**1 件残らず `BootProbeResult::$temporaryRoot` の配下**であり
  **`base_path()` の外**であることを測る。これは決定的で `--parallel` 安全であり、
  取り込む自己検査の S9 が採っている形と同じである。実体側は P-13 (印が一時ディレクトリ配下に実在する) が持つ。
  = 「向き」と「実体」の 2 方向で測り、リポジトリ側の before/after 差分は**採らない** (理由を docblock に書く)。

## [Suggestion] `timedOut` と 124 の同値を DTO の生成時不変条件に

- 判断: **見送る (バイト一致を崩さないため)。ただし契約を明記する**
- 根拠: 取り込む `BootProbeResult` は同値を構築時に表明しない。また**厳密には同値ではない** —
  終了要求を受け取ってから自分で `exit(0)` する子は `timedOut === true` かつ `exitCode === 0` になりうる。
  取り込みファイルを 1 バイトでも変えると逸脱の登録が必要になるので触らない。
- 対応内容: 呼び出し側の契約として「**判定には `timedOut` を使い、`exitCode === 124` を直接読まない**」を
  明記した。runner 側の対の固定は取り込む自己検査 S7 / S12 / S14 が既に持っている。
