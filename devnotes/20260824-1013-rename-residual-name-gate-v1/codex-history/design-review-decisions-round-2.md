# 対応マトリクス: design-review Round 2

Codex 判定: **APPROVED**（S1 / S2 / S3 すべて APPROVE。Critical 0 / Warning 0 / Suggestion 2）。
Suggestion 2 件はどちらも安価で意図の可読性が上がるため**対応する**。

## [Suggestion] 逆向き差分を持たない理由を実装の `array_diff` 付近にも短く残す
- 判断: **対応する**
- 根拠: 長い証明は詳細設計 §判定の含意 が正本。コード側に「なぜ片方向だけ見るのか」の
  判断理由が 1 行あると、後から読む人が逆向き差分を「足し忘れ」と誤読しない。
- 対応内容: `$undeclared = array_values(array_diff($actual, $declared));` の直前に
  2 行のコメントを追加した（証明の複写はしない）。

## [Suggestion] N-4 (k) の期待件数 2 は診断方針の契約であることをコメントに残す
- 判断: **対応する**
- 根拠: 2 件は別の情報（申告自体の不正 / 採用できなかった結果の未申告出現）であり、
  両方提示する方針は静的 gate の利用者にとって合理的。将来抑制する設計へ変えるのは
  セキュリティ退化ではなく診断方針の変更であることを明示しておくと、期待件数を直す判断が読める。
- 対応内容: N-4 (k) の直前にその趣旨のコメントを追加した。
