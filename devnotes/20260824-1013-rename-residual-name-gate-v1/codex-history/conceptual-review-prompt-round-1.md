# アプリの使命・禁止事項・思考原則 (AGENTS.md より挿入)

## 使命 (North Star)

<!-- app-codex-review スキルはこのセクションをレビュー使命として参照する。 -->

**AI-CUE** は、現場に既にある**作業手順書(SOP)を起点に**、AI が撮るべきカットを設計した**動画シナリオ**を生成し、そのシナリオを**スマホ(PWA)でナビゲーション撮影**することで、専門知識ゼロの現場作業者でも**標準化されたマニュアル動画**を作れるようにする。

- 「思考ゼロ・編集ゼロ」— 台本作成・撮影判断・編集の 3 ハードルを AI とナビ撮影で肩代わりする。
- 競合(OJT を撮って形式化する tebiki)と異なり、**標準作業を起点に AI が教材設計し撮影を指示する**（撮影者・教える人のスキルに品質を依存させない）。
- 熟練者の暗黙知を動画マニュアルという形式知へ変換する装置（SECI）。

> 詳細な設計は本リポジトリの `doc/`（01〜10）に置く。ドメインをテンプレート構造へどうマップしたかは `doc/08`〜`doc/10`（特に `doc/10 §10.8` に設計レビュー反映済み）。
> **v1 スコープ**: 字幕のみ(TTS 後回し) / 撮影は PWA(同一オリジン・セッション認証) / 動画合成は自前 ffmpeg / 単一 Default Project。


## 禁止事項

1. テストなしの実装完了報告(不変条件は対応する Architecture/Feature テストへの登録まで含めて「実装済み」)
2. PHPStan エラーの widen(型を緩めて黙らせる)・baseline 化
3. dev DB への破壊操作(`migrate:fresh` 等)をエージェント判断で実行すること
4. `response()->json()` の直書き(DTO / JsonResource / Inertia を使う。仕様固定 endpoint のみ例外)
5. LLM 呼び出しの Prism 直呼び(`app/Prompts/` の factory → 窓口 (`PromptDefense`) →
   実行単位 (`GuardedPrompt`) の**1 本道のみ**。`PromptGuardrailTest` が
   app/ routes/ database/ config/ bootstrap/ の 5 走査根で検出する)。
   **実行経路を持つ prompt factory は `LlmCallContextData` を必須引数で受け、
   `PromptDefense::load()` へ渡して帰属 (organization / subject) を付ける** — 付け忘れは
   PHPStan level 10 が落とす。帰属の対象を持たない見本 (`ExampleSummaryPrompt`) だけが
   `PromptDefense::loadUnattributed()` を使え、窓口 gate が**この 1 件を名指しで pin** する。
   併せて `PromptUntrustedInputContractTest` の inventory へ**帰属キーを空配列で exempt 登録**する
   (deny-by-default なので exempt にする操作がレビューで必ず見える)。
   欠けると `llm_call_logs.metadata_missing` になり組織別・対象別の費用が出せない
6. prompt 文字列のコード直書き(`resources/prompts/*.yaml` に置く)
7. 操作系 POST の応答での `redirect()->intended()`(ログイン直後フロー専用。
   招待送信等は `back()->with(...)` で完結させる)
8. 必須条件未充足を理由にボタンを disabled にする UI(押下時にエラー表示する。DESIGN.md)
9. Artifact の使用(Artifact ツールでの成果物公開を行わない。成果物はリポジトリ内のファイルとして出力する)

## 背景・課題

aicue は 2026-08-17 の T214 で bug-hunt ランタイム配線の 2 件を家系名へ改名し
(`BughuntBillingSeeder` → `BughuntStripeSyncSeeder` /
`FakeExternalsServiceProvider` → `BughuntFakesServiceProvider`)、旧名が戻らないことを
`tests/Architecture/BughuntNamingResidualTest.php` (276 行 / N-1〜N-5) で固定した。

2026-08-22、家系はこの関心事の正典を **v1 (出現特定式許可台帳 — 空縮退可)** に確定した。
判定は clear-superior で、形が割れていた軸は「記録として残ってよい旧名の扱い」1 つだけだった。
aicue の現行実装 (件数の完全一致 pin) は正典に対して **2 点足りない**。実コードを実読して裏を取った。

1. **許可が「出現の特定」になっていない**。`BUGHUNT_NAMING_KNOWN_MENTIONS` は
   `ファイル => 旧名 => 件数` の数値でしかなく、述語 `bughuntNamingViolationsIn()` は
   `substr_count()` の数値比較だけを持つ。したがって **同一ファイル内で件数を変えずに
   出現箇所をすり替える書き換えに沈黙する** (例: `docs/TODO-closed.md` の T015 の完了行から
   旧名を消し、代わりに新しい行へ旧名を 1 つ書く。件数は 2 のままで緑)。
   正典が v1 を選んだ根拠そのものがこの穴である。
2. **パス名を走査していない**。同述語は第 2 引数 `$content` だけを見ており、`$relative` は
   除外判定と件数 pin の引きにしか使っていない。**旧名をパス名に持つファイルの復活**
   (例: `app/Providers/FakeExternalsServiceProvider.php` の再出現) を検出できない。
   現 HEAD に該当パスは 0 件 (実測: `git ls-files | grep -E '旧名'` = 0) なので今は緑だが、
   **退化に沈黙する構造**である。正典は「内容だけでなくパス名も見る」を必須にしており、
   その理由も明示されている — 中身を書き換えただけのファイルが旧名のパスで復活する経路は
   内容走査だけでは塞げない。

一方で満たしている要求も実読で確認した (これは壊さない):
照合名一覧が空でないこと (N-3 が 2 件で完全一致 pin) / 母集団は `git ls-files` 全数 +
下限 500 (実測 9925) / 置き換え先の実在かつ git 追跡下 (N-2 の sentinel 4 本) /
読めないファイルで fail-closed (`bughuntNamingSourceOf()` が例外) /
保証しない範囲の明記 (docblock)。

無いと何が起きるかは 1 文で言える — **改名したはずの旧名が規約文書・スキル・手順書に静かに
戻り、それを読んだ人と開発を担うエージェントは、書いてあるとおりに実行して失敗するまで
誤りに気づかない**。コードなら型検査や参照解決が拾うが、文書・スキル・CI 定義の中の名前は
誰も検査していない。

## 改善アイデア

`tests/Architecture/BughuntNamingResidualTest.php` **1 ファイルだけ**を正典 v1 の形へ引き上げる。
アプリコード (`app/` / `routes/` / `database/` / `config/` / `bootstrap/`) は 1 バイトも触らない。

- **(A) 許可の表現を差し替える**。「ファイル × 旧名 × 件数」を捨て、
  「**ファイル × 旧名 × 出現ごとの申告 (その出現を一意に特定する周辺文字列 + 残す理由)**」にする。
  行番号は使わない (行番号は無関係な編集で動くので台帳が壊れやすい)。
  件数は申告の本数から導出する = **二重管理の pin を作らない**。
- **(B) 突き合わせを 3 方向で落とす**。(1) 申告されていない出現がある /
  (2) 申告があるのに実物から消えた (または周辺文字列が 1 回に特定できない) /
  (3) 申告数と実出現数が一致しない。特定は**実ファイル内の出現位置 (バイト位置) の集合の
  一致**で行う。位置は台帳に書かず、周辺文字列から**導出する**。
- **(C) 走査をパス名にも掛ける**。純関数の第 1 引数 `$relative` を照合対象へ昇格させ、
  「除外判定・申告の引き当て」と「照合」の役割を分ける。
  **パス名に申告の口は作らない** (記録としてのファイル名に旧名が要る事案は存在しないので
  0 件固定にし、そのことを保証範囲として書く)。
- **(D) 負のコントロールを新形へ拡張する**。同じ述語を通して少なくとも
  「件数は同じだが出現箇所をすり替えた入力が赤になる」「パス名に旧名を持つ入力が赤になる」
  「置き換え先の名前は誤検出しない」を実測する。合成の申告台帳を述語へ**引数で**渡せるように
  し、負のコントロールが実ファイルの内容に依存しないようにする (現行 N-4 は実 pin 値を
  ハードコードしている)。
- **(E) 空振り防止を 1 段強くする**。現行の下限 500 + sentinel 4 本に加え、
  **置き換え先の名前を同じ走査機構で実際に見つける正の対照**を置く
  (走査そのものが動いていることの証明。家系の先行実装 BHN-4 と同型)。
- **(F) docblock を書き直す**。パス名走査の追加・申告形式の沈黙範囲・
  `devnotes/` と自ファイルの丸ごと除外を保証の穴として明記する。
- N-5 (旧名クラスの不在 / 家系名クラスの存在) は正典が**任意強化として維持可**と認めており、
  既にあるので**残す** (削るのは既存テストの削除に当たる)。

### 現状の実測 (申告へそのまま写す)

`docs/TODO-closed.md` に旧名の出現が 5 件、`docs/TODO.md` に 0 件 (両方とも実測)。

| ファイル | 旧名 | 出現 | 出現の所在 |
|---|---|---|---|
| `docs/TODO-closed.md` | `BughuntBillingSeeder` | 2 | T015 の完了行 / T214 の完了行 (改名の対応表) |
| `docs/TODO-closed.md` | `FakeExternalsServiceProvider` | 3 | T015 の完了行 / T119 の完了行 (`…Test` の test 数) / T214 の完了行 |
| `docs/TODO.md` | 両方 | 0 | 現行 pin は「0 件」を明示登録しているが、v1 では**登録そのものを外す** |

`docs/TODO.md` の登録を外しても摩擦は消えない — 申告台帳は deny-by-default なので、
`docs/TODO.md` に旧名が 1 つ現れた瞬間「申告外の出現」で赤になる。
**0 件の登録は v1 では「実物から消えた申告」と区別できない無意味な行**になるため外す。

## 期待効果

- **使命への貢献 (間接・開発の進め方)**: aicue の使命は「SOP を起点に AI が撮るべきカットを
  設計し、PWA のナビ撮影で標準化されたマニュアル動画を作る」ことである。本件は業務機能では
  なく、**その開発を担うエージェントが読む規約・スキル・手順書の名前が腐らないこと**を守る。
  bug-hunt の配線名が古いまま残ると、探索的バグハントの provision が実行時に失敗するまで
  誰も気づかない (T214 の起点がまさにそれ)。
- **具体的な改善見込み (穴が 2 つ閉じる)**:
  - 件数を保ったまま出現箇所をすり替える書き換えが**赤になる** (現行は緑)。
  - 旧名をパス名に持つファイルの復活が**赤になる** (現行は緑)。
  - 副産物として、`docs/TODO-closed.md` の記録が「どの作業の記録として旧名を残しているか」を
    台帳の理由欄で読めるようになる (現行は件数だけなので追跡に実読が要る)。
- **家系との整合**: aicue セルが `update_pending` から `implemented` (version v1) へ戻る。
  正典 v1 の走査側要求 (パス名 + 内容 / fail-closed / 番兵 / 下限 / 非空主張) を全部満たす形になる。

## 実装方針（概要）

変更は **`tests/Architecture/BughuntNamingResidualTest.php` の 1 ファイルのみ**。

1. 定数 `BUGHUNT_NAMING_KNOWN_MENTIONS` (件数 pin) を撤去し、
   `BUGHUNT_NAMING_DECLARED_OCCURRENCES` (出現ごとの申告) を新設する。
   **後方互換の並走を残さない** (AGENTS.md 思考原則 3) — 同じ変更で件数 pin を消す。
2. 純関数 `bughuntNamingViolationsIn(string $relative, string $content, array $declarations)` を
   書き換える。役割は 3 つ: 除外判定 → **パス名の照合** → **内容の照合と申告の突き合わせ**。
3. 出現の特定は「周辺文字列 (needle) が実ファイルにちょうど 1 回現れ、その needle が対象の
   旧名をちょうど 1 回含む」ことを要求し、**needle の位置 + needle 内の旧名の位置**から
   出現位置を導出する。導出した位置の集合が**実出現位置の集合と完全一致**することを要求する。
4. 検査は 5 本のまま (N-1〜N-5)。N-1 は内容 + パス名、N-2 に正の対照を足し、N-3 は
   申告台帳の構造 (キー・理由の長さ) を pin、N-4 は負のコントロールを拡張、N-5 は現状維持。
5. docblock を書き直す。

### アプリコード・他テストへの波及

- **無い**。旧名は現役コードに 1 件も無く (実測)、本件は照合器の内部形式の変更に閉じる。
- 他の gate との相互作用も無い (走査対象の重なりはあるが照合語は 1 つも重ならない)。

## 制約・前提

- **走査基盤の共有はしない**。aicue には撤去物の不在 gate 用の `tests/Support/SurfaceRemoval/`
  (`RemovedSurfaceScanTargets` / `ScanPopulation` / `RemovedSurfaceScanner` 等) があるが、
  流用しない。理由は 3 つで、これは**設計上の裁定**である。
  1. **母集団の定義が違う**。あちらは走査根 8 本 (`.github` `app` `bootstrap` `config` `lang`
     `resources` `routes` `scripts`) に絞る設計で、`docs/` と `.claude/` と `tests/` を見ない。
     本件が守りたいのは**まさに `docs/` と `.claude/` の中の名前**である (規約文書・スキル・
     手順書に残る旧名が本 feature の主敵)。根を広げるとあちらの不変条件
     (`database/migrations` を含めない等) を壊す。
  2. **関心事の境界が台帳で明示的に分けられている**。lctl の boundary は
     「撤去物の不在」(surface-removal-absence-gate) と「旧名の残留」(本 feature) を
     名指しで分けており、aigenba 側でも `RemovedSurfaceLedger::excluded()` が同じ線引きを
     宣言している。基盤共有はこの境界をぼかす方向である。
  3. **`docs/template-divergence.md` D40 の対象パスを膨らませない**。SurfaceRemoval の共通基盤は
     D40 として登録済みで、対象パスに本 gate を足すと「撤去物の不在 gate の共通基盤」という
     登録の説明が実態と食い違う。
  代わりに、現行実装と同じく**本テスト内に閉じる**。ただし `git ls-files` を使う列挙が
  リポジトリに 3 本目として並ぶことになるため、`RemovedSurfaceScanTargets` が
  `TrackedPhpSourceFiles` に対して行っているのと同じく、**docblock に兄弟関係
  (同じ作法・違う母集団の定義) を書いて「列挙を 2 本持つのではない」ことを明示する**。
- **`docs/TODO.md` / `docs/TODO-closed.md` との構造的な摩擦**。本作業の TODO 登録行が旧名を
  綴ると `docs/TODO.md` の出現が増え、同じ変更で申告を足さないと赤になる。さらにクローズ時に
  行が `docs/TODO-closed.md` へ移るので申告をもう一度動かす必要がある。
  **本設計は「TODO の登録行・クローズ行に旧名を綴らない」書き方を選ぶ** (旧名は
  「bug-hunt 配線の旧名 2 件」と数で指し、綴りは devnotes の設計書側に置く)。
  摩擦の機構そのものは残す (deny-by-default なので、綴った瞬間に赤くなる) が、
  **今回は摩擦を踏まない**。踏んだ場合の正しい直し方は「記録を書き換える」のではなく
  「申告を足す / 移す」であることを docblock に残す。
- **AGENTS.md 「静的検査 (gate) と走査器の共通規約」5 条**に従う。本件で効くのは
  (b) 解決できない形を落とす (読めないファイルは例外)、(c) 検出力を負例で裏取り (N-4)、

  **(e) は本件では適用しない**。理由: 本 gate はクラス名という**連続した字面**を探す走査で、

  この判断を docblock に明記する。
