## 施策 4: REQUEST_CHANGES

- [Warning] 「runbook が順序の唯一の正本で、migration docblock は参照するだけ」という説明と、実際の migration docblock が一致していません。

  migration docblock には順序、逆順時の障害、rollback 手順、maintenance window まで再掲されています。これは「参照するだけ」ではありません。

  修正案は、次のどちらかに統一することです。

  1. runbook を唯一の正本にする場合  
     migration docblock は「コード先行が必須。詳細・rollback は runbook を参照」までに縮める。

  2. migration に安全上の要約を残す場合  
     「runbook が詳細手順の正本で、migration は最低限の破壊条件を要約する」と明記する。

  実務上は2が安全です。migration を単独で読んだ際にも drop-first の危険が見えるためです。

- [Warning] 旧結論確認用の grep は、現状の migration docblock 自体にも意図的にヒットします。

  「runbook 以外に順序記述がないことを確認する」という成功条件には使えません。許容ファイルと期待件数を明示するか、検索結果を人が分類する確認だと記述してください。
