## S4: REQUEST_CHANGES

[Warning] 「想定外の形では、例外に対象クラス・不正箇所・直し方を必ず含める」という実装契約と、実際の例外メッセージが一致していません。

少なくとも次の分岐には直し方がありません。

```php
throw new RuntimeException(
    "{$className}: schema の required に重複があります: {$key}"
);
```

また、以下の既存分岐も共通 `$hint` を含みません。

- パラメータ名が非空文字列でない
- パラメータ定義が配列でない

一方、テスト計画は I14 の負例について「クラス名・パラメータ名・直し方が含まれる」と宣言しています。required 重複テストはこのままでは設計どおりの assertion を通せません。

修正案:

- required 重複の例外へ `— {$hint}` を追加する。
- パラメータ名・定義の不正分岐にも同じ修正案を付ける。
- パラメータを特定できない構造異常では、「パラメータ名」ではなく `required` などの不正箇所を要求するようテスト記述を正確にする。

これは新機能ではなく、既に掲げた fail-closed のエラー契約を実装とテストで一致させる修正です。

## S6: REQUEST_CHANGES

[Warning] T4 のメッセージ検査が、上記 S4 の実装では成立しません。

修正案:

- 各負例で共通して検査するものを「対象クラス・不正箇所・直し方」とする。
- パラメータ名を特定できる負例だけ、追加でパラメータ名を検査する。
- required 重複など既にキーが判明している負例では、そのキーも検査する。

これにより、曖昧な一律 assertion を避けながら、I14 の診断可能性を固定できます。
