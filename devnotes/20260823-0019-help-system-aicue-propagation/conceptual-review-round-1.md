全体判定: **CHANGES_REQUESTED**

### 1. 使命との整合性

[Suggestion] MCP ツール参照の実装追従は、AI-CUE の撮影・シナリオ機能を直接増やすものではありませんが、外部 AI がアプリ操作を正確に理解する基盤として間接的・構造的に貢献します。家系正典への追従が主目的であることも明確で、位置付けは妥当です。

### 2. 禁止事項違反

[Suggestion] 現時点の概念設計には、禁止事項への抵触はありません。HTTP 面を増やさず、`response()->json()` も使わず、LLM 呼び出し・キャッシュ・DB 操作も導入しないため、既存の強い不変条件への影響は限定的です。

### 3. 実現可能性

[Warning] `McpToolMetadata` の「具象サブクラス走査」と、実際に `AppMcpServer` が公開しているツール集合との一致保証が設計されていません。`app/Mcp/Tools/` に具象クラスを追加しただけでサーバ登録を忘れた場合、生成文書には載るのに MCP からは呼べない、という不整合が起き得ます。

修正提案: 生成対象をサーバ登録済みツールから取得するか、少なくとも「`AppMcpTool` の具象サブクラス集合 = サーバ登録集合 = `ToolName` enum 集合」を固定する Architecture/Feature テストを追加してください。既存の enum ↔ 登録テストだけでは、ディレクトリ走査との一致を保証できません。

[Suggestion] `--check` を作業ツリー非変更で検証するには、コマンドの対象ルートをテスト用一時ディレクトリへ差し替えられる設計（設定注入または明示的な依存注入）が必要です。実装詳細設計で、プロダクションの `docs/help/` 固定とテスト隔離を両立する方法を明記するとよいです。

### 4. 期待効果の妥当性

[Warning] 「tool を足した瞬間に CI が赤くなる」という効果は、通常テストレーンが実リポジトリの `docs/help/manifest.json` と `_generated/mcp-tools.md` に対して `help:build --check` を必ず実行する場合にのみ成立します。一時ディレクトリだけで鮮度検査を完結すると、コミット済み生成物の陳腐化を CI が検知できません。

修正提案: `HelpBuildCommandTest` に、実際のリポジトリの生成物に対する `--check` を実行するテストを含めてください。破壊的な検証は一時ディレクトリで行い、CI 鮮度ゲートは読み取り専用の実ファイル検証として分離します。

### 5. リスク

[Suggestion] vendor MCP メタデータを表示文字列へ正規化し、想定外の形で停止させる方針は適切です。「静かに項目を欠落させない」という安全側の失敗になります。例外メッセージには対象 tool クラス・不正なメタデータ箇所・修復方法を含め、更新時に原因追跡できるようにしてください。

[Suggestion] ファイル・manifest を扱うため、`HelpRepository` のパス検査は symlink、`..`、絶対パス、生成物ディレクトリ外、階層化された生成物、manifest 未登録ファイルを含む負例で固定するのが適切です。

### 6. スコープの適切さ

[Suggestion] 正典の `canonical_version: v1` と AG-100 の必須条件に照らし、以下の境界は正しいです。

- `HelpRepository` / `HelpSection` / `help:build` / `docs/help/` 規約を含める
- MCP ツール一覧の自動生成を含める
- `--check` による鮮度検査を必須にする
- 表示 route、Svelte ページ、MCP ヘルプ参照 tool、本文執筆、Markdown→HTML、`VideoStepsGenerator` を含めない

特に `VideoStepsGenerator` は feature の広い boundary には現れますが、AG-100 が v1 必須として列挙した還流対象ではありません。したがって今回除外する判断は、正典に対して過小ではなく最小スコープとして妥当です。

### 7. 型安全性

[Suggestion] `HelpSection`、生成結果、MCP メタデータを不変 DTO として明示する方針は PHPStan level 10 と整合します。vendor 由来の `name()` / `description()` / `schema()` は `mixed` 境界として扱い、正規化関数で型検査・例外化してから DTO に閉じ込めてください。`mixed` を戻り値や配列形状として上流へ漏らさないことが重要です。

主な修正点は、**生成対象と実際の MCP 登録対象の一致保証**、および **実リポジトリの生成物を CI で必ず鮮度検査する構成の明文化**です。これらを設計へ追加すれば、正典 v1 に忠実な最小追従として承認可能です。
