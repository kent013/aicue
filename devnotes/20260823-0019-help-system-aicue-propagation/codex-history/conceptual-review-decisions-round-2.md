## [Warning] 走査器・gate 新設時の共通規約 4 点が検査計画に反映されていない

- 判断: **対応する**
- 根拠: 正当な指摘。`AGENTS.md` §「走査器・gate を新設・変更するときに同じ PR で揃える 4 点」を
  実読して確認した (L273-300)。発火条件は「走査ロジック・走査対象・名前解決・判定条件・目録の
  いずれかを新設または変更するとき」であり、本設計は `app/Mcp/Tools/` を走査する
  **走査ロジックの新設**なので明確に発火する。
  とりわけ Codex が名指しした「母集団が空でも 3 集合一致で緑になる」形は、
  `AGENTS.md` L254-259 が「**違反が 0 件**と**母集団が 0 件**を区別する。落とすのは後者だけである」
  として明示的に禁じている形そのものである。設計の抜けであり反論しない。
- 対応内容: 概念設計の「実装方針」に **走査器・gate の共通規約**の節を新設し、4 点を書き下した。
  1. 負例と正例 (テストファースト。負例の母集団を 6 種類まで具体化)
  2. 解決できない形を落とす分岐 (fail-closed。沈黙して空を返さない)
  3. 走査が空振りしていないことの検査 (走査根が生きている + 母集団が非空。床値と代表パスを pin)
  4. docblock に走査対象と保証しないものを書く (**正本は docblock 側**。本書へ写さない)
  あわせて検査の表へ 1 本追加した — `tests/Unit/Architecture/McpToolScannerTest.php`
  (走査器の自己検査。合成入力で正例/負例を両方向に固定)。
  `McpToolReferencePopulationTest` の責務にも「走査根が生きていること / 母集団が非空」を明記した。
  走査根が git 追跡 PHP 全数より狭いため `Tests\Support\TrackedPhpSourceFiles` は使わず
  自分の根 (`app/Mcp/Tools/` 1 本) を持つが、**存在しない根は fail-fast** で落とすことを明記した
  (`AGENTS.md`「走査根の単一出典」の但し書きに準拠)。
- 過大化していないことの確認: 追加したのは**検査 1 本と既存検査への責務追記**だけで、
  新しい機能・別の仕組みは 1 つも足していない (Codex の修正提案の指示どおり)。
