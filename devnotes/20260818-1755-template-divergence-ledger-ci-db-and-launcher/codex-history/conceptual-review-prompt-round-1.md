## アプリの使命 (North Star)

**AI-CUE** は、現場に既にある**作業手順書(SOP)を起点に**、AI が撮るべきカットを設計した**動画シナリオ**を生成し、そのシナリオを**スマホ(PWA)でナビゲーション撮影**することで、専門知識ゼロの現場作業者でも**標準化されたマニュアル動画**を作れるようにする。

- 「思考ゼロ・編集ゼロ」— 台本作成・撮影判断・編集の 3 ハードルを AI とナビ撮影で肩代わりする。
- 競合(OJT を撮って形式化する tebiki)と異なり、**標準作業を起点に AI が教材設計し撮影を指示する**（撮影者・教える人のスキルに品質を依存させない）。
- 熟練者の暗黙知を動画マニュアルという形式知へ変換する装置（SECI）。

> 詳細な設計は本リポジトリの `doc/`（01〜10）に置く。ドメインをテンプレート構造へどうマップしたかは `doc/08`〜`doc/10`（特に `doc/10 §10.8` に設計レビュー反映済み）。
> **v1 スコープ**: 字幕のみ(TTS 後回し) / 撮影は PWA(同一オリジン・セッション認証) / 動画合成は自前 ffmpeg / 単一 Default Project。

# 概念設計: テンプレート乖離台帳への 2 件の登録 (テスト DB の回収経路 / 起動ラッパ)

## 背景・課題

`docs/template-divergence.md` は「テンプレート (laravel-claude-template) の構造から
**わざと**外れた点」の正本である。登録簿自身が明記しているとおり、**登録漏れそのものは
機械で検出できない** (実体との突合は台帳リポジトリの巡回が持つ)。だから登録簿の規約節は
「登録するか迷ったら登録する」「台帳リポジトリの巡回から届いた指摘は登録する側へ倒す」と
定めている。

現在の登録は 28 件 (D1〜D29 のうち D9 は削除済みの欠番)。ここに未登録の乖離が 2 件ある。

### 未登録 1: `scripts/ci/` の 3 ファイル (テスト DB の作成と回収)

実測 (本アプリ HEAD `ae82d034` / 正典 `laravel-claude-template@93e91e36`):

| ファイル | 本アプリ | 正典 |
|---|---|---|
| `scripts/ci/drop-test-db.php` | 25878 バイト | 2508 バイト |
| `scripts/ci/ensure-test-db.php` | 2601 バイト | 8472 バイト |
| `scripts/ci/pgsql_test_conn.php` | 6446 バイト | 6193 バイト |

差の中身は **2 方向**に分かれる。

**(a) 本アプリ側の上積み** — aicue:T114 (コミット `829a78c2`、2026-08-05) で入れた孤児テスト DB の
回収経路である。

- `ensure-test-db.php` が基点 DB へ `COMMENT ON DATABASE <base> IS '<worktree の realpath>'` を
  記録する (作成時・既存時の両方 = 冪等。非破壊 DDL。付与失敗は無視する)
- `drop-test-db.php` に `--orphans` を足し、`pg_database` と `shobj_description` の **SELECT だけ**で
  `Protected → Live → Foreign → Orphan → Unlabeled` に分類して dry-run で列挙する
- `--apply` は `--confirm=<token>` 必須で、`.claude/worktrees/.setup.lock` の取得後に判定入力を
  取り直して token を再計算し、一致したときだけ DROP する
- `pgsql_test_conn.php` に `pgsqlCommentDatabaseSql()` / `pgsqlStampProvenance()` /
  `enum TestDatabaseEnsureAction` / `testDatabaseEnsurePlan()` を足した

これが要る理由は業務ではなく**この開発の進め方**にある。実装は必ず worktree で行う規約
(AGENTS.md §worktree 運用ルール) で、テスト DB 名は worktree の realpath の hash から作る。
worktree が `git worktree remove --force` で強制撤去されると **hash を再現できず**、
引数なしの `drop-test-db.php` では二度と回収できない。監査時点で孤児が 17 個 / 221.9 MB
積み上がっていた (背景は `docs/worktree-isolation-strategy.md`)。

t0 の不変条件は保っている — **DROP DDL の実行点は `drop-test-db.php` の 1 本のまま**、
dev DB の拒否 (`isDevDatabase()` / `isAllowedTestDatabase()`) は既存実装を共有、
DB 名は worktree 単位のまま。lctl の台帳もこの点を「遅れではなく上積み」と訂正済みである。

**(b) 正典側の後発の上積み (本アプリに無い)** — 正典 HEAD の `ensure-test-db.php` は
「基点 DB を存在させる」だけでなく「スキーマを最新にする」まで担う (家系の裁定 AG-135)。
`pgsql_test_conn.php` にも `pgsqlTestArtisanEnv()` / `pgsqlTestConfigCachePath()` /
`pgsqlTestDatabasePdo()` が足されている。本アプリの `ensure-test-db.php` は CREATE と
出自の記録までで、スキーマ更新を持たない。

**(b) は「わざと外した点」ではなく追従の遅れである。** 登録簿は逸脱を書く場所であって
遅れを書く場所ではない (遅れは追従して消す)。したがって本設計は (a) を登録し、
(b) は登録の本文で「この登録が扱わない範囲」として名指しし、別の作業項目へ送る。

### 未登録 2: `scripts/claude` (Claude Code の起動ラッパ)

本アプリ `18de4919` (3950 バイト) と正典 `49e03e31` (3368 バイト) は blob が一致しない。

背景を `devnotes/20260817-1230-claude-statusline-vendoring/` で確認した結果、**この乖離は
状態表示行の取り込み (aicue:T208) とは無関係**だった。T208 が足したのは
`scripts/claude-statusline` (正典と byte 一致) と `scripts/README.md` の行だけで、
`scripts/claude` には 1 文字も触れていない。

乖離を作ったのは aicue:T181 (コミット `ca512d3e`、2026-08-15) である。当時の
`scripts/claude` は拡張の探索を本文へ直書きしており、platform が完全一致する拡張が無い環境では
即 exit 1 で終わっていた。T181 は探索を `find_claude_extension()` 1 か所へまとめ、
完全一致が無ければ拾い直して警告する経路を足し、回帰テスト `scripts/claude-wrapper.test.ts`
(9 ケース) を新設した。**意図は確認できる変更である。**

そのうえで実測すると、**正典もその後に同じ目的の代替経路を別実装で持っている**。

| 観点 | 正典 (`49e03e31`) | 本アプリ (`18de4919`) |
|---|---|---|
| 探索の関数 | `find_latest_ext()` が**版の文字列**を返し、パス解決は関数の外 | `find_claude_extension()` が**採用パス**を返し、無ければ非ゼロで戻る |
| 警告を出す時点 | 拾い直しを**試す前**に無条件で出す (拡張が 1 つも無い環境でも出る) | 拾い直しが**成功したときだけ**出す |
| 警告の内容 | 期待した platform | 期待した platform と採用したパスの両方 |
| 採用後の存在検査 | `[ -z ... ] || [ ! -d ... ]` を残す | 関数が実在するディレクトリしか返さないので持たない |
| 回帰テスト | あり (6882 バイト) | あり (274 行 / 9 ケース。W2 の警告と W8 の負のコントロールを含む) |

不変条件 (2 つの置き場から最新版を採る / 完全一致が無ければ拾い直して警告する /
起動できなければ明示エラーで止める / ラッパ専用フラグを剥がして残りをそのまま透過する) は
両者で揃っており、差は同じ不変条件の実装の形である。

## 改善アイデア

`docs/template-divergence.md` へ **D30 / D31 の 2 件を追加**し、件数の 3 点一致
(明示行「登録エントリ: N 件」/ 見出しの実数 / `TemplateDivergenceLedgerFormatTest` の固定値) を
28 から 30 へ揃える。番号は削除済みの D9 を再利用せず、末尾の D29 に続けて採る。

- **D30**: `scripts/ci/drop-test-db.php` / `scripts/ci/ensure-test-db.php` /
  `scripts/ci/pgsql_test_conn.php` — 孤児テスト DB の回収経路の上積み。状態は `恒久`
- **D31**: `scripts/claude` — 起動ラッパの拡張探索と代替経路の別実装。状態は `監視中`

### なぜ D31 だけ `監視中` か

登録簿の規約は「`監視中` にするのは、期限付きで能動的に見直す根拠 (期限・予定時期・
追跡中の事象) があるときだけ」と定めている。D31 には追跡中の事象がある — **正典が後から
同じ目的の代替経路を別実装で持った**ため、「本アプリの形を保つ / 正典の形へ寄せる」の
判断が要る状態になっており、家系の feature `vscode-cli-wrappers` の本アプリのセルも
`update_pending` のままである。D30 にはそういう予定が無い (worktree で実装する規約が
続く限り回収経路は要る) ので `恒久` にする。

### D31 で「正典の内容へ戻す」を選ばない理由

戻す案 (正典 `49e03e31` を byte 一致で取り込む) も比較した。採らない理由は 3 つある。

1. **意図が確認できる変更である**。T181 の目的・実装・回帰テストが揃っており、
   「気付かないうちにずれた」類ではない。登録簿の「登録する側へ倒す」原則に素直に当てはまる
2. **振る舞いが後退する方向を含む**。正典は拾い直しを試す前に無条件で警告するので、
   拡張が 1 つも無い環境では「警告 → エラー」と 2 段で出る。本アプリの
   `scripts/claude-wrapper.test.ts` は W3 (拡張が 1 つも無ければ platform 名つきのエラーで終了) と
   W8 (完全一致では警告を 1 文字も出さない) を負のコントロールとして固定しており、
   戻すと期待の書き換えが要る
3. **収束の判断は家系の側にある**。どちらの形を正典とするかは台帳の巡回と還流提案の仕事で、
   下流が独断で寄せると「4 つ目の形」を作ったときと同種の害になる。
   本設計では登録して見える状態にし、期限を切って再判断する
