# 概念設計: forbidden-statement-token-gate (禁止する文の字句走査による検出)

## 背景・課題

家系の機能台帳 lctl に `forbidden-statement-token-gate` という feature がある。
PHP の **`echo` / `goto` / `global`** という 3 つの文と、**開始タグ付きの出力記法 `<?=`** を
ソースコード中から検出し、書かれていれば CI を落とす検査 (gate) である。

- 発生元は aigenba。2026-08-05 の裁定 AG-011 が
  「テンプレートへ還流し家系の標準装備とする」と決め、2026-08-08 に
  laravel-claude-template へ移植済み。**採否はすでに決着している**
- 本リポジトリ (aicue) には**この検査の実体が無い**。台帳の aicue セルは `pending`
  (未着手) であり、`reviewing` (採否未判断) ではない
- 台帳は移植コストを実測済みで、aicue は**例外の登録 1 件だけ**で足り、
  本体コードの書き換えは不要と見積もっている

### なぜこの 3 つ + 1 記法なのか (正典が挙げる理由)

- **`echo` / `<?=`**: 応答の組み立て経路の途中から直接出力へ書き出す。
  Laravel の応答 (Inertia / JsonResource / Response) を迂回するため、
  ヘッダ確定前の出力・JSON の破壊・`no-store` 等のヘッダ契約の破壊を招く
- **`goto`**: 任意の位置へ飛ぶ。制御フローが構造から読めなくなり、
  静的検査・レビューの前提 (関数の入口と出口) を壊す
- **`global`**: 関数の外の変数を関数内へ持ち込む。DI コンテナ経由の依存解決を迂回し、
  テストからの差し替えができない結合を作る

### 既存の検査では構造上とれない

本リポジトリの Architecture テストの多くは
「クラス / 関数の**参照**」を見る (`Tests\Support\PhpReferenceScanner` 系)。
`echo` / `goto` / `global` は**文 (statement)** であって名前参照ではないため、
参照の走査では原理的に拾えない。pest-plugin-arch の既製 preset にも名目上の
`echo` 禁止はあるが、構文木上の扱いの都合で実質的な検出力を持たないことが
発生元 aigenba の実測で分かっている (本リポジトリは `preset()->php()` を使っていない)。

### 現状の実測 (2026-08-15、HEAD で計測)

`git ls-files '*.php'` の 1567 ファイルを `token_get_all()` で走査した結果:

| 対象 | 件数 | 所在 |
|------|------|------|
| `echo` | 23 | `scripts/ci/drop-test-db.php` (361 行〜) |
| `echo` | 46 | `devnotes/` 配下の一時スクリプト 13 ファイル |
| `goto` | 0 | — |
| `global` | 0 | — |
| `<?=` | 0 | — |

`resources/views/**.blade.php` (24 ファイル) にも違反は 0 件である。
Blade でも **PHP 開始タグで開いた区間は通常の PHP として字句化される**ので、
`<?= $raw ?>` と `<?php echo …; ?>` は走査で見える (実測で確認)。
見えないのは `@php … @endphp` と `{{ }}` の中だけである。

台帳の事前見積もり (「echo 23 件が `scripts/ci/drop-test-db.php` の 1 ファイルへ集中。
他は 0 件。例外 1 件で足りる」) と**完全に一致した**。

## 改善アイデア

laravel-claude-template の実装形に揃えて、
**禁止する文を字句 (トークン) 単位で走査する gate** を新設する。

1. **走査器を `tests/Support/` へ切り出す** — 既存の字句走査器群
   (`PhpTokenScan` / `PhpReferenceScanner` / `PestTestNameScanner` …) と同じ作法。
   走査器は「何を禁止と呼ぶか」を知らず、`token_get_all()` の結果から
   禁止語彙の**出現位置**を返す純関数にする
2. **走査根を排他的に分類し、分類漏れを赤にする** — 追跡されている PHP ファイルの
   最上位ディレクトリを「走査する」「例外の登録を許す」「除外する (理由必須)」の
   3 つへ排他的に分け、どれにも当てはまらない置き場所が現れたら落ちる。
   走査根を検査ファイルにベタ書きすると、新しいディレクトリを足したときに
   黙って穴が開く (台帳が fail-open の一種として記録している事故の型)
3. **例外は 1 件だけ登録する** — `scripts/ci/drop-test-db.php` の `echo` 23 件。
   件数の完全一致・理由の必須・登録先ファイルの実在・登録したのに実測 0 件、の
   4 形で腐りを落とす
4. **負の対照で検出力を裏取りする** — わざと違反させた見本を検出できること、および
   **文でない位置に現れた同じ綴り**を違反にしないことを、走査器の自己検査で固定する。
   これは家系規約 (2026-08-08 のオーナー裁定) が gate の掲載条件としているもの。
   検体は**構文として成立する完全な PHP 断片**にする
   (半予約語をメンバ名に使えるのはクラス / 列挙の中だけなので、
    文脈を切り落とした断片は実在しない書き方になってしまう)

### 負の対照が必須である実測上の理由

PHP の字句解析器は、**文でない位置に書かれた `echo` / `goto` / `global` にも
同じトークン種別を割り当てる**。本設計のために HEAD の PHP で実測した:

| 書き方 | 割り当てられるトークン | 判定 |
|--------|----------------------|------|
| `echo "x";` | `T_ECHO` | 違反 |
| `Foo::goto()` (静的呼び出し) | `T_GOTO` | **違反ではない** |
| `function echo(): void {}` (メソッド宣言) | `T_ECHO` | **違反ではない** |
| `const echo = 1;` / `const ECHO = 1;` | `T_ECHO` | **違反ではない** |
| `case Echo = 'e';` (列挙の場合分け) | `T_ECHO` | **違反ではない** |
| `f(global: 2)` (名前つき引数) | `T_GLOBAL` | **違反ではない** |
| `#[Echo]` (属性) | `T_ECHO` | **違反ではない** |
| `$o->echo()` / `$o?->global()` | `T_STRING` | 対象外 (種別が違う) |
| コメント / 文字列リテラル中の同じ綴り | — | 対象外 (正規化で除去) |

つまり「トークン種別で照合するだけ」では**誤検出する**。
直前の有意トークンと直後の有意トークンによる読み飛ばし規則が要り、
その規則が効いていることは負の対照でしか固定できない。

## 期待効果

- **使命への貢献**: 撮影 PWA (iOS Safari) は応答ヘッダの契約に強く依存する
  (`no-store` baseline / bfcache 秘匿 / Inertia 履歴暗号化 — ドメイン規約 3)。
  応答の組み立て途中で直接出力へ書き出す文が 1 つ混ざると、
  ヘッダ確定前に本文が流れてこの 3 枚セットが崩れる。
  その侵入経路を機械で閉じる
- 家系の標準装備を 1 つ揃える (台帳の aicue セルが `pending` → `implemented`)
- 現在 0 件の語彙 (`goto` / `global` / `<?=`) を**0 件のまま固定する**
  = 新規混入をレビュー任せにしない
- 走査根の分類漏れが赤くなるので、新しいディレクトリを足したときに
  「その置き場所は検査の対象か」を必ず 1 度考えることになる

## 実装方針 (概要)

| # | 施策 | 新規/変更 |
|---|------|----------|
| 1 | 禁止語彙の列挙 (`ForbiddenStatementKind` enum) + 出現位置の値 (`ForbiddenStatementSite` readonly class) | 新規 |
| 2 | 字句走査器 (`ForbiddenStatementScanner`) | 新規 |
| 3 | 走査根の分類 (`ForbiddenStatementScanRoot` enum) | 新規 |
| 4 | 例外の目録 (`ForbiddenStatementExemption` enum + inventory) | 新規 |
| 5 | gate 本体 (`tests/Architecture/ForbiddenStatementTokenInvariantTest.php`) | 新規 |
| 6 | 走査器の自己検査 (`tests/Unit/Architecture/ForbiddenStatementScannerTest.php`) | 新規 |
| 7 | AGENTS.md への規約の追記 | 変更 |

gate 本体のファイル名は**テンプレートの実装と同じ名前**にする。
将来テンプレートの取り込みでテンプレート版が入ってきたときに、
黙って 2 本並走するのではなく**同じパスで衝突して人の目に触れる**ようにするためである
(思考原則 3「後方互換の並走を残さない」)。

**app/ resources/ routes/ database/ config/ の本体コードは 1 行も変えない**
(実測で違反が 0 件のため)。

### 走査根の分類 (aicue の実情に合わせる)

追跡されている PHP ファイルは、**実ディレクトリ 11 個**と
**リポジトリ直下 (ディレクトリを持たないファイル。現在 0 件)** に分かれる。
後者はディレクトリではないので疑似 root として 1 件に数え、**分類は計 12 件**になる。

- **走査する / 例外の登録を許さない (9)**: リポジトリ直下 (疑似 root) /
  `app` / `bootstrap` / `config` / `database` / `lang` / `public` / `resources` / `routes`
- **走査する / 例外の登録を許す (2)**: `scripts` / `tests`
  (別プロセスで走る CLI と検体は、標準出力が唯一の伝達手段になりうる)
- **除外する (理由必須) (1)**:
  - `devnotes` — 設計時の一時スクリプトの置き場所であり、
    アプリの実行経路に載らない (AGENTS.md「一時スクリプトは devnotes へ」)

正典 (テンプレート) の 10 root との差は次の 3 点である:

- `deploy` は本リポジトリに存在しない (デプロイ定義を持たない。AGENTS.md 参照)
- `resources` を**加える**。正典は root を 10 個列挙するだけで `resources` を含まないが、
  Blade でも PHP 開始タグ区間は普通に字句化されるため、除外すると
  `<?=` 禁止に穴が残る (実測に基づく判断)
- 正典は root を列挙するだけだが、本設計は**分類漏れを赤にする**ところまで持つ

これは正典と**同じ不変条件を、同じ抽象度で、より広い範囲に**適用するものであり、
不変条件そのものを緩めていない。したがって
`docs/template-divergence.md` の判定軸 (「同じ不変条件を同じタイミング / 抽象度で
保証するか」) では逸脱に当たらず、差分レジストリへの登録は不要と判断する。

### 例外の登録 (1 件)

```
scripts/ci/drop-test-db.php — echo 23 件
理由: worktree のテスト DB を回収する CLI スクリプト。artisan を通さない素の PHP として
      実行され (php scripts/ci/drop-test-db.php)、Laravel の Console 出力機構を持たない。
      既定 dry-run の分類結果を人間へ提示することがこのスクリプトの機能そのものであり、
      応答の組み立て経路には載らない。
```

## 制約・前提

- 本リポジトリは構文解析ライブラリ (nikic/php-parser) を持たない。
  裁定 AG-154 の (2) が「構文解析ライブラリの依存追加は求めない。
  正典の必須要素にはしない」と定めており、**字句ベースで実装してよい**
- 既存の字句走査基盤 `Tests\Support\PhpTokenScan::normalize()`
  (空白 / コメント / DocComment を除去した添字連番のリスト) をそのまま使う。
  同じ正規化を 2 本持たない
- 走査器の自己検査は `tests/Unit/Architecture/` に置く
  (既存 7 本と同じ置き場所・同じ作法。負例は見本ファイルではなくテスト内の文字列)
- 禁止語彙は正典 v1 の 3 つ + テンプレートの唯一の拡張 `<?=` の**計 4 つに限る**。
  `print` は正典が明示的に対象外としており、
  「禁止語彙の拡張は台帳の議題として起こす」決まりになっている

## スコープ外

- **`print` の禁止**。正典が対象外と明記している。足すなら台帳の議題が先
- **`printf` / `var_dump` / `fwrite(STDOUT, …)` の禁止**。名前の解決が要るので
  字句の走査では届かない。この検査は**完全性を主張しない**
- **Blade の `@php … @endphp` ブロックと `{{ }}` の中の検査**。これらは
  `token_get_all()` からは地の文 (`T_INLINE_HTML`) に見えるため届かない
  (PHP 開始タグで開いた区間は見える。上の実測表を参照)
- **走査根の定義を他の gate と共有する共通ヘルパの新設**。
  現時点で利用者が 1 本しかない (思考原則 2)。2 本目が現れた時点で
  単一の出典へ寄せる (設計書に申し送りとして残す)
- **既存の `scripts/ci/drop-test-db.php` の書き換え**。
  標準出力への提示がこのスクリプトの機能であり、直す対象ではない
- 台帳への書き戻し (`append_event`)。監督セッションの責務
