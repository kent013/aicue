## S2: REQUEST_CHANGES

[Warning] 複数属性の2件目以降を誤検出します。

R5 が救うのは、対象語彙が `T_ATTRIBUTE` の直後にある場合だけです。次の有効な属性構文では、`Echo` の直前が `,` になるため、現在の実装では `echo 文` として報告される可能性があります。

```php
#[Other, Echo]
class Foo {}
```

同様に、属性グループ内の名前位置は先頭要素だけとは限りません。「禁止する文」は属性の引数式内には構文上置けないため、属性グループを適切に追跡すれば取りこぼしにはなりません。

修正案: `T_ATTRIBUTE` から対応する `]` までを属性コンテキストとして追跡し、その中の対象トークンを名前位置として扱ってください。属性引数中の配列にも `]` が現れるため、単純に最初の `]` で閉じず、角括弧の深さを管理する必要があります。

状態追加を避ける場合は、最低限「属性コンテキスト内で、直前が `,`、直後が `(` / `]` / `,` の名前位置」のように限定できますが、属性引数のネストを考えると深さ管理の方が説明可能です。

[Suggestion] R3b の状態名は `inConstDeclaration` で妥当ですが、`T_CONST` はクラス定数以外にグローバル定数宣言や `use const` にも現れます。現在の条件では誤検出・取りこぼしには直結しませんが、説明を「クラス定数宣言」ではなく「`T_CONST` から始まる定数宣言区間」にすると実装と一致します。

## S3: REQUEST_CHANGES

[Warning] 複数属性の負の対照が不足しています。

次を追加し、0件になることを固定してください。

```php
<?php #[Other, Echo] class Foo {}
```

属性コンテキストを深さ管理する場合は、ネストした配列によって早く閉じないことも必要です。

```php
<?php #[Other(values: [1, 2]), Echo] class Foo {}
```

[Warning] N15 の「N1〜N14を1つに連結」は、そのままでは全検体が有効なPHPであるという契約を満たせません。

各断片には `<?php` があり、N12/N13 は同名の `trait T` と `class A` を宣言しています。単純連結では構文・宣言の衝突が生じます。

修正案: 次のいずれかを設計に明記してください。

- N15 専用に、開始タグを1つにし、宣言名をすべて一意にした統合検体を作る
- N15 を削除する。N1〜N14が個別に0件を固定するため、検出力上の重複は小さい

[Suggestion] 「`php -l` を25回起動する」という記述は、テスト総数30本への更新後に古くなっています。変動を避けるため「各検体について起動する」に変更してください。
