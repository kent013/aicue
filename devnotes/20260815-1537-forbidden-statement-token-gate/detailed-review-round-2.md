## S2: REQUEST_CHANGES

[Warning] 「複数定数宣言は実在しない」という前提が誤っています。

PHP は次の複数定数宣言をサポートします。

```php
class A
{
    const echo = 1, goto = 2;
}
```

先頭の `echo` を許容する以上、2つ目以降の半予約語も「文」ではなくメンバ名です。現在の設計では `goto` を違反として誤検出し、設計名称である「禁止する文」の責務を超えてしまいます。

修正案: `T_CONST` 直後だけを見るのではなく、クラス定数宣言の `T_CONST` から終端 `;` までを最小限の状態として追跡し、トップレベルの `,` の直後にある対象語彙も名前位置として扱ってください。少なくとも上記構文を S3 の負の対照へ追加してください。

[Warning] トレイト別名指定の説明と実装が一致していません。

`T_DOUBLE_COLON` が扱うのは主にトレイトメソッド参照です。別名そのものは次のように `T_AS` の後へ現れます。

```php
class A
{
    use T {
        method as echo;
    }
}
```

現在の R1 では別名 `echo` を救えません。

修正案: PHP 8.4 でこの構文が成立し、対象語が `T_ECHO` 等になることを確認したうえで、`T_AS` と必要なら可視性修飾子を含む別名位置を限定的に判定してください。成立する場合は負の対照を追加し、R1 の「トレイトの別名指定」という説明を正確に分離してください。

## S3: REQUEST_CHANGES

## S5: REQUEST_CHANGES

[Warning] `counts` のキーと値に対する inventory 自体の妥当性検査が明記されていません。

現在の型は `array<string, int>` なので、未知の語彙キーや `0`、負数をPHPStanでは防げません。deny-by-default の目録としては、登録内容そのものを検査する必要があります。

修正案:

- `counts` の全キーが `ForbiddenStatementKind::cases()` の `value` に含まれる
- 登録件数は正整数である
- `counts` は空でない

以上を G8 に含めるか、独立した gate として追加してください。
