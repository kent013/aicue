# 対応マトリクス: design-review Round 2

## [Warning] S2 — 複数定数宣言は実在する (前提が誤り)

- 判断: **対応する** (指摘のとおり、前回の記述が誤りだった)
- 根拠: `class A { const echo = 1, goto = 2, global = 3; }` を実測した。
  `php -l` は **OK** を返し、2 つ目以降のトークンは
  `T_GOTO prev=',' next='='` / `T_GLOBAL prev=',' next='='` になる。
  「実在しない書き方」という前回の記述は誤りである。
  誤検出は「禁止する文」という名前の責務を超える、という指摘も正しい。
- 対応内容: 規則 R3b を足す。**`T_CONST` から `;` までの区間**を真偽値 1 つで覚え、
  その区間の中で「直前が `,` かつ直後が `=`」の綴りを名前位置とする。
  - 取りこぼしを作らない理由: PHP の定数式には文を書けない。
  - 広がりすぎない理由: 配列リテラルの読点 (`const X = [1, 2], Y = 3;`) は
    直後が `=` にならないため一致しない (実測で 0 件を確認)。
  - 負の対照 N11 (複数定数宣言) と N14 (配列リテラルの読点) を追加する。

## [Warning] S2 — トレイト取り込みの別名指定が救えていない

- 判断: **対応する** (実測で構文の成立を確認した)
- 根拠: 実測結果。
  - `class A { use T { m as echo; } }` → `php -l` **OK**、`T_ECHO prev=T_AS next=';'`
  - `class A { use T { m as protected global; } }` → `php -l` **OK**、
    `T_GLOBAL prev=T_PROTECTED next=';'`
  すなわち別名側は R1 (`::`) では救えない。指摘のとおり。
- 対応内容: 規則 R7 を足す (直前が `T_AS` / `T_PUBLIC` / `T_PROTECTED` / `T_PRIVATE` で、
  かつ**直後が `;`**)。直後を `;` に限ることで、修飾子の直後に文が立つ余地を消す。
  可視性修飾子がこの位置に現れるのはトレイト取り込みの別名指定だけである
  (通常の宣言では間に `function` が入り R2 になる)。
  R1 の説明も「トレイトの別名指定」から「トレイト取り込みの**元メソッド指定** (`T::echo as x;`)」へ
  正確に書き直す。負の対照 N12 / N13 を追加する。

## [Warning] S5 — 目録の登録内容そのものの検査が無い

- 判断: **対応する**
- 根拠: 妥当。`counts` の型は `array<string, int>` なので、綴り間違いのキーや
  `0` / 負数を PHPStan は止められない。未知のキーは G1 が落とすが、
  失敗の理由が「登録したのに効いていない」形になり読み解きにくい。
- 対応内容: G12 を足す。`counts` が空でないこと / 全キーが
  `ForbiddenStatementKind::cases()` の値に含まれること / 全ての値が 1 以上であること。

## [Warning] S6 — AGENTS.md の「23 件」は G7/G8/G10 では固定されない

- 判断: **対応する** (指摘のとおり。前回の記述は誤り)
- 根拠: G10 が固定するのは**例外ファイルの登録件数 (1 本)** であって語彙別の件数ではない。
  `echo` が 23 → 24 になり目録も更新されれば、G7/G8/G10 はすべて緑のまま
  AGENTS.md の「23 件」だけが古くなる。
- 対応内容: 指摘の 2 案のうち**前者 (文書から数値を消す)** を採る (思考原則 2)。
  AGENTS.md には**変動する数値を 1 つも書かない**
  (例外の件数・語彙別の件数・走査ファイル数はすべて目録と gate が正本)。
  書くのは変動しないもの — 禁止する 4 語彙 / 置き場所の 3 分類 /
  例外を登録できる置き場所 / 保証しない範囲 — だけにする。
  これで「文書だけが古くなる」経路を構造的に消せるので、同期テストは要らない。
