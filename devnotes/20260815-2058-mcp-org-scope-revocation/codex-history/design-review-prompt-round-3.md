### [Warning] 施策 5 の検査 E → **トークン単位の意味的位置の検査へ作り直した**

出現回数による判定をやめた。既存の共有基盤 `Tests\Support\PhpTokenScan::normalize()`
(空白とコメントを除いた `token_get_all()` の正規化。`QueuedJobLeaseInventoryTest` と
`ExternalClientBoundaryScanner` が既に使っている) を使い、窓口の `revoke()` の本文について
次の**両方**を確認する形にした:

1. トークン上で変数 `$reason` の参照が**ちょうど 1 回**である
   (コメント・文字列リテラルは正規化で除外されるので、説明文に `$reason` と書いても落ちない)
2. その 1 回が `'reason' => $reason->value` という**監査 metadata の値の位置**に現れる
   (直前が `T_DOUBLE_ARROW`、直後が `T_OBJECT_OPERATOR` + `value`、
    さらにその前が文字列リテラル `'reason'` というトークン列で照合する)

負例 (検出器が働いていることの証明) は 4 形にした:

- `$this->applyRevocationPolicy($reason);` だけがある (回数は 1 だが位置が違う) → **赤になること**
- 説明のコメントに `$reason` があり、metadata にも正規の参照がある → **緑になること**
- metadata には固定文字列を入れ、別の用途で `$reason` を 1 回だけ使う → **赤になること**
- `match ($reason)` で分岐している → **赤になること**
