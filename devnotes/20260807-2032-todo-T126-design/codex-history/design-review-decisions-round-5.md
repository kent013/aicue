# 対応マトリクス: design-review Round 5

## [Critical] 施策 5: R1 の `use` 宣言は常に FileScope になり、`NamedClass` 帰属要求と両立しない

- 判断: **対応する**（提案された「R1 を名前解決情報として扱い R2〜R5 と帰属規則を分ける」を採用）
- 根拠: 指摘が完全に正しい。PHP の `use` はクラス本体の外に書かれるため、
  R1 を実行 site として `NamedClass` 帰属を要求すると、
  正規の `use Aws\S3\S3Client;` を持つ**すべてのファイルが違反**になる。
- 対応内容:
  1. **R1 は「site」ではなく「名前解決情報」**であることを scanner 仕様に明記し、
     **alias マップの構築にのみ使い、それ自体では母集団へ登録しない**と定めた
     （regex 表の R1 行にも `alias マップ構築専用。母集団に登録しない` を併記）。
  2. 帰属規則の表を 3 段に分けた:
     - R1: 帰属を問わない（`FileScope` が正常）。違反条件なし（未使用 import は dead import）
     - R2〜R5: `app/` の `NamedClass` 帰属を要求（`AnonymousClass` / `FileScope` は違反）
     - R6: scope を問わず `相対パス × シンボル × site 件数`
  3. **1 ファイルに複数の名前付きクラスがある場合**の扱いを明示した。
     Codex の 2 案のうち「**import 自体では母集団へ登録せず、R2〜R5 の site が置かれた
     scope のクラスへ帰属させる**」を採った。もう一方の案（`app/` ファイルに
     名前付きクラスちょうど 1 件を要求して fail-loud）は、
     既存コードの構成に制約を課す副作用が本タスクの目的と無関係であり、
     AGENTS.md 思考原則 2（今必要なものだけ作る）に反するため採らない。
  4. 走査精度テストの旧仕様の残骸を修正した
     （`null 帰属` → `AnonymousClass 帰属`）。併せて 2 本追加した:
     - `use Aws\… だけがあり参照 site が無いファイルは母集団に入らない`（R1 が site でないことの固定）
     - `1 ファイルに複数の名前付きクラスがあるとき、site は実際の scope のクラスへ帰属する`
