# 全体判定: CHANGES_REQUESTED

Critical はありません。Round 2 の主要問題は解消されていますが、A-2・B-1・C に残る境界条件を明文化する必要があります。

## 1. 使命との整合性

[Suggestion] C を主施策とする位置づけは妥当です。A/B も操作結果の一貫性を守る補助施策として適切です。

## 2. 禁止事項違反

[Warning] B-1 が fail しただけで B-2 を適用すると、「失敗を確認してから実装」ではあっても、H-a の検証にはなりません。テスト実装・待機条件・4秒経過が原因でも fail します。

修正提案: B-2 の適用条件を「fail」ではなく、次の確認まで含めてください。

- リダイレクト完了から assertion 開始まで4秒未満
- flash がレスポンスに存在する
- 着地ページが mount された
- それでも toast が一度も可視にならない

## 3. 実現可能性

[Warning] A-2 の「component 初期化時に clear」「`$effect` で consume」は概念上妥当ですが、実装方法によっては SSR 時にも module singleton を変更します。

修正提案: 詳細設計で、clear がブラウザ側の mount ごとに一度だけ実行され、SSRでは実行されないことを明記してください。テストでは初回 mount、再レンダー、partial reloadを区別します。

[Suggestion] clear → consume の順序は、着地時の境界としては成立します。A-2 のテスト責務も十分具体的です。

## 4. 期待効果の妥当性

[Warning] 判定表の「fail → H-a を支持」はまだ射程が広すぎます。fail はH-aと整合するだけで、H-a固有の証拠ではありません。

修正提案:

| 結果 | 言えること |
|---|---|
| 制御された4秒未満の条件で一度も表示されない | H-aを支持 |
| その他のfail | 原因判定不能 |
| pass | 自動テスト条件では未再現 |

「その他のfail」ではB-2を適用せず、テスト条件を調査してください。

## 5. リスク

[Warning] A-2 は別タブでログアウトした瞬間に、他タブの既表示 toast を消去しません。toast store はタブごとのJavaScript実行環境にあり、他タブのGuest/AuthLayoutもまだ初期化されないためです。

ただし、他タブが次に遷移して未認証layoutへ着地した時点ではA-2が機能します。現行の`onDestroy(clearToasts)`も即時の別タブ無効化は提供しないため、本変更による後退ではありません。

修正提案: 保証範囲を次のように限定してください。

> 認証失効後、次のサーバ遷移で未認証layoutへ着地した際に、認証文脈のtoastを持ち越さない。別タブの既表示UIを即時消去することは保証しない。

即時同期が必要ならBroadcastChannel等が必要ですが、本TODOではスコープ外で妥当です。

[Warning] C はsecretをconfirm成功時にしか破棄しません。キャンセル、モーダルを閉じる、enable再試行、別画面への遷移など、confirming状態から離れる全経路が定義されていません。

修正提案: `qrSvg`、`secretKey`、各取得エラーを以下で一括リセットしてください。

- enrollment開始前
- enrollmentのキャンセル・画面閉鎖
- confirm成功
- component破棄

また、両方の取得に失敗した場合は「続行可能」とせず、再試行可能なenrollment取得失敗として表示する契約が必要です。

## 6. スコープの適切さ

[Suggestion] A-1/A-2を不可分にし、B-2を条件付きにした分割は適切です。別タブ即時同期を追加しない判断も妥当です。

## 7. 型安全性

[Warning] `unknown` からのnarrowing方針は適切ですが、レスポンス全体を最初から`TwoFactor*Response`として受けると、検証前に型成立を仮定してしまいます。

修正提案: `fetchJson<unknown>`で受け、専用のtype guardまたは局所的な絞り込み後に型付き値へ代入してください。HTTP成功・不正shape・通信失敗は、同じ表示経路でも内部では識別できる形が望ましいです。

以上を反映すれば承認可能です。特に重要なのは、A-2の保証を「未認証layoutへの着地時」に限定すること、B-1の通常failと制御済み再現を分けること、Cの全終了経路でsecretを破棄することです。
