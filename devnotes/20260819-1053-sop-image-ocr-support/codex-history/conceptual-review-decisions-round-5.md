# 対応マトリクス: conceptual-review Round 5 (最終ラウンド)

Round 5 はスキル規定の上限 (最大 5 ラウンド) に達したラウンドである。以下の対応を
反映した版で概念設計を確定し、Phase 2 (詳細設計) へ進む。Round 5 の指摘はいずれも
「設計の方向性を覆すもの」ではなく「表現の精度・保証範囲の誇張」に関するものであり、
対応内容は本ファイルと概念設計本文に記録した。

## [Critical] 評価指標 (a)(b) が解析ジョブ単位で一意に定義されていない
- 判断: 対応する
- 根拠: 指摘のとおり。`llm_call_logs` は呼び出し単位であり、再試行で同一ジョブが
  複数行になりうる。(a)(b) を呼び出し単位のまま集計すると、テキスト経路との比較・
  再試行の扱い・LLM 呼び出し前失敗の扱いが一意にならない。
- 対応内容: (a)(b)(c) すべてを解析ジョブ 1 件単位に統一した。
  (a) は「各ジョブの OCR extract 呼び出し群 (初回 + 再試行) の入力 token 合計」の
  中央値と定義し、テキスト経路も同じ単位で比較する。
  (b) の分母を「受理判定を通り `startJob` された解析ジョブ」に固定し、
  provider 非対応・上限超過で `startJob` 前に弾かれたものは分母に含めないことを明記した。

## [Warning] `fromValidated()` の「検証済みだけを生成できる」という表現が強すぎる
- 判断: 対応する
- 対応内容: 「コンストラクタが private であること」自体が保証するのは
  「窓口の外から new できない」ことだけであり、「渡された引数が実際に検証済みか」は
  型・可視性だけでは表せないと明記した。保証は「生成経路をバリデーションサービス 1 つに
  限定し、呼び出し箇所を deny-by-default gate で走査・pin する」という運用と検査の
  組合せであると言い換えた。

## [Warning] PHPStan が union 拡張時に必ず該当箇所を落とすという主張が断定的すぎる
- 判断: 対応する
- 対応内容: 「PHPStan が必ず落とす」という断定を外し、(1) 実際に第 3 の DTO 型を足す
  fixture で pin している PHPStan バージョンが型エラーを出すことを確認したうえで
  主張する、(2) それとは独立に `default` の代わりに到達不能を明示する例外を
  実行時の保険として置く、の 2 重の保証にした。

## [Warning] vendor mapper への契約テストが Prism/Anthropic の内部構造に強く結合する
- 判断: 対応する
- 対応内容: Prism/Anthropic のバージョンを明示的に pin し、「アプリ側の責務
  (DTO → UserMessage の変換)」を検証する層と「vendor の MessageMap を実際に通す」層を
  テストとして分離することを明記した。

## [Warning] 再評価・再承認が運用条件だけでコード上変更を止められない
- 判断: 対応する
- 対応内容: 再評価対象 (provider/model pin・媒体 YAML・防御指示・vendor 媒体変換の
  契約テスト) を列挙するテストを置き、これらが変更された PR でレビューチェックリストを
  必ず通す運用にすることを明記した。このテストは変更の検知だけを担い、
  実モデルの再評価そのものは自動化しないことも明記した。

## [Warning] アップロード画面の案内文言が画像・PDF だけが送信されるように読める
- 判断: 対応する
- 対応内容: 「アップロードした手順書は AI 解析のため外部 LLM provider に送信される」
  という媒体共通の事実と、「画像・PDF は写真や紙面がそのまま送られるため
  個人情報・機密情報に特に注意」という画像特有の注意を分けて書く形に改めた。

## [Warning] 共通 interface のメンバーが将来 bytes()/MIME まで広がる余地
- 判断: 対応する
- 対応内容: 共通 interface に許すメンバーを列挙して固定し、バイト列や vendor 変換に
  関わるメンバーは interface に置かないことを明記した。union を interface に
  置き換える変更を静的検査の対象に含めることも明記した。

## [Warning] 「現在成功している解析の挙動は 1 件も変わらない」が事実と異なる
- 判断: 対応する
- 対応内容: 「既存のテキスト品質ゲートを通過する PDF / Excel / テキストの経路は
  変えない」に限定し、品質ゲートに失敗していた PDF・新規受理する画像には
  新たに外部 LLM 呼び出しが発生する (意図した挙動変化であり退行ではない) ことを
  明記した。期待効果節・実装方針節の両方を同じ表現に揃えた。
