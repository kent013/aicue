# Round 2: 概念設計の改訂版

Round 1 の指摘への対応マトリクスは
`devnotes/20260815-2057-retention-table-classification/codex-history/conceptual-review-decisions-round-1.md`
に記録した。以下は要点と改訂後の該当箇所である。再レビューを願う。

## 対応の要点

| 指摘 | 判断 | 対応 |
|---|---|---|
| [Critical] 保証していないのに保証しているように読める | 対応 | 「保証するもの 4 つ / 保証しないもの 6 つ」を概念設計に明記。区分名も保証範囲に合わせて改名 |
| [Warning] 基盤表を業務の保持期限と混ぜると意味が薄まる | 対応 | 区分を 5 → 6 に。「基準データ」と「基盤が寿命を持つ」を分離 (除外一覧は作らない) |
| [Warning] 「親と一緒に消える」が FK 1 本では不十分 | 対応 | `on delete cascade` の FK を 1 本以上必須。cascade でないなら削除責務クラスの宣言必須 |
| [Warning] FK 不在を「個人情報を持たない」の裏取りにするのは弱い | 対応 | 区分名から個人情報の含意を削除。主張を「期限が要る表を親に持つなら期限の連鎖の中にある」に限定 |
| [Suggestion] 列名ヒューリスティックを足す | **見送る** | 当て推量は偽陽性・偽陰性の両方を生み、外れた分を黙らせる例外の口が目録に増える。本リポジトリは目録に例外の口を作ることを一貫して避けており、当たらない検査のためにその方針を曲げない |
| [Warning] 期限の保持者が自由文字列だと二重管理 | 対応 | 解決点クラスは `class_exists()`、artisan コマンド名は登録済みコマンド一覧への実在を検査 |
| [Suggestion] holder を enum / value object へ | **見送る** | 実在検査で腐りは検出できる。対象 5〜6 件のために型を増やすのは「今必要なものだけ作る」に反する |
| [Warning] 構造検査を増やすこと自体を目的にしない | 対応 | 「区分ごとに 1 つ」の書き方をやめた。FK を見る検査は 2 本だけで、うち 1 本が 2 区分を兼ねる |
| [Warning] 検証コマンドの明記 | 対応 | `composer test` / `composer phpstan` / `vendor/bin/pint --test` を制約節に明記 |

## 改訂後の区分 (6 種)

| 区分 | 意味 | 機械の裏取り |
|---|---|---|
| 課金取引の記録 | 7 年保持。期限と実処理の正本は `BillingRetentionTarget` | この区分の表集合が `BillingRetentionTarget` のテーブル集合と**両方向で一致** |
| 定期実行が消す | 掃除のバッチが期限を執行する | 期限の**保持者**の宣言が必須。解決点クラスは `class_exists()`、artisan コマンド名は登録済みコマンド一覧への実在を検査する |
| 親と一緒に消える | 独自の期限を持たず、親行の削除に連動する | 実スキーマの外部キーのうち **`on delete cascade` のものを 1 本以上持つ**。cascade でない場合は削除責務を持つクラスの宣言が必須 |
| 基準データ | 期限を持たない。運用者が入れ替えるまで残る (プラン / 権限 / 分類) | **期限が要る区分の表への外部キーを 1 本も持たない** |
| 基盤が寿命を持つ | フレームワーク・キュー・セッションの実装が寿命を決める表 | 同上 (基準データと同じ 1 本の検査が担う) |
| 未確定 | 保持期限をまだ決めていない | 件数と表名を現在値ちょうどで pin |

全区分に共通して 30 文字以上の根拠を必須にする。

「基準データ」「基盤が寿命を持つ」に課す FK 検査が言えるのは
**「期限が要る表を親に持つなら、その表自身も期限の連鎖の中にある」**までであり、
**「個人情報を持たない」の証明ではない** (外部キーが無くてもメールアドレス・token・IP は
単独で個人や端末に紐づきうる)。区分名から個人情報の含意を外したのはこのためである。

## 改訂後の「保証するもの / 保証しないもの」

保証するもの (4 つ):

1. 実スキーマの表一覧と台帳が両方向で集合等価であること (表を足せば分類が要る)
2. 課金 7 年の表集合が `BillingRetentionTarget` と一致していること (片方だけ増減したら赤)
3. 期限が未確定の表が無音で増えないこと (件数と表名を現在値ちょうどで pin)
4. 宣言された期限の保持者 (クラス / コマンド) が実在すること

保証しないもの:

- 列の内容が個人情報かどうかは見ない (単位は表であり、列は見ない)
- 実データが実際に消えることは保証しない (各掃除バッチの behavioral テストの担当)
- `on delete cascade` があることは「親が実際に消される」ことを意味しない (親を消す経路の存在は見ていない)
- 区分の意味が正しいかは人間のレビュー対象である (機械が見るのは構造だけ)
- S3 上の実体 (レンダ出力・撮影テイク) の保持期限は対象外 (単位が表ではない)
- ビュー・マテリアライズドビュー・他スキーマの表は対象外 (現在のスキーマの表だけを読む)
