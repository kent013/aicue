# 対応マトリクス: impl-review Round 1

## [Warning] RC-8 の保証範囲の記述が「区分ごとの件数も pin する」と読める (詳細設計 検査一覧の行)

- 判断: 対応する
- 根拠: 指摘のとおり詳細設計の中で食い違っていた。検査一覧の行は初稿の名残で、
  同じ設計書の後半 (RC-8 の本文) が「区分ごとの件数は pin しない」と明記している。
  実装と gate の docblock と `docs/architecture.md` は既に「総件数と未確定の表名」に
  揃っており、**設計書だけが強い保証を主張していた** = 誇張の残骸である。
- 対応内容:
  - `detailed-design.md` の検査一覧の RC-8 行を
    「総件数と**未確定の表名一覧**を現在値ちょうどで pin (**区分ごとの件数は pin しない**)」へ修正。
  - 同設計書の gate docblock 案の RC-8 の行も、実装の docblock と同じ文言へ揃えた。

## [Suggestion] RC-6 の正の自己検証が弱い (宣言だけを数えており、実スキーマの cascade を見ていない)

- 判断: 対応する
- 根拠: 指摘のとおり、旧実装は「DeletedWithParent かつ ownerClass が null の宣言が 1 件以上ある」
  ことしか見ていなかった。これでは **cascade を 1 本も持たない台帳**でも緑になり、
  「(a) の経路が実際に評価された」ことの裏取りになっていない (RC-6 本体は違反 0 件を見るだけなので、
  母集団が空でも緑になる)。空振り検知としては実スキーマ側を見る必要がある。
- 対応内容: 正の自己検証を `retentionForeignKeyMap()` の実測と突き合わせ、
  **実スキーマで cascade を持つ表が 1 件以上ある**ことを確かめる形へ変更した。
