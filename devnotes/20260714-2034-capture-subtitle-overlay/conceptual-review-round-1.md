全体判定: **CHANGES_REQUESTED**

**1. 使命との整合性**
- [Critical] 「焼込との一貫性」を価値の中心に置いている一方で、一致条件が「上部中央 / 下部中央」までしか定義されていません。字幕の折返し、最大幅、上下マージン、安全領域が未定義だと、撮影者は最終焼込と違う形の字幕を見ながら構図判断することになり、North Star の「思考ゼロ・編集ゼロ」に直結しません。  
  修正提案: overlay を「位置」だけでなく「レイアウト契約」まで定義してください。少なくとも `max-width` 相当の DS 指定、中央揃え、複数行時の扱い、上下 inset、安全領域、primary/secondary の行間を明文化し、ASS 側と許容差を持たせるならその差も明記するべきです。
- [Suggestion] 仮説は良いです。成功判定に UI の green だけでなく、「撮影者が字幕占有領域を事前認識できること」という受け入れ条件を 1 つ足すと、使命との接続がさらに明確になります。

**2. 禁止事項違反**
- [Warning] 現時点で明確な禁止事項違反は見当たりませんが、「字幕が空ならトグルを見せない / 無効化する」方向に実装が流れる余地があります。これは禁止事項 8 と衝突しやすいです。  
  修正提案: 設計に「字幕データが空でもトグルは disabled にしない。押下時は何も出ないだけ、または説明を出す」と明記してください。
- [Suggestion] プロジェクト原則に合わせ、実装順を「まず failing vitest を追加してから実装」と書いておくと運用に乗りやすいです。

**3. 実現可能性**
- [Warning] Laravel / Inertia 側の変更不要という前提は妥当ですが、frontend 実装の成立条件として DS token 名と Lucide アイコン名の存在確認が設計に入っていません。ここが外れると設計どおりに実装できず、別案検討が発生します。  
  修正提案: `bg-text/70`、`text-surface`、typography ramp、`Captions` / `CaptionsOff` が現行デザインシステムと依存バージョンで利用可能であることを事前確認項目に加えてください。無い場合の代替 token / icon も 1 つ決めておくべきです。
- [Suggestion] frontend-only で閉じる点、MediaRecorder に混入しない点は技術的に自然で、Svelte 5 でも十分実現可能です。

**4. 期待効果の妥当性**
- [Warning] 「再撮影の手戻りが減る」は合理的ですが、現段階では因果を強く言い切りすぎです。設計としては「期待される効果」で留める方が適切です。  
  修正提案: 効果表現を「字幕とかぶらない構図判断を支援する」に下げ、後続で測るなら再撮影率や QA 指摘件数などの観測指標を別途置いてください。
- [Suggestion] 「v1 の中核価値が字幕である」という根拠づけは強く、方向性自体は妥当です。

**5. リスク**
- [Critical] 長文字幕・空白だけの字幕・小画面端末・横持ち時の safe area が未定義です。これが抜けたまま実装すると、空の黒帯だけが出る、字幕が被写体を大きく隠す、ホームインジケータに重なる、という後退が起こりえます。  
  修正提案: `trim` 基準で空判定すること、複数行折返しと最大行数、safe-area 対応 inset、長い日本語字幕での表示テストを設計に追加してください。
- [Warning] アイコンボタン設計に `aria-pressed` はありますが、icon-only 操作としての `aria-label` が書かれていません。アクセシビリティ後退の恐れがあります。  
  修正提案: `aria-label="字幕を表示"` / `aria-label="字幕を非表示"` のように状態連動ラベルを必須要件にしてください。

**6. スコープの適切さ**
- [Warning] `doc/05 §5.2` を「satisfy する」と書くのは広すぎます。同節の他機能を明示的にスコープ外としている以上、レビューや進捗判断で誤解を生みます。  
  修正提案: 「`doc/05 §5.2` のうち字幕重畳要件を満たす」に表現を狭めてください。
- [Warning] 「3 ファイルの変更」としながら、実際にはテストファイルの新規追加・追記も含んでいます。設計の見積もり粒度として不正確です。  
  修正提案: 「実装 3 ファイル + テスト追加/更新」と書き換えてください。
- [Suggestion] TTS、焼込、ファイル選択フォールバックを外している点は v1 スコープに合っています。

**7. 型安全性**
- [Warning] `SubtitleOverlay` / `CameraRecorder` の props を手で再定義すると、既存 `CaptureCut` との型ドリフトが起こりやすいです。frontend-only 変更でも、ここが崩れると将来の Inertia props 変更で静かにズレます。  
  修正提案: `CaptureCut` から `Pick` した共有型、または `selectedCut` 由来の型をそのまま流す形にして、`primary`/`secondary` の正規化ルールも 1 箇所に寄せてください。
- [Suggestion] PHP 側 DTO/JsonResource には触れない前提なので PHPStan 影響は小さいです。代わりに TypeScript/Vitest で `null`、空文字、空白のみ、複数行日本語、toggle state を押さえると安全です。

要するに、この案は方向性自体は良く、使命にも合っています。ただし「最終焼込と同じ構図判断を可能にする」ための表示契約がまだ粗く、既定 ON の仕様解釈も未確定です。そこを詰めれば承認可能です。
