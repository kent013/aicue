全体判定: CHANGES_REQUESTED

### 1. 使命との整合性

[Suggestion] 字幕位置を事前に把握させる目的、既定 ON、ASS との差を「占有領域の目安」とする整理は North Star と整合しています。

### 2. 禁止事項違反

[Suggestion] テストファースト、非 disabled、frontend 限定、DS token 利用が明記され、禁止事項への抵触はありません。

### 3. 実現可能性

[Warning] 「上部 inset／下部 inset」が抽象的なままで、実際にどのクラスまたは DS spacing ramp を使うか確定していません。`px-3` / `py-2` は帯内部の余白であり、プレビュー端からの inset ではありません。

修正提案: `top-*` / `bottom-*` など、端からの配置値を DS ramp に基づいて明記してください。ASS の上下 margin との対応方針も示すと、実装者による解釈差を防げます。

### 4. 期待効果の妥当性

[Suggestion] 効果を「構図判断の支援」に限定したことで妥当な主張になっています。定量計測を本件の受け入れ条件にしない判断も適切です。

### 5. リスク

[Critical] `whitespace-pre-line`、非 truncate、行数無制限では、長文や多数の改行によって上下帯が中央まで広がります。「上下帯のみ・映像中央を覆わない」という不変条件を保証できません。primary と secondary が重なる可能性もあります。

修正提案: 表示可能領域の上限を定義してください。例えば各帯に `max-height` と overflow 処理を設ける、または事前に定めた最大行数を超えた場合だけプレビュー表示を省略記号付きで制限します。最終字幕全文との違いが生じる場合は「位置・占有領域確認用であり全文確認用ではない」と契約に明記し、極端な長文・多数改行・上下帯同時表示のテストを追加してください。

### 6. スコープの適切さ

[Suggestion] 字幕プレビューだけに限定され、TTS、焼込、フルスクリーン対応を切り離したスコープは適切です。safe-area を将来のフルスクリーン UI の責務とする整理にも問題ありません。

### 7. 型安全性

[Suggestion] `CaptureCut` の indexed access による型導出と、`trim()` 正規化を `SubtitleOverlay` に集約する方針は妥当です。テストでは、正規化後の文字列が実際の表示にも使われるのか、空判定だけに使われるのかを明確にしてください。

残る承認条件は、端からの inset 値と、長文時にも中央領域を侵食しない表示上限の明文化です。
