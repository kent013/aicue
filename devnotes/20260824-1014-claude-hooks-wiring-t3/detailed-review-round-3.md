## S2: REQUEST_CHANGES

[Warning] 「1か所だけ変異」をヘルパが保証していません。

`Assert::contains()` は1件以上の存在しか保証せず、`str_replace()` は全出現箇所を置換します。特に基準本文では stdin の正準文字列がコメントと実行行の両方に含まれるため、stdin の変異は実際には2か所を書き換えます。

修正案:

- `substr_count($body, $mutate) === 1` を検査してから置換する。
- stdin の変異元は、先頭の改行を含めるなどして実行行だけに一意化する。
- あるいは基準本文の各位置へ固有マーカーを置き、マーカー単位で置換する。

[Warning] 新設した候補語彙走査に、共通規約 (e) の3形の裏取りがありません。

S13b は非正準の `timeout` を検出できることを確認していますが、`xtimeout` / `!timeout` / `timeoutx` や、`XINNER_TIMEOUT_SECONDS` 等を誤って候補にしないことは固定していません。

修正案: 候補計数だけを直接検査する正例・負例を追加してください。

- `read` / `timeout` / `INNER_TIMEOUT_SECONDS` は候補になる。
- 接頭辞付き・打ち消し付き・接尾辞付きの3形は候補にならない。
- タブ区切りは候補になることも、宣言した区切り仕様として固定する。

[Warning] 「非正準の実行行を検出する」という主張は、候補語彙の定義より広く読めます。

例えば `/usr/bin/timeout -k ...` の先頭トークンは `timeout` と完全一致しないため候補になりません。正準行との併存も通ります。

修正案は次のいずれかです。

- `/usr/bin/timeout` 等、同じ操作を行える既知の表記も fail-closed で候補にする。
- 保証を「宣言した候補語彙に一致する非正準行の併存を検出する」に限定し、絶対パス形式などを保証外として明記する。

[Warning] S13/S13c のコメントが検出力を少し誇張しています。

> S13 側の比較を消したら S13c が赤くなる

S13 から共通関数の呼び出し自体を削除しても、S13c は引き続き共通関数を直接呼ぶため緑です。検出できるのは「共通関数内の比較を削除・反転した場合」です。

修正案: コメントを「共通関数内の比較を消したり向きを逆にしたら」に修正してください。

## S6: REQUEST_CHANGES

[Critical] 未追跡の新規ファイルが i15 の回収説明から漏れています。

実読記録によれば更新対象は次です。

```text
git diff --name-only HEAD~1 --
```

通常の `git diff` は未追跡ファイルを列挙しません。そのため、Bash ツールで新規ファイルを作った場合、そのファイルは作業ツリーに存在していても次の Write/Edit が起こす `update` の対象に入りません。以後そのファイルを Write/Edit で触っても、未追跡のままなら同じです。

現在の次の記述は成立しません。

> シェルで変えたファイルも次の Write / Edit の起動でまとめて回収される

また、「回収されない形が1つある」も誤りで、少なくとも次の2系統があります。

- Bash で作成した未追跡ファイル
- 変更をコミット後、Write/Edit を挟まずさらにコミットを重ねたファイル

修正案:

- 実読記録へ「git diff は未追跡ファイルを含まない」を追加する。
- 回収対象を「`HEAD~1` と比較可能な追跡対象パス」に限定する。
- docblock と AGENTS.md の冒頭から無条件の「回収される」を削除する。
- 未追跡ファイルを受容する穴として扱うのか、正典 i15 の前提崩壊として家系へ差し戻すのかを明示する。
- 既存の撤回規則 (a) は、このソース実読により既知となった未回収経路をどう扱うか整理し直す。実害の観測まで待つなら、その判断理由も書く。

例えば次の程度まで狭める必要があります。

> Bash で変更した追跡対象ファイルが `HEAD~1` と作業ツリーの差分に残っている間は、次の Write/Edit で回収される。未追跡の新規ファイルと、差分基準から外れた過去コミットの変更は回収されない。

[Warning] 「それでも索引が置いていかれない」という断定と、その直後の非回収ケースが矛盾しています。

修正案: 最初から「条件を満たす追跡対象ファイルは通常回収される」と条件付きで記述し、例外を後置きだけで処理しないでください。
