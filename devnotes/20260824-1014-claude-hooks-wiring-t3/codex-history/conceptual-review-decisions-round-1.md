## [Critical] i8 の適用が索引更新 hook しか示されていない (2 配線それぞれの内側上限と比較式が無い)
- 判断: 対応する
- 根拠: 指摘は正しい。実読では bug-hunt ガード側にも内側の上限が実在する
  (`IFS= read -r -N 1048576 -t 5 input` の 5 秒。それ以外に待つ箇所は無く、判定は bash の組み込みだけで
  外部プロセスを 1 つも起こさない) が、概念設計に書いていなかった。新しい自己終了機構は追加しない
  (思考原則 2 / 隣接 feature の領分)。
- 対応内容: 「i8 の内側上限の一覧」表を追加し、2 配線それぞれで
  (設定の timeout / 内側上限の定義箇所 / 比較式 / 成立値) を固定した。
  bug-hunt ガード = 5 < 10、索引更新 = 5 + 20 + 2 = 27 < 30。

## [Warning] `timeout -k 5` → `-k 2` の各数値の意味が読めない
- 判断: 対応する
- 根拠: 指摘どおり。`-k` は TERM 後の KILL 猶予で、`read -t` は起動直後の標準入力待ちである。
- 対応内容: 上記の表で「標準入力待ち / 本体上限 / KILL 猶予」を分け、実際のコマンド引数
  (`read -r -N 1048576 -t 5` / `timeout -k 2 "${INNER_TIMEOUT_SECONDS}"`) と抽出値を 1 対 1 で対応させた。

## [Warning] settings.local.json の全キー照合契約を明記せよ

- 対応内容: 判定を純関数へ切り出し、(a) ファイル不在 = 合格 (b) 存在時は全キーを申告と完全一致で照合
  (c) 合成入力の負例 3 形 (`hooks` を持つ / 未知キー / JSON オブジェクトでない) と正例 (空オブジェクト) で
  検出力を裏取りする、を概念設計へ明記した。
