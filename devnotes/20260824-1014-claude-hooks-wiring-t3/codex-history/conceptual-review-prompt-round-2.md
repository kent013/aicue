満たしている分 (i1 常設 / i2 必須 2 配線と `Write|Edit` / i3 照合条件の語彙 / i6 `-p` / i9 既定拒否の台帳 /

## 改善アイデア

**起動子を「スクリプトを起こすだけの 1 行」へ戻し、配線層の保証と非保証を検査側の台帳に集約する。**

1. 起動コマンド文字列を `/bin/bash -p "$CLAUDE_PROJECT_DIR/scripts/<name>"` の直呼び 1 行にする
   (i5 / i6 / i7)。起動前の 7 条件検証とインラインのシェル片を落とす。
2. 終了コードの写像を落とす帰結として、bug-hunt ガードの拒否コードを **97 → 2** (harness の拒否信号) に
   変える。これは `scripts/bughunt-worktree-hook.sh` の中身 = 隣接 feature (bug-hunt-exec-infra) の
   領分に触れるが、i7 の帰結として避けられない**従属変更**である。
3. 配線台帳検査 `ClaudeHooksWiringTest` の向きを正典側へ反転する。
   - S06b: 「3 役をすべて持つこと」→「直呼びであり、引数も条件分岐もインラインのシェル片も持たないこと」
   - B41〜B50: 「97 だけを 2 へ写し他を 0 に畳む」→「内側の終了コードがそのまま返ること」
   - B51 (`-p` の実証) と、設定の起動コマンド文字列そのものを起こす形 (i11) は正典に採られたので維持
4. i8: 配線の timeout (10 / 30) と起動先が自分で諦める内側の上限を**両方から数値で抽出して比較**する
   検査を新設する。B17 / B18 のテスト内直書き (`30.0` / `'20 秒'`) も台帳・スクリプト由来に直す。

#### i8 の内側上限の一覧 (2 配線とも固定する)

内側の上限は「起動先が**自分から**諦めるまでの最悪の待ち時間」の合計である。
数値は 3 種に分けて扱う — **標準入力待ち** (`read -t`) / **本体の上限** (`timeout` の秒数) /
**KILL 猶予** (`timeout -k` の秒数。TERM で終わらない相手を KILL するまで) 。

| 配線 | 設定の timeout | 内側上限の定義箇所 (抽出元) | 比較式 | 成立値 |
|---|---|---|---|---|
| PreToolUse (bug-hunt ガード) | 10 | `scripts/bughunt-worktree-hook.sh` の `IFS= read -r -N 1048576 -t 5 input` (標準入力待ちのみ。判定は bash の組み込みだけで完結し外部プロセスを 1 つも起こさないので、他に待つ箇所が無い) | 標準入力待ち < 設定の timeout | 5 < 10 |
| PostToolUse (索引更新) | 30 | `scripts/code-review-graph-update-hook.sh` の `IFS= read -r -N 1048576 -t 5 input` / `readonly INNER_TIMEOUT_SECONDS=20` / `timeout -k 2 "${INNER_TIMEOUT_SECONDS}"` (`flock -n` は非ブロッキングなので待ち 0) | 標準入力待ち + 本体上限 + KILL 猶予 < 設定の timeout | 5 + 20 + 2 = 27 < 30 |

現行の `timeout -k 5` では 5 + 20 + 5 = 30 で**等しくなり内側に収まらない**。
これが `-k 2` へ変える唯一の理由であり (家系で実証済みの値)、本体の 20 秒は動かさない。
検査は上の 3 値を**正規表現で抽出**し、読めない形は fail-closed で落とす (無言で候補から外さない)。
5. i10: ローカル層のトップレベルを全数申告制にする (申告に `hooks` を含めない)。判定は
   **純関数**へ切り出し、契約を 3 つに固定する — (a) ファイル不在は合格 (常設配線を上書きする経路が
   そもそも無い)、(b) 存在するときは**全キーを申告と完全一致で照合**する (許可外が 1 つでもあれば違反)、
   (c) 入口で「トップレベルが JSON object であること」「キーが string であること」を
   `Webmozart\Assert` で narrow してから照合へ渡す (PHPStan level 10 で `mixed` を通さない)。
   検出力は合成入力で裏取りする — 負例 3 形 (`hooks` を持つ / 未知の項目を持つ / object でない) と
   正例 (空オブジェクト)。
6. i14 / i15: 塞がない脅威 3 点と、シェル経由の編集が次の `Write` / `Edit` で回収される根拠 +
   撤回規則を、**検査ファイルの台帳の傍ら**に書く (正本は 1 か所。AGENTS.md には写さず参照だけ置く)。
   撤回規則の発火条件は 2 つ — (1) シェルで変えたファイルが次の `Write` / `Edit` の起動でも
   索引へ入っていない実測が 1 件でも出た、(2) 索引ツールが差分方式 (直前の索引時点からの差分を見る)
   でなくなった。発火したときに採る手は**matcher へ `Bash` を足すことではない** (正典が費用構造で
   外している) — 正典の未決論点へ差し戻す (索引状態をセッション開始時に出す任意配線 = q1 /
   非同期配線 = q2) と決めておく。
7. AGENTS.md の `CLAUDE_HOOKS_WIRING` マーカー区間を新しい契約へ書き換える
   (現行は「起動子は終了コードの写像器を兼ねる」「ブロックできるのは 97 だけ」と書いてあり、
   実装を変えると**文書が嘘になる**。S12a がマーカー区間の実在を固定しているので区間ごとは消せない)。
8. `docs/template-divergence.md` D18 を**縮小**し、`ClaudeHooksWiringTest.php` の採用時債務を
   逸脱の登録へ移す (下記「制約・前提」)。

### 保証の反転を明文で受け入れる

現行の写像器は「hook の 1 文字のタイプミスがセッションの Bash 操作を全滅させない」ための安全網であり、
D18 と T172 がその存在理由を明記している。**t3 はこの安全網を意図して捨てる**。
正典の理由は「写像は harness の唯一の制御信号を潰し、配線ミスと実行時の異常が区別できなくなる」ことで、
実際に家系では起動先が配線ミスを非 0 で知らせる設計が写像器のせいで 0 に畳まれた事例がある。

追従後は `scripts/bughunt-worktree-hook.sh` の構文エラー (bash が返す 2) が**そのまま Bash ツールの
ブロックになる**。この交換を受け入れる代わりに、次の 2 つを埋め合わせとして持つ (どちらも既存)。

- **着地前の検査**: 同じ検査ファイルの S09 が 2 本のスクリプトに `bash -n` をかける
  (構文エラーは main に着く前に赤くなる)
- **実挙動の検査**: B26〜B40b が実プロセスで拒否・通過の判定を実証する

## 期待効果

- 使命への貢献は間接である (開発の進め方の層)。効くのは「**現場作業者向けアプリの品質を守る規律が
  6 リポジトリで同じ形で効く**」という一点で、hook が止める操作 (bug-hunt の main 直叩き) と
  hook が回すもの (コード索引) はどちらも開発時のみの機構である。
- 具体の改善は 3 つ。(a) 配線ミスと実行時の異常が harness と人の両方から区別できるようになる。
  (b) **git 追跡下の** `.claude/settings.local.json` に `hooks` や未知のトップレベル項目が
  現れたことを既定拒否で検出できる (**リポジトリ外の利用者層・管理者層の設定は防げない** —
  そこは i14 の非保証として明記する側に回す)。
  (c) 内側の上限と外側の timeout の**数値の関係**が壊れたことを機械が検出する
  (現状は文字列一致すら無い)。
- 台帳のセルが `update_pending (pre-t3)` → `implemented (t3)` になり、家系で t3 到達の 1 本目になる
  (正典 t3 の全数を満たす実装は現時点で家系に無い)。

| 7 | i15 | (同上) |

#2 / #3 の pass-through は**設定から取り出した起動コマンド文字列そのもの**を起こして
観測値を 5 通り固定する — **0 / 2 / 3 / 97 / 127**。0 は通過、2 は意図した拒否 (ブロック)、
3 は「ブロックしない異常」、97 は**もう特別扱いされないこと**の負のコントロール、
127 は起動先が無いとき (`CLAUDE_PROJECT_DIR` 未設定を含む) に bash が返す値である。

**後方互換の並走を残さない** (思考原則 3): 写像器は同じ変更で消す。
「97 も 2 も拒否として受ける」ような移行期の二重受けは作らない。

## 制約・前提

### 乖離台帳 (D18) と採用時債務の決着

`docs/template-fingerprints.json` の母集合に本件の 5 パスが在る (実測)。

| パス | テンプレート側 | 現況 | 追従後 | 始末 |
|---|---|---|---|---|
| `.claude/settings.json` | `/bin/bash "$CLAUDE_PROJECT_DIR/…"` (`-p` 無し) | D18 に登録済み | `-p` の差だけが残る | D18 を**縮小して維持** |
| `scripts/bughunt-worktree-hook.sh` | `grep` / `printf` 依存・拒否は 2 | D18 に登録済み | 判定が組み込みのみ・1 MiB 上限の差が残る | D18 を維持 |
| `scripts/code-review-graph-update-hook.sh` | 別実装 | D18 に登録済み | 差は残る | D18 を維持 |
| `tests/Architecture/ClaudeHooksWiringTest.php` | 49 本の別構成 | **採用時債務** (`adoption-debt.tsv` 80 行目) | 内容が変わる | **債務では残せない** — 逸脱の登録へ移し、債務の行を削って件数 pin を 148 → 147 |
| `scripts/README.md` | 別内容 | D20 に登録済み | 差は残る | 追加の drift は検出対象外 (そのまま) |

債務パスは「変更したまま債務に残す」が選べない (突合 gate の `mutatedDebtPaths` が落とす)。
選べる 3 つ ((1) 採用時の姿へ戻す / (2) テンプレートへ同期して債務から削る /
(3) 意図的逸脱として登録し債務から削る) のうち、**(3) を採る** — 検査の内容は正典 t3 の要求
(i8 / i10 / i11 / i14 / i15) を満たす形で本アプリ側が先に組むものであり、テンプレートは未追従である。
登録は D18 に混ぜず**新規の登録 (D50)** とする (説明の筋が別で、対象パスは全登録の和集合で重複できない)。

D18 は丸ごと消せない。テンプレート側の起動子は `-p` を持たないため追従後も差分が残り、
消すと突合 gate の「食い違いに登録が無い」(3a) で落ちる。

### その他の前提

- 実装は worktree 必須。着手前に `/app-todo-add` (概念設計 + 詳細設計が devnotes に揃っていることが条件)。
- 配線を変えても**新しいセッションを開始するまで反映されない** (設定はセッション開始時に 1 度だけ読まれる)。
  したがって「実際に配線が効いていること」の確認は次セッションの人手確認になる。
- `.claude/settings.local.json` は現在**存在しない**。i10 の申告集合は空集合 (どのトップレベル項目も
  置けない) とし、置きたくなったら台帳を同じ変更で更新する。判定は純関数へ切り出し、
  合成入力の負例 (`hooks` を持つ / 未知の項目を持つ) で検出力を裏取りする。
- `docs/TODO.md` との衝突は無い。Open の T249 (起動 probe の共通 runner 化) は
  `ClaudeHooksWiringTest` の Process 起動を明示的に非スコープにしている。T172 / T227 は Closed。
- lctl への書き込み (append_event) は本設計では行わない (実装完了後の報告の責務)。

## スコープ外

- **i4 の第 3 の配線 (`SessionStart` で索引状態を出す)**: 正典が任意と定めた配線。必須化するかは
  正典の未決論点 q1 (オーナー裁定待ち) なので採らない。
- **`async: true` の非同期配線**: 正典の未決論点 q2 (家系に実測が 1 本も無い)。

- **hook スクリプトの中身の設計変更**: 隣接 feature の領分。触るのは i7 の帰結である拒否コードと、
  i8 の数値関係を成立させるための KILL 猶予の 2 点だけに限る。
- **索引ツールの導入先を検索パスへ載せる層の決着**: 正典の未決論点 q3 (本 feature の境界外)。

  「台帳の傍らに書く」までであり、家系の先行実装 (テンプレート / spirux) もファイル冒頭の散文として
  持っている。自分の docblock を自分で grep する検査は、書いた語の存在しか見えないので
  保証を強くしない (思考原則 2)。**ただし AGENTS.md 側のマーカー区間の実在は既存の S12a が固定する**。
