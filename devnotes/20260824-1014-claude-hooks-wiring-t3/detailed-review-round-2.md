## S2: REQUEST_CHANGES

[Critical] S13b の行継続バックスラッシュが過剰にエスケープされており、意図した分岐を通らない可能性が高いです。

提示された次の形式は、PHP の二重引用符内で「バックスラッシュ1文字＋改行」ではなく「バックスラッシュ2文字＋改行」になる構成に見えます。

```php
."timeout -k 0 \"\${INNER_TIMEOUT_SECONDS}\" \\\\\n"
```

正規表現は行末のバックスラッシュ1文字を要求するため、`0秒` ケースは値 `0` の検査へ到達せず、「kill の正準行が0件」という別理由で赤になる可能性があります。これでは `if ($value <= 0)` を削除しても負例が赤いままです。

修正案:

- エスケープの曖昧さを避け、nowdoc で shell 本文を作る。
- または正準本文を生成するテスト専用純関数を用意し、対象の1項目だけ置換する。
- 0秒ケースでは、抽出結果の違反が「正の整数でない」を含むことまで検査する。
- 正のコントロールにも合成入力を1件置き、期待する3値が取れることを確認する。

[Critical] 正準行が1件あれば、別の非正準実行行が共存しても検出されません。

例えば以下は、正準形の count が1なので抽出器を通ります。

```bash
timeout -k 2 "${INNER_TIMEOUT_SECONDS}" \
    true

timeout -k "${OTHER_LIMIT}" "${INNER_TIMEOUT_SECONDS}" \
    code-review-graph update ...
```

Round 2 の説明は「同じ語彙を持つ別行は違反」としていますが、実装が数えているのは正準形に一致する行だけです。正準形と非正準形の併存は検出されません。stdin や `INNER_TIMEOUT_SECONDS` の代替代入についても同じ問題があります。

修正案:

- コメントを除く実行行から、関連語彙の候補母集団も別途列挙する。
- `read ... -t`、`INNER_TIMEOUT_SECONDS=...`、`timeout ... INNER_TIMEOUT_SECONDS` の候補数と、正準形の一致数が同じであることを要求する。
- kill 行は可能なら次行の `code-review-graph update` まで含む複数行の正準形で固定し、猶予が更新本体へ実際に接続されていることを見る。
- これを保証しないなら、「同じ語彙を持つ別行も拒否」「囮の実行行を拒否」という主張を削り、保証をさらに狭める必要があります。

[Warning] S13b の複数のケースが複数箇所を同時に壊しています。

例えば「本体の上限が変数展開」の fixture は、stdin に `|| true` がなく、kill 行にも行継続がありません。body 分岐を削除しても、他の違反によりテストは赤いままです。

修正案: 完全に有効な基準本文を1つ作り、各データセットでは1箇所だけ変異させてください。少なくとも次の分岐を個別に裏取りする必要があります。

- 必要な正準形が0件
- 必要な正準形が2件
- 申告にない形が存在
- 値が0
- 未知のスクリプト
- 関係が等しい
- 関係が超える

[Warning] S13c の Pest closure に `array` の要素型がありません。

```php
function (array $limits, int $harness, bool $shouldFail): void
```

テスト群も PHPStan の対象なら、level 10 で iterable value type の不足として落ちる可能性があります。

修正案:

- closure に `array{stdin: ?int, body: ?int, kill: ?int}` の `@param` を付ける。
- または dataset の引数を `?int $stdin, ?int $body, ?int $kill` に分解し、closure 内で shape を組み立てる。

[Warning] B18 の「CI の揺らぎ5秒」は新しい閾値ですが、根拠となる計測がありません。

思考原則上、値を締めるなら実測分布か構造的根拠が必要です。単に 25 秒から5秒へ変更すると、遅いCIで不安定になる可能性があります。

修正案:

- 実測に基づいて余裕を決め、その記録を残す。
- 実測がない場合は設定由来の harness timeout 30秒を上限に使い、静的な27秒比較と役割分担する。
- 5秒を採用するなら「どの環境で何回測定し、最大値がいくつだったか」を根拠にしてください。
