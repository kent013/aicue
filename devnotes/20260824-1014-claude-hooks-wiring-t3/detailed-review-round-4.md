## S2: REQUEST_CHANGES

[Warning] `env timeout` に関する保証外の説明が実装と一致しません。

候補計数は空白・タブで分割した全トークンを見ます。

```php
if (in_array('timeout', $tokens, true) && in_array('-k', $tokens, true))
```

そのため、次の行は `timeout` と `-k` の両方を含み、kill 候補として数えられます。

```bash
env timeout -k 2 ...
```

しかし docblock では `env timeout` は候補にならないと説明しています。

修正案:

- `env timeout` を保証外一覧から削除し、「候補になる」と整理する。
- S13e に `env timeout -k 2` が kill 候補1件になる正例を追加する。

[Warning] body 語彙について、共通規約 (e) の「打ち消し付き」がありません。

`timeout` と `read` は接頭辞・`!`・接尾辞の3形がありますが、`INNER_TIMEOUT_SECONDS` は接頭辞と接尾辞だけです。

修正案: 次を S13e に追加してください。

```php
'!INNER_TIMEOUT_SECONDS=20'
```

これが body 候補にならないことを固定すれば、3語彙すべてについて規約の意図が明確になります。

[Warning] `claudeHooksInnerLimits()` 側の説明が、候補計数側で狭めた保証より強く読めます。

次の記述は、あらゆる非正準表記を検出するように読めます。

> 申告に無い形が 1 件でも現れたら違反にする  
> 重複・囮の行はすべて違反である

実際に検出するのは、候補走査が宣言した語彙へ完全一致する行だけです。

修正案:

> 候補走査が申告対象と分類した、正準形でない行が1件でも現れたら違反

のように限定し、絶対パス・別名・変数経由は候補計数の docblock に記載した保証外であることを参照してください。

そのほか、nowdoc、`substr_count() === 1`、一意化された stdin 変異、S13c の型、B18 の設定由来上限は妥当です。

## S6: REQUEST_CHANGES

[Warning] 実読記録の撤回規則が内部で矛盾しています。

発火条件3は次の内容です。

> 隣接 feature 側で未追跡ファイルへの対処が入ったら、本記録と台帳を更新する

これは改善への追従です。一方、その直後に次のように書かれています。

> どちらの場合も……家系の未決論点へ差し戻す

問題は2点あります。

- 条件は3件なので「どちら」ではなく「いずれ」です。
- 条件3は文書更新の契機であり、当然には未決論点への差し戻し理由になりません。

修正案: 条件ごとの対応を分けてください。

- 条件1: 新版を再実読し、保証と非保証を再評価する。
- 条件2: 実害が出たため、家系の未決論点へ差し戻す。
- 条件3: 改善後の実装に合わせて実読記録・docblock・AGENTS.md を更新する。必要な場合だけ家系判断を再提起する。

[Warning] AGENTS.md の次の括弧書きは、直後の限定より先に無条件の回収を連想させます。

> 差分方式であること (= シェル経由の変更が次の Write / Edit で回収される前提)

本文では正しく追跡下・`HEAD~1` 差分という条件を書いているため、ここも同じ条件へ揃える方が安全です。

修正案:

> 差分方式であること (= 条件を満たす追跡下の変更が次の Write / Edit で回収される前提)

未追跡ファイルと過去コミットの2系統を受容する判断、matcher と直交するという分析、家系への申し送りは妥当です。
