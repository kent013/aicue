# 対応マトリクス: conceptual-review Round 2

## [Critical] 動的な `type` 属性の扱いが未定義 = 母集団が fail-closed でない (観点 3)

- 判断: **対応する (提案をそのまま採用)**
- 根拠: 指摘は共通規約 (b) の「未解決を解決済みと同じ値へ混ぜない / 無言で候補から外さない」
  に直接該当する。`type="file"` の静的形だけを母集団にすると、
  `<input type={kind}>` や `<input {...attrs}>` が保護対象になりうるのに黙って外れる。
- 対応内容: (D) に**母集団の取り方の表**を追記し、走査対象を
  「`resources/js` 配下の native `input` 要素の全数」へ広げた。
  静的に file 以外 = 対象外 / 静的に file = 目録対象 /
  式・短縮記法・spread で確定できない = **失敗** /
  `type="file"` と spread の併存 = **失敗** /
  `accept` 属性なし = **失敗** / parse 失敗 = **失敗**。
  負例・正例の両方向で固定することも明記した。

## [Suggestion] 区分名「サーバ props 由来」は gate が由来を検証しているように読める (観点 6)

- 判断: **対応する**
- 根拠: 保証範囲を誇張しない (AGENTS.md の全体方針) に照らして、名前は
  検証済みの事実の側に寄せるべき。gate が確認できるのは
  「その値が静的に確定できない (実行時に決まる) こと」までである。
- 対応内容: 区分名を「**動的値** (SOP は Inertia props で供給する意図。
  gate は由来を検証しない)」へ改め、その旨を (D) 本文に書いた。

## [Suggestion] ラベルメソッドは明示的な `string` 戻り値型、テストは最終メッセージの完全一致で比較 (観点 7)

- 判断: **対応する (詳細設計で反映)**
- 根拠: 部分一致 assert は文面の劣化を見逃す。既存テストも
  「対応していないファイル形式です。…でアップロードし直してください。」の
  完全一致で書かれている。
- 対応内容: 詳細設計のテスト計画で、FormRequest の 422 文言は**完全一致**で比較し、
  ラベルメソッドの戻り値型は `string` を明示することを施策に書く。
