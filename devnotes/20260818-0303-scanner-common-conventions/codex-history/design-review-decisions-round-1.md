# 対応マトリクス: design-review Round 1

## [Critical] 新設規約が本 PR 自身の施策 2 と矛盾する
- 判断: **対応する**
- 根拠: 指摘のとおり。「変更するときに 4 点を揃える」を無条件に書くと、
  docblock の訂正だけの施策 2 が自分の規約に抵触する。
- 対応内容: 4 点に**発火条件**を付けた —
  「走査ロジック・走査対象・名前解決・判定条件・目録のいずれかを新設または変更するとき。
  **コメントや docblock を実態に合わせて訂正するだけで検出範囲を変えない変更は発火しない**」。
  併せて施策 2 の変更箇所に「本施策は発火対象ではない」と明記した。

## [Warning] 「5 条を満たす」の対象が広すぎる / gate 内直書きの走査が漏れる
- 判断: **対応する**
- 対応内容: 節の冒頭を書き直した。**対象** = `tests/Support/` の検出器 /
  gate の中に直接書かれた走査ロジック / それらを使う gate。
  **条ごとの適用範囲** = (b)〜(d) は該当するすべての走査、(a) はクラス名・名前参照を解決する走査、
  (e) は語彙一致を判定する走査。

## [Warning] (a) と (b) で「対象外」と「fail-closed」が競合 / 「落とす」の意味が曖昧
- 判断: **対応する**
- 根拠: 「落とす」が「結果から除外する」と読まれると、まさに D1 の見逃しを正当化する。
- 対応内容: (a) から「対象外だと明示してよい」を外し、(b) に 3 つの下位規則として整理した。
  (i) 未解決を解決済みと同じ値へ混ぜず、判別できる結果か解析の失敗として返して gate を失敗させる /
  無言で候補から外さない。(ii) 保証範囲の外にする構文は docblock へ明記し、明記したなら
  検出力を主張しない (明記せずに落ちこぼすのは違反)。(iii) 「違反 0 件」と「母集団 0 件」の区別。
  「拾いすぎる方向へ倒すのは可」にも「見逃さないという意味であり、
  正常なコードを違反と断定することではない」を添えた。

## [Warning] 「新しい不変条件を導入していない」というテスト不要理由が本文と整合しない
- 判断: **対応する**
- 根拠: 指摘のとおり。D5 は「要求として書かれた場所が無かった」と述べており、
  「4 点を揃える」「docblock から負例へ辿れること」は新しい要求である。
- 対応内容: 理由 1 を「**実行できる不変条件を実装するものではない**。規約としては新しい要求を
  含むが、それらはレビューの手続きであってテストが判定できる状態ではない。
  したがって完了報告は『人向け規約の文書化と既存挙動の説明の訂正』に限り、
  5 条の機械強制も既存 gate の全準拠も実装済みとは報告しない」へ書き直し、
  同じ制約を完了条件の 3 番へも入れた。
