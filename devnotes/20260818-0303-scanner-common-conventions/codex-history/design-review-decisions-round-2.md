# 対応マトリクス: design-review Round 2

## [Critical] (b) の「保証範囲外」規則で D1 を規約適合へ読み替えられる
- 判断: **対応する**
- 根拠: 指摘のとおり。走査器 1 本の docblock に「部分修飾名は範囲外」と書き足すだけで
  適合になるなら、**限界を書くほど規約に適合していく**という倒錯した規則になる。
  実際に守っているのは利用側 gate の不変条件である。
- 対応内容: (b) の 2 つ目の下位規則へ追記した —
  「**保証範囲は走査器 1 本の docblock だけでは決まらない**。利用側 gate の名前・
  守ると宣言した不変条件・検出力の主張まで含めて判定する。
  **走査器の限界を書き足すことは、既にある見逃しを規約適合へ変えない**。
  保証範囲の外にした構文で保護対象の操作を書ける場合、利用側 gate は検出力の主張を
  その構文を除く形へ明示的に狭めるか、未解決として失敗させる」。
  棚卸し D1 にも「**docblock へ限界を書けば済む、ではない**。上に立つ gate
  (外部到達点の目録 / プロンプト防御の窓口) は部分修飾名を除外する形で主張を狭めていないので、
  D1 は引き続き (a)・(b) 違反である」を明記した。

## [Warning] 付録に `BughuntNamingResidualTest` が漏れている / 「9 箇所すべて」が成立しない
- 判断: **対応する**
- 実測: 同テストは `AGENTS.md` をリテラルで持たず、`git ls-files -z` で**追跡下を丸ごと列挙**して
  撤去済みの bug-hunt クラス名を探す。したがってパスのリテラル検索では原理的に拾えない。
- 対応内容: 付録を**母集団 A (パスのリテラル) と母集団 B (追跡下を丸ごと列挙する走査)** の
  2 段構えへ作り直し、B から `AGENTS.md` を母集団に含む 3 本を確定した。
  B に当たった 10 本のうち含まないものは**除外理由を 1 本ずつ明記**した
  (`*.php` 限定 / 走査根が `.claude` と `scripts` / `resources/js/` 限定 /
  bug-hunt 所見台帳の検証器 / 手順書の散文)。件数は実測値へ更新し、
  「9 箇所すべて」という固定文言をやめた。

## [Warning] 列挙コマンドが直接参照の全数性も担保していない
- 判断: **対応する**
- 対応内容: 1 本目を「ファイルを開く処理と `AGENTS` が同じ行にある形」から
  **追跡下ファイル全体に対する引用符つきリテラルの検索**へ替えた。
  観測コミット (`main` @ 1194d34) を併記し、
  **「主張の範囲は母集団 A と B の 2 つに限る」「パスを定数や変数から組み立てる形・
  複数行に割った呼び出し・リポジトリ外のツールは見ていない」「動的に組み立てる形は存在しない、
  とは言えない」** を冒頭へ書いた。

## [Suggestion] 分類型の説明が表と一致していない
- 判断: **対応する**
- 対応内容: 指摘の分類をそのまま採用し **5 型**にした —
  マーカー区間 / 全文の必須語句 / 全文の禁止語句 / 全文を対象にした構造・件数の判定 /

## [Warning] 棚卸し D1 に旧表現「母集団から外れる」が残っている
- 判断: **対応する**
- 対応内容: 「利用側の完全修飾名の一覧に一致しないため、参照 site は emit されていても
  **違反候補として認識されず、無言で見逃される** (走査器の母集団から消えるのではなく、
  利用側の照合の段で落ちる)」へ書き直した。空振り問題 (D2) との混同が消える。

## [Warning] リスク節の「group use は従来どおり解決を主張する」が広すぎる
- 判断: **対応する**
- 対応内容: 影響範囲を「**名前空間またはクラスの別名を先頭要素に使った部分修飾名
  (`T_NAME_QUALIFIED`) の参照**」に限定し、主張する側は「完全修飾名」と
  「対象クラス自体を直接取り込んで短名や別名で参照する形」に絞った。
  **「group use は従来どおり」とは書かない**ことと、その理由
  (取り込んだ先頭要素に部分修飾名を続ける形は穴の側に入り得る) を明記した。
