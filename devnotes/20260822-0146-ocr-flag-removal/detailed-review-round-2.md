## 施策1: configからフラグ削除

判定: REQUEST_CHANGES

[Warning] `config()->boolean('manual.ocr_analysis_enabled')` の参照が残った場合、「未定義キー参照としてPHPStanまたは実行時に判明する」という説明は不正確です。Laravelのconfigキーは文字列で動的に参照されるため、PHPStanは通常キーの不存在を検出できず、実行時も黙ってfalse相当になる可能性があります。

修正案:

- 「未定義キーとして検出される」ではなく、「旧コードが黙ってfalse側へ倒れるため、部分適用するとOCRが無効になる」と記載する。
- 検出手段はPHPStanではなく施策10の残存検索であることを明記する。

同一PRでの同時適用とconfig cache再生成を明記した点は適切です。

## 施策6: バックエンドテストの畳み込み

判定: REQUEST_CHANGES

[Warning] 「公開面の一貫性」テストで、同じマニュアルに対して次の処理を順番に行うと、状態が干渉する可能性があります。

1. HTTP経路でJPEGをアップロード
2. `SourceDocumentService::appendDocument()` でもJPEGを追加

既存仕様には「画像は1手順書につき1枚」という制約があるため、Service境界の確認が2枚目画像として拒否される可能性があります。

修正案:

- 3境界を別テストへ分割する、または
- FormRequest経路とService経路で別々のmanual fixtureを使う

どちらの状態分離を採用するか設計書に明記してください。

[Warning] HEICだけが残る `$cases` に、`[true, fn () => ...]` という旧フラグ由来の不要な要素を残し、`foreach ($cases as [, $makeFile])` で捨てる設計になっています。これは後方互換の並走を残さない方針と整合しません。

修正案:

```php
$cases = [
    fn (): UploadedFile => UploadedFile::fake()->create(/* ... */),
];

foreach ($cases as $makeFile) {
    // ...
}
```

ケースが1件だけなら、配列とループ自体をなくして直接検査する方が明快です。

テスト名と実際の3境界を明示したこと、PHPStan対象範囲の断定を修正したことは適切です。

## 施策8: rollout文書更新

判定: REQUEST_CHANGES

[Warning] rollbackについて、まだ本文内に矛盾があります。

先に「復旧は、無効化・修正するコード変更を作った上で反映する」と限定した後で、「rollback可能性は運用手順に依存する」としています。rollbackが可能なら、新たなコード変更を作らず旧リリースへ戻す可能性があります。

修正案:

```text
問題発覚時の復旧手段は、本番環境を運用する側の手順に依存する。
運用手順が対応している場合は承認済みリリースへのrollbackを行い、
対応していない場合またはrollbackが適切でない場合は、
無効化・修正patchを通常のデプロイ手順で反映する。
本リポジトリはrollbackの可否を保証しない。
```

過去手順を「廃止済み・実行不可」とし、実施済みと計画を区別する修正、およびリポジトリ外Secretを運用側へ引き継ぐ整理は適切です。

## 施策10: 残存確認

判定: REQUEST_CHANGES

[Warning] 未追跡 `.env*` の確認がまだ受入条件を満たしていません。

現在のコマンドは `.env` と `.env.local` の2ファイルしか検査せず、宣言している「未追跡 `.env*` 全体」と一致しません。たとえば `.env.testing.local` や別名の環境ファイルを見逃します。

また、`2>/dev/null` によりファイル不存在だけでなく読み取りエラーも隠れるため、deny-by-defaultの完了確認としては不適切です。

修正案:

- hidden/ignore対象を含み、`.env*` をglob指定できる検索方法へ変更する。
- 検索エラーと「一致ゼロ」を区別し、エラー時は完了扱いにしない。
- 検査対象となった `.env*` のファイル一覧もPR証跡に残す。

例:

```bash
rg --hidden --no-ignore-vcs -n \
  "ocr_analysis_enabled|MANUAL_OCR_ANALYSIS_ENABLED" \
  -g '.env*' .
```

実装環境で `rg` の終了コード1を「一致なし」、2以上をエラーとして区別してください。

検索語の追加と、AGENTS.md所定の検証コマンド10本をすべて追加した点は適切です。恒久的な専用Architecture gateを新設しない判断も引き続き妥当です。

## 最終所見

修正が必要なのは次の4点です。

- configキー不存在をPHPStan／実行時が検出するという説明の訂正

- rollbackと修正patchを排他的な復旧候補として正確に記述

これらが反映されれば、全体をAPPROVEDにできる設計です。
