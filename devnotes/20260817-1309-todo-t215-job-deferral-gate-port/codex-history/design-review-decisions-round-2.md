# 対応マトリクス: design-review Round 2

Round 1 の Warning 6 件は「すべて適切に解消」と確認された。
施策 1〜7 はすべて **APPROVE**。残ったのは受け入れ条件の 1 件だけである。

## [Warning] AC-7 が fail-open (untracked を見ない / 比較基準が動く)

- 判断: **対応する**
- 根拠: 指摘のとおり 2 つの穴がある。
  (1) `git diff` は**追跡外のファイルを見ない**ので、`app/` に新しいファイルを置いても
  「差分 0」と読める。(2) `main` は実装中に進むので、名前で比較すると
  「何と比べたのか」が実行のたびに変わる。
  どちらも「`app/` を 1 行も変えない」という本設計の中心的な主張を検証できなくする。
- 対応内容: AC-7 を **2 条件の同時成立**へ書き直した。
  (a) 追跡下の差分が無い: `git diff --exit-code <base-sha> -- app/` が終了コード 0。
  (b) 追跡外を含む作業ツリーの差分が無い: `git status --porcelain -- app/` の出力が空。
  `<base-sha>` は worktree を作った時点の `main` の SHA を
  `devnotes/.../base-sha.txt` へ記録して固定する。
  全検証コマンドの節にも、なぜ名前ではなく SHA で固定するのか・
  なぜ `git diff` だけでは足りないのかを書き添えた。

## [Suggestion] `mutations/` と `mutation-log.md` の扱いが曖昧

- 判断: **対応する**
- 根拠: 指摘のとおり「恒久化しない」と「受け入れの証跡にする」が並んでいると読み手が迷う。
  実際には矛盾しておらず、語の意味を書いていなかっただけである。
- 対応内容: 「作業用」一覧の下に注記を足し、
  **PR に含めてコミットする** (証跡を消すと AC-7 / AC-8 / AC-9 が後から検証不能になる) こと、
  「恒久化しない」とは **`scripts/` へ昇格させない** (= `scripts/README.md` の台帳に載せず、
  CI や定期実行の配線を作らない) 意味であることを明記した。
  `base-sha.txt` も同じ一覧へ加えた。
