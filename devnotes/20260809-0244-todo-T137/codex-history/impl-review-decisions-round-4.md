# 対応マトリクス: impl-review Round 4

全体判定: `CHANGES_REQUESTED` (Critical 0 / Warning 2 / Suggestion 2)

## [Warning] `truthyLiteral()` の数値評価が PHP の数値リテラル意味論と一致しない (0x1 / 0b1 / 0o1)
- 判断: **対応する**
- 根拠: 指摘が正しい。`(float) '0x1'` は `0.0` になるため、実行時 truthy な基数付きリテラルを
  falsy と誤判定して検出をすり抜ける。「非ゼロ数値を検出する」という主張と実装が食い違っていた。
- 対応内容: 数値区切り `_` を除去したうえで `0x` / `0b` / `0o` / 先頭 0 の旧式 8 進を
  それぞれ `hexdec` / `bindec` / `octdec` で評価するようにした。
  負のコントロール (`0x1` / `0b1` / `0o1` / `010` / `1_000` の 5 件検出) と
  偽陰性コントロール (`0x0` / `0b0` / `0o0` / `000` / `0e5` を 0 件) を追加した。

## [Warning] 文字列リテラルをソース表記で判定しており `"\x30"` が偽陽性になる
- 判断: **対応する** (完全なエスケープ評価は行わず、評価不能へ倒す)
- 根拠: 指摘が正しい。`"\x30"` の実行時値は `"0"` = falsy だが、ソース表記のままだと
  truthy 判定になる。完全なエスケープ評価は検出器を不必要に複雑にする (思考原則 2)。
- 対応内容: **バックスラッシュを含む文字列リテラルは評価不能 (null) へ倒す**ようにし、
  その制限を docblock と `docs/architecture.md` の「保証しないもの」へ明記した。
  偽陰性コントロールに `"\x30"` のケースを追加した。
