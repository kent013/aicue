# 対応マトリクス: design-review Round 2

Codex 全体判定: **CHANGES_REQUESTED** (Critical 0 / Warning 1 / Suggestion 0)。
施策別: 1〜5 = APPROVE / 6 = REQUEST_CHANGES (「保証しないもの 11」の文言のみ)。

## [Warning] 「保証しないもの 11」の「他のいかなる状態変更も許さない」が事実と一致しない

- 判断: **対応する (全面的に受け入れる)**
- 根拠: **指摘が正しく、こちらの記述が誤り**だった。`ALLOWED_ROUTE_NAMES` には元から変更系 route が
  複数入っている (`two-factor.enable` / `two-factor.confirm` / `two-factor.regenerate-recovery-codes` /
  `recent-auth.password` / `passkey.confirm` / `verification.send` / `logout`)。
  したがって「未準拠セッションは取消以外の状態変更を一切できない」は**偽**であり、
  本タスクの必須事項「誇張しない」に真正面から反していた。
  また、保証**する**内容を「保証しないもの」節に書いていた構造上の誤りも指摘のとおり。
- 対応内容 (2 箇所):
  1. 施策 1 に **「セキュリティ境界の差分 (この施策が変えるもの / 変えないもの)」** 節を新設し、
     「新たに allowlist へ追加する変更系 route は退会取消 1 本だけ」「既存 allowlist は一切変更しない」
     「予約作成・即時削除・2FA 無効化・業務操作を新たに許可しない」「この差分を
     『未準拠でもアカウント操作全般ができる』と要約しない」を記述した。
  2. 「保証しないもの 11」を **「2FA 未準拠セッションで状態変更が一切起きないことは保証しない。
     準拠達成・認証回復・離脱に必要な既存 allowlist route は従来どおり許可される」** に書き換えた
     (該当 route 名を列挙して具体化)。

## 反論しなかった理由

Round 2 の指摘は事実誤認の訂正であり、思考原則 2 (過剰に作らない) との衝突も無い。
文言修正のみで完結し、機構は 1 つも増えていない。
