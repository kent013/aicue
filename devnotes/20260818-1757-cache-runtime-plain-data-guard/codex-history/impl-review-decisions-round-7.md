# 対応マトリクス: impl-review Round 7

## [Critical] 「最初の型宣言で打ち切る」は「名前空間スコープの取り込みだけ読む」と同義ではない

- 判断: **対応する**
- 根拠: 指摘のとおり。PHP は型宣言の**後ろ**にも名前空間スコープの取り込みを置けるので、
  打ち切り方式では後置の取り込みを丸ごと落とし、`extends Guarded` が
  `App\Demo\Guarded` と誤解されて L4d の母集団から外れる。
- 対応内容:
  - `cachePayloadNamespaceBodyDepth()` / `cacheGuardNamespaceBodyDepth()` を新設し、
    `namespace A;` なら 0、`namespace A { … }` なら 1 を返す
  - 両 gate の取り込み表を**波括弧の深さ**で判定する形にした
    (名前空間本体の直下にある `use` だけを読む)。位置ではなくスコープで区別するので、
    後置の取り込みも読め、クラス本体の trait 取り込みと closure capture は除外できる
  - 結線 gate の**trait 取り込みの走査も深さ判定へ**変えた
    (「最初の型宣言より後の `use` を全部見る」形だと、後置の名前空間取り込みまで
    trait の適用として数えてしまい負例の件数が合わなくなる)
  - 負例を 3 形追加した:
    - 静的 gate: **型宣言の後ろに置いた取り込み** (指摘の合成入力そのもの) /
      **波括弧形の名前空間**
    - 結線 gate: **型宣言の後ろに置いた別名**の取り込みで trait を適用する形
