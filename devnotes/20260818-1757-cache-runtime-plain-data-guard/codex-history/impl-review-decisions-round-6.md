# 対応マトリクス: impl-review Round 6

## [Critical] クラス本体の trait `use` が名前空間スコープの取り込みを上書きする

- 判断: **対応する**
- 根拠: 指摘のとおり。`use X as Guarded;` の後に `class T { use \Other\Guarded; }` があると
  取り込み表の `Guarded` が上書きされ、`class Bypass extends Guarded {}` が別クラスへ
  解決されて L4d の母集団から外れる。走査規約 (a) の違反である。
- 対応内容: `cachePayloadUseMap()` を**名前空間スコープの取り込みだけ**を読む形にした。
  型宣言 (`class` / `trait` / `interface` / `enum`) の開始で打ち切る。
  ただし `Foo::class` の `class` は型宣言ではないので、直前が `::` のときは打ち切らない。
  結線 gate の `cacheGuardUseMap()` にも同じ `::class` の除外を入れた。
  負例は**指摘の合成入力そのもの**を収集関数へ通す形で追加した。

## [Warning] W4 の保証外に `call_user_func('uses', …)` を書くだけでは足りない

- 判断: **対応する (主張を明示的に狭める側を選んだ)**
- 根拠: AGENTS.md 走査規約 (b) の 2 択のうち、動的関数呼び出しまで解決するのは
  本 gate の目的 (vendor 追随の前提の確認) に対して過剰である。
  主張の側を狭めるのが正しい。
- 対応内容:
  - テスト名を「**クラス本体の use 文と字句の uses()** で … 適用するテストが 0 件である」へ変更
  - docblock の「保証するもの」を同じ 2 形へ限定し、
    「主張はこの 2 形に限る」と明記した
  - 「保証しないもの」に「関数名ごと動的にする形には沈黙するので、
    『対象 trait を適用する経路が 1 つも無い』とは読めない」と書いた
  - `uses()` と**書いた**うえで引数を変数にした形は従来どおり未解決として落とす
