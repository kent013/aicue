# 対応マトリクス: impl-review Round 5

## [Warning] 波括弧の深さだけでは「無条件に実行される文」を保証できない

- 判断: **対応する**
- 根拠: 指摘のとおり。波括弧を使わない `if`・代替構文 (`if (…): … endif;`)・
  三項演算子・短絡評価の右辺は、いずれも波括弧の深さが 0 のまま実行されない置き方を作れる。
- 対応内容:
  - `cacheGuardIsDirectStatement()` に**直前の token が文の境界 (`{` / `}` / `;`) である**
    という条件を足した (波括弧なしの `if` は直前が `)`、代替構文は `:`、
    短絡評価は `&&`、三項は `?` になるのですべて落ちる)
  - `cacheGuardIsStandaloneCall()` を新設し、`Guard::method(…)` については
    **引数リストの閉じ括弧の直後が `;`** であることまで見る (代入・連鎖・条件式の一部を除く)。
    assertInstalled / flush / reset の 3 つはこちらで判定する
  - try 文は**`try` キーワードの位置**で判定する (`{` の位置だと直前が常に `try` になる)
  - 負例を 3 形追加した (波括弧なしの if / 代替構文の if / 短絡評価の右辺)

## [Suggestion] docblock の保証外一覧に「動的な uses() には沈黙する」が残っている

- 判断: **対応する**
- 対応内容: 「静的に解決できない `uses($trait)` は未解決として落とすが、
  `call_user_func('uses', …)` のように関数名ごと動的にする形には沈黙する」へ直した。

## [Warning] `cachePayloadUseMap()` が `use function` / `use const` を除外できていない

- 判断: **対応する**
- 根拠: 指摘のとおり、`$pending = null` にした後も走査を続けるので後続の名前が
  再び `$pending` に入り、末尾でクラス取り込み表へ登録され得た。同名のクラス取り込みを
  上書きして名前解決を壊す経路である。
- 対応内容:
  - `use` の直後が `T_FUNCTION` / `T_CONST` なら**文ごと読み飛ばす**
  - グループ use の中の `function foo` / `const BAR` の混在指定は、
    その要素だけを `,` / `}` まで読み飛ばす
  - 正例を追加した (クラス取り込み / 単独の `use function` / 単独の `use const` /
    グループ use の混在指定を 1 つのソースに入れ、表に載るのはクラス 2 件だけであることを固定)
