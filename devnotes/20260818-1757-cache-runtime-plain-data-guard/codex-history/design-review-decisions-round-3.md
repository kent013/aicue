# 対応マトリクス: design-review Round 3

## [Critical] 実装順どおりでは S5 / S6 を緑にできない

- 判断: **指摘のとおり。対応する**
- 根拠: S5 を足した時点で、既存の静的 gate が新しい書き込み経路・面・迂回呼び出しを検出して落ちる。
  L2 / L3 / 語彙を変える S7 が未実装だと「S5 / S6 が緑」も「全レーンで計測」も成立しない。
- 対応内容: 実装順を次に改めた。
  1. **S5 / S6 / S7 の負例を先に書いて赤くする**
  2. **S1〜S4 と S7 を実装する**（S7 を S8 より前へ動かした）
  3. 新しい振る舞い検査・結線 gate・既存の静的 gate をすべて緑にする
  4. **S8 の反復計測**（計測 → 是正 → 再計測を違反 0 まで）
  5. S9 → S10 → S11
  S8 で新しい書き込み経路を是正した結果 L2 目録が動くので、
  **S7 の目録の確定は S8 の各 wave のたびに更新する**ことも明記した。

## [Critical] L4 自己テストが静的に必ず検出される設計になっていない

- 判断: **指摘のとおり。対応する**
- 根拠: 既存 scanner の受け手名は**型宣言**から作られる。`$cache = Cache::store('array');` では
  受け手にならず、`PlainDataGuardedRepository` は受け手型に含まれず継承も解決しない。
  そのままだと実測 0 件になり、exact-fit 目録が落ちる。
- 対応内容:
  - **境界の自己テスト呼び出しを `tests/Support/Cache/GuardedBoundaryProbe.php` の
    1 ファイルへ集約**し、受け皿は **`Illuminate\Cache\Repository` 型の引数**で受ける
    （scanner が受け手として解決する形にそろえる）
  - `Cache::extend(...)` は facade 受け手、`Repository::macro(...)` / `flushMacros()` は
    受け手型への静的呼び出しなので、いずれも既存の解決経路で検出される
  - **`storePassthrough`（未知メソッド）の自己テストは静的には `unclassified` になる**ので、
    **検査 1 は自己テスト目録に登録された呼び出しを母集団から除く**規則にする
    （目録に載っていない未知 API は従来どおり落ちる）
  - **母集団の非空**を検査に加える（自己テスト目録の全 entry が実測で 1 度ずつ対応したこと）

## [Warning] `new` の自己テスト目録 key は短名ではなく完全修飾名にする

- 判断: **対応する**（AGENTS.md の走査規約 (a) に合わせる）
- 対応内容: key を `{相対パス}::new {完全修飾名}` にする。
  scanner が解決した完全修飾名を使い、**解決できないときは目録照合へ進めず
  `unclassified` として落とす**。

## [Warning] W5b は `#[\Override]` を別途 pin する必要がある / 許可差分の位置

- 判断: **対応する**
- 対応内容:
  - `#[\Override]` は **reflection で別途検査**する（`getAttributes(Override::class)` が 1 件）。
    token の切り出しに属性行が入る保証が無いため
  - 許可差分は**位置まで固定する**。ローカルの期待 token 列を定数として持ち完全一致で比較し、
    **さらに**「その定数から許可差分を取り除くと vendor 期待列に一致する」ことも検査する
    （部分列の除去だけだと別の位置に同じ列を置いても通るため、二重にする）

## [Warning] 境界自己テストを登録できるパスが広い

- 判断: **対応する**
- 対応内容: 「`tests/Support/Cache/` 配下」をやめ、**名指し 1 ファイル
  (`tests/Support/Cache/GuardedBoundaryProbe.php`) だけ**に固定する。
  境界 API を呼ぶ自己テストはすべてこのファイルへ集約する。
  許可集合を変えるときは負例も同じ変更で更新する。

## [Warning] 第三者 Store についての「唯一の登録口」は不正確

- 判断: **指摘のとおり。対応する**
- 対応内容: 表現を
  「`Cache::extend()` の pin は **CacheManager 経由で第三者 Store の面を増やす経路**を閉じる。
  走査根の外の第三者 Store を直接生成する / 独自のコンテナ束縛で取得する経路までは保証しない」
  に限定した。
