# 対応マトリクス: design-review Round 2

## [Critical] 施策 3 置換の途中失敗で部分的な生成物が残る

- 判断: 対応する
- 対応内容: 差し替え手順を 6 段に変更した。
  (1) 一時ファイル 2 本を書き切る → (2) 既存 2 ファイルを同ディレクトリの控えへ複製 →
  (3) `os.replace()` を 2 回連続 → (4) 2 本目が失敗したら控えから 1 本目を戻して exit 2 →
  (5) 戻すのも失敗したら元 / 一時 / 控えを消さず全パスを標準エラーへ出して exit 2 → (6) 成功したら控えを消す。
  自己テストは「通常の置換失敗では呼び出し前の 2 ファイルが byte 単位で保たれる」を固定する
  (前ラウンドの「部分更新が残ることを仕様化した」テストは差し替えた)。
  世代ディレクトリによる完全な多ファイル原子性は作らない (生成物 2 つに対して過剰)。

## [Warning] 施策 3 無名・重複名の検査母集合が曖昧

- 判断: 対応する
- 対応内容: 母集合を 3 つに分けて表にした。
  web 面に入った無名 / 空名 = **致命**、面の外の無名 route = **許容** (実測 12 件)、
  重複名 = **全 named route を対象に致命** (段 4 の全 route 名参照が曖昧になるため)。
  「面の外に無名 route があっても成功する」テストを追加した。

## [Warning] 施策 5 `correlate.py` との実結合が固定されていない

- 判断: 対応する (結合テスト + 上流での禁止の 2 段)
- 対応内容:
  (a) 自己テストに結合テストを 1 本置く — レンダリングした `operations.md` を一時ファイルへ書き、
      `correlate.py` の `load_operations()` で読み、route 集合の完全一致と
      `story` / `kubun` / `operation` の一致を確認する。
  (b) 散文ノートに `name` / `story` / `区分` を含む表ヘッダがあれば**段 2 の drift** にする
      (下流ローダはヘッダらしい行を見つけるたびに列位置を更新するため、
      ノート側の表が operation として読まれる穴を上流で塞ぐ)。
      結合テストの負の対照としてこの fixture を置く。
