# 対応マトリクス: impl-review Round 2

Round 2 で matcher の過剰一致の指摘は撤回された。残った 3 件はいずれも
**保証範囲の書き方**に関するもので、指摘のとおり誤りだった。

## [Warning] 「台帳テストで完全一致に固定して気づける」は成立しない (AGENTS.md)

- 判断: **対応する**
- 根拠: 指摘のとおりである。台帳テストが固定するのは
  **設定ファイルに書かれた matcher 文字列だけ**で、Claude Code 本体の判定機序が
  変わったことは検出しない。文字列が `Write|Edit` のまま意味だけ変われば緑のままである。
  自分で書いた文が「自動検出がある」と読める以上、これは保証範囲の誇張である。
- 対応内容: `AGENTS.md` §常設 hook 配線 を書き直した。
  (a) 実測は **Claude Code 2.1.233** での挙動であると版を明示、
  (b) **Claude Code を更新したら人手で再確認する**と運用を明示、
  (c) 台帳テストが見るのは設定の文字列だけで**本体側の機序の変化は検出しない**と明記、
  (d) アンカーを足しても意味論の変化は防げない、という理由付けに直した。

## [Warning] 設計 E6 の帰結も同じ理由で誤り

- 判断: **対応する**
- 根拠: 同上。文字列のずれの検出と、本体の意味論のずれの検出は別物である。
- 対応内容: 詳細設計の E6 と「matcher の対象」節の両方を、
  「台帳テストでは守れない / 再確認は Claude Code 更新時の人手の運用で担う」と書き直した。

## [Warning] 実測記録の結論が「自動検出」と読める (matcher-semantics-evidence.md)

- 判断: **対応する**
- 根拠: 同上。
- 対応内容: 結論節を書き直し、「**自動検出は無い**」と明示したうえで、
  再確認の手順 (同文書の「何を見たか」を繰り返す) と、申し送りに載せることを書いた。

## [Suggestion] 訂正表の件数が 5 のまま / E5 と E6 の並びが逆転

- 判断: **対応する**
- 根拠: 記録としての読みやすさの問題であり、直さない理由がない。
- 対応内容: 「5 つ」→「6 件」に直し、E5 → E6 の番号順へ並べ替えた。
