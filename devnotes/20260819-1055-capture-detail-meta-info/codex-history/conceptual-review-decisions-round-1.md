# 対応マトリクス: conceptual-review Round 1

## [Critical] 表示値の意味と期待効果のずれ (使命との整合性)
- 判断: 対応する
- 根拠: 指摘のとおり。未確定カットを除外した部分和を「撮り切ると何分になるか」と説明するのは嘘になる。
  v1 にナレーション尺推定が無い以上、完成見込み尺は原理的に出せない。
- 対応内容: 期待効果の記述を「現時点で尺が確定している素材の合計を把握できる」へ限定した。
  表示は**常に未確定カット数を併記**する形へ変更 (下の Warning と同じ変更)。

## [Critical] 「合計時間」という語が総尺と読まれるリスク
- 判断: 対応する
- 根拠: 部分和であることが値の見た目から分からないのは危険。
- 対応内容: 未確定が 1 件以上あるときは `合計時間 3:20（確定分・未確定 2 カット）` と書く。
  未確定 0 件のときだけ `合計時間 3:20` (このときは部分和ではなく全体の合計なので補足が要らない)。
  ラベル自体を「確定済み素材の合計時間」にはしない — 未確定 0 件が正常な完成状態であり、
  そのときに毎回「確定済み」と断るのは冗長で、かえって読み手に何かの但し書きを探させる。

## [Warning] loadMissing のクエリ数の書き方
- 判断: 対応する
- 根拠: 「固定 2 クエリ」は不正確。既ロードなら 0 件、未ロードなら最大 2 件。
- 対応内容: 記述を「追加は最大 2 件・既ロードなら 0 件」へ修正し、
  詳細画面 1 回ぶんのクエリ数が**カット数・テイク数に比例しない**ことを Pest で固定する項目を追加した
  (一覧側の `CaptureManualListQueryCountTest` と同じ作法)。

## [Warning] 全件未確定のときに件数が出ないと情報量が落ちる
- 判断: 対応する
- 根拠: `—` だけでは「カットが無い」のか「全カット未撮影」なのか区別できない。
- 対応内容: 未確定件数は**常に**併記する。カット 0 件のときだけ `合計時間 —` (未確定も 0 件のため)。
  全カット未確定なら `合計時間 —（未確定 5 カット）`。

## [Warning] レンダ上限ゲートの安全側代用値を表示式へ混ぜる危険
- 判断: 対応する (もともと同じ方針だが明示が足りなかった)
- 根拠: 60 秒代用はゲートの政策であって尺そのものではない。
- 対応内容: 切り出すのは**カット単位の式だけ** (`DeterminedCutDuration`)。
  `?? config('manual.render_default_take_duration_ms')` は `RenderJobService` 側に残すことを明記し、
  ゲートの境界値 (上限ちょうど / 上限 +1ms / duration_ms=null テイク) で挙動不変を固定するテストを追加した。

## [Suggestion] クラス名を性質が読める形にする
- 判断: 対応する
- 根拠: `CutDurationEstimate` の "Estimate" は推定を含意するが、実際は「確定しているか、していないか」である。
- 対応内容: `DeterminedCutDuration` (カット 1 本の確定尺 or null) と
  `DeterminedScenarioDuration` (確定分の合計 + 未確定カット数) に改名した。

## [Warning] updated_at の型契約が未定義
- 判断: 対応する
- 対応内容: DTO は ISO 8601 文字列 or null に正規化する (`?->toIso8601String()` =
  一覧 DTO と同じ形) と明記し、TS 側も `string | null` で対にすることを書いた。

## [Suggestion] テストファーストの手順を明記
- 判断: 対応する
- 対応内容: 「先に赤くしてから実装する」を実装方針へ明記した。

## [Suggestion] 「長すぎるなら分割する」は撮影 PWA の責務を超える
- 判断: 対応する
- 対応内容: 期待効果から「分割する」判断への言及を外し、「気付ける」までに留めた。

## [Suggestion] 型の明示 (total_duration_ms / undetermined_cut_count / *_name)
- 判断: 対応する
- 対応内容: DTO・TS・component props のキーと型を概念設計の段階で明記した。

## [Suggestion] 禁止事項に抵触なし / スコープ妥当 / relation を読まない設計は維持
