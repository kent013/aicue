# 対応マトリクス: conceptual-review Round 3

Critical はゼロ。Warning 4 件はすべて対応した。

## [Warning] sr-only 文言がプラン名を含まないと、対象が DOM 構造依存になる
- 判断: **対応する**
- 根拠: 指摘のとおり。`PricingPlanCard` は semantic group ではないので、
  「このプランが選択されています」だけでは支援技術利用者がテキスト単位で移動したときに
  どのプランを指すかが読み上げ順に依存する。文言に名前を埋めれば構造非依存になる。
- 対応内容: 文言を `{plan.name} プランが選択されています` に変更し、
  「文言にプラン名を含めるのが要点」である理由を施策 C 本文に明記。
  受入条件 9/10 も「**プラン名を含む**選択状態テキスト」に強化した。

## [Warning] 施策 C の見出し「状態を操作要素の側に出す」が改訂内容と食い違う
- 判断: **対応する**
- 根拠: Round 2 で `aria-pressed` (操作要素) から sr-only テキスト (カード見出し領域) へ
  方針を変えたのに、見出しが前案のままだった。設計名と実装の乖離は後で読む人を誤らせる。
- 対応内容: 見出しを「**施策 C: プラン事前選択を、視覚と同等のテキストで伝える (F-2-01)**」に変更した。

## [Warning] 受入条件 11「3 画面の視覚的レンダリングが同一」は証明不能かつ過剰
- 判断: **対応する**
- 根拠: 指摘のとおり 2 点で悪い。(a) 「視覚的に同一」は DOM/レイアウト検査では証明できない、
  (b) コードを 1 行も変えない Billing / Pricing に回帰テストを課すのは分母の水増しになる。
- 対応内容: 受入条件 11 を **Checkout 限定**にし、検査可能な 3 条件へ具体化した ——
  (a) 選択/未選択カードで見出し・価格・選択ボタンの位置とサイズが不変、
  (b) `headerBadges` ラッパが可視領域を持たない (幅・高さ 0)、
  (c) sr-only 文言がスクリーンショットに描画されない。
  併せて「Billing / Guest/Pricing には新規 Browser 回帰テストを課さない」と明記した。

## [Warning] 受入条件 1「撮影パネルが viewport 内に入る」は 1px 交差でも通る
- 判断: **対応する**
- 根拠: 指摘のとおり、交差判定だけだと「スクロールした形にはなったが撮影操作には届かない」
  実装が受入条件をすり抜ける。
- 対応内容: 受入条件 1 を「**撮影パネル先頭の見出しが矩形全体として** viewport 内に入る
  (1px 交差では不可)」に具体化した。あわせて「CameraRecorder 全体の可視は要求しない」と
  明記した (小さい viewport では成立せず、条件として過大になるため。Codex の指摘どおり)。

## [Suggestion] 受け止めたもの
- **`captureActive` の反論はコード提示に依存**しており、Codex 側は行番号と実コードの一致を
  独立検証していない旨の留保が付いた。妥当な留保として受け止める。
  詳細設計フェーズで `CameraRecorder.svelte` の実コード
  (`starting` / `resuming` の代入が `await` より前にあること) を引用して裏を取る。

  (元 finding は「事前選択を確認できない」ことであり、常時アナウンスは今回の範囲外)。
