全体判定: **CHANGES_REQUESTED**

設計の方向性は North Star に強く合っていますが、施策 A/C に a11y と意味論の詰めが不足しています。実装前にここを明確化してください。

## 1. 使命との整合性

[Suggestion] 施策 A は非常に妥当です。撮影 PWA の「カットを選ぶ → 撮る」という主導線の摩擦を減らすため、North Star への貢献は本質的です。

[Suggestion] 施策 B/C も、支援技術利用者が動画確認・契約選択に到達できるようにする改善であり、アプリの品質基盤として妥当です。

## 2. 禁止事項違反

[Warning] 「テストは詳細設計で確定」としている点は弱いです。禁止事項 1 に照らすと、概念設計時点で最低限の回帰固定方針を明示した方がよいです。

修正提案:
- 施策 A: Browser テスト必須。モバイル幅ではカット選択後に撮影パネルが viewport 内へ入ること、lg 以上ではスクロールしないこと。
- 施策 B/C: DOM テストまたは Browser テストで `aria-label` / 状態表明属性を検査。
- Chromium + WebKit の対象範囲も明記。

## 3. 実現可能性

[Warning] 施策 A は `scrollIntoView` だけだと、視覚位置は移動してもキーボード・スクリーンリーダー利用者の現在位置は一覧側に残る可能性があります。これは F-1-03 の修正が新しい a11y 欠落を作るリスクです。

修正提案:
- 撮影パネル先頭に見出しまたはランドマークを置き、必要なら `tabindex="-1"` を付ける。
- タッチ/クリック時のスクロールと、キーボード操作時のフォーカス移動を分けて設計する。
- 少なくとも「選択されたカット」と「次に撮影できる状態」が支援技術に伝わる受入条件を追加する。

[Suggestion] `prefers-reduced-motion` を見る方針は妥当です。`matchMedia('(prefers-reduced-motion: reduce)')` の SSR/ブラウザ境界に注意すれば Svelte 5 で問題なく実装できます。

## 4. 期待効果の妥当性

[Suggestion] 施策 A の効果主張は合理的です。カット数に比例する手動スクロールを消すので、主要ワークフローに効きます。

[Warning] 「次回以降の bug-hunt で再燃しない」は、Browser テストの具体化が前提です。現状の文面だと期待効果として少し先走っています。

修正提案:
- 「再燃しない」ではなく「同一条件を Browser/DOM テストで固定する」に落とす。
- 受入条件を finding ごとに 1 行ずつ明記する。

## 5. リスク

[Warning] 施策 C の `aria-current="true"` は意味論がやや危ういです。プランカードが「現在ページ/現在位置」を示すナビゲーション項目なら妥当ですが、「選択中の選択肢」なら `radio` / `aria-checked`、または選択済みテキストの明示の方が適切な場合があります。

修正提案:
- `PricingPlanCard` の実際の役割を先に分類する。
- 契約中プラン: `aria-current` が妥当か検討。
- チェックアウトの事前選択: 選択肢 UI なら `aria-checked` / radio group 相当、単なる誘導状態なら視覚強調とは別にスクリーンリーダー向けテキストを追加。
- prop 名も `currentLabel` 固定ではなく、意味に合わせて `selectionLabel` / `statusLabel` などを検討する。

[Warning] 「カット一覧へ戻る」を撮影パネル先頭に置く方針は良いですが、録画中・権限ダイアログ表示中・メディア取得中にカット切替やスクロールがどう振る舞うかを詳細設計で確認してください。

修正提案:
- 録画中に別カットを選べる既存仕様か確認する。
- 既存仕様を変えないなら、その前提を明記する。
- 録画中の自動スクロールや戻る操作で状態が壊れないことを受入条件に入れる。

## 6. スコープの適切さ

[Suggestion] スコープは概ね適切です。タブ/ドロワー化を見送る判断は、「今必要なものだけ作る」に合っています。

[Suggestion] bug-hunt 基盤の不具合や仕様未確定項目を分離している点も妥当です。

## 7. 型安全性

[Suggestion] PHP 側に触らず Inertia Props も変えないため、DTO/JsonResource への影響はありません。

[Warning] Svelte 側の prop 追加は TypeScript で明示型を持たせ、未指定時のレンダリング差分が出ないことをテストしてください。

修正提案:
- `PricingPlanCard` の新 prop は optional かつ既定値を明示。
- 呼び出し元 3 箇所の意味差分をテストまたは Story 相当で固定。
- `isHighlighted` と状態表明 prop の責務分離は維持する。
