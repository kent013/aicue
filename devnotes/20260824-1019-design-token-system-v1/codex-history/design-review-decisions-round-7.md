# 対応マトリクス: design-review Round 7 (最終確認ラウンド)

Critical 2 件・Warning 4 件 (行頭ラベルの機械カウント)。**すべて対応する** (反論は 0 件)。

本ラウンドで **12 施策のうち 8 施策が APPROVE** になった
(S1 / S4 / S6 / S7 / S8 / S10 / S11 と施策別表のとおり)。
残った指摘は「公開型の食い違い」と「契約が対象文書を自己拒否する」の 2 系統だけである。

## [Critical] S3 で結果型を導入したのに S2 の公開シグネチャが参照配列のまま

- 判断: **対応する** (正本が二通りに読める状態だった)
- 対応内容: `scanCssVarReferencesSource(source, file)` と `scanCssVarReferences()` の
  戻り値を **`CssVarReferenceScan`** へ統一した。
  利用側は `.references` と `.diagnostics` を**両方とも明示的に消費する**
  (診断の消費先は `token-reference-closure.test.ts`)。

## [Critical] 「行内コード span は 1〜2 個のバッククォート」は誤り / 契約が対象文書を自己拒否する

- 判断: **対応する** (**本ラウンドで最も重い**。指摘は 2 つの事実を含む)
- 事実 1: Markdown の行内コード span は **3 個以上の delimiter も使える**ので、
  「1〜2 個だから誤検出しない」は成立しない。
- 事実 2: **S9 / S11 が `docs/design-system.md` へ足す説明文に 3 連 marker が入っており、
  確定した契約ではその文書自身が診断で必ず赤くなる**。
- 対応内容:
  - 契約を **「正規の top-level fence 行以外に、3 個以上連続した marker を書くこと自体を禁じる」**
    と明記した。3 個以上の delimiter の行内コード span も**拒否例**として固定検体に置く
    (「誤検出しない正例」ではない)。
  - **対象文書へ足す説明文から連続 marker の表記を除いた** — 説明は「囲みコード記法」という語で書く。
    ★これは「検査を緩める」のではなく「**書き方を変える**」対処であり、S9 の一貫した方針と同じである。

## [Warning] S2 のテスト計画に「例外になる」が残り、union コメントも旧定義のまま

- 判断: **対応する**
- 対応内容: 未終端系をすべて「**診断を返し、当該ファイルの `occurrences` / `pairs` は空**」へ統一した。
  `variant-composition` の union コメントも
  「単位内の非空 variant 列の集合 `S` が `|S| >= 2`」の定義へ揃えた。

## [Warning] `var()` 走査が部分文字列一致までしか定義されていない

- 判断: **対応する**
- 対応内容: 受理契約へ 3 条を追加した。
  - **関数トークンの境界**: `var` の直前が識別子文字 (`[A-Za-z0-9_-]`) でも `\` でもなく、
    直後が `(` であること (`myvar(--x)` は参照に数えない)
  - **最初のトップレベルのカンマ** (括弧の深さ 0・引用区間の外) で名前と fallback 全体を分ける
  - 名前は前後の空白を除いた**全体**が `^--[A-Za-z0-9_-]+$` に一致すること
    (`var(--x garbage)` は診断 `unresolvable-var`)
  固定検体に `myvar(--x)` / `var(--x garbage)` / `var(--a, b, c)` を足した。

## [Warning] 「union から機械的に導出」は TypeScript では実行時に不可能

- 判断: **対応する** (指摘のとおり。**網羅の検査そのものが書けない**設計だった)
- 対応内容: **実行時の配列 `UNDECIDABLE_REASONS` を正本**にし、
  `UndecidableReason` を `(typeof UNDECIDABLE_REASONS)[number]["id"]` で導出する。
  fixture の網羅 (「各 reason を発火させる検体が 1 つ以上ある」)・表示ラベル・
  `PENDING_CONTRAST_PAIRS` の説明も**すべてこの配列から導出**する。

## [Warning] S9 の文書修正文が引用 fence だけを禁止対象として説明している / 旧呼称が残る

- 判断: **対応する**
- 対応内容: S9 の説明を「**正規 top-level fence 以外の 3 連 marker**」(引用・リストの中・
  行の途中・行内コードを含む) へ揃え、S9 の施策名・節名、D28、D51 をすべて
  **「規範判定対象外領域」**へ統一した
  (HTML コメントは非描画 / 囲みコードは描画されるが規範の本文として数えない)。
