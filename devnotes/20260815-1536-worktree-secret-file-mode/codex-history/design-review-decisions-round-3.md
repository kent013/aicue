# 対応マトリクス: design-review Round 3

## [Warning] 施策 4: S-3 の assert が `toContain()` で「行の完全一致」になっていない
- 判断: 対応する
- 根拠: 指摘の退行例 `install -m 600 -- "${src}" "${dst}" || true` が部分一致では通る。
  この形は install の失敗を握り潰すので、まさに守りたい契約が抜ける。
  D-11 (書き込み不可ディレクトリで非ゼロ) は root では skip されるため、静的側で閉じる必要がある。
- 対応内容: `/^ {4}install -m 600 -- "\$\{src\}" "\$\{dst\}"$/m` の行アンカー付き完全一致へ変更し、
  なぜ部分一致では駄目かをテストのコメントに残す形で設計へ書いた。

## [Warning] 受入確認 V-4: マージ後の mode 確認が `stat` の表示だけ
- 判断: 対応する
- 根拠: 644 のままでも `stat` は成功するので、マージでの取り込み漏れを偽緑にする。
  V-2 で直した同じ穴が V-4 に残っていた。
- 対応内容: `test "$(stat -c '%a' ...)" = 600` を `&&` の鎖に挟み、終了コードへ反映させた。

## [Suggestion] 受入確認 V-4: 失敗時に残る検証用 worktree の後片付け
- 判断: 対応する
- 根拠: 原因調査のために残るのは正しいが、放置すると孤児テスト DB の元になる。
- 対応内容: 調査後に teardown とブランチ削除で必ず片付ける旨を 1 文足した。
