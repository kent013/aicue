# 概念設計: stale-preview-note (完成動画の直下に矛盾する古いプレビュー注記が残る)

> bug-hunt run 20260812-100645 の **F-1-02 (Medium / H10)** 起点。

## 背景・課題

### 症状 (実走で再現済み)

1. 採用テイク 0 件の時点で 1 度プレビューを生成する (20/20 カットが黒背景)
2. その後 20 カット全てにテイクを撮影・採用する
3. 完成動画を生成 → `published`。完成動画の再生とダウンロードが出る
4. **その直下に**、手順 1 のプレビューと
   「このプレビューは **20 件**のカットに使用できる採用テイクがないため、その区間が黒背景になっています。」
   が**そのまま残る**

利用者は「本当に全カット撮れているのか」を確認できない。実際には全カット採用済みで
完成動画も正しく生成されている (未採用があれば render は 422 でブロックされる)。

### 何が正しくて何が間違っているのか

**注記の値そのものは正しい。** aicue:T148 は `placeholder_cut_count` を
「**生成物の説明であり現在状態から再計算しない**」と決めており、`RenderPanel` の実装も
「注記と動画 URL は同一の `playbackJob` から出す (別世代の値で説明しない)」と明記している。
プレビューは確かに生成時点で 20 件が黒背景だった。

**間違っているのは提示のしかた**である。現在形の文
(「〜ないため、〜黒背景になっています」) を、**現在は解消済みの事実**について書いており、
しかも完成動画の直下に並べている。読み手には「いま 20 件足りない」と読める。

## 改善アイデア

**注記を「生成時点の事実」として書き、解消済みのときだけ現在状態を添える。**

2 段構えにする:

1. **常に**「**生成時点で** N 件のカットが黒背景でした」と書く (現在形をやめる)。
   これだけで「いま N 件足りない」という誤読は全ケースで消える
   (プレビュー生成時 20 件 → 現在 5 件、のような**部分的に解消した場合**にも効く)。
2. **完全に解消しているときだけ** (`placeholder_cut_count > 0` かつ `coverage.missing_count === 0`)、
   「現在のシナリオでは未採用のカットはありません」と再生成の案内を足す。

判定材料は**すでに props にある**:

| 値 | 意味 | 出所 |
|---|---|---|
| `playbackJob.placeholder_cut_count` | **その動画が生成された時点**の黒背景カット数 | T148 の値契約 (再計算しない) |
| `coverage.missing_count` | **描画時点**で採用テイクが無いカット数 | 事前告知 (T148) |

`placeholder_cut_count > 0` かつ `missing_count === 0` のときは、
**そのプレビューの黒背景の理由が現在は完全に解消している**と機械的に言える。
判定名も**その意味のまま**にする (`previewPlaceholderStateFullyResolved`)。
**「プレビューが古い」という一般命題は名乗らない** — それは他の要因
(シナリオ編集・カット追加・テイク差し替え) でも起こり、この 2 値では判定できないからである。

- **`placeholder_cut_count` は再計算しない** (T148 の値契約を守る)。
  足すのは**現在状態の文脈**だけである。
- **プレビュー動画そのものは消さない**。古くても「前はこうだった」を見る価値はあり、
  消すと「なぜ消えたのか」が分からなくなる。
- **サーバ側の変更は 0 行**。判定に要る 2 値は既に `RenderPanel` の props にある。

### 「完成動画があるかどうか」で判定しない

`finishedJob !== null` を条件にする案は採らない。プレビューが古くなるのは
**テイクを採用したとき**であって、完成動画を作ったときではない。
完成動画が無くても (撮影だけ済ませた段階でも) 同じ矛盾は起きるので、
**食い違いそのもの**を条件にするのが正しい。

## 期待効果

- 完成動画の直下で「20 件足りない」と読める表示が消える。
- 完成動画を作っていない段階 (撮影しただけ) でも、古いプレビューの注記が現在と食い違うことが分かる。
- T148 の値契約 (生成物の説明を再計算しない) を**壊さずに**矛盾を解く。

## 実装方針（概要）

| 対象 | 変更 |
|---|---|
| `resources/js/components/features/manual/RenderPanel.svelte` | 注記を常に「生成時点で」に言い換え、完全解消時のみ現在状態と再生成案内を足す |
| `docs/architecture.md` (T148 節) | 「生成物の値は再計算しないが、**現在 coverage との食い違いを表示の文脈として使う**」を明記 |
| `tests/js/components/features/manual/RenderPanel.test.ts` | 契約を固定 |

## 保証しないもの（誇張しない）

- **`placeholder_cut_count` の意味は変えない**。生成物の説明のままで、再計算もしない。
- **「プレビューが古い」ことを判定するものではない**。判定できるのは
  「黒背景があったのに**今は未採用ゼロ**」という**片方向の完全解消**だけである。
  次はいずれも**検出しない** (Codex Round 1 の指摘をそのまま記録する):
  - 生成時 20 件 → 現在 5 件の**部分解消** (ただし「生成時点で」の言い換えは効く)
  - 生成時 0 件 → その後テイク削除/採用解除で現在 > 0 件
  - シナリオ編集・カット追加・テイク差し替えで内容が古くなった場合
- **文言で「古い」と断定しない**。書くのは「生成時点で N 件だった」「現在は未採用なし」という
  **観測できた事実**だけで、そこから先の判断は利用者に委ねる。
- **自動で再生成はしない**。案内を出すだけで、押すかどうかは利用者が決める。
- **サーバの props も 404/認可も変えない**。
