# 対応マトリクス: conceptual-review Round 1

## [Warning] 観点3: 宣言位置判定の「文の先頭」を曖昧語のまま実装しない
- 判断: 対応する
- 根拠: 指摘どおり。判定は閉じた集合として宣言しないと docblock 契約 (走査器共通規約の 4 点目) を満たせない。
- 対応内容: 概念設計を修正。宣言候補とみなす直前有意トークンの集合を
  `null` (ファイル先頭) / `T_OPEN_TAG` / `;` / `}` の 4 形に閉じて明記し、docblock へ
  書くことを契約化した。正例カバレッジは既存検体 (declare の後の宣言 = `;` 形、
  名前つきブロック後のグローバルブロック = `}` 形) で固定済みであることを確認し、
  `T_OPEN_TAG` 直後の宣言形が既存検体に無ければ追加検体のどちらかで補う方針を明記した。
  既存の正しい宣言の退行が無いことは既存検体 12 本の照合の緑で固定する。

## [Warning] 観点4: 「メソッド名など」の識別子文脈が負例で裏取りされていない
- 判断: 対応する
- 根拠: 検出力 (誤検出しないこと) の主張は裏取りした形に限るのが AGENTS.md の規約
  (「検出力の主張の書き方」)。
- 対応内容: `clean-namespace-identifier` 検体へメソッド名 `namespace` の宣言と
  `$this->namespace()` 呼び出しを追加 (メソッド名は半予約語として合法であることは
  実装時に検体の php -l 構文妥当性検査が固定する)。裏取りする識別子文脈を
  「定数名・自クラスの定数参照・メソッド名の宣言と呼び出し」に列挙し、
  それ以外 (enum case 名・trait 別名・名前つき引数など) は「同原理だが個別には
  裏取りしていない」と docblock で限定する形に概念設計を修正した。

## [Warning] 観点5: `}` の直後は宣言の構文的位置を完全には表せない
- 判断: 対応する
- 根拠: 指摘のとおり `}` は class / function / 制御構文いずれも閉じ得るので、
  この判定は宣言の確定ではない。
- 対応内容: 概念設計に「このガードは宣言であることの確定ではなく、識別子として
  無視しない候補抽出である」と明記し、docblock 契約に含めた。宣言候補で形を成さない
  ものは従来どおり unresolved (fail-closed) を維持し、構文不正な namespace 配置は
  検体の構文妥当性検査 (php -l 終了コード) と真値照合の不一致で捕まることを追記した。

## [Warning] 観点6: 採用時債務→逸脱登録の切り替えは登録内容を具体化する
- 判断: 対応する
- 根拠: 件数操作だけの登録は追跡不能で、登録簿の書式 (9 行メタ表 + 再判定条件必須) にも
  合わない。
- 対応内容: 概念設計に登録へ書く内容 (対象パス / テンプレートとの差異 / 維持する理由 /
  再判定条件) と「登録・債務 1 行削除・pin 更新を同一変更で行う」ことを明記。
  D 登録の全文は詳細設計で起草する。
