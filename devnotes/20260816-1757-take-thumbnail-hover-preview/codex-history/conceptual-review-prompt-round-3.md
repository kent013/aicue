# Round 3: Round 2 指摘への対応

Round 2 の [Warning] 2 件と [Suggestion] 2 件をすべて**対応**しました。

## 対応マトリクス

### [Warning] `<video>` を mount するだけでは自動再生されない
- 判断: **対応する**
- 対応内容: 属性を `autoplay muted loop playsinline preload="metadata"` と明示し、
  「`muted` / `playsinline` は許可されやすくなる条件であって再生開始そのものではない。
  **開始の手段は `autoplay` 属性**である」と設計に書いた。
  併せて失敗時の扱いを規定: 自動再生拒否・取得失敗は `onerror` で video を unmount し `<img>` へ戻す。
  `poster` に同じサムネイルを張ってあるため見た目の落差も出ない。
  **エラー文言・トーストは出さない** (補助的な確認手段の失敗が編集作業を妨げない)。

### [Warning] `event.buttons === 0` を pointerenter でだけ見てもドラッグ中の起動を防げない
- 判断: **対応する**
- 対応内容: 停止条件に **`pointerdown`** を追加 (計 5 つ)。さらに
  **滞留タイマー満了時にも起動条件 (ホバー継続 / ボタン非押下 / reduced-motion) を再評価する**と規定。
  「入口で 1 回」ではなく「入口 + 満了時」の 2 点判定にした。
  `visibilitychange` の listener は component 破棄時に必ず外すことも明記。

### [Suggestion] 期待効果の表現が言い過ぎ
- 判断: **対応する**
- 対応内容: 「カットの文言を直すか撮り直すかの判断が 1 画面で完結する」を削り、
  「**採用テイクの撮れ高**をシナリオと同じ画面で確認できるようになり、そのカットのために
  画面遷移する往復が消える (未採用テイクの比較はテイク選択画面の仕事なので、
  『判断がここで完結する』とは書かない)」に書き換えた。

### [Suggestion] DTO 変換テストの母数 / visibilitychange リスナ破棄のテスト
- 判断: **対応する** (詳細設計のテスト計画で確定させる)
- 対応内容: DTO 変換テストは 4 ケース固定 (採用なし / ready+サムネイルあり / ready+サムネイルなし /
  非 ready)。フロント側は「再生エラー時の停止」「visibilitychange リスナの破棄」もテスト対象に含める。

## 修正後の該当箇所 (全文)

### 期待効果 (書き換え後)

- **使命への貢献**: 「編集ゼロ」。編集者が**採用テイクの撮れ高**をシナリオ (台本) と同じ画面で
  確認できるようになり、そのカットのために画面遷移する往復が消える
  (未採用テイクの比較はテイク選択画面の仕事なので、「判断がここで完結する」とは書かない)。
- 静止画では区別できない「本当に狙った動きが撮れているか」を、押す前に確認できる。
- 動画列に「このカットの採用テイク」が視覚的に出るため、採用済み / 未採用の区別がバッジの文字だけで
  なくなる。

### 実装方針 2. ホバー自動再生 component (書き換え後・全文)

`resources/js/components/features/manual/TakeHoverPreview.svelte` (features/manual 層)。

- 既定は `<img>` (静止サムネイル)。
- 起動条件は 3 つすべて成立したときだけ:
  1. `pointerType === "mouse"` (タッチ・ペンは起動しない)
  2. `event.buttons === 0` (ボタンが押されている間は起動しない = ドラッグ中・範囲選択中は動かない)
  3. `prefersReducedMotion() === false`
- 上記の成立後 **200ms の滞留**を待ち、**満了時にも起動条件を再評価**してから `<video>` を
  差し替えで mount する (入口で 1 回だけ見ると「入った直後にドラッグを始めた」経路で
  ドラッグ中に mount されてしまう)。
- 属性は **`autoplay muted loop playsinline preload="metadata"`**、`controls` なし、
  `poster` に同じサムネイル URL。`muted` / `playsinline` は自動再生が**許可されやすくなる条件**であって
  再生開始そのものではないため、**開始の手段は `autoplay` 属性**であることを明記する。
- **失敗しても静かに静止画へ戻す**: 自動再生が拒否された / 動画の取得に失敗した場合は
  `onerror` で video を unmount して `<img>` へ戻す。`poster` に同じサムネイルを張ってあるので
  見た目の落差も出ない。**エラー文言・トーストは出さない**。
- **停止条件は 5 つ**で、どれでも「滞留タイマーの clear」と「video の unmount」を必ず両方行う:
  `pointerleave` / `pointercancel` / **`pointerdown`** / component の破棄 /
  ページ非表示 (`visibilitychange`)。`visibilitychange` の listener は破棄時に必ず外す。
- 主張の粒度 (誇張しない): `<video>` はホバー中しか DOM に存在しないので
  **1 コンポーネントにつき高々 1 本**である。画面全体で 1 本に収まるのは
  「マウスが同時に 1 か所しかホバーできない」ことに依る性質であり、
  コンポーネント側が画面横断で相互排他を保証しているわけではない。
- 再生 URL は既存の `capture.takes.playback` (302 → 署名 URL)。props に署名 URL を載せない。
