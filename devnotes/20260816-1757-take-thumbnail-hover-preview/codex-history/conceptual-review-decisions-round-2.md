# 対応マトリクス: conceptual-review Round 2

Codex 全体判定: CHANGES_REQUESTED (Round 1 の 3 件は解消と確認された。新規 [Warning] 2 件)

## [Warning] `<video>` を mount するだけでは自動再生されない (autoplay / play() の規定が無い)

- 判断: **対応する**
- 根拠: 指摘のとおり。`muted` / `playsinline` は自動再生が**許可されやすくなる条件**であって
  再生開始そのものではない。設計に再生開始の手段が書かれていなかったのは欠落である。
- 対応内容: `autoplay` 属性を明示した (`autoplay muted loop playsinline preload="metadata"`)。
  併せて**失敗時の扱い**を規定した — `autoplay` が拒否された / 動画取得に失敗した場合は
  `poster` に張った静止サムネイルがそのまま残る。`onerror` で video を unmount して `<img>` へ戻し、
  **エラーを画面へ波及させない** (トースト・エラー文言を出さない。ホバーは補助的な確認手段であり、
  失敗しても編集作業を妨げてはならない)。

## [Warning] `event.buttons === 0` を pointerenter でだけ見てもドラッグ中の起動を防げない

- 判断: **対応する**
- 根拠: 指摘の順序 (enter → 200ms 以内に pointerdown → タイマー満了 → mount) は実際に起きうる。
  起動条件を「入った瞬間」だけで評価したのは設計の穴である。
- 対応内容: 停止条件に **`pointerdown`** を追加し (計 5 つ)、さらに
  **タイマー満了時にも起動条件 (ホバー継続中 / ボタン非押下 / reduced-motion) を再評価する**と規定した。
  「入口で 1 回」ではなく「入口 + 満了時」の 2 点で判定する。

## [Suggestion] 期待効果の「文言を直すか撮り直すかの判断が完結する」は言い過ぎ

- 判断: **対応する**
- 根拠: 未採用テイクを比較できない以上、「判断が完結する」は常には成立しない。
  部分充足を明記した直後の節で過大な効果を書くのは一貫性を欠く。
- 対応内容: 「採用テイクの撮れ高をシナリオと同じ画面で確認できる」に書き換えた。

## [Suggestion] DTO 変換テストの母数 4 パターン / visibilitychange リスナ破棄のテスト

- 判断: **対応する** (詳細設計のテスト計画へ反映)
- 対応内容: DTO 変換テストは「採用なし / ready+サムネイルあり / ready+サムネイルなし / 非 ready」の
  4 ケースを固定する。フロント側は「再生エラー時の停止」「visibilitychange リスナの破棄」を
  テスト対象に含める。
