# 対応マトリクス: conceptual-review Round 3

Codex 全体判定: CHANGES_REQUESTED (残 1 件。Round 2 の D&D 指摘は解消と確認された)

## [Warning] 自動再生の拒否は `error` イベントでは検出できない

- 判断: **対応する**
- 根拠: 指摘は Web API の事実として正しい。自動再生ポリシーによる拒否では `<video>` が静止したまま
  残り `error` は発火しない。`onerror` に拒否検出を担わせた設計は誤りだった。
- 対応内容:
  - `autoplay` 属性を**削除**し、**再生開始の正本を `play()` の明示呼び出し**に一本化した
    (`el.muted = true; void el.play().catch(stopPreview)`)。開始経路を 2 本持たないことで
    拒否の検出点も 1 つに定まる。
  - 失敗経路を 2 つに分けて明記した — 自動再生の拒否 = `play()` の Promise rejection /
    取得・デコードの失敗 = `error` イベント。**どちらも同じ `stopPreview()` へ流す**。

## [Suggestion] タイマー満了時の「ボタン非押下」は保存した event の buttons を読み直さない

- 判断: **対応する**
- 根拠: 過去のイベントオブジェクトを現在の状態の代理にするのは、まさに「値が古い」型の欠陥である。
- 対応内容: 満了時に見るのは「**タイマーがまだ生きていること** (= `pointerdown` に破棄されていない)」と
  「ホバーが継続していること」だけにした。`pointerdown` が停止条件としてタイマーを破棄することを
  保証の実体にする、と設計へ明記した。
