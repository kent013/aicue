# 対応マトリクス: conceptual-review Round 4

## [Warning] 古い `play()` の rejection が新しいプレビューを停止させる

- 判断: **対応する**
- 根拠: 指摘の順序 (A 再生 → unmount → B mount → A の rejection 到着 → B が止まる) は実際に起きうる。
  `stopPreview()` を冪等にしても「古い試行が現在の試行を止める」問題は解けない。世代の識別が要る。
- 対応内容: 失敗の処理は「**現在 mount されている video 要素と同一のときだけ**」行うと規定した
  (要素の同一性で世代を判定する。`error` イベントも同じ規則)。
  component 破棄後に到着した完了・失敗は何もしない、も明記。

## [Warning] タイマー満了時の再評価条件の記述が矛盾している

- 判断: **対応する**
- 根拠: 前半で「起動条件を再評価」と書きながら、後半で見るものを 2 つに限定していた。
  200ms の間に `prefers-reduced-motion` が `reduce` へ変わった場合の仕様が定まっていなかった。
  これは私の記述の不整合であり、指摘は正しい。
- 対応内容: 満了時に確認するものを**明示的に 3 つ**へ確定した —
  (1) タイマーが無効化されていない / (2) ホバーが継続している / (3) `prefersReducedMotion() === false`。
  ボタンの押下状態だけは満了時に読み直さず、`pointerdown` によるタイマー破棄で保証する、と
  切り分けを明記した。
